# 10-day plan — ship a real demo

**Goal:** A mentor can assign a course, a mentee can learn through **real** progress
(not localStorage / scroll bars pretending to be completion), chapters **lock** until the
previous one is done, and a mentee can **ask the mentor for help**. The UI looks consistent
enough to put in front of people.

This is a **demo-first** cut of M3–M7. Ship the mandatory loop. Do not rewrite the stack.
Do not polish every one of the ~350 chapters.

**Reads:** [`../04-progress-and-gating.mdx`](../04-progress-and-gating.mdx),
[`../09-security.mdx`](../09-security.mdx), [`../11-decisions-and-open-questions.mdx`](../11-decisions-and-open-questions.mdx)

## What is already true (keep this)

The app is past a scaffold. Do **not** throw it away.

- Auth, roles, enrollments, invites, review queue, reports, MDX reader, and a real course import
  all exist.
- Quizzes, predict, open questions, and code exercises already POST to
  `/api/blocks/[blockId]/respond` and write append-only `Response` rows.
- Open questions already restore the latest attempt after a reload.
- **Postgres stays.** The LMS is relational (enrollment → chapter progress → responses →
  reviews). The *course content* teaches MongoDB for FreshMarket; that is the student's
  project, not our database. Switching the LMS to NoSQL would burn the demo window and
  break reports, gating, and Prisma. See the decision log.

## What is actually broken (why it feels like a basic demo)

Diagnosed 2026-09-22:

1. **Progress is fake in the places people look.**
   - The reader progress bar is **scroll position**, not checkpoints.
   - Checklists save in **localStorage** ("progress saves in your browser").
   - Quiz / Predict / Code reset on reload — they do not restore the latest `Response`.
   - The chapter reader hardcodes `blockCount: 0`, so the sidebar never shows exercises.
   - `recomputeChapterProgress` counts **every** block, including presentational ones
     (`STEPS`, `PROJECT_PREVIEW`, `LEARNING_OBJECTIVES`, `CHAPTER_RECAP`) that never get a
     response. Those chapters **cannot** complete. Course `%` therefore stays near zero.
   - Prose-only chapters have no "Mark complete" action, so sequential gating would
     deadlock even after the count bug is fixed.
2. **Locking is not enforced.** `Course.sequential` exists. There is no `gate.ts`. The
   chapter loader never 403s. Next/prev links always work. Sidebar has no lock icons.
3. **Ask-the-mentor does not exist.** Review queue is only for graded open questions, not
   "I'm stuck on this chapter."
4. **UI is inconsistent.** Learner dashboard, reader, and mentor tools share a palette but
   not a structure (different cards, missing empty states, reader vs. main-nav shells).
5. **Some chapters fail to render** (unknown MDX / escaped tags). The error boundary is a
   generic amber card. `Predict` is missing from MDX block extraction.
6. **Content is uneven.** A full-course improvement program runs via `content/import/STYLE.md`
   and `pnpm content:audit`; demo path modules 01–03 are hardened first.

## Database decision (do not reopen during these 10 days)

**Keep Postgres + Prisma.**

| If we switched to Mongo / NoSQL | Cost |
|---|---|
| Re-model Enrollment, ChapterProgress, Response, Review, BlockStats | Days of schema + rewrites |
| Lose SQL rollups that reports already read | Reports have to be rebuilt |
| Break Auth.js Prisma adapter sessions | Auth work we already have |
| Zero demo benefit | FreshMarket (the *course*) already teaches Mongo |

Use Mongo in the **student project**. Use Postgres for **buildment**.

## Demo the 10 days must support

A 15-minute walkthrough:

1. Sign in as mentee (dev login).
2. Open the course. Chapter 2+ show **locked** until chapter 1 is complete.
3. Complete chapter 1 (quiz / mark complete). Sidebar ticks green. Chapter 2 unlocks.
4. Reload — the quiz still shows the submitted answer.
5. Click **Ask mentor** from a chapter. Mentor sees it and replies.
6. Mentor dashboard shows real `%`, not zeros. Review queue still works.

## Day 1 — Real progress (not static components)

**Ship criterion:** Answering a quiz, then reloading, still shows the answer, and the
sidebar/course `%` moves. Presentational blocks no longer trap a chapter at 0%.

- [x] Split completable vs presentational block types in `server/progress/rules.ts`.
- [x] Recompute chapter progress from **required completable** blocks only.
- [x] Restore latest Quiz / Predict / Code responses in the reader (Open Question already
      does this).
- [x] `router.refresh()` after a successful submit so the sidebar updates without a
      full navigation.
- [x] Pass real `blockCount` + status into the chapter sidebar (stop hardcoding `0`).
- [x] Persist checklists to `ChapterProgress` (same JSON channel as the learning log) so
      they survive devices, not just one browser.
- [x] "Mark chapter complete" for chapters with zero completable blocks.
- [x] Unit tests for completion math (presentational blocks ignored, mark-complete, scores).

**Out of scope today:** locking, help threads, content rewrites.

## Day 2 — Chapter locking (server-enforced)

**Ship criterion:** With `Course.sequential = true`, chapter N+1 does not render MDX until
chapter N is `COMPLETED`. Direct URL access shows a locked screen, not the content.

- [x] `server/progress/gate.ts` — sequential lock from flattened module/chapter order.
- [x] Chapter loader: if locked, **do not compile/send MDX**. Show a locked screen with a
      link to the previous chapter.
- [x] Reject `POST /api/blocks/[blockId]/respond` on a locked chapter (403).
- [x] Lock icons on syllabus + sidebar. Next-chapter CTA disabled until current is complete.
- [x] Visiting an unlocked chapter marks it `IN_PROGRESS` (started).
- [x] Unit tests for lock-set calculation (first chapter free, gap locks the rest).

**Out of scope today:** `<Test>` block type, heartbeat, nightly cron.

## Day 3 — Ask the mentor

**Ship criterion:** From any unlocked chapter, a mentee sends a question. The mentor
answers it. The mentee sees the reply on reload.

- [x] `HelpThread` + `HelpMessage` models (course + optional chapter, append-only messages).
- [x] Mentee: **Ask for help** in the chapter header (modal help note).
- [x] Mentor: **Mentee requests** at `/help` (nav badge), oldest-open first, reply box.
- [x] Mentee: **My help notes** at `/my-questions`.
- [x] Auth through `guards.ts` + `server/help/access.ts` (mentor of course / enrolled mentee).
- [x] Empty states: no questions yet / all resolved.
- [x] Tests: mentee cannot read another mentee's thread; mentor cannot reply on a course
      they don't own (`server/help/access.test.ts`).

**Do not build:** realtime chat, file uploads, email notifications (log the link like
invites do).

## Day 4 — Learner UI consistency

**Ship criterion:** Dashboard, syllabus, reader, and progress page feel like one product.

- [x] Reader header shows **checkpoint progress** (2/4) plus the existing scroll bar.
- [x] Progress page: per-chapter list, not only a course `%` bar.
- [x] Dashboard "Continue" lands on the first incomplete *unlocked* chapter.
- [x] Mobile: sidebar becomes a sheet; TOC collapses by default under `md`.
- [x] Empty states already on dashboard/progress stay; add them anywhere a list can be
      empty.
- [x] Kill leftover copy like "progress saves in your browser."
