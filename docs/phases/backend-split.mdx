# Backend split

Buildment currently runs UI and backend in one Next.js process. We are splitting it into two
deployables so the API can serve the web app, a future desktop app, and third parties (Pathment
already calls `/integrations/v1`).

```
buildment/
├─ frontend/   Next.js app — UI only, talks to the API over HTTP; own package.json + lockfile
│  └─ src/shared   committed copy of server/src/shared (generated by `pnpm sync-shared`)
├─ server/     Express 5 + TypeScript API — owns Prisma, auth, email, jobs, scripts; own lockfile
│  └─ src/shared   the contract code both apps run (block schemas + graders, API wire types,
│                  enums, MDX block extraction, pure helpers)
├─ content/    course source material (imported by server scripts)
└─ docs/
```

## Revision — no workspace package (2026-10-13)

The phases below were built with a third workspace package, `@buildment/shared`, linked into both
apps with `workspace:*`. That link made neither folder deployable on its own: Vercel with Root
Directory `frontend` and Heroku from `server` both failed at install because the package lived
outside the folder. The package was folded into the server:

- `server/src/shared` is the single source. The server imports it relatively.
- `frontend/src/shared` is a committed copy written by `server/scripts/sync-shared.mjs`
  (relative imports lose their `.js` suffix for Next.js, and every file gets a "generated" header).
  CI runs `pnpm sync-shared:check` and fails when the copy is stale.
- The root `pnpm-workspace.yaml` and lockfile are gone; each app has its own lockfile, Dockerfile
  and `.dockerignore`, and the root `package.json` only keeps convenience scripts.
- `server/prisma.config.ts` falls back to a placeholder URL so `prisma generate` works in any
  install without a database.

Where the sections below say `@buildment/shared`, read `src/shared` in either app.

## Decisions

- **TypeScript on the server.** Every backend module is already TS with Prisma-generated types,
  and block grading schemas are shared with the UI. A JS rewrite would drop that safety for no
  gain.
- **Zod, not Joi, for request validation.** Same pattern as Pathment (`validations/` schemas,
  `validateBody/Query/Params` in routes), but Zod because it is already the project's validation
  library, infers TS types, and the block payload schemas live in `shared/`.
- **Layering:** `routes → validations → controllers → services`. Controllers never touch Prisma.
  Services throw typed errors from `utils/errors`; the global error handler maps them to one
  envelope.
- **Response envelope (first-party API `/api/v1`):**
  success `{ success: true, data }`, error `{ success: false, message, code, errors? }`.
  The public organisation API (`/integrations/v1`) keeps its existing snake_case bodies and
  `{ error }` shape — Pathment depends on it.
- **Sessions:** opaque token in the existing `Session` table (30 days). Accepted as
  `Authorization: Bearer <token>` (desktop / third party) or the `authjs.session-token` cookie
  (web). Since Phase 2 the API issues them: password login, signup, email verification, magic
  links and logout live under `/api/v1/auth`; the web app holds only the cookie and asks
  `/auth/me` once per request (React `cache()`).
- **Web wiring:** Next.js rewrites `/api/v1/*` and `/integrations/v1/*` to `API_URL`. Browser code
  keeps calling same-origin paths; the proxy forwards cookies, so no CORS or token juggling in
  the browser. Desktop/third-party clients call the API host directly.
- **ESM throughout** (`unified`/`remark` are ESM-only). Server and shared compile with `tsc`;
  dev runs through `tsx`.
- **Prisma lives in `server/prisma`.** During the migration (until Phase 6) the
  schema has a second, clearly-marked generator that emits a client into `frontend/`.
- **pnpm uses the hoisted linker** (`.npmrc`). Turbopack could not resolve `next` through pnpm's
  isolated symlink layout on an ntfs3 checkout; a flat `node_modules` with the monorepo as
  `turbopack.root` builds everywhere. Webpack builds were unaffected either way.

## Phases

| # | Scope | Exit criteria |
|---|-------|---------------|
| 1 | Repo restructure, `shared/`, server foundation (config, logger, errors, responses, validate, auth + integration-credential middlewares, rate limits, error handler), port every endpoint the browser/Pathment already calls over HTTP, Next proxy, tests | Both apps build; unit + supertest suites green; chapter reader submits blocks / timers through the API; Pathment endpoints byte-compatible |
| 2 | Auth owned by the API: signup, login, logout, verify/resend, `me`, dev-login; frontend drops Auth.js, keeps a thin cookie + `apiFetch` | Login/signup/logout work via API; no `next-auth` import left |
| 3 | Learner domain: dashboard, catalog, course overview, chapter reader data, progress actions, study timers, help threads, learning log, heading notes, weekly goal, enroll/checkout, profile | Learner pages render from API responses only |
| 4 | Instructor domain: courses/modules/chapters CRUD + block sync, mentees, invites, review queue, AI review draft, reports export, nudges, instructor access | Teach pages render from API only |
| 5 | Admin domain: organisations, credentials, allocations, users, requests | Admin pages render from API only |
| 6 | Cleanup & ops: remove Prisma and `src/server` from frontend, delete the transitional generator, move scripts/seeds to server, in-process job scheduler, Docker/deploy files, docs refresh | Frontend has no DB dependency; CI runs both suites; deploy docs updated |

### Phase 2 — auth endpoints

| Endpoint | Notes |
|---|---|
| `POST /api/v1/auth/signup` | 201 `{ email, status: verified \| verification_sent }`; 409 `EMAIL_TAKEN` |
| `POST /api/v1/auth/login` | sets the cookie and returns `{ user, session: { token, expiresAt } }`; 401 `INVALID_CREDENTIALS`, 403 `EMAIL_UNVERIFIED` |
| `POST /api/v1/auth/logout` | deletes the session row, clears the cookie |
| `GET /api/v1/auth/me` | current user; activates seeded / no-email-delivery accounts |
| `POST /api/v1/auth/resend-verification` | with `email`: always 200; signed in: 400 `ALREADY_VERIFIED` when nothing to do |
| `POST /api/v1/auth/magic-link` | always 200; `GET /magic-link/verify?token=` signs in (creating the account like Auth.js did) |

Server Actions in the frontend call these through `serverApiFetch` and store the returned token
as the cookie themselves; `next-auth` and `@auth/prisma-adapter` are gone. Browser-facing API
redirects (dev login, email confirmation, magic-link verify) are relative so they resolve against
whatever host the web app is served from.

### Phase 6 — cleanup and operations

- Content and seed scripts moved from `frontend/scripts` to `server/scripts` (typechecked with
  the API, run with `tsx`); the chapter validator now compiles with `@mdx-js/mdx` exactly like
  publish does. The transitional Prisma generator, the frontend's generated client and its
  Prisma dependencies are gone, and `frontend/.env.example` has no `DATABASE_URL`.
- The 52 re-export shims under `frontend/src` were removed; importers name the
  `@buildment/shared` module directly. `frontend/src/server` now holds only Server Actions
  (API wrappers) and the session/surface guards.
- Background jobs run inside the API (`src/jobs/scheduler.ts`) at a configurable UTC hour;
  `JOBS_ENABLED=false` hands the schedule to an external cron hitting `/api/v1/jobs/*`.
- Deployment: `server/Dockerfile` and `frontend/Dockerfile` (Next.js standalone output), a root
  `.dockerignore`, `docker compose --profile app` for the full stack with migrations, and
  `.github/workflows/ci.yml` running typecheck, lint, all suites against Postgres, both builds and
  both images.

- `shared`: 67 tests. `frontend`: `tsc` clean with no Prisma dependency, 68 unit tests, Turbopack

### Phase 5 — admin endpoints

Every admin page renders from `/api/v1/admin` behind an ADMIN-only middleware. With this phase no
file under `frontend/src` reads the database any more; `src/server/db.ts` is gone and only the
transitional Prisma generator output remains for the content scripts (Phase 6).

| Endpoint | Serves |
|---|---|
| `GET /api/v1/admin/overview` · `GET /courses` | tile counts and shell badges, read-only course catalog |
| `GET /api/v1/admin/organizations` · `POST /organizations` · `GET /:orgId` | tenants; creation returns the first credential pair (the secret is visible only in that response) |
| `POST /api/v1/admin/organizations/:orgId/credentials/rotate` · `PUT /:orgId/allocations` | credential rotation, bulk course allocations (422 `COURSE_NOT_PUBLISHED`) |
| `GET /api/v1/admin/course-requests` · `POST /:id/approve` · `POST /:id/reject` | the organisation course request queue (409 `REQUEST_ALREADY_REVIEWED`) |
| `GET /api/v1/admin/users` · `PATCH /users/:id/instructor-access` · `POST /instructors` | accounts, instructor capability, grant by email |
| `POST /api/v1/admin/instructor-access-requests/:id/approve` · `/reject` | learner requests for instructor tools |

The admin Server Actions stay form handlers that throw on failure (the pages have no inline
error state); they call the API through `src/server/actions/admin/call.ts`.

### Phase 4 — instructor endpoints

enrollment ownership (the API answers 403). The only Prisma reads left in `frontend/src` belong
to the admin pages and actions (Phase 5).

| Endpoint | Serves |
|---|---|
| `GET /api/v1/teach/workspace` · `GET /courses` · `POST /courses` | sidebar courses + access state, course list, create |
| `GET /api/v1/teach/courses/:slug/builder` · `PATCH /:id/settings` · `POST /:id/publish` · `/unpublish` · `/restore` | course builder and lifecycle (422 `COURSE_NOT_PUBLISHABLE` lists the reasons) |
| `POST /api/v1/teach/courses/:id/modules` · `PATCH /modules/:id` · `POST /modules/:id/move` | modules (409 `ALREADY_AT_EDGE`) |
| `POST /api/v1/teach/courses/:id/chapters` · `POST /chapters/:id/move` · `GET /chapters/:id/editor` · `PATCH /settings` · `PUT /draft` · `POST /publish` | chapter editor: draft autosave with block sync, publish validation (MDX compile, component allowlist, block configs) |
| `GET /api/v1/teach/courses/:slug/mentees` · `GET /mentees/:enrollmentId` | roster with attention flags, mentee evaluation |
| `POST /api/v1/teach/courses/:id/invites/assign` · `POST /invites/link` · `DELETE /invites/:inviteId` | assignment by email, reusable invite link, revoke |
| `POST /api/v1/teach/enrollments/:id/nudge` · `POST /repair-progress` | check-in email, rollup repair |
| `GET /api/v1/teach/courses/:slug/reports` · `GET /reports/export` (CSV) · `GET /activity` | course insights |
| `GET /api/v1/teach/review` · `GET /review/:id` · `POST /review/:id` · `POST /review/:id/ai-draft` | review queue, verdicts, OpenRouter draft (keys live in the server env) |
