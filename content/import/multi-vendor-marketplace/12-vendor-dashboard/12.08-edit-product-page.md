# 12.8 — Edit product page

> **[Build]** · Chapter 12 — Vendor dashboard · *Pre-fill + PATCH*

Vendors change prices and stock every day. The edit page loads an existing product, lets them update fields, and saves with PATCH — the same round-trip pattern as store settings in Chapter 10.

<BigWordAlert term="Edit form prefill" plainEnglish="Loading existing product into form fields via GET, then PATCH on save." whyItMatters="FreshMarket edit page must not reset fields to empty — fetch before render." />

## Target UI preview

![Edit product — UI preview](/showcase/multi-vendor-marketplace/edit-product-page.png)

*Production-style UI preview — pre-filled form, Published toggle, Save button.*

---

## Step 1 — Create EditProduct.jsx

**Route:** `/vendor/products/:id/edit`  
**Link from:** Edit button on product list (12.6)

Same form fields as create (12.7) — pre-filled instead of empty.

---

## Step 2 — Load product data

**MVP approach:** On mount, call `listVendorProducts()` and find the product where `_id === params.id`.

| Result | UI |
|---|---|
| Found | Pre-fill form |
| Not found | "Product not found" + link back to list |
| Loading | Spinner |

Alternative: add `GET /vendor/products/:id` if you built one — either works.

---

## Step 3 — Pre-fill the form

Copy values into controlled inputs:

- name, description, price, unit, stockQty, isPerishable, weightOrQuantity

Do **not** expose `_id` or `storeId` as editable fields.

---

## Step 4 — Save with PATCH

Add to `api/products.js`:

```javascript
updateProduct(id, data) → PATCH /api/products/:id
```

```
onSubmit:
  1. updateProduct(id, formData)
  2. 200 → navigate to /vendor/products (list refetches)
  3. 400 → field errors
  4. 403/404 → error banner
```

---

## Step 5 — Optional delete button

If you add delete:

- Confirm dialog
- `DELETE /api/products/:id`
- Navigate to list on 204

Not required for gate if edit + publish are working.

---

## Step 6 — Verify round-trip

1. Change price on edit page → Save
2. List shows new price
3. Hard refresh edit URL — still loads correct product
4. Wrong id in URL → friendly not-found page

---

## Common mistakes

| Mistake | Fix |
|---|---|
| Allow editing storeId | Server-owned — read only |
| Stale list after save | Refetch on navigate back |
| Invalid ObjectId in URL | Show 404 UX |
