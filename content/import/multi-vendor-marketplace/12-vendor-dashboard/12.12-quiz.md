```quiz
type: mcq
id: q1
question: Maya submits the Add product form with price -2 and an empty stock quantity. POST /products returns 400 with errors listing both fields. What should the form do?
options:
  - "Show each message under its field and keep the values"
  - "Show a single banner with the raw error JSON, clearing the form"
  - "Redirect to the login page and retry the POST one time"
  - "Treat it as a network failure and offer a retry button"
correct: 0
explanation: "A 400 means the request was understood but the fields failed validation, and the error body names those fields, so each message belongs beside its own input while the rest of Maya's typing survives. A banner of raw JSON hides which field is wrong, and the other two files diagnose the wrong status family: a retry only resends the same invalid body, and a 401 would have arrived as a 401."
```

```quiz
type: mcq
id: q2
question: Maya flips Published on Organic Kale and the badge turns green at once. The PATCH that follows comes back 500. What should the toggle and the page do?
options:
  - "Leave it published and let the next list refetch correct it"
  - "Revert the switch and show a save-failed message"
  - "Log out at once so the stale session cannot retry"
  - "Delete the row and re-create it after the network recovers"
correct: 1
explanation: "The toggle was optimistic, so the UI claimed Published before the server agreed; when the PATCH fails the control has to fall back to Draft and say why, or the screen disagrees with the database. Hoping a later refetch repairs it leaves a green Published switch over a draft product, and a 500 is a server problem, so dropping a working login or deleting the row destroys real data over a retryable failure."
```

```quiz
type: mcq
id: q3
question: Maya opens a bookmarked /vendor/products/64b.../edit, but that id belongs to a product she deleted last week. Her own product list loads fine and contains no match. What should the edit page render?
options:
  - "A 'Could not reach server' banner with a retry button"
  - "An empty create form that POSTs the id as a new draft"
  - "A login redirect, because a 404 means the session expired"
  - "Product not found, plus a link back to the list"
correct: 3
explanation: "The edit route fills its form from the vendor-scoped list, so an id that is not in that list is not a product this vendor can edit — that is a not-found state, not a server failure. A retry banner points at the network that is already working, an empty form quietly turns a dead link into a duplicate draft, and a 404 says nothing about the session, which is why logging Maya out is the worst option here."
```
