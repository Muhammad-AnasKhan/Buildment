```quiz
type: mcq
id: q1
question: "A shopper bought 2 kg of Organic Tomatoes at ₹350/kg last week. The vendor now charges ₹400/kg and has unpublished the item. What should that line show on /orders today?"
options:
  - "The live price of ₹400/kg, fetched once per line from /products"
  - "Today's catalogue price, with the line hidden because it is delisted"
  - "Stored snapshot fields only: ₹350/kg, qty 2, plus a product link"
  - "A total recomputed from current catalogue prices for every line"
correct: 2
explanation: "The order is a receipt, so nameAtPurchase, priceAtPurchase and unitAtPurchase still render ₹350/kg even after the price rise, and the product link may 404. The tempting live-lookup option passes today's ₹400/kg to a receipt the customer already paid, which quietly rewrites history and reintroduces the per-line product fetch."
```

```quiz
type: mcq
id: q2
question: "Order 8f2 is pending. Vendor A has /vendor/orders open in two tabs and clicks Mark packed in the first, which returns 200. The second tab still shows the stale row, so they click Mark packed there too. What should the API return?"
options:
  - "200 OK — the same packed status is written again"
  - "409 Conflict — the order is no longer pending"
  - "400 Bad Request — packed is not a valid status"
  - "200 OK — and paymentStatus moves to packed too"
correct: 1
explanation: "The conditional update matches on the expected current status, so a second write against packed finds no pending row and returns 409 so the client refetches. The tempting 200 replay hides that another tab already advanced the order, and the paymentStatus option conflates Stripe's paid flag with a fulfilment step."
```

```quiz
type: mcq
id: q3
question: "A customer checks out one cart holding Vendor A's tomatoes and Vendor B's milk, which creates two orders. Both vendors then open /vendor/orders. Which outcome is correct?"
options:
  - "Both orders, filtered in React by a storeId URL param"
  - "Both orders, with the other store's line items read-only"
  - "One order, filtered in React after a single combined fetch"
  - "One order, scoped by the server from the vendor token"
correct: 3
explanation: "GET /vendor/orders resolves the caller's store from the token, so Vendor A receives only the tomatoes order and Vendor B only the milk one. The tempting storeId-in-React option looks isolated in the UI, but the response still carries the other store's order and its customer details, which is a cross-vendor data leak rather than a display bug."
```
