# 20.8 — Vendor orders page

> **[Build]** · Chapter 20 — Track orders · *List from `GET /vendor/orders`*

**Why this step matters:** Vendors cannot fulfil orders they cannot see. This inbox completes the marketplace loop — without it, Week 3 demo stops at the customer side only.

<BigWordAlert term="Vendor fulfillment queue" plainEnglish="Dashboard page listing incoming orders for vendor's store — pack and ship workflow." whyItMatters="FreshMarket vendors live here during rush hours — status updates drive operations." />

**Where the project is now:** Customer has checkout, confirmation, and `/orders` history. Vendors have dashboard and product tools (Ch 10–12) but **no order inbox** — queue exists only in MongoDB and curl.

**After this step:** Vendor sees fulfilment queue at `/vendor/orders` from `GET /vendor/orders` — scoped to their store only.

## Step 1 — API contract

```
GET /api/vendor/orders
Authorization: Bearer <vendor-token>
```

**Middleware:** `requireAuth`, `requireRole('vendor')` — Ch 18.14.

| Field | Use in UI |
|---|---|
| `_id` | Row key |
| `status` | Badge — usually `pending` |
| `total` | Order total |
| `createdAt` | Sort/display date |
| `customer` / populated `customerId` | Name or email only |
| `orderItems[]` | Snapshot lines with `unitAtPurchase` |

**Scope:** Server resolves store via ownership — **not** client `storeId` query param.

## Step 2 — Page load contract

1. Mount inside `VendorLayout`.
2. On mount → `getVendorOrders()`.
3. Loading → spinner; zero orders → empty state.
4. With orders → table or card list (your choice).
5. `401` → login redirect; `403` → wrong-role message.

## Step 3 — List row contract

| Column | Source |
|---|---|
| Order id | `_id` truncated |
| Customer | `customer.name` or email |
| Date | `createdAt` formatted |
| Status | `OrderStatusBadge` |
| Total | `total` |
| Lines summary | "3 items" or first line + "and N more" |

Expand row for full `orderItems` via `OrderLineRow`. Show grocery units — kg, each, bunch matter for fulfilment.

**Privacy:** Show name/email only. **❌ Don't** expose password or full user document.

## Isolation — verify in demo 20.11

| Actor | Must see | Must not see |
|---|---|---|
| Vendor A | A's store orders | Vendor B's orders |
| Vendor B | B's store orders | Vendor A's orders |

Client must not filter by URL `storeId` without server enforcement.

## Troubleshooting

| Observation | Likely cause | Action |
|---|---|---|
| All marketplace orders visible | Missing store scope on API | Fix Ch 18.14 |
| Zero after checkout | Wrong vendor / store ownership | Check seed + cart `storeId` |
| Customer column blank | Populate path mismatch | Read API shape from curl |
| Prices differ from customer view | Used product populate | Use `orderItems` snapshots |
