## Why MVP skips guest cart

Guest cart sounds friendly ("browse without account") but adds:

- Session ids or localStorage sync
- Merge logic when guest becomes logged-in user
- Duplicate line handling
- More security review on anonymous writes

For learning **multi-vendor persistence and user scoping**, authenticated-only cart keeps the chapter focused. Chapter 17 can require login before add-to-cart — document that in README.

**You are not behind** if your app forces login to cart — that is the course gate.

## Interesting read — cart merge on login

Search topics:

- "e-commerce merge anonymous cart on login"  
- "Redis session cart vs database cart"  

**Typical pattern:**

1. Guest browses with session id — cart in Redis or localStorage  
2. User logs in — server merges guest cart into user cart  
3. Conflicts: same product in both — sum quantities or max  

**FreshMarket MVP:** No guest cart. Customer must login before POST /cart. Chapter 17 may require login to add to cart — document in README.

## Questions for learning log (optional answers)

1. Why defer guest cart to reduce scope?  
2. If you added guest cart, where would session id live?  
3. How would merge handle two storeIds already on lines — no change needed?  
4. Race: two tabs PATCH same line — last write wins acceptable for MVP?  
5. Should vendor role have a cart? — Yes as customer; same API.

## Related patterns

There are four ways a cart can live on the server. Three of them are real production patterns; one of them is the course's choice. Knowing which is which tells you *why* Chapter 5 picked a CartItem collection.

| Pattern | This course |
|---|---|
| DB cart per user | ✅ CartItem collection |
| Session-only cart | ❌ not MVP |
| Client localStorage cart | ❌ not persisted gate |
| Cart as embedded array on User | ❌ use separate collection |

Chapter 5 chose CartItem collection — stick with it.

## Stock and concurrency preview

Add to cart checks stock **at write**. Checkout Ch 18 decrements atomically — two customers can both add last item; checkout race handled later.

Note in learning log: cart quantity can exceed available stock if stock drops after add — checkout must re-validate.
