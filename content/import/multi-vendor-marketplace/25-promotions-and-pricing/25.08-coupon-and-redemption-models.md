# 25.08 — Coupon and redemption models

> **[Build]** · Chapter 25 — Promotions & pricing

Two records serve different jobs. `Coupon` is editable policy: an administrator can shorten its window or use the kill switch. `CouponRedemption` is history: after payment, it records what promotion was consumed by one checkout and should not be edited to match later policy.

## Step 1 — Coupon policy

Add `server/models/coupon.model.js`:

```javascript
import mongoose from 'mongoose';

const couponSchema = new mongoose.Schema(
  {
    code: { type: String, required: true, uppercase: true, trim: true, unique: true },
    scope: { type: String, enum: ['platform', 'store'], required: true },
    storeId: { type: mongoose.Schema.Types.ObjectId, ref: 'Store', default: null },
    type: { type: String, enum: ['percent', 'fixed_cents'], required: true },
    value: { type: Number, required: true, min: 1 },
    maxDiscountCents: { type: Number, default: null },
    minSubtotalCents: { type: Number, default: 0 },
    startsAt: { type: Date, required: true },
    endsAt: { type: Date, required: true },
    maxRedemptions: { type: Number, default: null },
    maxRedemptionsPerUser: { type: Number, default: 1 },
    redemptionCount: { type: Number, default: 0 },
    isActive: { type: Boolean, default: true },
  },
  { timestamps: true }
);

couponSchema.index({ storeId: 1, isActive: 1 });

couponSchema.pre('validate', function validateCouponShape(next) {
  if (this.scope === 'store' && !this.storeId) {
    return next(new Error('STORE_SCOPE_REQUIRES_STORE_ID'));
  }
  if (this.scope === 'platform') this.storeId = null;
  if (this.type === 'percent' && this.value > 100) {
    return next(new Error('PERCENT_OUT_OF_RANGE'));
  }
  if (this.endsAt <= this.startsAt) {
    return next(new Error('INVALID_COUPON_WINDOW'));
  }
  next();
});

export const Coupon = mongoose.model('Coupon', couponSchema);
```

`unique: true` on `code` already creates the unique index, so do not declare the same index a second time. Schema validation also prevents combinations that individual field rules cannot express: a store coupon without a store, a percentage over 100, or an inverted time window.

## Step 2 — Redemption event

Add `server/models/couponRedemption.model.js`:

```javascript
import mongoose from 'mongoose';

const couponRedemptionSchema = new mongoose.Schema(
  {
    couponId: { type: mongoose.Schema.Types.ObjectId, ref: 'Coupon', required: true, index: true },
    userId: { type: mongoose.Schema.Types.ObjectId, ref: 'User', required: true, index: true },
    checkoutId: { type: String, required: true },
    paymentIntentId: { type: String, required: true },
    orderIds: [{ type: mongoose.Schema.Types.ObjectId, ref: 'Order', required: true }],
    discountCents: { type: Number, required: true, min: 0 },
  },
  { timestamps: true }
);

couponRedemptionSchema.index({ couponId: 1, userId: 1 });
couponRedemptionSchema.index({ couponId: 1, checkoutId: 1 }, { unique: true });
couponRedemptionSchema.index({ paymentIntentId: 1 }, { unique: true });

export const CouponRedemption = mongoose.model(
  'CouponRedemption',
  couponRedemptionSchema
);
```

One checkout may create several vendor orders, so `orderIds` is an array. The unique indexes make both a duplicated Stripe event and a retried application-level handler converge on the same redemption.

## Step 3 — Cart intent and order truth

Extend the **Cart** schema from Chapter 16 with optional `appliedCouponCode: String`. The field means “try this code during pricing”; it does not freeze eligibility or discount value.

Extend the Order schema with the receipt fields the next lessons will populate:

```javascript
subtotalCents: { type: Number, required: true, min: 0 },
discountCents: { type: Number, required: true, min: 0, default: 0 },
totalCents: { type: Number, required: true, min: 0 },
couponCode: { type: String, default: null },
couponScope: { type: String, enum: ['platform', 'store'], default: null },
pricingVersion: { type: Number, required: true, default: 1 },
```

Keep per-line `discountCents` in the embedded order item when you need vendor settlement or receipt-level explanation. For every order, enforce `subtotalCents - discountCents === totalCents` in the checkout service before insert.

## Verify the model layer

Seed the representative coupons, then check these failure cases in a model test or a short script:

- two spellings that normalize to the same uppercase code cannot both be inserted;
- a store coupon without `storeId` fails validation;
- a percentage value of `101` fails validation;
- the same `{ couponId, checkoutId }` cannot create two redemptions.
