# 25.10 — Recalculate cart totals

> **[Build]** · Chapter 25 — Promotions & pricing

Create `server/modules/pricing/computeCartPricing.js`. This is the module's center of gravity: the cart API uses it for a preview, and checkout uses it again for the amount that becomes money.

Its input is identity and intent, not trusted prices. Load the authenticated cart and current products on the server, build line subtotals in integer units, then validate the saved coupon. Missing or inactive products should fail normal cart validation before discount math begins.

## Discount computation

```javascript
function computeDiscountCents(coupon, eligibleSubtotalCents) {
  if (coupon.type === 'fixed_cents') {
    return Math.min(coupon.value, eligibleSubtotalCents);
  }
  let discount = Math.floor((eligibleSubtotalCents * coupon.value) / 100);
  if (coupon.maxDiscountCents != null) {
    discount = Math.min(discount, coupon.maxDiscountCents);
  }
  return discount;
}
```

Keep the rounding rule consistent with 25.04. A price service that rounds one way for preview and another way for checkout is two pricing services, even if both functions have the same name.

## Line allocation

After calculating `discountTotalCents`, allocate it across eligible lines. Do not independently apply the percentage to every line; line-level rounding can produce a sum different from the cart discount.

- Non-eligible lines → `discountCents: 0`
- Eligible lines → proportional floor share
- Remaining cents → largest eligible lines first, with product ID as stable tie-breaker

A useful allocation helper makes its invariant executable:

```javascript
function allocateDiscount(eligibleLines, discountTotalCents) {
  const eligibleSubtotalCents = eligibleLines.reduce(
    (sum, line) => sum + line.subtotalCents,
    0
  );

  const allocated = eligibleLines.map((line) => ({
    ...line,
    discountCents: Math.floor(
      (discountTotalCents * line.subtotalCents) / eligibleSubtotalCents
    ),
  }));

  let remainder = discountTotalCents - allocated.reduce(
    (sum, line) => sum + line.discountCents,
    0
  );

  const recipients = [...allocated].sort(
    (a, b) => b.subtotalCents - a.subtotalCents ||
      String(a.productId).localeCompare(String(b.productId))
  );

  for (let index = 0; remainder > 0; index += 1, remainder -= 1) {
    recipients[index % recipients.length].discountCents += 1;
  }

  return allocated;
}
```

Objects in `recipients` are references to the same line objects held by `allocated`, so remainder updates appear in the returned array. If your implementation copies again, return the sorted collection or map the updates back explicitly.

Build `payableCents` for every line and assert:

```javascript
if (lines.some((line) => line.discountCents > line.subtotalCents)) {
  throw new Error('INVALID_DISCOUNT_ALLOCATION');
}
if (sum(lines, 'discountCents') !== discountTotalCents) {
  throw new Error('DISCOUNT_ALLOCATION_MISMATCH');
}
```

## Client (Chapter 17 extension)

Add a coupon input and Apply action calling `POST /cart/coupon`. Bind the displayed discount and total to the server response only. It is fine for the UI to calculate non-authoritative display details such as item counts, but remove any local `reduce` that applies discounts or chooses the checkout amount.

## Verification matrix

| Cart | Code | Expected total |
|---|---|---|
| $50 mixed two stores | `FRESH10` max $4 | $46.00 |
| $15 at Store X | Store X $5 off min $20 | Invalid |
| $25 at Store X | Store X $5 off | $20.00 |
| $20 Store X + $30 Store Y | Store X $5 off | $45.00; Store Y unchanged |
| Three uneven eligible lines | Fixed $1 off | Allocations sum to exactly $1.00 |
| Empty cart | Any code | Cart validation error; no divide by zero |
