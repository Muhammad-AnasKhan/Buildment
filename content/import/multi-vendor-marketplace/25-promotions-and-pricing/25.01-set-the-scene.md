# 25.01 — Set the scene

> **[Open]** · Chapter 25 — Promotions & pricing · *After inventory, fix the money*

Chapter 24 stopped overselling. Chapter 25 stops **undercharging**: manipulated client totals, reused single-use codes, expired campaigns still applied, and vendor-funded discounts charged to the platform.

Promotions touch every layer — MongoDB schemas, cart recalculation, checkout PaymentIntent amounts, and order line snapshots for accounting.

## Objectives

- Model **coupons** with scope (platform vs store), type (percent vs fixed), caps, and validity window.
- Validate codes in an API that returns a **pricing preview**, not hidden client math.
- Recalculate cart subtotals server-side when a coupon is applied or removed.
- Snapshot discount breakdown on each order at checkout (Chapter 18 pattern extended).
- Rate-limit validation attempts and enforce per-user redemption limits.

## Out of scope

- Stackable coupons (only one active code per checkout in this pass)
- Dynamic pricing / surge
- Stripe Coupons API as source of truth (FreshMarket owns rules in MongoDB; Stripe amount must match server total)
