# 21.3 — What you'll build

> **[Read]** · Chapter 21 — Cache & search · *Redis cache + text index + invalidation*

Blueprint for the **performance layer** on catalogue reads. Read once; verify against your repo after 21.14.

<BigWordAlert term="Redis cache layer" plainEnglish="In-memory cache for hot catalogue queries plus bust logic on product updates." whyItMatters="FreshMarket shop page under load reads from Redis first — MongoDB on cache miss only." />

You are adding **speed and search** — not new customer-facing features. The shop should look the same; repeat loads should feel faster and `?search=` should use an index.

## Server additions

```
server/src/shared/redis.js           ← connect client (if not from earlier stub)
server/src/shared/cache.js           ← get/set/del helpers optional
server/src/middleware/cacheCatalogue.js  ← or inline in products route
```

**Env:** `REDIS_URL` in `server/.env` + `.env.example`

## Behaviour contract

| Feature | Spec |
|---|---|
| Cache | `GET /products` and query variants — key from path + sorted query string |
| TTL | 300–900 seconds — document chosen value in README |
| Invalidation | Product create/update/delete clears catalogue keys |
| Search | `?search=` uses MongoDB `$text` on name + category |
| Text index | Created on Product collection in 21.12 |
| Fallback | Redis connection fail → skip cache, query MongoDB |
| Metrics | Log before/after response time once (21.10) |

The client contract does not change. A cache hit, cache miss, and Redis-down fallback must return the same status code and JSON shape for the same MongoDB state. Development logs may reveal which path ran, but React should not need separate rendering logic for cached data.

## What you will not build

| Out of scope | Why |

| Elasticsearch | MongoDB text index is enough for course |
| CDN for images | Cloudinary already serves images |

## Gate headlines

- [ ] Second identical GET faster or HIT logged
- [ ] PATCH product → next GET shows new data (not stale)
- [ ] Search uses index — `explain()` shows text index
- [ ] Stop Redis → API still returns products

## Definition of done

The gate asks for evidence, not the presence of files. You must be able to demonstrate that:

- two identical URLs produce a miss followed by a hit;
- reordered query parameters resolve to the same canonical key;
- different pages or filters never share a key;
- a successful product write makes the next read miss and return fresh data;
- `$text` search uses the named MongoDB index;
- stopping Redis still returns the catalogue from MongoDB.

Document the Redis package, canonical key format, TTL, search-cache choice, invalidation call sites, and fallback behaviour in the README. Those decisions are part of the design.
