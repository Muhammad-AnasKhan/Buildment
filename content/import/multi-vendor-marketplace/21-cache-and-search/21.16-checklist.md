# 21.16 — Checklist and learning log
> **[Gate]** · Chapter 21 — Cache and search

This is the **gate** for Chapter 21. Tick every box honestly and answer the learning log below before opening Chapter 22.

## Chapter 21 — Cache and search checklist (gate)

Do **not** open Chapter 22 until every box is ticked and learning log answers are written below.

### Redis

- [ ] `REDIS_URL` in `server/.env.example`
- [ ] One shared Redis client connects when available
- [ ] API boots within a bounded time when Redis is unavailable
- [ ] Runtime Redis disconnect falls back without a catalogue 500

### Cache

- [ ] `GET /products` uses cache-aside
- [ ] HIT/MISS observable in dev logs
- [ ] TTL documented in README
- [ ] Second identical request hits cache
- [ ] Equivalent reordered query parameters share a key
- [ ] Different page, filter, and search values do not collide
- [ ] Cached and uncached responses have the same status and JSON shape

### Invalidation

- [ ] Product POST/PATCH/DELETE invalidates catalogue cache
- [ ] Price change visible on next GET without waiting TTL
- [ ] Publish/unpublish or delete cannot linger in a warmed filtered page
- [ ] Invalidation runs only after a successful database write

### Search

- [ ] Text index on `name` + `category`
- [ ] `?search=` uses `$text` query
- [ ] Search still enforces published-product and existing filter rules
- [ ] explain output references `product_text_search`

### Performance

- [ ] README records method, sample count, seed size, miss timing, and hit timing
- [ ] HIT evidence shows the catalogue MongoDB query was skipped

### Prior gates

- [ ] Chapter 20 browser-commerce gate complete
- [ ] Chapter 14 public catalogue works

### Learning log — write now

Answer **in your own words** in the fields below:

1. **Cache key:** How do you canonicalize query parameters, and which requests must never share a key?

2. **Stale trap:** Describe the evidence that a warmed filtered page becomes fresh after a product write.

3. **Fallback:** What happens when Redis is absent at boot and when it disconnects at runtime?

4. **Text index:** Record the index name, winning-plan evidence, and documents examined.

5. **TTL choice:** What TTL did you pick, and what failure does it limit rather than prevent?

6. **Production preview:** Will Redis run on the same host or as a managed service, and how will Chapter 22 share it safely?
