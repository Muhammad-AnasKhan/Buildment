## Trace the finished read path

For an identical public catalogue request, FreshMarket now takes one of three paths:

```text
Redis ready + key exists  → return cached payload
Redis ready + key missing → query indexed MongoDB path → cache successful payload → return it
Redis unavailable         → query MongoDB directly → return the same payload
```

A product write updates MongoDB first and then clears the catalogue namespace. The next customer therefore takes the miss path and repopulates Redis with fresh data. That complete story—read, write, failure, recovery—is more important than any single helper file.

## What remains intentionally simple

This module does not solve cache stampedes, selective per-product invalidation, autocomplete, or distributed tracing. Those are valid production extensions, but the current design has a clear correctness boundary and evidence you can explain.
