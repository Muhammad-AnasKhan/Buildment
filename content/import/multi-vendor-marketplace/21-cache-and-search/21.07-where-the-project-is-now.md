# 21.7 — Where the project is now

> **[Build]** · Chapter 21 — Cache & search · *Full app works; every browse hits MongoDB*

**Why this step matters:** You cannot prove cache helped if you never recorded baseline speed. This continuity step captures "before Redis" timings and confirms commerce still works — the reference point for every HIT/MISS test in 21.9–21.10.

**Build cluster starts here.** Week 3 commerce works in browser. Every `GET /products` still hits MongoDB on every page load — fine for demo, wrong for scale. Chapter 21 adds **Redis cache-aside** on catalogue reads and a **text index** for search.

**After this chapter:** Identical browse UX with faster repeat loads; search uses index; cache busts on product write; API survives Redis stopped.

Invalidation in 21.11 must delete keys matching catalogue prefix — not `FLUSHALL`.

## MongoDB query count reminder

Before cache, confirm Ch 14 gate still true:

- One list request → **~2 queries** with populate (not N+1 loop)

Cache does not fix N+1 — it only avoids repeat work.
