# 14.15 — Recap and what's next

> **[Wrap]** · Chapter 14 — Browse catalogue API · *Recap — what you built and what comes next*

**Why this step matters:** Pausing to narrate what you built locks in the public read model before Chapter 15 — if you cannot explain `/products` vs `/vendor/products`, the shop UI will duplicate logic in the wrong place.

<BigWordAlert term="Shop-ready API" plainEnglish="Public product list and detail routes with pagination — backend ready for customer UI." whyItMatters="Chapter 15 builds shop pages; Chapter 16 adds cart API for add-to-cart." />

You entered Chapter 14 with vendor-only product reads. You leave with a **public catalogue API** — filtered, paginated, store name populated, N+1 avoided — ready for the customer shop in Chapter 15.

## What you built — narrative recap

**Public read model:** `GET /products` and `GET /products/:id` without auth — visibility enforced in service layer.

**Filters:** `category`, `storeId` AND with published + in-stock base filter.

**Pagination:** `page`, `limit`, `total`, `totalPages` — default limit 20.

**Populate:** Store name on each card without per-product store queries — query count verified.

**DTO discipline:** No draft leaks, no vendor PII, no Cloudinary public_ids on public JSON.

## Repo changes

```

  products.routes.js   ← + GET /products, GET /products/:id

```

No client changes this chapter — intentional backend-first pairing.

## Decisions for viva

1. **Public vs vendor routes?** — Scope and auth differ; same Product collection.  
2. **Why 404 on unpublished detail?** — No information leak.  
3. **How N+1 was avoided?** — populate; measured queries.  
4. **Why countDocuments + find?** — Pagination metadata.  
5. **Why exclude OOS from browse?** — Prevent dead-end add-to-cart — detail 404 aligns.

## Handoff to Chapter 15 — API fields → UI components

Chapter 15 does not invent catalogue rules. Every pixel maps to a field you tested in curl:

| API response field | Chapter 15 component | Student mistake to avoid |
|---|---|---|
| `items[].imageUrl` | `ProductCard` photo | Hardcoding placeholder URLs when API has real Cloudinary links |
| `items[].store.name` | "Sold by …" line on card | Hiding store name — defeats multi-vendor identity |
| `items[].price` + `unit` | Price line formatter | Client-side filter hiding unpublished items |
| `page`, `totalPages` | Pagination controls | Fetching all products once and paginating in React |
| `?category=` / `?storeId=` | Filter bar refetch | Filtering array in memory after one big GET |
| `GET /products/:id` | ProductDetail page | Duplicating publish/stock checks in UI |
