# 14.9 — Public products route

> **[Build]** · Chapter 14 — Browse catalogue API · *`GET /products` — published, in-stock only*

**Why this step matters:** This is the **first endpoint customers will use** — the foundation of the whole shop. Getting the visibility filter right here (`published` + in-stock only) prevents draft products leaking to the public before you add filters and pagination.

<BigWordAlert term="GET /products" plainEnglish="Public list endpoint returning published products with optional filters and pagination params." whyItMatters="FreshMarket shop grid loads from this route — only isPublished true, never vendor drafts." />

**Where the project is now:** Only vendor-scoped product reads exist.

**After this step:** `GET /products` returns published in-stock products — pagination and populate added in 14.11–14.12; filters in 14.10.

## Route contract

| Field | Value |
|---|---|
| Method | GET |
| Path | `/products` |
| Auth | None |
| Handler | `listPublicProducts(req.query)` |

## Public visibility filter (base)

Every public product query **must** include:

```javascript
// Spec — exact syntax yours
{
  isPublished: true,
  stockQty: { $gt: 0 }
}
```

| Product state | In public list? |
|---|---|
| Published, stock > 0 | ✅ |
| Published, stock 0 | ❌ |
| Draft / unpublished | ❌ |

**You implement** in `buildPublicFilter()` — extend with query params in 14.10.

## Initial response shape (minimal)

Before pagination metadata (14.11), acceptable interim:

```json
{
  "items": [ /* product array */ ]
}
```

Gate requires full pagination object — complete in 14.11.

## Public product DTO fields

| Field | Include |
|---|---|
| `id` | ✅ |
| `name`, `price`, `unit`, `weightOrQuantity`, `category` | ✅ |
| `imageUrl` | ✅ |
| `stockQty` | ✅ optional — shows scarcity; or hide for UX |
| `storeId` raw | ❌ prefer nested `store` after populate |
| `imagePublicId` | ❌ |
| Internal vendor fields | ❌ |

## Route registration

Mount on existing products router — **before** parameterized vendor-only routes if path conflicts.

No `requireAuth` middleware on this route.

CORS: already open for GET from Vite — verify in 14.14.
