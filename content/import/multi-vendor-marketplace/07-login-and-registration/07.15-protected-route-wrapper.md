# 7.15 — Protected route wrapper

> **[Build]** · Chapter 07 — Login & registration · *Redirect unauthenticated users to login*

**Why this step matters:** Public Home and auth pages stay open; vendor stubs must reject strangers. `ProtectedRoute` is the client-side door check — authorization by role deepens in Chapter 8, but unauthenticated users should never see vendor screens.

<BigWordAlert term="Protected route" plainEnglish="A wrapper component that redirects to login if no valid token — guards vendor dashboard and cart." whyItMatters="FreshMarket `/vendor/*` routes render nothing until auth context confirms a logged-in vendor." />

**Where the project is now:** Auth state exists; vendor routes publicly accessible.

**After this step:** `ProtectedRoute` component redirects unauthenticated users to `/login`, preserves intended URL optional, waits for auth boot loading.

## File

```
client/src/components/ProtectedRoute.jsx
```

## Component contract

**Props:**

| Prop | Type | Purpose |
|---|---|---|
| children | node | protected page |
| roles | string[] optional | if set, require role match — basic check; full RBAC Ch 8 |

**Behaviour:**

```
if isLoading → return loading UI or null
if !isAuthenticated → <Navigate to="/login" replace state={{ from: location }} />
if roles && !roles.includes(user.role) → <Navigate to="/" /> or 403 page stub
return children
```

Chapter 8 adds proper 403 UX — here optional role prop preview.

## Client guard vs server guard — read before Chapter 8

`ProtectedRoute` improves UX — strangers never see vendor form fields flash on screen. It is **not security**. Anyone can bypass React with curl or DevTools and call your API directly.

| Layer | What it blocks | Can attacker bypass? |
|---|---|---|
| `ProtectedRoute` (this step) | Unauthenticated browser navigation | Yes — curl with stolen JWT |
| `requireAuth` (Ch 6) | Requests without valid JWT | No — server returns 401 |
| `requireRole` + ownership (Ch 8) | Wrong role or wrong store id | No — server returns 403 |

<Callout type="info" title="Production rule">
Ship both. Client guards for experience; server guards for correctness. Chapter 8 is where marketplace isolation actually lives — do not skip it because ProtectedRoute "feels secure enough."
</Callout>

## Usage in router

```
<Route path="/vendor" element={
  <ProtectedRoute roles={['vendor']}>
    <VendorHomeStub />
  </ProtectedRoute>
} />
```

Customer-only route example with `roles={['customer']}` optional.

## ✅ Do / ❌ Don't

**✅ Do:** Wait for isLoading before redirect — avoids flash.

**✅ Do:** use `<Outlet />` if nesting layout routes — optional pattern.

**❌ Don't:** Duplicate auth check in every page — use wrapper.
