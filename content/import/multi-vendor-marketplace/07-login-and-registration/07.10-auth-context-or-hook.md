# 7.10 — Auth context or hook

> **[Build]** · Chapter 07 — Login & registration · *`hooks/useAuth.js` or Context — access token in memory*

**Why this step matters:** Login state shared across pages needs one source of truth — `useAuth` or Context — so Header, protected routes, and the API client all agree whether someone is signed in without prop drilling.

<BigWordAlert term="React Context" plainEnglish="Shared state (user, tokens, login/logout) available to any component without prop drilling." whyItMatters="FreshMarket's header shows login vs avatar based on auth context — one source of truth for session." />

**Where the project is now:** Auth pages scaffolded; no shared auth state.

**After this step:** `useAuth` hook (via AuthProvider) manages user, access token in memory, login/logout/register/verify methods, boot refresh, and `isLoading` gate.

## Why a single auth source of truth

Without Context or a global hook, every page would need props like `user={user} onLogout={...}` passed through Header → Layout → Page. One missed prop and the navbar shows "Login" while the user is on a protected route.

| Pattern | When teams use it |
|---|---|
| React Context + hook | Small/medium SPAs — **this course** |
| Redux/Zustand auth slice | Large apps with many cross-cutting subscribers |
| Server sessions + cookies only | Traditional multi-page apps — not this SPA |

`useAuth` is the **contract** every auth-aware component shares: pages, ProtectedRoute, and the API client (via token getter). Chapter 8 adds server-side checks — client auth state still drives UI, but never replaces API permission checks.

## File

```
client/src/hooks/useAuth.js
```

Or split:

```
client/src/context/AuthContext.jsx
client/src/hooks/useAuth.js   ← re-exports useContext
```

## Context value contract

| Property / method | Type | Purpose |
|---|---|---|
| user | object \| null | id, email, role, displayName |
| isAuthenticated | boolean | derived |
| isLoading | boolean | boot refresh in progress |
| login(email, password) | async | POST login, set tokens |
| register(data) | async | POST register |
| verifyOtp(email, otp) | async | POST verify |
| logout() | async | clear state, call logout API |
| getAccessToken() | fn | for api client — internal |

Do not expose setAccessToken publicly.

## Provider placement

Wrap router in `main.jsx`:

```
<AuthProvider>
  <App />
</AuthProvider>
```

## Boot refresh (on mount)

```
useEffect once:
  try POST /auth/refresh credentials include
  if ok: set access, optionally GET /me
  catch: leave logged out
  finally: isLoading false
```

## Access token storage

Use `useRef` for accessToken string — update when login/refresh succeeds.

Pass getter to api client module:

```
setAuthTokenGetter(() => getAccessToken())
```

Pattern avoids stale closure in interceptor.

## User state after login

Option A: login response includes user — set directly

Option B: login then GET /me — richer profile

Either acceptable — document choice.

## Common mistakes

| Mistake | Symptom | Fix |
|---|---|---|
| Access token in localStorage | XSS can steal persistent token | Keep in useRef/memory only (7.2) |
| Skip boot refresh | User logged out on every page reload | `useEffect` POST /refresh on mount |
| `isLoading` never false | Infinite spinner on ProtectedRoute | `finally` block always clears loading |
| Expose `setAccessToken` publicly | Random components mutate auth state | Only login/refresh/logout methods |
| useAuth outside Provider | Runtime crash or null context | Wrap `<App />` in AuthProvider in main.jsx |
| Stale closure in interceptor | Bearer header empty after login | Pass getter function, not token value |

## Commit

```bash
git add client/src/hooks/ client/src/context/ client/src/main.jsx
git commit -m "feat(client): add AuthProvider and useAuth hook"
```

## ✅ Do / ❌ Don't

**✅ Do:** Throw clear errors from login for form catch.

**✅ Do:** Set isLoading false even on refresh failure.

**❌ Don't:** Persist access token to localStorage.

**❌ Don't:** Call useAuth outside provider — guard with error in hook.

## Verify checklist

- [ ] AuthProvider wraps app
- [ ] useAuth available in pages
- [ ] Boot refresh runs (network tab on load)
- [ ] isLoading prevents flash redirect
