```quiz
type: mcq
id: q1
question: Maya's open-shop form receives 201 from POST /stores, but her code navigates to /vendor without refetching the store. What does she see?
options:
  - The vendor dashboard, because the POST already returned 201 Created
  - The open-shop form again, because the gate still sees no store
  - A 409 duplicate page, because a store now exists for her
  - The login screen, because her session token is now store-scoped
correct: 1
explanation: "The gate trusts the API, not the form: it re-checks GET /stores/me on layout entry, so navigating with stale state sends her straight back to open-shop. The tempting answer assumes the 201 updates everything, but the layout never saw that response — only a refetch turns the gate green."
```

```quiz
type: mcq
id: q2
question: A teammate puts the store check inside VendorHome and OpenShop instead of the layout. What fails first?
options:
  - Nothing breaks, because each vendor page calls the store API anyway
  - Every vendor page hangs on a spinner while the store loads
  - The open-shop form blocks vendors who genuinely have no store
  - Products and settings render for a vendor who has no store yet
correct: 3
explanation: "The gate only protects the pages that run it. VendorHome and OpenShop checking themselves leaves /vendor/products and /vendor/settings unguarded, so a storeless vendor reaches a page whose API calls have no storeId. Duplicating the check per page also means the next page someone adds inherits no protection at all."
```

```quiz
type: mcq
id: q3
question: A vendor who already owns a shop types /vendor/open-shop and submits. The API answers 409. What should the page do?
options:
  - Show that a shop already exists and link to settings
  - Retry the POST once with a slightly different store name
  - Treat the response as success and open the vendor dashboard
  - Show a name field error and leave the typed values in place
correct: 0
explanation: "The 409 means the one-store rule was already satisfied, so editing is the real next step — a plain message plus a link to settings puts the vendor where the change belongs. Swallowing it as success is tempting because the store does exist, but the typed values were never saved, so the dashboard would quietly show the old name."
```
