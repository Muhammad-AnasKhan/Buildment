## Chapter 10 — Open your shop checklist (gate)

Do **not** open Chapter 11 until every box is ticked and learning log answers are written below.

### Vendor layout & routing

- [ ] `VendorLayout.jsx` wraps vendor routes with `Outlet`  
  *Verify:* Child page renders inside shared header/nav.
- [ ] Unauthenticated users redirected to login
- [ ] Customers cannot access vendor routes
- [ ] Nav includes Settings and placeholder Products/Dashboard

### Open shop page

- [ ] `OpenShop.jsx` at `/vendor/open-shop`
- [ ] Form fields match store API (name, description, address, logoUrl)
- [ ] Submit calls `POST /api/stores` with Bearer auth  
  *Verify:* Network tab shows 201.
- [ ] Success navigates vendor into dashboard
- [ ] 400 shows field errors; 409 handled gracefully
- [ ] Double-submit mitigated (disabled while loading)

### Store settings page

- [ ] `StoreSettings.jsx` at `/vendor/settings`
- [ ] Loads store via `GET /api/stores/me` on mount
- [ ] 404 on load redirects to open-shop
- [ ] Save calls `PATCH /api/stores/:id` with id from GET me
- [ ] Changes persist after hard refresh  
  *Verify:* Change name → refresh → name still updated.

### Onboarding gate

- [ ] `GET /stores/me` → 404 triggers redirect to open-shop (except on open-shop itself)
- [ ] Storeless vendor typing `/vendor/products` in URL → ends on open-shop
- [ ] Vendor with store bypasses open-shop
- [ ] No redirect loop on open-shop path

### API helpers & integration

- [ ] `stores.js` implements getMyStore, createStore, updateStore
- [ ] Auth interceptor attaches token to store requests
- [ ] Network tab shows correct status codes during full onboarding test

### Prior gates

- [ ] Chapter 9 store API still passes curl tests
- [ ] Chapter 7 auth + refresh still works in browser
- [ ] I can explain onboarding gate vs server-side auth
- [ ] I can explain open-shop (POST) vs settings (PATCH)
- [ ] I can explain how 404 on GET me drives client routing
- [ ] I can trace vendor journey from register to shop open in browser

### Learning log — write now

Answer **in your own words** in the fields below:

1. **Gate design:** Where does store-exists check live? What happens on each HTTP status from GET /stores/me?

2. **Open shop flow:** Describe Scenario A from 10.10 step by step. What URL did you see at each stage?

3. **Settings flow:** How do you obtain `storeId` for PATCH? What proves persistence after refresh?

4. **Loop prevention:** How does layout avoid redirecting open-shop to itself?

5. **Error UX:** How does UI handle 400, 409, and network errors on POST?

6. **Role routing:** Where does vendor go after login vs customer? Which files control that?

7. **API helpers:** How do store API functions reuse auth from Chapter 7?

8. **Chapter 11 preview:** Why must vendor have store before POST /products? What will storeId link look like?
