# 2.7 — Quiz

> **[Check]** · Chapter 02 — Project skeleton · *Three questions: health route, module folders, one repo*

Before you create the repository, confirm you understand the skeleton chapter. Answer each question below — your responses are saved to your enrollment and stay visible after reload.

<BigWordAlert term="Health check route" plainEnglish="A tiny API endpoint that returns OK so you can prove the server is alive before building real features." whyItMatters="FreshMarket's `/health` route is the canary — if it fails, nothing downstream will work either." />

```quiz
type: mcq
id: q1
question: What does a successful GET /health response prove in Chapter 2?
options:
  - MongoDB is connected and seeded
  - The Express server is running and reachable over HTTP
  - React Router is configured correctly
  - Stripe test keys are loaded
correct: 1
```

```quiz
type: mcq
id: q2
question: Why does this course use a module-based folder layout under server/src/modules/ instead of a flat controllers/ folder?
options:
  - It is required by MongoDB
  - Related routes, models, and logic stay together per domain (auth, cart, etc.)
  - Vite only works with modules
  - It avoids using environment variables
correct: 1
```

```quiz
type: short
id: q3
question: In one sentence, why do server/ and client/ live in one Git repository for this course?
allowSpeechInput: true
modelAnswer: One repo keeps the API and UI in sync, makes health-check and end-to-end demos easy, and matches how many small teams ship full-stack products.
```

When you finish, continue to **Create the repo** (next lesson).

<InterestingRead title="Colocate by feature vs organise by type" hook="Folders named `controllers/` age badly when products multiply." readMinutes={5}>

Many teams start with layer-first folders (all routes together, all models together). Feature-first layouts group everything for one capability — auth, cart, checkout — in one place. FreshMarket uses module folders on the server so each capability stays findable as the codebase grows.
