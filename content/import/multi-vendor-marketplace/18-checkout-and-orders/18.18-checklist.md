## Chapter 18 — Checkout and orders checklist (gate)

Do **not** open Chapter 19 until every box is ticked and learning log answers are written below.

### Checkout

- [ ] `POST /checkout` requires customer auth  
  *Verify:* No token → 401.
- [ ] Empty cart returns 400
- [ ] Two-store cart creates **two** Order documents  
  *Verify:* Count orders in Compass — must match store count in cart.
- [ ] Each order has single `storeId` — no mixed-store orders
- [ ] `orderItems` have nameAtPurchase, priceAtPurchase, unitAtPurchase, quantity, lineTotal
- [ ] Order `total` equals sum of line totals
- [ ] Stock decremented atomically with `$gte` guard
- [ ] Insufficient stock fails entire checkout — no partial orders
- [ ] Cart empty after successful checkout  
  *Verify:* GET /cart → items: []
- [ ] Cart unchanged after failed checkout

### List routes

- [ ] `GET /orders/my` returns customer's orders only
- [ ] `GET /vendor/orders` returns vendor store's orders only
- [ ] Cross-vendor list does not leak other stores' orders
- [ ] List uses snapshot prices — not live product.price

### Immutability (18.16)

- [ ] Product price PATCH after order does not change priceAtPurchase  
  *Verify:* Change product price in Compass → old order line unchanged.
- [ ] Test documented in learning log

### Prior gates

- [ ] Chapter 17 cart UI works

- [ ] I can explain one checkout → many orders
- [ ] I can explain snapshot trap and fix
- [ ] I can explain atomic stock decrement

<InterestingRead title="Stripe idempotency keys" hook="Networks retry; without idempotency, customers pay twice." readMinutes={5}>

If a checkout request times out, clients and webhooks may retry. Idempotency keys tell Stripe to treat duplicates as the same charge. FreshMarket introduces this pattern where money first enters the system.

</InterestingRead>

<RealWorldEvent title="Double-charge incidents during flash sales" when="Various" summary="E-commerce outages and retries caused duplicate charges until teams adopted idempotent payment APIs and clear order states." lesson="Model order status explicitly — pending, paid, failed — and never create a second order for the same checkout attempt." />
