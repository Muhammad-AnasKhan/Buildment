# 18.13 — Clear cart on success

> **[Build]** · Chapter 18 — Checkout & orders API · *Cart empty after checkout*

Checkout created orders and reduced stock. If the cart still has items, the customer can hit **POST /checkout** again and duplicate the order. Clearing the cart is part of the checkout contract.

<BigWordAlert term="Cart clearing" plainEnglish="Deleting or emptying cart document after successful checkout — prevents double-order same items." whyItMatters="Shopper hitting back button should not still see pre-checkout cart as purchasable." />

---

## Step 1 — Add clearCart to checkout success path

After orders inserted and stock decremented:

```javascript
await CartItem.deleteMany({ userId })
// or reuse: await cartService.clearCart(userId)
```

**Only on full success.** If checkout threw earlier, cart must be untouched.

---

## Step 2 — Preferred transaction order

Inside one transaction when possible:

1. Decrement stock (all products)
2. Insert orders (with snapshots)
3. Delete cart items
4. Commit

Customer never sees an empty cart without matching orders in the database.

---

## Step 4 — Failed checkout must not clear

Force a stock failure (qty > stockQty). After 409/400:

- Cart still has items
- No new orders
- Stock unchanged

---

## Double-order prevention (MVP)

With cart cleared, immediate second `POST /checkout` → `400` empty cart. Good enough for MVP — full idempotency is a stretch goal from 18.6.

---

## Common mistakes

| Mistake | Fix |
|---|---|
| Clear before orders saved | Transaction ordering |
| Client loops DELETE | Server clears in checkout service |
| Clear on partial failure | Fail-all rollback |
