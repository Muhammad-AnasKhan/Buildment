# 24.12 — Verify concurrent checkout

> **[Build]** · Chapter 24 — Inventory reservations · *Evidence*

Production inventory work is not done until you **demonstrate** the race is closed. This lesson is your test plan — run it before the gate.

## Setup

1. Pick seed product `LastBanana` with `stockQty: 1`.
2. Two browser profiles or incognito + normal, same customer account or two accounts.

## Test matrix

| # | Action | Expected |
|---|---|---|
| A | Tab 1 starts checkout | 201 + PI client secret |
| B | Tab 2 starts checkout immediately after | 409 `INSUFFICIENT_STOCK` |
| C | Tab 1 completes payment | Order paid; reservation confirmed; `stockQty: 0` |
| D | Refresh catalogue | `stockQty: 0`, `reservedQty: 0`, `availableQty: 0` |
| E | Reset stock to 1; start checkout and do not pay | `stockQty: 1`, `reservedQty: 1`, `availableQty: 0` |
| F | Wait past TTL and run worker | Released; `stockQty: 1`, `reservedQty: 0`, `availableQty: 1` |

## Optional: scripted race

Use `curl` in parallel against checkout start (with auth tokens):

```bash
# illustrative — adapt URL and body to your API
for i in 1 2; do
  curl -s -o "/tmp/co-$i.json" -w "%{http_code}\n" \
    -X POST "$API/checkout/start" \
    -H "Authorization: Bearer $TOKEN" \
    -H "Content-Type: application/json" \
    -d @checkout-body.json &
done
wait
```

Exactly one `201`/`200` and one `409` — never two successes.

Save both response bodies and inspect the Product plus StockReservation rows immediately after the
race. An HTTP status assertion alone can hide a leaked counter.

## Catalogue check

`GET /products/:id` returns `stockQty`, `reservedQty`, and `availableQty`. UI product cards should
bind to **availableQty** for “Add to cart” enablement. Treat these fields as display data only;
checkout repeats the server-side guarded claim.

## What to capture for learning log

Capture the two HTTP outcomes and the three inventory values after reserve, confirm, and expiry.
Include a short note explaining why a transaction without the guarded `reservedQty` write would
still allow a write-skew race.
