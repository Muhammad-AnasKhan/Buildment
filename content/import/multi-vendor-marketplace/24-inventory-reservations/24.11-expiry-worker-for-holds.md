# 24.11 — Expiry worker for holds

> **[Build]** · Chapter 24 — Inventory reservations · *Background hygiene*

Customers abandon card forms. Without expiry, ATP stays artificially low and vendors lose sales. A worker sweep every minute is enough for FreshMarket scale.

## Step 1 — Processor

Add `server/modules/inventory/releaseExpired.js`:

```javascript
export async function releaseExpiredReservations(batchSize = 100) {
  const now = new Date();
  const expired = await StockReservation.find({
    status: 'active',
    expiresAt: { $lte: now },
  })
    .limit(batchSize)
    .select('_id');

  let released = 0;
  for (const doc of expired) {
    const res = await StockReservation.updateOne(
      { _id: doc._id, status: 'active' },
      { $set: { status: 'released', releasedAt: now } }
    );
    released += res.modifiedCount;
  }
  return { released };
}
```

Conditional update ensures a confirm that lands between find and update does not get clobbered.

## Step 2 — Queue job (Chapter 22 pattern)

In `worker.js`, register processor `inventory.releaseExpired`:

```javascript
import { releaseExpiredReservations } from './server/modules/inventory/releaseExpired.js';

// inside worker setup
queue.process('inventory.releaseExpired', async () => {
  const result = await releaseExpiredReservations();
  console.log('[inventory] released expired holds', result);
});
```

Schedule with BullMQ repeat `{ every: 60_000 }` from API boot **once** (or a small `scripts/schedule-inventory-jobs.js` you run in prod).

Alternative: enqueue a delayed job per reservation at create time — fewer sweeps, more jobs. FreshMarket uses **sweep** for teaching clarity.

## Step 3 — Observability

Log `{ released }` counts. Mentors can grep worker logs during demo.

## Verify

- Start checkout, note `expiresAt` in DB (or shorten TTL in dev).
- Do not pay; run worker — status `released`, `stockQty` unchanged, ATP back.
