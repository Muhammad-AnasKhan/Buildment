# 24.04 — Reserve vs decrement

> **[Learn]** · Chapter 24 — Inventory reservations · *Two different moments*

Inventory math fails when teams pick **one** moment to subtract stock. FreshMarket uses **two** moments on purpose.

## Two clocks

| Moment | Action | Updates `stockQty`? | Updates ATP? |
|---|---|---|---|
| Customer clicks **Pay** / checkout starts | Create `active` reservations | No | Yes (lower) |
| Stripe webhook **payment succeeded** | Confirm reservations | Yes (decrement) | Already reflected |
| TTL or cancel | Release reservations | No | Yes (restore) |

Decrementing `stockQty` at checkout **start** would strand inventory when payments fail. Decrementing only at **display** time would still oversell under concurrency.

## ATP formula (this course)

For a product `P`:

```
activeHeld = SUM(quantity) WHERE productId = P AND status = 'active'
availableQty = max(0, P.stockQty - activeHeld)
```

After payment confirm for quantity `q`:

```
P.stockQty -= q   // reservation already removed from activeHeld via status → confirmed
```

Confirmed rows are terminal — they should **not** count in `activeHeld`.

## MongoDB pattern: conditional reserve

Reserve must be **one round trip** that fails if ATP would go negative:

1. Aggregate active holds for `productId` (or maintain `reservedQty` denormalized — out of scope here).
2. If `stockQty - activeHeld < requestedQty`, return 409 `INSUFFICIENT_STOCK`.
3. Insert reservation with `status: active` and `expiresAt`.

For high traffic SKUs, a follow-up course might add `$inc` on a `reservedQty` field with `$lte` guard — you will document that tradeoff in your learning log.

## Idempotent confirm

Webhooks retry. Confirm handler:

```
find reservation by paymentIntentId + productId + checkoutId
update where status = 'active' → 'confirmed'
if matchedCount = 0, check if already confirmed → return 200 anyway
else decrement stockQty with $gte guard on quantity
```

If decrement fails after confirm, you log loudly — that is a **support** scenario, not silent oversell.

## Vendor dashboard copy

Show three numbers:

- **On shelf** — `stockQty`
- **Held at checkout** — sum active reservations
- **Available online** — ATP

Vendors understand “held at checkout” better than “reserved documents in MongoDB.”
