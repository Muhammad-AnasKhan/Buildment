# 24.09 — Reserve stock at checkout

> **[Build]** · Chapter 24 — Inventory reservations · *Checkout gate*

Wire reservations into the same handler that today creates orders and a PaymentIntent. Order of operations matters: **validate cart → atomically claim all lines → create PaymentIntent with checkoutId metadata → attach its id to the holds**. If Stripe creation fails, release the claims before returning an error.

## Step 1 — Service module

Create `server/modules/inventory/reserve.js`:

```javascript
import mongoose from 'mongoose';
import { StockReservation } from '../../models/stockReservation.model.js';
import { Product } from '../../models/product.model.js';
import { RESERVATION_TTL_MINUTES } from './constants.js';

export async function reserveForCheckout({ checkoutId, lines, paymentIntentId = null }) {
  const expiresAt = new Date(Date.now() + RESERVATION_TTL_MINUTES * 60_000);
  const session = await mongoose.startSession();
  session.startTransaction();
  try {
    for (const line of lines) {
      const product = await Product.findOneAndUpdate(
        {
          _id: line.productId,
          isPublished: true,
          $expr: {
            $gte: [
              { $subtract: ['$stockQty', { $ifNull: ['$reservedQty', 0] }] },
              line.quantity,
            ],
          },
        },
        { $inc: { reservedQty: line.quantity } },
        { new: true, session }
      );
      if (!product) {
        throw Object.assign(new Error('INSUFFICIENT_STOCK'), {
          status: 409,
          productId: line.productId,
        });
      }
      await StockReservation.create(
        [{
          productId: product._id,
          storeId: product.storeId,
          quantity: line.quantity,
          checkoutId,
          paymentIntentId,
          expiresAt,
          status: 'active',
        }],
        { session }
      );
    }
    await session.commitTransaction();
  } catch (err) {
    await session.abortTransaction();
    throw err;
  } finally {
    session.endSession();
  }
}
```

Adapt field names (`storeId`, line shape) to match your cart module from Chapter 16.

The transaction is essential for a multi-line cart: if line three cannot be claimed, MongoDB rolls
back the `reservedQty` increments and reservation inserts for lines one and two. The customer gets
one honest failure instead of a partially held basket.

## Step 2 — Checkout handler

Generate one stable `checkoutId` (UUID) per checkout attempt and reuse it when the client retries
the same request. Call `reserveForCheckout` **before** Stripe `paymentIntents.create`. Put
`checkoutId` in PaymentIntent metadata so the webhook can correlate even if attaching
`paymentIntentId` to the reservation is delayed.

If PaymentIntent creation throws, call `releaseForCheckout(checkoutId)` before returning. Otherwise
a Stripe outage would strand reserved units until the TTL worker runs.

On 409, return JSON:

```json
{
  "error": "INSUFFICIENT_STOCK",
  "productId": "...",
  "available": 0
}
```

Client should toast and refresh product/cart — do not send the user to Stripe.

## Step 3 — Client copy

When `availableQty < cart quantity`, disable increment button on cart lines (Chapter 17 UI tweak).

## Verify

- Single checkout still pays end-to-end.
- Temporarily set `stockQty: 1`, put 2 in cart — checkout start fails before Stripe.
- Send two checkout requests concurrently for the last unit — exactly one guarded Product update succeeds.
- Force Stripe creation to fail — the compensating release returns `reservedQty` to its original value.
