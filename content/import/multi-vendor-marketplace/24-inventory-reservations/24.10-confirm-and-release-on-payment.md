# 24.10 — Confirm and release on payment

> **[Build]** · Chapter 24 — Inventory reservations · *Money and atoms align*

Payment success is the only place `stockQty` drops. Abandonment and explicit cancel **release** holds without touching on-hand count.

## Step 1 — confirmReservations

Add `server/modules/inventory/confirm.js`:

```javascript
export async function confirmReservationsForPaymentIntent(paymentIntentId) {
  const reservations = await StockReservation.find({
    paymentIntentId,
    status: 'active',
  });

  for (const r of reservations) {
    const updated = await StockReservation.findOneAndUpdate(
      { _id: r._id, status: 'active' },
      { $set: { status: 'confirmed', confirmedAt: new Date() } },
      { new: true }
    );
    if (!updated) continue; // already confirmed — idempotent

    const dec = await Product.findOneAndUpdate(
      { _id: r.productId, stockQty: { $gte: r.quantity } },
      { $inc: { stockQty: -r.quantity } }
    );
    if (!dec) {
      // Log for ops — payment succeeded but shelf math failed
      console.error('STOCK_DECREMENT_FAILED', { reservationId: r._id });
    }
  }
}
```

Call this from your existing `payment_intent.succeeded` handler **after** order paid flags — order state and inventory should commit in sensible order (document your choice in code comments).

## Step 2 — Attach paymentIntentId to reservations

When Stripe returns the PaymentIntent id at checkout, update reservations:

```javascript
await StockReservation.updateMany(
  { checkoutId, status: 'active' },
  { $set: { paymentIntentId: pi.id } }
);
```

## Step 3 — releaseForCheckout

```javascript
export async function releaseForCheckout(checkoutId) {
  await StockReservation.updateMany(
    { checkoutId, status: 'active' },
    { $set: { status: 'released', releasedAt: new Date() } }
  );
}
```

Invoke from cart clear, checkout cancel endpoint, or `payment_intent.canceled` if you handle it.

## Step 4 — Webhook idempotency

If your webhook handler already stores processed event ids, keep that — confirm function must tolerate duplicate calls.

## Verify

- Pay once — reservation `confirmed`, `stockQty` decreased by line qty.
- Replay webhook payload (Stripe CLI) — no double decrement.
- Cancel before pay — reservations `released`, ATP restored.
