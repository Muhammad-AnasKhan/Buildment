# 11.14 — Recap and what's next

> **[Wrap]** · Chapter 11 — Manage products API · *Recap — what you built and what comes next*

Chapter 11 completes **vendor product CRUD on the API** — create on own store, scoped list, update, delete, with cross-vendor mutation blocked at 403. The shop has shelves; the browser dashboard comes next.

## Narrative recap

Each line below is a *decision* you made, not just a file you created — if you can explain the reasoning behind any of them, the chapter has done its job.

**Products module:** routes, service, schema wired to existing model.

**POST /products:** storeId from vendor's store; grocery fields validated.

**GET /vendor/products:** inventory scoped to JWT — drafts included.

**PATCH /products/:id:** partial update including isPublished.

**DELETE /products/:id:** hard delete with ownership.

**Isolation:** Vendor B cannot PATCH/DELETE Vendor A's product.

## Viva prep

Four questions, four one-breath answers. If you can answer these without opening your editor, you understand the chapter's core idea: the API serves two different audiences with one model and two entry points.

1. **Two views of products?** — Vendor inventory (Ch 11) vs public catalogue (Ch 14).

2. **Why GET /vendor/products?** — Token-scoped; no client storeId.

3. **Ownership chain?** — product.storeId → store.vendorId === userId.

4. **Default isPublished?** — false — drafts until vendor publishes in Ch 12.
