## Chapter 9 — Vendor store API checklist (gate)

Do **not** open Chapter 10 until every box is ticked and learning log answers are written below.

### Stores module

- [ ] `server/src/modules/stores/stores.routes.js` exists and exports router
- [ ] `server/src/modules/stores/stores.service.js` — create, getByVendorId, update
- [ ] `server/src/modules/stores/stores.schema.js` — POST and PATCH validation
- [ ] Router mounted at `/api/stores` (or documented equivalent prefix)
- [ ] `GET /me` registered before `/:id` routes

### POST /api/stores

- [ ] Requires authentication — 401 without token
- [ ] Requires vendor role — 403 for customer
- [ ] Creates store with `vendorId` from JWT — not from body
- [ ] Returns 201 with store document on first create
- [ ] Second create same vendor → **409 Conflict**
- [ ] Invalid body → 400 with field errors

### GET /api/stores/me

- [ ] Vendor with store → 200 + document
- [ ] Vendor without store → **404** (or documented alternative)
- [ ] Customer → 403
- [ ] Query scoped by authenticated vendor only

### PATCH /api/stores/:id

- [ ] Owner can update mutable fields → 200
- [ ] Vendor B patching Vendor A store → **403**
- [ ] Invalid id or missing store → 404
- [ ] `vendorId` cannot be changed via PATCH
- [ ] Uses `assertStoreOwner` or equivalent from Ch 8

### Testing & docs

- [ ] Full curl lifecycle completed (9.12)
- [ ] `docs/AUTHORIZATION.md` updated with store routes
- [ ] Unique index on `vendorId` verified in Store model
- [ ] No secrets or full JWTs committed

### Prior chapter gates still true

- [ ] Auth register/login/refresh still works
- [ ] Chapter 8 IDOR pattern still understood and tested
- [ ] Store model from Ch 5 intact or changes documented
- [ ] I can explain **one store per vendor** and where it is enforced
- [ ] I can explain **409 vs 403** for duplicate create vs wrong role
- [ ] I can explain why **`GET /stores/me`** beats query-param vendor id
- [ ] I can trace **ownership chain**: User → Store → Product (preview Ch 11)
- [ ] I can explain how Chapter 10 will use **404 on GET me**

### Learning log — write now

Answer **in your own words** in the fields below:

1. **Create flow:** Walk through `POST /stores` from HTTP request to MongoDB document. Where is `vendorId` set? What happens on duplicate create?

2. **GET /stores/me:** What status do you return when a vendor has no store? Why did you choose that contract for Chapter 10 onboarding?

3. **PATCH ownership:** How does `assertStoreOwner` (or your equivalent) prevent IDOR? Describe your Vendor B → Vendor A PATCH test result.

4. **Validation:** Which fields are required on create vs optional on PATCH? How do you reject `vendorId` in the body?

5. **Route design:** Why is `/me` registered before `/:id`? Did you use ObjectId or slug in PATCH URLs?

6. **Error mapping:** List the status codes your store routes return (401, 403, 404, 409, 400, 201, 200) and one scenario for each.

7. **Database:** How does the unique index on `vendorId` help? What happens if two POST requests race?

8. **Chapter 10 preview:** What three API calls will the open-shop and settings pages make? What UI happens on 404 from GET me?
