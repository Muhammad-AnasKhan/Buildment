# 23.8 — Production env checklist

The safest environment checklist comes from the code, not memory. Search every `process.env`, configuration-schema, and `import.meta.env` read, then assign each variable to the process that consumes it.

**After this step:** variable names are documented, real values live only in the appropriate host secret store, and both API and worker fail fast when required configuration is absent.

## API runtime inventory

| Variable | Purpose |
|---|---|
| `MONGODB_URI` | Production database |
| `PORT` | Often set by host |
| `NODE_ENV` | `production` |
| `JWT_ACCESS_SECRET` | Auth |
| `JWT_REFRESH_SECRET` or pepper | Auth |
| `CLOUDINARY_CLOUD_NAME` | Images |
| `CLOUDINARY_API_KEY` | Images |
| `CLOUDINARY_API_SECRET` | Images |
| `REDIS_URL` | Cache and BullMQ producer; required for the Chapter 21–22 production path |
| `CLIENT_ORIGIN` or CORS origin | Production client URL |
| `STRIPE_SECRET_KEY` | Stripe **test-mode** server key for the course deployment |
| `STRIPE_WEBHOOK_SECRET` | Secret for the deployed test-mode webhook endpoint |

Your names may differ. Treat the application's config module as canonical and update `.env.example` with placeholders only.

## Worker runtime inventory

The worker is a separate process and receives its own configuration:

- `NODE_ENV=production`
- the exact same `REDIS_URL` used by the API's BullMQ producer;
- `MONGODB_URI` only if processors read or write database records;
- provider credentials only for processors that call those providers.

Do not automatically copy JWT or Stripe secrets into the worker. Least privilege makes a worker compromise less damaging and makes its true dependencies visible.

## Client build inventory

| Variable | Purpose |
|---|---|
| `VITE_API_URL` | `https://api.yourdomain.com` at build |

Every `VITE_*` value is public because Vite embeds it in browser JavaScript. A public API origin is fine; database URLs, private API keys, and signing secrets are not.

## Host configuration contract

Copy each key to the correct service. Add startup validation that names a missing variable and exits before accepting traffic. A crash with `Missing REDIS_URL` is easier to repair than a checkout that returns success while jobs silently disappear.

Verify `NODE_ENV=production` on API — affects logging and cookies if secure flag.

---

## Production JWT cookies

If refresh tokens use an HTTP-only cookie, set `Secure` in production and test the exact client/API domain arrangement. Cross-origin requests also need an exact CORS origin, credentials enabled on client and server, and a compatible cookie `SameSite` policy. Do not solve cookie failures with `origin: *`.

## Preflight verification

1. Search server and worker code for environment reads.
2. Compare the results with `.env.example` and the config validator.
3. Compare API and worker panels separately.
4. Confirm Stripe values are test-mode values and the webhook secret belongs to the deployed endpoint.
5. Confirm no secret appears in any `VITE_*` variable.

## ✅ Do / ❌ Don't

**✅ Do:** Cross-check every `process.env` / `config.` read in server code.

**❌ Don't:** Deploy with a localhost database, Redis URL, client origin, or webhook destination.
