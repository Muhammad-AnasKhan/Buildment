# 23.10 — Deploy API

> **[Build]** · Chapter 23 — Deploy · *Server on VPS/Render/Railway; PM2 or native*

**Why this step matters:** The API is the brain — auth, checkout, cache, and job enqueue all live here. Until `/health` returns 200 on HTTPS with `db: connected`, nothing else in production can work.

<BigWordAlert term="API deployment" plainEnglish="Running Node server on host with process manager, env vars, and health check exposed." whyItMatters="FreshMarket API must survive restarts — PM2 or platform health checks keep it alive." />

**Where the project is now:** Full marketplace runs on localhost (Ch 2–22); production env checklist and client build are prepped (23.8–23.9) — the API has no public URL.

**After this step:** Express API reachable at **HTTPS** production URL; `/health` returns 200.

## Deploy contract — you implement per host

| Step | Spec |
|---|---|
| Push code | Git deploy or image build |
| Install deps | `npm ci --production` in `server/` |
| Set env | All keys from 23.8 |
| Start command | `node src/server.js` or `npm start` |
| Process manager | PM2, systemd, or PaaS native restart |

**Listen on `process.env.PORT`** — host sets dynamically on PaaS.

## MongoDB Atlas

Before the API can talk to the database, your Atlas cluster has to accept connections from your host. A production-ready setup needs three things:

- Production cluster or dedicated DB user
- Network access allows deploy IP
- Connection string in host env only

## Logs

Tail host logs on first deploy — fix `MONGODB_URI` typos, missing JWT secret, CORS not blocking health (health usually unauthenticated).

## ✅ Do / ❌ Don't

**✅ Do:** Run seed on production **only** if intentional — prefer separate prod seed; document.

**✅ Do:** Keep `npm run dev` for local — production uses `start`.

**❌ Don't:** Expose MongoDB port publicly.
