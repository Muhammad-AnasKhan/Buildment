# 23.7 — Where the project is now

> **[Build]** · Chapter 23 — Deploy · *Full app + worker works locally*

**Why this step matters:** Deploying a broken local build wastes platform setup time. This step proves API + worker + client still run together and `npm run build` passes before you configure production hosts.

**Build cluster starts here.** Chapters 2–22 left a complete marketplace on localhost: auth, vendor shop, customer browse, cart, split checkout, orders UI, Redis cache, search, and a BullMQ worker. Deployment should expose that known-good system, not mix hosting diagnosis with unfinished feature work.

**After this chapter:** HTTPS URLs for client and API; worker running in production; smoke tests pass on live environment.

## Environment inventory — classify before copying

Do not copy one large `.env` to every process. Build three lists from actual code reads:

| Process | Typical configuration |
|---|---|
| API | MongoDB, Redis, JWT secrets, Stripe test secret + webhook secret, Cloudinary secret, client origin |
| Worker | Redis, plus MongoDB or provider credentials used by processors |
| Client build | Public `VITE_API_URL` and other intentionally public `VITE_*` values only |

The platform normally provides `PORT`; your code must read it but you may not set it yourself. Generate new production signing secrets rather than copying development strings. For the course deploy, keep Stripe in test mode so smoke tests cannot create real charges.

Chapter **23.8** checklist expands this — start gathering values now.

**✅ Do:** Deploy worker — checkout notifications silently stop if only API is deployed.

**❌ Don't:** Put production secrets in client env except `VITE_API_URL`.

**❌ Don't:** Deploy with `CORS origin: *` — set production client URL.
