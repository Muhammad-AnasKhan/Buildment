# 19.10 — Payment Intent route

> **[Build]** · Chapter 19 — Payment processing · *POST /payments/intent*

Before the customer enters a card, the server tells Stripe **how much to charge**. The amount must come from the cart on the server — never from the client.

<BigWordAlert term="POST /payments/intent" plainEnglish="Server route creating Stripe Payment Intent for pending checkout total." whyItMatters="FreshMarket client calls this before showing card form — amount computed server-side." />

## Step 2 — createPaymentIntent(userId)

1. Load cart (same as checkout) — empty → **400**
2. Validate each line: published, stock OK (same pre-checks as Ch 18)
3. Compute a positive integer `amount` in **smallest currency unit** (paise for INR, cents for USD)
4. Build a stable cart fingerprint/version and bind the intent to the authenticated user.
5. Call Stripe with an idempotency key for this logical create attempt:

```javascript
paymentIntents.create({
  amount,
  currency: 'inr',  // or your config
  automatic_payment_methods: { enabled: true },
  metadata: { userId, cartFingerprint }
}, {
  idempotencyKey: requestId
})
```

5. Return:

```json
{
  "paymentIntentId": "pi_...",
  "clientSecret": "pi_..._secret_...",
  "amount": 34500,
  "currency": "inr"
}
```

**Do not** create orders. **Do not** decrement stock. **Do not** clear cart.

The idempotency key protects a retried create call from producing two Payment Intents. It is separate from checkout idempotency in 19.13. Reusing one key with different parameters makes Stripe reject the request, so retain it only for retries of the same logical attempt.

## Common mistakes

| Mistake | Fix |
|---|---|
| Accept amount from client body | Server computes from cart |
| Clear cart on intent create | Cart clears only on successful checkout |
| Vendor can create intent | Customer role only |
| Different total formula than checkout | Shared helper |
| Retry creates multiple intents | Reuse one create-attempt idempotency key |
| Floating-point money math | Sum integer paise/cents once |
| Another customer can present the intent | Bind user and cart fingerprint in metadata |
