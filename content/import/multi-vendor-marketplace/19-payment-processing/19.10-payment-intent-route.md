# 19.10 — Payment Intent route

> **[Build]** · Chapter 19 — Payment processing · *POST `/payments/intent` from cart total*

**Why this step matters:** The Payment Intent is the **price tag** Stripe will charge — amount must match your server cart total, created before the client collects card details.

**Where the project is now:** Stripe client in `shared/stripe.js`; no `payments` module yet; checkout still accepts unpaid requests.

**After this step:** `POST /payments/intent` returns `paymentIntentId`, `clientSecret`, `amount`, and `currency` for the authenticated customer's current cart.

## Scaffold payments module

Create:

```
server/src/modules/payments/
  payments.routes.js
  payments.service.js
  payments.schema.js   ← optional Joi/Zod for empty body
```

Mount router at `/payments` under `/api` — full path `POST /api/payments/intent`.

Wire `requireAuth` + `requireRole('customer')` same as checkout.

## createPaymentIntent(userId) — contract

**Steps (spec — you implement):**

1. Reuse cart load logic from checkout — populated products, empty cart → 400.
2. Validate each line: exists, published, stock ≥ quantity (same as Ch 18 pre-checks).
3. Compute `amount` in **smallest currency unit** — sum `(price × quantity)` per line using **current catalogue price** (same basis as checkout total).
4. Call Stripe `paymentIntents.create` with:
   - `amount`, `currency` (from config/README)
   - `automatic_payment_methods: { enabled: true }` **or** explicit `payment_method_types` — document choice
   - `metadata`: `userId`, optional `storeCount`, `cartItemCount`
5. Return JSON:

```json
{
  "paymentIntentId": "pi_...",
  "clientSecret": "pi_..._secret_...",
  "amount": 34500,
  "currency": "inr"
}
```

**Do not** insert orders. **Do not** decrement stock. Intent only.

## Shared total helper

Extract `computeCartTotal(cartLines)` used by:

- `payments.service.js` (this route)
- `orders.service.js` checkout verify (19.11)

One function — prevents intent amount ≠ checkout verify mismatch.

## Error contract

| Condition | Status | Message hint |
|---|---|---|
| Empty cart | 400 | Cart is empty |
| Unpublished / OOS line | 400 | Same as checkout validation |
| Stripe API error | 502 or 500 | Generic external error — log Stripe message server-side |
| Vendor token | 403 | Customers only |

## curl verification — intent only

```bash
curl -s -X POST http://localhost:5000/api/payments/intent \\
  -H "Authorization: Bearer <customer-token>" \\
  -H "Content-Type: application/json" \\
  -d '{}'
```

**Expected:** 200 with `paymentIntentId`, `clientSecret`, `amount` matching cart sum in smallest unit.

**Dashboard:** New Payment Intent in **requires_payment_method** (or similar) — amount matches.

**Not expected yet:** Orders in MongoDB — intent alone does not checkout.

## ✅ Do / ❌ Don't

**✅ Do:** Require auth — anonymous users must not create intents.

**✅ Do:** Log `paymentIntentId` at info in dev — not `clientSecret` in production logs.

**❌ Don't:** Accept `amount` from request body.

**❌ Don't:** Clear cart on intent creation — cart clears only on successful checkout.
