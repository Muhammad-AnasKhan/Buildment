# 19.5 — Stripe test mode

> **[Learn]** · Chapter 19 — Payment processing · *Test cards; `pk_test_` / `sk_test_` keys*

You will never touch real card numbers in this course. **Test mode** gives you the same API shapes, Dashboard views, and error codes — with fake money and test keys.

<BigWordAlert term="Stripe test mode" plainEnglish="Sandbox using test API keys and card numbers — no real money moves." whyItMatters="FreshMarket development uses `pk_test_` / `sk_test_` — switch to live keys only in production." />

This sub-chapter teaches what to create in Stripe before sub-chapter 19.9 adds keys to `.env`.

## In plain English

| Term | Simple meaning |
|---|---|
| **Test mode** | Toggle in Stripe Dashboard — all API calls use test data |
| **Publishable key** | `pk_test_…` — safe to embed in client (Stripe.js) |
| **Secret key** | `sk_test_…` — server only; creates Payment Intents |
| **Webhook signing secret** | `whsec_…` — proves webhook POST really came from Stripe |
| **Test card** | Fake PAN that always succeeds in test mode — `4242 4242 4242 4242` |

## Think of it like a flight simulator

Pilots train in simulators before passengers board. Stripe test mode is the simulator: throttles feel real, runway is fake. **`sk_live_` keys are the real plane** — keep them out of this repo forever.

## Create a Stripe account (one-time)

1. Sign up at [stripe.com](https://stripe.com).
2. Stay in **Test mode** (toggle top-right of Dashboard — should say "Test mode").
3. Open **Developers → API keys**.
4. Copy **Publishable key** and **Secret key** — both `pk_test_` / `sk_test_`.

**Do not** activate live payments for the course. Mentors grade test-mode proof only.

## Keys go where

| Key | File | Committed to Git? |
|---|---|---|
| `STRIPE_SECRET_KEY` | `server/.env` | **Never** — only `.env.example` placeholder |
| `VITE_STRIPE_PUBLISHABLE_KEY` | `client/.env` | **Never** — example only |
| `STRIPE_WEBHOOK_SECRET` | `server/.env` | **Never** — from CLI or Dashboard webhook |

Chapter 19 build uses server keys in 19.9. Client publishable key matters in Chapter 20 checkout UI — add to `.env.example` now so nothing is forgotten.

## Test cards you need

| Card number | Behaviour |
|---|---|
| `4242 4242 4242 4242` | Success — use for gate |
| `4000 0000 0000 9995` | Decline — optional failure test |
| Any future expiry, any CVC, any postal | Stripe accepts in test |

Use any name and email in test. No real bank is charged.

## Dashboard views worth knowing

| Dashboard section | Why open it during build |
|---|---|
| **Payments → Payment Intents** | See each intent move to `succeeded` |
| **Developers → Events** | Raw webhook payloads when debugging |
| **Developers → Webhooks** | Register endpoint or see CLI deliveries |
| **Logs** | API errors with request ids |

When checkout fails, compare **your MongoDB orders** with **Dashboard PI status** — they must agree after a successful flow.

Also record Stripe's request ID from SDK errors. It lets you correlate a server failure with Stripe Dashboard logs without printing keys, client secrets, card details, or the full webhook payload.

## Stripe CLI for local webhooks

Webhooks need a public URL. Locally, use Stripe CLI:

```bash
# Install Stripe CLI — see stripe.com/docs/stripe-cli
stripe login
stripe listen --forward-to localhost:5000/api/webhooks/stripe
```

CLI prints a **webhook signing secret** (`whsec_…`) — put that in `STRIPE_WEBHOOK_SECRET` for local dev.

Production (Chapter 23) registers a real HTTPS URL — same handler code, different secret per endpoint.

## Common beginner questions

**Q: I accidentally committed a test key to Git — is that OK?**  
A: Rotate it in the Stripe Dashboard immediately, and treat the habit as the real problem. Test keys are far lower risk than live keys — they can't move real money — so the practical damage is small. But committing keys trains you to do it when it matters, and committing `sk_live_…` would be catastrophic. The rule is absolute: no secret of any kind gets committed. Remove the key from Git history if you can, rotate it, and confirm `.env` is in `.gitignore` so it can't happen again.

**Q: What's the difference between test mode and a sandbox?**  
A: In this course, nothing — they're the same idea with different names. Stripe doesn't hand you a separate "sandbox" account; you create **one** Stripe account and flip it into **test mode** with the toggle at the top of the Dashboard. In test mode, every API call uses fake money and your test keys, and nothing is real. Other payment providers literally call this a sandbox, which is why you'll hear both terms. For Stripe, just make sure the Dashboard says "Test mode" before you copy any keys.

**Q: INR or USD — which currency should I use?**  
A: Pick one and stay consistent — FreshMarket is a grocery marketplace, and the course examples use Indian Rupees (₹). Stripe supports INR in test mode, but confirm the currency in your Dashboard account settings before creating intents. One easy bug to remember: Stripe takes amounts in the **smallest currency unit**, so ₹120.50 is sent as `12050` paise — send `120.5` and the charge will be wrong or rejected. Apply that conversion every time you create or compare an intent amount.

**Q: Do I need business verification to use test mode?**  
A: No. Test mode needs nothing from you beyond a free Stripe account — no business documents, no bank details — because no real money moves. Live mode is where Stripe verifies who you are before letting you charge real customers, and this course explicitly doesn't go live. So create the account, flip to test mode, and you're ready to copy your test keys. Keep it that way for the whole course — mentors grade test-mode proof only.

**Q: Can I use Stripe's API without the Dashboard or CLI?**  
A: Not for first setup, no. You need the Dashboard at least once to create your account and copy your publishable and secret keys (`pk_test_…`, `sk_test_…`). And for local webhook testing you need the Stripe CLI (`stripe listen --forward-to localhost:5000/api/webhooks/stripe`), which hands you the `whsec_…` signing secret that proves webhook POSTs really came from Stripe. After that, your code talks to the API on its own — but keys and secrets have to come from somewhere, and that somewhere is the Dashboard or CLI.

## Security habits (course minimum)

Test keys are still secrets — a leaked `sk_test_` key is a leak. Meet this minimum bar on every deliverable:

- [ ] `.env` in `.gitignore` (should already be from Ch 4)
- [ ] `.env.example` has empty placeholders, not real keys
- [ ] README says "test mode only"
- [ ] No `sk_live_` or `pk_live_` in repo or screenshots
- [ ] No Payment Intent `client_secret` or full webhook payload in logs

## ✅ Do / ❌ Don't

**✅ Do:** Verify Dashboard toggle says **Test mode** before copying keys.

**✅ Do:** Save webhook secret from `stripe listen` when testing locally.

**❌ Don't:** Use real card numbers in test mode — they will fail or confuse.

**❌ Don't:** Share secret key in Discord screenshots.
