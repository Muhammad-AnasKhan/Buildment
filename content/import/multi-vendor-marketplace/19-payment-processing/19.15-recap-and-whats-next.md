# 19.15 — Recap and what's next

> **[Wrap]** · Chapter 19 — Payment processing · *Recap — what you built and what comes next*

**Why this step matters:** Chapter 20 adds checkout **UI** with Stripe.js on top of this API — you need a crisp story for Payment Intents, gated checkout, and one-payment-many-orders before building buttons.

<BigWordAlert term="Paid orders" plainEnglish="Checkout + Stripe confirms money collected — orders ready for vendor fulfillment UI." whyItMatters="Chapter 20 track orders assumes payment status on order documents is reliable." />

You entered Chapter 19 with free checkout. You leave with **real Stripe test-mode payments** — intent from cart, server verification, shared PI on split orders, webhooks with signature verify, idempotent checkout.

## What you built — narrative recap

**POST /payments/intent:** Loads cart, validates lines, computes total, creates Stripe Payment Intent, returns `clientSecret`.

**POST /checkout { paymentIntentId }:** Retrieves PI from Stripe; requires `succeeded` and amount match; runs Chapter 18 pipeline; sets `stripePaymentIntentId` and `paymentStatus: 'paid'` on every split order.

**POST /webhooks/stripe:** Raw body + `Stripe-Signature` verification; handles `payment_intent.succeeded` without duplicate orders.

**Idempotency:** Same PI never creates two order sets — checkout replay and webhook retries safe.

## Server tree now

```
server/src/shared/
  stripe.js                 ← Stripe SDK client

server/src/modules/payments/
  payments.routes.js        ← POST /payments/intent
  payments.service.js

server/src/modules/orders/
  orders.service.js         ← verify PI + existing checkout pipeline

server/src/modules/webhooks/
  webhooks.routes.js        ← POST /webhooks/stripe
  webhooks.service.js
```

Order model includes `stripePaymentIntentId`, `paymentStatus`.

## Viva-ready answers

1. **Why orders before payment in course order?** — Test commerce pipeline without gateway; payment plugs in at clear seam.
2. **Why one Payment Intent for multi-vendor cart?** — One customer charge; split fulfilment stays per-store orders.
3. **Why server retrieve PI?** — Client untrusted; Stripe API is source of truth.
4. **Why webhooks?** — Async confirmation, retries, client disconnect resilience.
5. **Why raw body on webhook?** — Signature over exact bytes; JSON parser breaks verify.
6. **Why idempotency on PI id?** — Double submit and webhook retries must not duplicate stock/orders.
