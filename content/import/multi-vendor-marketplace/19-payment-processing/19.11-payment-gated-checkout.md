# 19.11 — Payment-gated checkout

> **[Build]** · Chapter 19 — Payment processing · *No payment, no orders*

Chapter 18 let checkout run without money — the "fake checkout trap." This lesson adds the **payment gate**: orders only exist after Stripe confirms payment succeeded.

<BigWordAlert term="Payment-gated checkout" plainEnglish="Orders stay pending until Stripe confirms payment — no fulfillment on unpaid orders." whyItMatters="FreshMarket vendors should not pack orders that might fail card authorization." />

---

## What changes

**Before:** `POST /checkout` with `{}` → orders created  
**After:** `POST /checkout` with `{ paymentIntentId }` → verify Stripe → then Chapter 18 pipeline

<DiffBlock
  title="Checkout handler signature"
  language="javascript"
  before={`async function checkoutHandler(req, res) {
  const orders = await createOrdersFromCart(req.user.id);
  return res.status(201).json({ orders });
}`}
  after={`async function checkoutHandler(req, res) {
  const { paymentIntentId } = req.body;
  if (!paymentIntentId) {
    return res.status(400).json({ message: 'Payment required' });
  }
  await verifyPaymentSucceeded(paymentIntentId, req.user.id);
  const orders = await createOrdersFromCart(req.user.id, paymentIntentId);
  return res.status(201).json({ orders });
}`}
/>

## Step 2 — Phase A: verify payment (new)

Before any order logic:

1. `stripe.paymentIntents.retrieve(paymentIntentId)`
2. Status must be **`succeeded`** — else 402/400
3. Recompute cart total with **same helper** as 19.10
4. `paymentIntent.metadata.userId` must match the authenticated customer
5. Currency, amount, and cart fingerprint must match current authoritative cart state
6. **Idempotency:** atomically claim this PI or return its existing complete order set

If these checks fail after payment already succeeded, preserve the cart and record a reconciliation error with the Payment Intent ID. Do not silently create altered orders; follow the documented refund/support path.

---

## Step 3 — Phase B: Chapter 18 pipeline (unchanged logic)

Call your existing functions from 18.10–18.13:

7. Load cart, validate, group by storeId
8. Snapshot order lines
9. Atomic stock decrement (fail-all)
10. Set on each order: `stripePaymentIntentId`, `paymentStatus: 'paid'`
11. Insert orders, clear cart
12. Return `{ orders: [...] }` — 201 first time

**Do not rewrite** snapshot/stock/clear — reuse what you built in Chapter 18.

## Common mistakes

| Mistake | Result | Fix |
|---|---|---|
| Trust client "paid" flag | Free groceries | Retrieve PI from Stripe |
| Skip cart re-validation | Wrong stock/price | Re-validate after payment |
| Different amount formulas | Checkout fails mysteriously | Shared computeCartTotal |
| Orders on `requires_payment_method` | Unpaid orders | Check status === succeeded |
| Another customer's succeeded PI | Stolen reference funds a cart | Require metadata ownership |
| Cart changed after payment | Amount/order mismatch | Compare fingerprint and reconcile |
