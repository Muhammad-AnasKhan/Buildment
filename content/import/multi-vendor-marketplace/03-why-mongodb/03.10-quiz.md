```quiz
type: mcq
id: q1
question: A customer bought 2 kg of rice at ₹120/kg in March. In June the vendor raises the price to ₹150/kg and renames the product. What should the March order show in purchase history?
options:
  - ₹150/kg read live from the product document
  - ₹120/kg and the name captured at purchase
  - ₹120/kg pulled from the cart line kept since March
  - ₹150/kg, with the March price shown beside it
correct: 1
explanation: "Order lines embed the snapshot fields at checkout, so history keeps what was paid and what the item was called then. Reading live product fields lets a later price rise rewrite an old receipt, and the cart cannot help because checkout clears it — a kept-around cart line would also drift to the current price."
```

```quiz
type: mcq
id: q2
question: The catalogue page is slow because every product card needs its shop name, so a teammate proposes copying storeName onto each product document. What is the better fix?
options:
  - Copy it, so one product read also returns the shop name
  - Embed the whole store document inside each product
  - Keep storeId and populate the store once per page
  - Copy the name and refresh every product on rename
correct: 2
explanation: "A shop name is live, mutable data, so the reference plus one populate per page keeps every card correct for the cost of a single extra query. Copying it feels fast until the vendor renames the shop and thousands of documents go stale; refreshing them all on rename is a write storm that will eventually miss one. Copying is only correct for frozen history — order snapshots, not catalogue rows."
```

```quiz
type: mcq
id: q3
question: A cart holds rice from Stall A and milk from Stall B. What must checkout write, and what must the cart line already carry?
options:
  - One order per storeId, from cart lines with storeId
  - One order holding both vendors' lines, tagged per store
  - One order per cart line, each carrying its storeId
  - Two orders, each rebuilt from the customer's full cart
correct: 0
explanation: "Checkout splits the cart by storeId, so each vendor gets exactly one order containing only their own lines and the customer owns a separate order per shop. A single mixed order breaks per-vendor status and vendor isolation, one order per line makes a receipt per line instead of per vendor, and rebuilding each order from the full cart leaks another vendor's items and prices into the wrong order."
```
