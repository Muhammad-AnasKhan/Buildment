# 22.7 — Quiz

Background work should improve response reliability, not become part of the payment transaction. Check the producer and worker boundary.

```quiz
type: mcq
question: Why should checkout enqueue an order email instead of sending it inline?
options:
  - Slow or failing email delivery should not make a successful payment request fail
  - BullMQ can confirm card payments without Stripe
  - Email addresses cannot appear in HTTP requests
  - Workers make database writes unnecessary
correct: 0
```

```quiz
type: mcq
question: Which process is responsible for executing a queued job?
options:
  - The API producer that only adds the job
  - A worker running the matching processor
  - The customer's browser after navigation
  - MongoDB's schema validator
correct: 1
```

```quiz
type: mcq
question: The worker is offline when checkout finishes. What should the shopper see if payment and order persistence succeeded?
options:
  - A successful checkout while the durable job waits for a worker
  - A payment failure caused only by missing email
  - A second charge attempt
  - Another shopper's receipt
correct: 0
```
