```quiz
type: mcq
id: q1
question: A shopper adds the same brand of rice from Green Valley and from Harbor Market, and the cart page must show two sections. Where should that split be produced?
options:
  - From a new GET /cart response already nested by store
  - Into React groups keyed by each line's storeId
  - From a client map keyed on the product's name prefix
  - From a local carts collection, one cart per store
correct: 1
explanation: "GET /cart already returns a flat array where every line carries storeId and a populated store, so the page can key its sections on storeId without touching the contract. Nesting the response by store would couple one endpoint to one screen and force checkout, which groups server-side at its own layer, to duplicate the shape. Grouping by product name is a heuristic that fails the moment two vendors stock the same product, and a separate per-store cart collection would abandon the single user-scoped cart Chapter 16 proved."
```

```quiz
type: mcq
id: q2
question: A shopper adds a second item from product detail and the toast confirms it, but the header badge still reads 1 until they open /cart. What should the add handler do?
options:
  - Add one to a counter held by the header
  - Cache the new count in localStorage on success
  - Count rows in the header's cached cart copy
  - Refetch GET /cart in the add success handler
correct: 3
explanation: "The badge is a view of the server cart, so the add handler has to re-read GET /cart after a 201 and let the count follow from that response. Bumping a local counter or counting a cached copy drifts the moment a PATCH, a DELETE or a second tab changes the cart, and localStorage is the client-side store this chapter replaced with the MongoDB cart."
```

```quiz
type: mcq
id: q3
question: A customer logs out and a colleague logs in as a different customer in the same tab. The badge still shows 3 and /cart lists the first customer's items. What is the correct behaviour?
options:
  - Keep the badge and let the server filter on the next write
  - Copy the lines into the new customer's cart at login
  - Clear cart state on logout and refetch with the new token
  - Hide the badge until the new customer adds an item
correct: 2
explanation: "Cart data is user-scoped, so logout must drop the cached lines and the next mount must call GET /cart with the new token; whatever comes back is the only cart this user owns. Leaving the badge alone shows a stale count against another user's rows, copying lines would leak one customer's cart into another's, and hiding only the badge still leaves the /cart page displaying the wrong items."
```
