```quiz
type: mcq
question: "Yousef tests a retriever on one question with 3 relevant chunks. The retriever ranks them at 1, 4 and 8, and the service sends the top 5 chunks to the model. What are recall@5 and precision@5?"
options:
  - "Recall 0.40 and precision 0.67"
  - "Recall 0.67 and precision 0.40"
  - "Recall 1.00 and precision 0.60"
  - "Recall 0.67 and precision 0.67"
correct: 1
explanations:
  - "These two numbers are swapped. Recall divides by the 3 relevant chunks, and precision divides by k = 5."
  - "Right. Two of the 3 relevant chunks are in the top 5, so recall is 2 / 3 = 0.67. Two of the 5 slots are relevant, so precision is 2 / 5 = 0.40."
  - "The chunk at rank 8 is outside the top 5, so recall cannot be 1.00. Only 2 relevant chunks count."
  - "Recall is right, but precision divides by k = 5, not by the 3 relevant chunks, so it is 0.40."
```

```quiz
type: mcq
question: "Ahmad's HR policy assistant answers a question about leave with four claims. Three are in the retrieved chunks; one, 'unused leave is paid out in cash', is in none of them. For this question, recall@5 is 1.00. Where should Ahmad look first?"
options:
  - "Retrieval, because recall must be wrong when an answer has an error"
  - "The documents, because a faithful system cannot produce this error"
  - "The golden set, because the labels for this question are out of date"
  - "Generation, because the model added a claim the context lacks"
correct: 3
explanations:
  - "Recall of 1.00 means every relevant chunk reached the model. Retrieval did its job for this question."
  - "The documents never made this claim, so the error is not in them. This answer is not faithful, which points at generation."
  - "Nothing suggests the labels are wrong. The unsupported claim is in the answer, not in the retrieval results."
  - "Right. The right chunks were retrieved, but the answer contains a claim they do not support. That is a faithfulness failure in the prompt or the model."
```

```quiz
type: mcq
question: "Reem compares two prompts with a pairwise judge. She already runs every pair in both orders and counts only consistent wins. The new prompt wins 70 percent, and its answers are about 40 percent longer. What should she check next?"
options:
  - "Compare win rates on pairs where both answers have a similar length"
  - "Run every pair a third time in the original order to confirm the result"
  - "Switch the judge to a 10-point scale so it can show finer differences"
  - "Use the same model as the judge that wrote the new prompt's answers"
correct: 0
explanations:
  - "Right. Judges tend to prefer longer answers. If the new prompt still wins on pairs of similar length, the win is about quality, not verbosity."
  - "She already removed position bias with both orders. A third run in one order adds cost and tests nothing new."
  - "A longer scale does not remove a preference for length, and it usually makes judges less consistent."
  - "Using the same model as the judge invites self-preference bias. It makes the comparison less fair, not more."
```

```quiz
type: mcq
question: "Tamer's eval has 40 questions and a recall@5 of 0.86. He set the floor in the regression test to exactly 0.86. Now almost every pull request that touches retrieval fails, and the team wants to delete the test. What is the best fix?"
options:
  - "Delete the test, and check quality by hand before each release"
  - "Set the floor to 0.50, so that the test fails only on a disaster"
  - "Set the floor a little below 0.86, and raise it when quality improves"
  - "Mark the eval as allowed to fail, so that it never blocks a merge"
correct: 2
explanations:
  - "Hand checks are the problem the eval was built to solve. They are slow and easy to skip."
  - "A floor that low lets real drops pass. With 40 questions, losing several questions would still look fine."
  - "Right. A floor just below the baseline tolerates tiny moves but catches a real drop, and raising it after real gains keeps them."
  - "A check that can never fail gives no protection. People stop reading it within a few weeks."
```

```quiz
type: mcq
question: "Lina changes the chunk size of her document assistant from 60 words to 120. Her eval now fails with 'q08 points at unknown chunks'. What should she do?"
options:
  - "Remove the data check, because it only tests the golden set file"
  - "Re-check the golden labels against the new chunk ids, then rerun"
  - "Change the chunk size back, because labels must never be changed"
  - "Lower the recall floor until the eval passes with the new chunks"
correct: 1
explanations:
  - "The data check found a real problem: the labels point at chunks that no longer exist. Removing it hides that."
  - "Right. Chunk ids depend on chunk size, so a chunking change needs a label check. Only then is the new score comparable."
  - "Labels describe the current chunks, so they must follow chunking changes. The new chunk size may well be better."
  - "With stale labels, the score measures nothing real. Lowering the floor would accept a meaningless number."
```
