```quiz
type: mcq
question: "A pharmacy chain's assistant uses vector search only. Staff questions in plain words work well, but questions with batch codes such as 'LT-4471' rarely find the chunk that names the code. What is the best change?"
options:
  - "Replace vector search with keyword search for every question"
  - "Add BM25 next to vector search and fuse the two lists by rank"
  - "Switch to an embedding model with a larger vector dimension"
  - "Rerank the vector search's top 10 results with a cross-encoder"
correct: 1
explanations:
  - "Keyword search would find the codes but lose the plain-word questions that vector search already handles well."
  - "Right. BM25 rewards the rare exact token LT-4471, vector search keeps the paraphrased questions, and rank fusion merges both."
  - "A larger dimension does not give a code like LT-4471 more meaning, so the chunk still looks like many others."
  - "A reranker only reorders the list it gets. If the chunk with the code is not in the top 10, reranking cannot bring it in."
```

```quiz
type: mcq
question: "With reciprocal rank fusion and constant 60, chunk X is 1st in keyword search and 10th in vector search. Chunk Y is 3rd in both lists. Which chunk ranks higher after fusion?"
options:
  - "X, because a first place outweighs a lower rank in a second list"
  - "They tie, because both chunks appear in both lists exactly once"
  - "X, because its keyword score is probably much higher than Y's"
  - "Y, because 1/63 + 1/63 is larger than 1/61 + 1/70 for X"
correct: 3
explanations:
  - "X gets 1/61 + 1/70 = 0.0307, while Y gets 2/63 = 0.0317. Two good ranks beat one first place and one weak rank here."
  - "Appearing in both lists is not enough for a tie. Each list adds 1 / (60 + rank), and the ranks differ."
  - "Rank fusion ignores the raw scores. Only positions in each list count."
  - "Right. Y = 0.0317 and X = 0.0307, so Y ranks higher."
```

```quiz
type: mcq
question: "On 200 test questions, the right chunk is in the fused top 20 for 96% of them and in the top 50 for 97%. Reranking 20 chunks takes 120 ms and 50 chunks takes 300 ms. The retrieval budget is 200 ms. What should the team do?"
options:
  - "Rerank the top 20: it keeps nearly all recall within the budget"
  - "Rerank the top 50, since a deeper list always gives better answers"
  - "Skip the reranker and send the fused top 20 straight to the model"
  - "Rerank every chunk overnight and reuse those scores per question"
correct: 0
explanations:
  - "Right. Going from 20 to 50 adds one point of recall but 180 ms, which breaks the budget. The top 20 already holds the right chunk 96% of the time."
  - "Reranking 50 chunks takes 300 ms, over the 200 ms budget, for one extra point of recall."
  - "Twenty chunks is a long prompt, and without reranking the right chunk may sit far down it. A reranker that fits the budget is worth keeping."
  - "A cross-encoder scores a question and a chunk together, so scores cannot be computed before the question arrives."
```

```quiz
type: mcq
question: "Which of these questions needs multi-hop retrieval, where the second search depends on what the first one finds, rather than splitting into sub-questions up front?"
options:
  - "What were the Q2 and Q3 budgets for the East district school?"
  - "Compare the late-fee rules for farming loans and emergency loans"
  - "What is the delay rule of the courier that delivered order 5521?"
  - "How many staff work in North district and in South district now?"
correct: 2
explanations:
  - "Both parts are known up front: the Q2 budget and the Q3 budget. They can be split and searched at the same time."
  - "Both loan types are named in the question, so two independent searches can run in parallel."
  - "Right. The courier's name is not in the question. The first search must find which courier delivered order 5521; only then can the second search find that courier's delay rule."
  - "Both districts are named, so this splits into two independent sub-questions."
```

```quiz
type: mcq
question: "A team measures its router on 300 labelled questions. It sends 3% of policy questions to the no-retrieval route, and 12% of greetings to the single-step route. Which error should they fix first?"
options:
  - "The 12% of greetings, since that error happens four times as often"
  - "The 3% of policy questions, since they can get an invented rule"
  - "Neither, since the escalation step already catches both of them"
  - "Both equally, by retraining the router on a larger balanced set"
correct: 1
explanations:
  - "Greetings that get a search waste about a second each, but the answer is still harmless."
  - "Right. A policy question with no retrieval is answered from the model's memory and may state a rule that does not exist. That cost is far higher than a wasted search."
  - "Escalation moves a weak single-step search to multi-step. A question sent to no retrieval never searches, so nothing escalates it."
  - "The two errors have very different costs, so treating them equally hides the dangerous one."
```
