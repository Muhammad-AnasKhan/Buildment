```quiz
type: mcq
question: "In a deep dive, the interviewer says: 'For your four test questions, the first relevant chunk was at rank 1, rank 2, rank 4, and not found at all. What is your MRR?' Which answer is correct?"
options:
  - "0.58, the mean of 1, 0.5 and 0.25 over the three questions that found a chunk"
  - "0.75, because three of the four questions found at least one relevant chunk"
  - "0.44, the mean of 1, 0.5, 0.25 and 0 over all four of the test questions"
  - "0.25, because the reciprocal of the worst rank that was found, rank 4, is 0.25"
correct: 2
explanations:
  - "This leaves out the question with no relevant chunk. Its reciprocal rank is 0 and it must stay in the average, or failures are hidden."
  - "This is the share of questions with any hit, sometimes called hit rate. MRR also cares where the first hit is."
  - "Right. The reciprocal ranks are 1, 0.5, 0.25 and 0. Their sum is 1.75, and 1.75 divided by 4 is about 0.44."
  - "MRR is a mean over all questions, not the value for the worst one."
```

```quiz
type: mcq
question: "In the coding round, Omar has written a retry decorator for model calls. The interviewer asks: 'Which failures should it retry?' Which answer is strongest?"
options:
  - "Timeouts, 429 and 5xx responses, with backoff and jitter inside a total time budget"
  - "Every exception, three times each, because a model provider is not always reliable"
  - "400 errors too, because sending the same request again might work the next time"
  - "Only 500 errors, retried at once with no delay, so that the user waits less overall"
correct: 0
explanations:
  - "Right. These failures are often temporary, so a later try can succeed. Backoff, jitter and a total budget stop retries from adding load or blowing the latency target."
  - "Some exceptions, such as a validation error or a bug in your code, fail the same way every time. Retrying them only adds load and delay."
  - "A 400 means the request itself is wrong. The same request will be rejected again, so a retry wastes time."
  - "Retrying at once with no delay hits a struggling provider again immediately, and it also ignores timeouts and 429 responses."
```

```quiz
type: mcq
question: "In a design round, Lina proposes an agent for a fictional pharmacy chain that can cancel customer orders. The interviewer asks: 'How do you stop a wrong cancellation?' Which design is strongest?"
options:
  - "The system prompt says to cancel an order only when the customer clearly asks for it"
  - "The temperature is set to 0, so the model makes the same safe choice every single time"
  - "A person reviews the cancellation log each morning and reverses any mistaken orders"
  - "The cancel tool pauses the graph before it runs, and waits until a person approves it"
correct: 3
explanations:
  - "A prompt instruction is useful, but it is not a control. Injected text or a model mistake can still trigger the tool."
  - "Temperature 0 makes output more repeatable, not more correct. A repeatable wrong choice is still wrong."
  - "Reviewing after the action is too late: the order is already cancelled and the customer already affected."
  - "Right. The check happens before the side effect, so a wrong cancellation never runs without a person saying yes."
```

```quiz
type: mcq
question: "The interviewer asks Karim: 'Every answer in your system cites a chunk. Does that prove your answers are faithful?' Which answer is correct?"
options:
  - "Yes. When the model cites a retrieved chunk, the answer must come from that chunk"
  - "No. A citation shows which chunk was used, not that each claim is supported by it"
  - "Yes, as long as the cited chunk was ranked first by the reranker for that question"
  - "No, because faithfulness can only be measured by asking real users about answers"
correct: 1
explanations:
  - "A model can cite a real chunk and still add a claim the chunk does not contain. The citation is not proof."
  - "Right. Faithfulness means every claim is supported by the source, so each claim must be checked against the cited text, by a person or a calibrated judge."
  - "Rank says the chunk was relevant to the question. It says nothing about whether the answer's claims match the chunk."
  - "The answer 'no' is right, but the reason is wrong. Faithfulness is checked against the sources with a rubric, not by asking users."
```

```quiz
type: mcq
question: "In the managerial round, the hiring manager asks Reem: 'Tell me about a project that failed.' Which opening is strongest?"
options:
  - "My weakness is perfectionism, so my projects take longer, but they never really fail."
  - "The client changed the scope twice, so the project was late, but it was not my fault."
  - "I tuned prompts on 40 clean examples, live accuracy fell to 55%, so now I test first."
  - "We had a project that failed once, and the whole team learned a lot from that time."
correct: 2
explanations:
  - "This avoids the question. A manager hears that you will hide problems instead of reporting them."
  - "It blames someone else and gives no lesson. Managers score what you owned and what you changed."
  - "Right. It owns a specific mistake, gives a number for the impact, and names the change in her own process."
  - "It says 'we', gives no detail and no number, and the lesson is vague. The manager cannot tell what Reem did."
```
