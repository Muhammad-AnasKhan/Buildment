In chapters 10.3 to 10.5 you moved three clocks by hand. A Lamport clock took the larger number and added 1. A vector clock took the larger value in every slot. A hybrid clock took the later time and counted ties. All three are short, and each has an edge where a small mistake survives a simple test and shows up later as an event in the wrong place. In this chapter you write all three yourself, so you know exactly what they do at their edges.

By the end you will have a set of tested JavaScript pieces. `LamportClock` keeps one counter and has `tick`, `send` and `receive`. Four functions, `vcTick`, `vcMerge`, `vcReceive` and `vcCompare`, work on vector clocks stored as plain objects. `HybridClock` keeps a pair of numbers and reads a physical clock that you pass in. `hlcCompare` orders two hybrid stamps. You will reuse all of them in challenge 9, where they run on a simulated network.

## Why the physical clock is passed in

The hybrid clock needs the time of day, and time of day is awkward in tests. If your code calls `Date.now()`, a test cannot say "the clock now reads 70", and it cannot make the clock go backwards. The fix is the same one you met in the LRU cache in chapter 5.8: the constructor takes a function `now` that returns milliseconds. In production you pass `() => Date.now()`. In a test you pass a function that reads a variable the test moves by hand.

```js
let t = 100;                          // the fake physical time, in ms
const clock = new HybridClock(() => t);
clock.tick();                         // { l: 100, c: 0 }
t = 90;                               // the physical clock goes backwards
clock.tick();                         // { l: 100, c: 1 }: the stamp does not
```

A class that calls `Date.now()` inside its methods fails the tests on the server, because the fake clock moves and the real one barely does.

## The contract

Fix the rules first, including the awkward cases. The tests check these exact rules.

**LamportClock.** The property `time` starts at 0. `tick()` adds 1 to `time` and returns the new time. `send()` is also an event: it adds 1 and returns the new time, which is the stamp to attach to the message. `receive(stamp)` sets `time` to the larger of `time` and `stamp`, adds 1, and returns the new time. A receive never lowers `time`, even when the stamp is smaller.

**Vector clocks as plain objects.** A vector is an object such as `{ A: 2, B: 1 }`, and a slot that is not there counts as 0. All four functions return new objects and never change their inputs. `vcTick(vc, id)` returns a copy with slot `id` increased by 1. `vcMerge(a, b)` returns a copy that holds the larger value of every slot that appears in either. `vcReceive(local, remote, id)` merges the two vectors and then adds 1 to slot `id`, the receiving node. `vcCompare(a, b)` returns one of four strings: `"before"` when a happened before b, `"after"` when b happened before a, `"equal"` when every slot is the same, and `"concurrent"` when each is bigger in at least one slot.

**HybridClock.** The constructor takes `now`, a function that returns milliseconds. The clock keeps `l` and `c`, both starting at 0. `tick()` reads `now()` once. If that reading is bigger than `l`, then `l` becomes the reading and `c` becomes 0. Otherwise `l` stays and `c` goes up by 1. It returns `{ l, c }`. `send()` does the same as `tick()`. `receive(message)` reads `now()` once, takes `l` as the biggest of its own `l`, the message's `l` and the reading, and sets `c` by one rule: if the new `l` equals both its own `l` and the message's `l`, then `c` is the larger counter plus 1; if it equals only its own `l`, then `c` is its own counter plus 1; if it equals only the message's `l`, then `c` is the message's counter plus 1; otherwise `c` is 0. `hlcCompare(a, b)` returns -1, 0 or 1: it compares `l` first and `c` second.

Notice that in all three the receive is an event too. That is why Lamport and vector clocks add 1 after taking the larger value. The hybrid clock gets the same effect from its counter. If you forget that the receive is an event, the effect can get the same stamp as its cause, and the test that replays a chain catches it.

## A worked example: a hybrid receive by hand

Here is the hybrid contract applied to two cases that are not in the tests. Node B is at `{ l: 50, c: 2 }`.

First case: B's physical clock reads 55 and a message arrives with `{ l: 50, c: 4 }`. The biggest of 50, 50 and 55 is 55. Only the clock equals it, so `c` restarts at 0. The new stamp is `{ l: 55, c: 0 }`. The clock moved past everything B had seen.

Second case: B's clock reads 40 and the same message arrives. The biggest of 50, 50 and 40 is 50. It equals both B's `l` and the message's `l`, so the counter must beat both: the larger of 2 and 4 is 4, plus 1 is 5. The new stamp is `{ l: 50, c: 5 }`. Notice that 5 is bigger than the old stamp's counter 2 and the message's counter 4, so the new stamp is after both.

The subgoal in each case is to find the new `l` first and then ask which inputs equal it. Writing the code in that order keeps the four branches short.

## Three ways this goes wrong

**Changing a vector in place.** If `vcReceive` starts from `local` and edits it, the caller's vector changes too. Worse, the vector in transit is the sender's own object, so the sender's state changes when the receiver merges. The tests pass an object, call your function, and check that the object is unchanged.

**Treating a missing slot as undefined.** `undefined > 1` is `false` and `undefined < 1` is also `false`, so a comparison that reads `a[id]` directly gets the wrong answer when one vector has a slot the other lacks. Read every slot as `a[id] ?? 0`. This matters whenever a new node joins.

**Reading the clock twice, or ignoring a step back.** If `receive` calls `now()` more than once, the two readings can differ and the branches see different times. Read it once at the top. And if `tick` assumes the reading is always bigger than `l`, a physical clock that goes backwards makes the stamp go backwards. The rule keeps `l` and adds to `c`, so stamps from one node always increase.

solution: |
  class LamportClock {
    constructor() {
      this.time = 0;
    }

    tick() {
      this.time += 1;
      return this.time;
    }

    send() {
      return this.tick();
    }

    receive(stamp) {
      this.time = Math.max(this.time, stamp) + 1;
      return this.time;
    }
  }

  function vcTick(vc, id) {
    return { ...vc, [id]: (vc[id] ?? 0) + 1 };
  }

  function vcMerge(a, b) {
    const out = { ...a };
    for (const id of Object.keys(b)) out[id] = Math.max(out[id] ?? 0, b[id]);
    return out;
  }

  function vcReceive(local, remote, id) {
    return vcTick(vcMerge(local, remote), id);
  }

  function vcCompare(a, b) {
    let aLeads = false;
    let bLeads = false;
    for (const id of new Set([...Object.keys(a), ...Object.keys(b)])) {
      const x = a[id] ?? 0;
      const y = b[id] ?? 0;
      if (x > y) aLeads = true;
      if (y > x) bLeads = true;
    }
    if (aLeads && bLeads) return "concurrent";
    if (aLeads) return "after";
    if (bLeads) return "before";
    return "equal";
  }

  class HybridClock {
    constructor(now = () => Date.now()) {
      this.now = now;
      this.l = 0;
      this.c = 0;
    }

    tick() {
      const pt = this.now();
      if (pt > this.l) {
        this.l = pt;
        this.c = 0;
      } else {
        this.c += 1;
      }
      return { l: this.l, c: this.c };
    }

    send() {
      return this.tick();
    }

    receive(message) {
      const pt = this.now();
      const l = Math.max(this.l, message.l, pt);
      let c;
      if (l === this.l && l === message.l) c = Math.max(this.c, message.c) + 1;
      else if (l === this.l) c = this.c + 1;
      else if (l === message.l) c = message.c + 1;
      else c = 0;
      this.l = l;
      this.c = c;
      return { l, c };
    }
  }

  function hlcCompare(a, b) {
    if (a.l !== b.l) return a.l < b.l ? -1 : 1;
    if (a.c !== b.c) return a.c < b.c ? -1 : 1;
    return 0;
  }
