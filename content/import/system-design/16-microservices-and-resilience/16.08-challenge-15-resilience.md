## How the experiment works

There are two small servers, each in its own process. **Picks** is the dependency. It answers in about 40 ms, and you can switch it with a plain request to `ok`, `slow` (2 seconds per call) or `down` (an error at once). **Checkout** is the service under test. It has two routes. `/home` builds the home page: it does 20 ms of its own work, then calls Picks, and if Picks fails or is too slow it returns the page without the picks row. `/pay` takes a payment in 30 ms and needs nothing from Picks.

Checkout also has a **pool of workers**. Node.js does not block a thread while it waits for a network answer, so a real Node server would not run out of workers in this way. Most servers do: a Java or Python web server has a fixed number of threads, and each one is stuck while it waits. So the `Pool` class in `toolkit/pool.js` models those threads. A request must get a worker before it starts and gives it back when it finishes. When all 20 workers are busy, the next request waits in a line, or is refused if the line is already full. This is exactly the exhaustion you saw in 16.1.

Three design choices keep the numbers honest.

**Picks counts every call it receives.** The question in parts 1 and 2 is how much load a protection puts on, or keeps off, a failing dependency. So Picks keeps a counter, and the script reads it. A protection that looks good in latency but doubles the calls to a failing Picks is not good, and the counter shows it.

**Checkout returns something even when Picks fails.** A page without the picks row still counts as a served page, and Checkout counts how many pages were served with and without picks. The latency you measure is therefore the time to a useful page, not the time until an error.

**Every run starts fresh, and warms up first.** The first requests pay for opening connections and loading code. If you measure them, your p99 shows start-up costs and not the protection. The helper `lab.js` starts both servers, sends 30 home requests and 10 payments, and resets the counters before the experiment.

Next, `toolkit/pool.js`. The pool hands out `size` workers. When none is free, a request waits in a line, unless the line is already `queueMax` long, in which case `acquire()` returns `null` at once: the request is refused instead of waiting. That refusal is a small, honest version of load shedding. When a worker is released, it goes straight to the next waiting request.

```js
// toolkit/pool.js: a fixed number of workers. A request holds one worker while
// it waits for a dependency, like a thread blocked on a slow call.
export class Pool {
  constructor(size, queueMax = Infinity) {
    this.size = size;
    this.queueMax = queueMax;
    this.inUse = 0;
    this.waiting = [];
  }

  // Resolves to a release function, or to null when the waiting line is full.
  async acquire() {
    if (this.inUse < this.size) {
      this.inUse += 1;
    } else if (this.waiting.length >= this.queueMax) {
      return null;
    } else {
      await new Promise((resolve) => this.waiting.push(resolve)); // the slot is handed over
    }
    let released = false;
    return () => {
      if (released) return;
      released = true;
      const next = this.waiting.shift();
      if (next) next(); // pass the slot on: inUse stays the same
      else this.inUse -= 1;
    };
  }
}
```

## Step 2: the two servers

Create `challenges/challenge-15-resilience/dependency.js`. It is Picks. A request to `/mode/slow` switches it, `/count` reports how many calls arrived, and `/reset` zeroes the count. The `keepAliveTimeout` line stops Node from closing idle connections after 5 seconds, which would otherwise cause random "connection reset" errors between experiments.

```js
// The Picks service: a dependency that can be switched between modes while it runs.
// GET /picks answers by mode. GET /mode/slow (or ok, down) switches it.
// GET /count returns how many /picks calls arrived since the last /reset.
import http from "node:http";

const SLOW_MS = Number(process.env.SLOW_MS ?? 2000); // how long "slow" takes
const OK_MS = Number(process.env.OK_MS ?? 40); // how long a healthy answer takes
let mode = "ok"; // "ok", "slow" or "down"
let calls = 0;
const sleep = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

const server = http.createServer(async (req, res) => {
  const { pathname } = new URL(req.url, "http://x");
  if (pathname.startsWith("/mode/")) {
    mode = pathname.slice("/mode/".length);
    return res.end(`mode ${mode}\n`);
  }
  if (pathname === "/count") return res.end(JSON.stringify({ calls }));
  if (pathname === "/reset") {
    calls = 0;
    return res.end("reset\n");
  }
  calls += 1;
  if (mode === "down") {
    res.statusCode = 500;
    return res.end("down\n");
  }
  await sleep(mode === "slow" ? SLOW_MS : OK_MS); // waiting does not block other requests
  res.end("picks\n");
});

server.keepAliveTimeout = 60_000; // keep idle connections open longer than the default 5 s
server.listen(0, "127.0.0.1", () => {
  const { port } = server.address();
  if (process.send) process.send({ port });
  else console.log(`picks on http://127.0.0.1:${port}/`);
});
```

Now `checkout.js`. Read `callPicks` slowly: it is the whole module in one function. Every protection is a switch in the environment, so each experiment can start Checkout in a different mode. The time limit uses `AbortSignal.timeout`. The retry loop asks the budget before it retries, and waits a full-jitter delay if `JITTER` is on. The breaker is asked before every call and told how every call ended. If anything throws, the route returns the page without picks.

```js
// The Checkout service under test. /home shows the home page and calls Picks.
// /pay takes a payment and needs no dependency. Settings come from environment
// variables so each part can start it with different protections.
import http from "node:http";
import { Pool } from "../../toolkit/pool.js";
import { createBreaker, createRetryBudget, fullJitterDelay, sleep } from "../../toolkit/resilience.js";

const PICKS_URL = process.env.PICKS_URL;
const TIMEOUT_MS = Number(process.env.TIMEOUT_MS ?? 0); // 0 means wait forever
const RETRIES = Number(process.env.RETRIES ?? 0); // extra tries after the first
const JITTER = process.env.JITTER === "1"; // wait a full-jitter delay between tries
const BUDGET = process.env.BUDGET === "1"; // one retry per 10 requests
const BREAKER = process.env.BREAKER === "1";
const HOME_WORKERS = Number(process.env.HOME_WORKERS ?? 20);
const PAY_WORKERS = Number(process.env.PAY_WORKERS ?? 0); // 0 means pay shares the home pool
const QUEUE_MAX = Number(process.env.QUEUE_MAX ?? 1e9); // longest waiting line before a 503

const homePool = new Pool(HOME_WORKERS, QUEUE_MAX);
const payPool = PAY_WORKERS > 0 ? new Pool(PAY_WORKERS, QUEUE_MAX) : homePool;
const budget = BUDGET ? createRetryBudget({ requestsPerRetry: 10, maxRetries: 10 }) : null;
const breaker = BREAKER ? createBreaker({ failureThreshold: 5, openMs: 2000 }) : null;

const fresh = () => ({ home: { ok: 0, fallback: 0, rejected: 0 }, pay: { ok: 0, rejected: 0 }, refusedByBreaker: 0 });
let stats = fresh();

// One call to Picks, with the protections that are switched on.
async function callPicks() {
  budget?.recordRequest();
  for (let attempt = 0; ; attempt++) {
    if (breaker && !breaker.allowRequest()) {
      stats.refusedByBreaker += 1;
      throw new Error("breaker open");
    }
    try {
      const res = await fetch(`${PICKS_URL}picks`, { signal: TIMEOUT_MS ? AbortSignal.timeout(TIMEOUT_MS) : undefined });
      if (!res.ok) throw new Error(`picks answered ${res.status}`);
      await res.text();
      breaker?.recordSuccess();
      return;
    } catch (err) {
      breaker?.recordFailure();
      if (attempt >= RETRIES) throw err;
      if (budget && !budget.tryRetry()) throw err;
      if (JITTER) await sleep(fullJitterDelay(attempt + 1, 50, 1000));
    }
  }
}

const server = http.createServer(async (req, res) => {
  const { pathname } = new URL(req.url, "http://x");
  if (pathname === "/stats") return res.end(JSON.stringify(stats));
  if (pathname === "/reset") {
    stats = fresh();
    return res.end("reset\n");
  }
  const route = pathname === "/pay" ? "pay" : "home";
  const release = await (route === "pay" ? payPool : homePool).acquire();
  if (!release) {
    stats[route].rejected += 1;
    res.statusCode = 503;
    return res.end("busy\n");
  }
  try {
    if (route === "pay") {
      await sleep(30); // the payment work
      stats.pay.ok += 1;
      return res.end("paid\n");
    }
    await sleep(20); // the page's own work
    try {
      await callPicks();
      stats.home.ok += 1;
      res.end("home with picks\n");
    } catch {
      stats.home.fallback += 1; // the page still loads, without the picks row
      res.end("home without picks\n");
    }
  } finally {
    release(); // the worker is free again
  }
});

server.keepAliveTimeout = 60_000; // keep idle connections open longer than the default 5 s
server.listen(0, "127.0.0.1", () => {
  const { port } = server.address();
  if (process.send) process.send({ port });
  else console.log(`checkout on http://127.0.0.1:${port}/`);
});
```

Last, `lab.js`, which starts both servers, warms them up, and gives the scripts short helpers. It uses a plain `http.get` on a new connection for its control calls, so a connection that the server already closed can never break them.

```js
// Start Picks and Checkout as two processes, and read their counters.
import http from "node:http";
import { spawnServer } from "../../toolkit/load.js";

// A plain GET on a fresh connection, so an idle connection that the server
// already closed can never break a control call.
const get = (url) =>
  new Promise((resolve, reject) => {
    http.get(url, { agent: false }, (res) => {
      let body = "";
      res.on("data", (chunk) => (body += chunk));
      res.on("end", () => resolve(body));
    }).on("error", reject);
  });

export async function startLab(checkoutEnv = {}, picksEnv = {}) {
  const picks = await spawnServer(new URL("./dependency.js", import.meta.url), picksEnv);
  const checkout = await spawnServer(new URL("./checkout.js", import.meta.url), { PICKS_URL: picks.url, ...checkoutEnv });
  const lab = {
    homeUrl: `${checkout.url}home`,
    payUrl: `${checkout.url}pay`,
    setPicks: (mode) => get(`${picks.url}mode/${mode}`),
    picksCalls: async () => JSON.parse(await get(`${picks.url}count`)).calls,
    stats: async () => JSON.parse(await get(`${checkout.url}stats`)),
    reset: async () => {
      await get(`${picks.url}reset`);
      await get(`${checkout.url}reset`);
    },
    stop: () => {
      checkout.stop();
      picks.stop();
    },
  };
  // Warm up: the first requests pay for connection set-up and code start-up.
  for (let i = 0; i < 30; i++) await get(lab.homeUrl);
  for (let i = 0; i < 10; i++) await get(lab.payUrl);
  await lab.reset();
  return lab;
}
```

## Step 3: part 1, timeouts and retries

Picks answers in 2 seconds for the whole run. Forty home pages arrive every second for 6 seconds, and Checkout has 20 workers. With a healthy Picks, each page holds a worker for about 100 ms, so only 4 of the 20 are busy. The script runs four setups, one after the other, each on a fresh Checkout: no protection, a 200 ms time limit, the time limit with two immediate retries, and the time limit with two retries that use full jitter and a retry budget. Create `part-1-timeouts-and-retries/retries.js`:

```js
// Part 1: Picks is slow (2 seconds per call). Run the home page under four
// protections and compare the page's p99 and the load Picks receives.
import { writeFileSync } from "node:fs";
import { runLoad } from "../../../toolkit/load.js";
import { summarize } from "../../../toolkit/stats.js";
import { lineChart } from "../../../toolkit/chart.js";
import { startLab } from "../lab.js";

const RATE = 40; // pages per second; 20 workers hold a page for ~100 ms, so 2 are busy when Picks is healthy
const SECONDS = Number(process.env.STEP_SECONDS ?? 6);
const ROWS = [
  { name: "1 no protection", env: {} },
  { name: "2 timeout 200 ms", env: { TIMEOUT_MS: "200" } },
  { name: "3 timeout + 2 retries at once", env: { TIMEOUT_MS: "200", RETRIES: "2" } },
  { name: "4 timeout + 2 retries, jitter, budget", env: { TIMEOUT_MS: "200", RETRIES: "2", JITTER: "1", BUDGET: "1" } },
];

console.log(`Picks answers in 2000 ms. ${RATE} pages per second for ${SECONDS} s, 20 workers.\n`);
console.log("protection                              p50 ms   p99 ms  Picks calls/page  page without picks");

const points = [];
for (const row of ROWS) {
  const lab = await startLab({ HOME_WORKERS: "20", ...row.env });
  await lab.setPicks("slow");
  await lab.reset();
  const { latencies } = await runLoad({ url: lab.homeUrl, rate: RATE, seconds: SECONDS });
  const s = summarize(latencies);
  const calls = await lab.picksCalls();
  const stats = await lab.stats();
  const pages = stats.home.ok + stats.home.fallback;
  points.push({ x: points.length + 1, p50: s.p50, p99: s.p99 });

  );

}

writeFileSync(new URL("./chart.svg", import.meta.url), lineChart({
  title: "Page latency with Picks slow (1 none, 2 timeout, 3 retries, 4 budget)",
  xLabel: "protection (see results.md)",
```

Its test, `retries.test.js`, starts a real Checkout. It checks that a 200 ms limit keeps the page fast, that three immediate retries send exactly 4 calls to Picks for every page (when Picks answers an error at once) while a budget keeps it below 1.4, and that jitter stays under its ceiling.

```js
import test from "node:test";
import assert from "node:assert/strict";
import { runLoad } from "../../../toolkit/load.js";
import { percentile } from "../../../toolkit/stats.js";
import { fullJitterDelay } from "../../../toolkit/resilience.js";
import { startLab } from "../lab.js";

test("a timeout keeps the page fast while Picks is slow", async () => {
  const lab = await startLab({ TIMEOUT_MS: "200" });
  try {
    await lab.setPicks("slow");
    await lab.reset();
    const { latencies } = await runLoad({ url: lab.homeUrl, rate: 20, seconds: 2 });
    const p99 = percentile(latencies, 99);
    assert.ok(p99 < 700, `p99 was ${p99.toFixed(0)} ms, the 200 ms timeout did not work`);
    const stats = await lab.stats();
    assert.equal(stats.home.ok, 0);
    assert.ok(stats.home.fallback > 20, "pages should load without picks");
  } finally {
    lab.stop();
  }
});

test("three immediate retries multiply the load on Picks by 4; a budget keeps it near 1", async () => {
  const callsPerPage = async (env) => {
    const lab = await startLab({ RETRIES: "3", ...env });
    try {
      await lab.setPicks("down");
      await lab.reset();
      await runLoad({ url: lab.homeUrl, rate: 20, seconds: 2 });
      const stats = await lab.stats();
      return (await lab.picksCalls()) / (stats.home.ok + stats.home.fallback);
    } finally {
      lab.stop();
    }
  };
  assert.equal(await callsPerPage({}), 4);
  const withBudget = await callsPerPage({ BUDGET: "1" });
  assert.ok(withBudget < 1.4, `with a budget there were ${withBudget.toFixed(2)} calls per page`);
});

test("full jitter spreads the waits below the ceiling", () => {
  const waits = Array.from({ length: 200 }, (_, i) => fullJitterDelay(3, 50, 1000, () => i / 200));
  assert.ok(Math.max(...waits) < 400);
  assert.ok(new Set(waits).size > 150);
});
```

## Step 4: part 2, the circuit breaker

Now Picks hangs for a while and then comes back. The script runs three phases on one Checkout: 4 seconds with Picks healthy, 8 seconds with Picks hanging (2 seconds per call), and 8 seconds healthy again. It does this twice: once with a 200 ms limit only, and once with the limit and a breaker (5 failures in a row, open for 2 seconds). Create `part-2-circuit-breaker/breaker.js`:

```js
// Part 2: Picks works for 4 s, hangs for 8 s, then works again for 8 s.
// Compare a timeout alone with a timeout plus a circuit breaker.
import { writeFileSync } from "node:fs";
import { runLoad } from "../../../toolkit/load.js";
import { summarize } from "../../../toolkit/stats.js";
import { lineChart } from "../../../toolkit/chart.js";
import { startLab } from "../lab.js";

const RATE = 40;
const PHASES = [
  { name: "Picks healthy", mode: "ok", seconds: 4 },
  { name: "Picks hangs", mode: "slow", seconds: 8 },
  { name: "Picks healthy again", mode: "ok", seconds: 8 },
];
const SETUPS = [
  { name: "timeout only", env: { TIMEOUT_MS: "200" } },
  { name: "timeout + breaker", env: { TIMEOUT_MS: "200", BREAKER: "1" } },
];

const points = [];
for (const setup of SETUPS) {
  console.log(`\n${setup.name}`);
  console.log("phase                  p50 ms  p99 ms  Picks calls  refused by breaker  pages without picks");
  const lab = await startLab({ HOME_WORKERS: "20", ...setup.env });
  for (const [i, phase] of PHASES.entries()) {
    await lab.setPicks(phase.mode);
    await lab.reset();
    const { latencies } = await runLoad({ url: lab.homeUrl, rate: RATE, seconds: phase.seconds, seed: 7 + i });
    const s = summarize(latencies);
    const stats = await lab.stats();
    const pages = stats.home.ok + stats.home.fallback;
    if (i === 1) points.push({ x: points.length + 1, p99: s.p99, calls: await lab.picksCalls() });
    console.log(
      `${phase.name.padEnd(21)}  ${s.p50.toFixed(0).padStart(6)}  ${s.p99.toFixed(0).padStart(6)}  ` +
      `${String(await lab.picksCalls()).padStart(11)}  ${String(stats.refusedByBreaker).padStart(18)}  ` +
      `${String(Math.round((stats.home.fallback / pages) * 100)).padStart(18)}%`
    );
  }
  lab.stop();
}

writeFileSync(new URL("./chart.svg", import.meta.url), lineChart({
```

The test `breaker.test.js` checks the three claims in a short run: the breaker opens on 5 failures in a row and half-opens after the wait, a hanging Picks gets fewer than 30 calls from 90 requests while the breaker refuses most, and when Picks comes back the breaker closes and pages get picks again.

```js

test("the breaker opens on 5 failures in a row and half-opens after the wait", () => {
  let t = 0;

  t = 2000;
  assert.equal(b.state(), "half-open");
});

test("while Picks hangs, the breaker sends almost no calls to it", async () => {
  const lab = await startLab({ TIMEOUT_MS: "200", BREAKER: "1" });

    await lab.setPicks("slow");
    await lab.reset();

    const stats = await lab.stats();

    assert.ok(stats.refusedByBreaker > 30, "the breaker should have refused most calls");
    assert.equal(stats.home.ok, 0);
  } finally {
    lab.stop();
  }
});

test("when Picks comes back, the breaker closes again", async () => {
  const lab = await startLab({ TIMEOUT_MS: "200", BREAKER: "1" });

    lab.stop();
  }
});
```

## Step 5: part 3, bulkheads

The last part asks the question from 16.1 again. Picks is slow, and home pages wait up to 1.5 seconds for it. Payments need nothing from Picks. Does a slow Picks hurt payments? The script sends 40 home pages and 20 payments every second at the same time. The waiting line is limited to 10, so a full pool refuses at once instead of growing without end. It runs three setups: a healthy Picks with one shared pool of 20 workers, a slow Picks with the shared pool, and a slow Picks with two pools, 12 workers for home and 8 for payments. Create `part-3-bulkheads/bulkheads.js`:

```js
// Part 3: Picks is slow, and the home page waits up to 1.5 s for it.
// Payments needs nothing from Picks. Does a slow Picks hurt payments?
import { writeFileSync } from "node:fs";
import { runLoad } from "../../../toolkit/load.js";
import { summarize } from "../../../toolkit/stats.js";
import { lineChart } from "../../../toolkit/chart.js";
import { startLab } from "../lab.js";

const SECONDS = Number(process.env.STEP_SECONDS ?? 8);
const SETUPS = [
  { name: "Picks healthy, one shared pool", picks: "ok", env: { HOME_WORKERS: "20" } },
  { name: "Picks slow, one shared pool", picks: "slow", env: { HOME_WORKERS: "20" } },
  { name: "Picks slow, bulkheads 12 + 8", picks: "slow", env: { HOME_WORKERS: "12", PAY_WORKERS: "8" } },
];

console.log(`home 40/s and pay 20/s together for ${SECONDS} s, 20 workers in total, waiting line at most 10\n`);
console.log("setup                              pay p99 ms  pay served  home p99 ms  home served");

  await lab.setPicks(setup.picks);
  await lab.reset();
  const [home, pay] = await Promise.all([
    runLoad({ url: lab.homeUrl, rate: 40, seconds: SECONDS, seed: 7 }),
```

The test `bulkheads.test.js` checks the pool itself (a third request gets a worker only when one is released, and a full line refuses at once) and then runs a short real experiment with bulkheads: payments must almost never be refused while the home pool is full.

```js
import test from "node:test";
import assert from "node:assert/strict";
import { runLoad } from "../../../toolkit/load.js";
import { Pool } from "../../../toolkit/pool.js";
import { startLab } from "../lab.js";

test("a pool of 2 hands the third request a worker only when one is released", async () => {
  const pool = new Pool(2);
  const first = await pool.acquire();
  await pool.acquire();
  let thirdGotIn = false;
  const third = pool.acquire().then((release) => {
    thirdGotIn = true;
    return release;
  });
  await new Promise((resolve) => setImmediate(resolve));
  assert.equal(thirdGotIn, false);
  first();
  (await third)();
  assert.equal(thirdGotIn, true);
});

test("a full waiting line refuses at once", async () => {
  const pool = new Pool(1, 1);
  await pool.acquire();
  pool.acquire(); // takes the one waiting place
  assert.equal(await pool.acquire(), null);
});

test("with bulkheads, payments keep working while Picks is slow", async () => {
  const lab = await startLab({ TIMEOUT_MS: "1500", QUEUE_MAX: "10", HOME_WORKERS: "12", PAY_WORKERS: "8" });
  try {
    await lab.setPicks("slow");
    await lab.reset();
    await Promise.all([
      runLoad({ url: lab.homeUrl, rate: 40, seconds: 4, seed: 7 }),
      runLoad({ url: lab.payUrl, rate: 20, seconds: 4, seed: 11 }),
    ]);
    const stats = await lab.stats();
    assert.ok(stats.pay.rejected <= stats.pay.ok * 0.1, "payments should almost never be refused");
    assert.ok(stats.home.rejected > 0, "the home page pool should be the one that is full");
  } finally {
    lab.stop();
  }
});
```

## When something goes wrong

**`SyntaxError: ... does not provide an export named 'createBreaker'`.** You pasted the functions without `export` in front, or you named one differently. Fix `toolkit/resilience.js`.

**Part 1 row 2 is not fast.** Check that the environment variable is `TIMEOUT_MS` and that `AbortSignal.timeout` gets a number, not a string. A timeout of `0` means no limit.

**`ECONNRESET` or `socket hang up` between steps.** A server closed an idle connection. The two `keepAliveTimeout` lines and the plain `get` in `lab.js` prevent this. If you wrote them differently, copy them exactly.

**All numbers are large, even in the healthy rows.** Something else is using the CPU, or the laptop is saving power. Three processes plus the load generator are running. Close programs, plug in, and run again. If a healthy page takes more than 300 ms, write that in your results; it is a finding about your machine.

**The breaker never closes in part 2.** Check that `recordSuccess()` is called when a call works, and that your `allowRequest()` lets exactly one probe through in half-open. Run the 16.7 exercise tests again.

**Break it on purpose.** See a test fail before you trust it. In `checkout.js`, change `breaker.recordFailure()` to do nothing, and run the part 2 tests: the breaker never opens, and the "almost no calls" test fails. Undo it. Then in `toolkit/pool.js`, remove the `queueMax` check and run part 3: payments stop being protected from a full home line, and the bulkhead test fails.
