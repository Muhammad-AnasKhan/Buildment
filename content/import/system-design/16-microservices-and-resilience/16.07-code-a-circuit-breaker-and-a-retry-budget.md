In 16.4 and 16.5 you saw the ideas: wait a random time before a retry, spend retries from a budget, and open a breaker when a dependency keeps failing. Each one is only a few lines of code, and each is easy to get slightly wrong. A breaker that never closes, a budget that drifts, or a delay that grows without a cap will pass a quick test and fail on the worst night of the year. In this chapter you write all three, and the tests check the awkward cases first.

By the end, you will have three small, tested functions. `fullJitterDelay(attempt, baseMs, capMs, random)` returns how long to wait before a retry. `createRetryBudget` returns a budget that allows a retry only when enough requests have been made. `createBreaker` returns a circuit breaker with the closed, open and half-open states. ## The contract for each function

Fix what each function promises before writing it, including the awkward inputs. The tests start with the awkward inputs, because that is where real bugs live.

**`fullJitterDelay(attempt, baseMs, capMs, random)`** returns the wait before a retry, in milliseconds. `attempt` counts from 0. The ceiling is `baseMs` times 2 to the power `attempt`, but never more than `capMs`. The wait is a random number between 0 and that ceiling: `random()` times the ceiling. `random` is a function that returns a number from 0 up to, but not including, 1. It defaults to `Math.random`, and tests pass their own so the result is exact. This is the full jitter of chapter 16.4.

It must handle two awkward inputs. A very large `attempt`, such as 2000, makes `2 ** attempt` equal to `Infinity` in JavaScript. `Math.min(capMs, Infinity)` is just `capMs`, so the cap protects you, but only if you take the minimum. And it must refuse nonsense: an `attempt` that is negative or not a whole number, or a `baseMs` or `capMs` that is not positive, throws a `RangeError`, because the caller has a bug and a quiet wrong delay would hide it.

**`createRetryBudget({ requestsPerRetry, maxRetries })`** returns an object with three methods. `recordRequest()` is called once for every original request. `tryRetry()` is called when a retry is wanted: it returns `true` and spends the budget, or returns `false` and spends nothing. `available()` returns how many retries could be spent right now. The budget works in whole units. Each request earns 1 unit. A retry costs `requestsPerRetry` units. The stock never holds more than `maxRetries` retries, which is `requestsPerRetry` times `maxRetries` units. With `requestsPerRetry` of 10, retries stay near 10% of requests.

Why whole units? The obvious design earns 0.1 of a retry for each request and compares the stock with 1. But in floating point, adding 0.1 ten times gives 0.9999999999999999, not 1, so the tenth request would not pay for a retry. Counting in whole numbers removes the problem. Bad settings, meaning a `requestsPerRetry` or `maxRetries` that is not a positive whole number, throw a `RangeError`.

**`createBreaker({ failureThreshold, openMs, now })`** returns an object with four methods. `state()` returns `"closed"`, `"open"` or `"half-open"`. `allowRequest()` says whether a call may be made. `recordSuccess()` and `recordFailure()` report how a call ended. The `now` argument is a function that returns the time in milliseconds, and it defaults to `Date.now`. Tests pass a fake clock, so they never wait. The rules are the ones from 16.5.

When the breaker is closed, `allowRequest()` is `true`. `recordFailure()` counts failures in a row, and `recordSuccess()` resets the count to 0. When the count reaches `failureThreshold`, the breaker opens and remembers the time. When it is open, `allowRequest()` is `false`, and once `openMs` milliseconds have passed, the state becomes half-open. When it is half-open, the first `allowRequest()` returns `true` and is the probe. Until the probe is reported, every further `allowRequest()` returns `false`. A `recordSuccess()` closes the breaker and resets the count. A `recordFailure()` opens it again, and the wait of `openMs` starts again from that moment.

One more rule is easy to miss. A call that began before the breaker opened may finish later, and report a success while the breaker is open. That old answer says nothing about the dependency now, so `recordSuccess()` while open does nothing. Settings are checked too: `failureThreshold` must be a positive whole number and `openMs` positive, or a `RangeError` is thrown.

## A worked example: a breaker with a threshold of 3

Walk through the breaker by hand, with `failureThreshold` 3 and `openMs` 1000, on a clock that you control. This example is not in the tests.

At time 0 the breaker is closed. A call fails: the count is 1. A second call fails: the count is 2. A third call succeeds, so the count resets to 0. This is the first subgoal: the threshold counts failures in a row, not failures in total. Two failures, a success and two more failures never reach 3 in a row.

Now three failures arrive in a row at times 100, 110 and 120. The count reaches 3 at time 120, so the breaker opens, and it remembers 120 as the time it opened. At time 500, `allowRequest()` returns `false`. At time 1119, 999 milliseconds after opening, the breaker is still open. At time 1120 the difference is 1000, which is not less than `openMs`, so `state()` reports `"half-open"`. This is the second subgoal: compare with "at least", not "more than".

The first `allowRequest()` at time 1120 returns `true` and marks a probe as out. A second `allowRequest()` at time 1121 returns `false`, because only one probe may fly. The probe fails at time 1150, so the breaker opens again, and the new wait runs from 1150: the breaker stays open until time 2150. That is the third subgoal. If the probe had succeeded at 1150, the breaker would close with the count at 0, and a single failure would not open it.

## Four ways this goes wrong

**Floating point in the budget.** As described above, `0.1` added ten times is not 1. If your budget refuses the tenth request's retry, check how you add. The test "in a storm, retries stay near one tenth of the requests" runs 1,000 requests and expects exactly 100 retries.

**A breaker that checks the clock only in `allowRequest`.** If `state()` just returns a stored value, it says `"open"` long after `openMs` has passed, and a dashboard would show a breaker stuck open. Write one small helper that moves open to half-open when the time is up, and call it at the start of every method.

**Two probes.** Without a flag to say that a probe is out, ten requests arriving together in half-open would all be allowed through, and a dependency that is still hurt would get ten calls at once. The point of half-open is one careful call.

**A breaker that forgets to reset.** After a probe succeeds, the failure count must go back to 0. If it keeps the old count, the very next failure opens the breaker again at once. A test covers this.

  function fullJitterDelay(attempt, baseMs, capMs, random = Math.random) {
    if (!Number.isInteger(attempt) || attempt < 0) throw new RangeError("attempt must be a whole number from 0, got " + attempt);
    if (!(baseMs > 0) || !(capMs > 0)) throw new RangeError("baseMs and capMs must be positive");
    const ceiling = Math.min(capMs, baseMs * 2 ** attempt);
    return random() * ceiling;
  }

  function createRetryBudget({ requestsPerRetry = 10, maxRetries = 10 } = {}) {
    if (!Number.isInteger(requestsPerRetry) || requestsPerRetry < 1) throw new RangeError("requestsPerRetry must be a positive whole number");
    if (!Number.isInteger(maxRetries) || maxRetries < 1) throw new RangeError("maxRetries must be a positive whole number");
    const maxUnits = requestsPerRetry * maxRetries;
    let units = 0;
    return {
      recordRequest() {
        units = Math.min(maxUnits, units + 1);
      },
      tryRetry() {
        if (units < requestsPerRetry) return false;
        units -= requestsPerRetry;
        return true;
      },
      available() {
        return Math.floor(units / requestsPerRetry);
      },
    };
  }

  function createBreaker({ failureThreshold = 5, openMs = 10000, now = Date.now } = {}) {
    if (!Number.isInteger(failureThreshold) || failureThreshold < 1) throw new RangeError("failureThreshold must be a positive whole number");
    if (!(openMs > 0)) throw new RangeError("openMs must be positive");
    let state = "closed";
    let failures = 0;
    let openedAt = 0;
    let probing = false;

    function refresh() {
      if (state === "open" && now() - openedAt >= openMs) {
        state = "half-open";
        probing = false;
      }
    }
    function open() {
      state = "open";
      openedAt = now();
      probing = false;
    }

    return {
      state() {
        refresh();
        return state;
      },
      allowRequest() {
        refresh();
        if (state === "closed") return true;
        if (state === "open" || probing) return false;
        probing = true;
        return true;
      },
      recordSuccess() {
        refresh();
        if (state === "half-open") {
          state = "closed";
          failures = 0;
          probing = false;
        } else if (state === "closed") {
          failures = 0;
        }
      },
      recordFailure() {
        refresh();
        if (state === "half-open") {
          open();
        } else if (state === "closed") {
          failures += 1;
          if (failures >= failureThreshold) open();
        }
      },
    };
  }
