You will also see the two bugs this module warned about happen on your own laptop: two servers each allowing the full limit, and a payment charged several times for one tap.

By the end of this chapter, your `system-design-challenges` repository has `challenges/challenge-5-rate-limiter/` with four parts. Each part has its own `README.md` that teaches the idea from zero, a script you can run, a `node:test` test, a `results.md` filled with your own numbers, and a `chart.svg` drawn from them. ## How the pieces fit

Every part follows the same pattern as challenge 1. A script starts one or more servers as separate processes, sends them requests at planned moments, records every answer and prints a table. Parts 3 and 4 add Valkey, which keeps the shared state: the token buckets in part 3 and the idempotency keys in part 4.

Three design choices keep the numbers honest.

**Requests leave on schedule.** The sender does not wait for an answer before sending the next request, the same open loop as challenge 1. A burst of 30 really is 30 requests in the same millisecond, which is exactly the case a limiter must handle.

**Each server is its own process.** In part 3, two copies of the same server run side by side, each with its own memory, like two machines behind a load balancer. The sender takes turns between them, which is round robin from module 4. That is what makes the "one bucket per server" bug visible.

**The payment provider is fake but slow.** In part 4 the provider is a function that waits a number of milliseconds the script chooses, then records a charge in a list. The list is the truth: you count charges in it, not in what the app was told. A real provider would charge a real card at the same moment.

```js
// export function createTokenBucket({ capacity, refillPerSecond, now }) { ... }
// export function createSlidingWindowCounter({ limit, windowMs, now }) { ... }

// ---- Given: two more limiters to compare against in part 2 ----

// Fixed window: one counter per window; it resets to 0 when a new window starts.
export function createFixedWindow({ limit, windowMs, now }) {
  let windowStart = -1;
  let count = 0;
  return {
    allow() {
      const start = Math.floor(now() / windowMs) * windowMs;
      if (start !== windowStart) {
        windowStart = start;
        count = 0;
      }
      if (count < limit) {
        count += 1;
        return { allowed: true };
      }
      return { allowed: false };
    },
  };
}

// Sliding log: remember the time of every allowed request in the last window.
// Exact, but it stores one number per request.
export function createSlidingLog({ limit, windowMs, now }) {
  const log = [];
  return {
    allow() {
      const t = now();
      while (log.length > 0 && log[0] <= t - windowMs) log.shift();
      if (log.length < limit) {
        log.push(t);
        return { allowed: true };
      }
      return { allowed: false };
    },
    size: () => log.length,
  };
}
```

## Step 2: the server and the sender

The server reads its settings from environment variables, so each part can start it differently. `CAPACITY` and `RATE` set the token bucket. `LIMITER` chooses where the bucket lives: `memory` keeps one bucket per client inside this process; the two Valkey modes are for part 3, and the server only loads their code when asked, so part 1 runs before those files exist. Every client is identified by an `x-client-id` header, standing in for the API key or user id a real API would use. Create `challenges/challenge-5-rate-limiter/server.js`:

```js
// server.js: a tiny search API with a rate limiter in front of it.
// LIMITER picks where the limit lives:
//   memory         a token bucket inside this process (parts 1 and 3)
//   valkey-naive   one bucket in Valkey, read and written in two steps (part 3)
//   valkey-script  one bucket in Valkey, changed by one atomic script (part 3)
import http from "node:http";
import { createTokenBucket } from "./limiters.js";

const CAPACITY = Number(process.env.CAPACITY ?? 10); // the biggest burst
const RATE = Number(process.env.RATE ?? 5); // tokens added per second
const MODE = process.env.LIMITER ?? "memory";

function memoryLimiter() {
  const buckets = new Map(); // one bucket per client
  return async (client) => {
    if (!buckets.has(client)) {
      buckets.set(client, createTokenBucket({ capacity: CAPACITY, refillPerSecond: RATE, now: () => performance.now() }));
    }
    return buckets.get(client).take();
  };
}

// The Valkey limiters are only loaded when asked for, so part 1 runs without them.
const take = MODE === "memory"
  ? memoryLimiter()
  : (await import("./shared-limiters.js")).sharedLimiter(MODE, { capacity: CAPACITY, rate: RATE });

const server = http.createServer(async (req, res) => {
  const client = req.headers["x-client-id"] ?? "anonymous";
  const result = await take(client);
  if (!result.allowed) {
    // 429 Too Many Requests, and how many seconds to wait before trying again.
    res.writeHead(429, { "retry-after": String(Math.ceil(result.retryAfterMs / 1000)) });
    res.end("too many requests\n");
    return;
  }
  res.writeHead(200, { "content-type": "text/plain" });
  res.end("search results\n");
});

server.listen(0, "127.0.0.1", () => {
  const { port } = server.address();
  if (process.send) process.send({ port }); // started by toolkit/load.js
  else console.log(`listening on http://127.0.0.1:${port}/ (limiter ${MODE})`);
});
```

Then `send.js`, the sender. `burst` and `steady` build a plan: a list of moments, in milliseconds from the start, at which to send. `sendPlan` sends one request per moment, taking turns between the server addresses you give it, and returns every status code with its planned moment. `bySlot` counts sent and allowed requests in time slots for the tables.

```js
// send.js: send requests at planned moments and record each answer's status.
import http from "node:http";

const agent = new http.Agent({ keepAlive: true, maxSockets: Infinity });

function request(url, client) {
  return new Promise((resolve, reject) => {
    const req = http.request(url, { agent, headers: { "x-client-id": client } }, (res) => {
      res.resume();
      res.on("end", () => resolve(res.statusCode));
    });
    req.on("error", reject);
    req.end();
  });
}

// Timers on Windows tick about every 15 ms, so check the clock in a loop instead.
async function waitUntil(t) {
  while (performance.now() < t) await new Promise((resolve) => setImmediate(resolve));
}

// n requests all at the same moment, `at` ms after the start.
export const burst = (at, n) => Array(n).fill(at);

// Evenly spaced requests from `from` up to (not including) `to`, in ms.
export function steady(from, to, perSecond) {
  const out = [];
  for (let t = from; t < to; t += 1000 / perSecond) out.push(Math.round(t));
  return out;
}

// Send one request per planned time. With several urls, requests take turns,
// like a round-robin load balancer in front of several instances.
export async function sendPlan({ urls, plan, client = "student-1" }) {
  const start = performance.now();
  const pending = [];
  for (const [i, at] of plan.entries()) {
    await waitUntil(start + at);
    pending.push(request(urls[i % urls.length], client).then((status) => ({ at, status })));
  }
  return Promise.all(pending);
}

// Count sent and allowed requests in time slots of `slotMs`.
export function bySlot(results, slotMs, endMs) {
  const rows = [];
  for (let from = 0; from < endMs; from += slotMs) {
    const inSlot = results.filter((r) => r.at >= from && r.at < from + slotMs);
    rows.push({ from, sent: inSlot.length, allowed: inSlot.filter((r) => r.status === 200).length });
  }
  return rows;
}
```

## Step 3: part 1, the token bucket

Part 1 sends three kinds of traffic at one server whose bucket holds 10 tokens and refills at 5 a second: 20 requests at once, then 8 a second for 3.5 seconds, more than the refill rate, then 3 a second, less than it. The last column of the table is the most a token bucket may ever allow by that time: a full bucket plus everything that dripped in, `capacity + rate x seconds`. Create `part-1-token-bucket/bucket.js`:

```js
// Part 1: a token bucket in front of one server. Send a burst, then more
// than the refill rate, then less, and count what gets through.
import { writeFileSync } from "node:fs";
import { spawnServer } from "../../../toolkit/load.js";
import { lineChart } from "../../../toolkit/chart.js";
import { burst, bySlot, sendPlan, steady } from "../send.js";

const CAPACITY = 10; // the biggest burst the bucket lets through
const RATE = 5; // tokens added per second
const END_MS = 6000;

const server = await spawnServer(new URL("../server.js", import.meta.url), {
  LIMITER: "memory", CAPACITY: String(CAPACITY), RATE: String(RATE),
});

// 20 at once, then 8 a second (above the rate), then 3 a second (below it).
const plan = [...burst(0, 20), ...steady(500, 4000, 8), ...steady(4000, END_MS, 3)];
const results = await sendPlan({ urls: [server.url], plan });
server.stop();

console.log(`bucket: capacity ${CAPACITY}, refill ${RATE} tokens a second\n`);
console.log("time s  sent  allowed  total sent  total allowed  most allowed by now");
const points = [];
let totalSent = 0;
let totalAllowed = 0;
for (const row of bySlot(results, 500, END_MS)) {
  totalSent += row.sent;
  totalAllowed += row.allowed;
  const end = (row.from + 500) / 1000;
  const most = CAPACITY + RATE * end; // a full bucket plus everything that dripped in
  points.push({ x: end, sent: totalSent, allowed: totalAllowed, limit: most });
  console.log(
    `${end.toFixed(1).padStart(6)}  ${String(row.sent).padStart(4)}  ${String(row.allowed).padStart(7)}  ` +
    `${String(totalSent).padStart(10)}  ${String(totalAllowed).padStart(13)}  ${String(most).padStart(19)}`
  );
}

writeFileSync(new URL("./chart.svg", import.meta.url), lineChart({
  title: `Token bucket: capacity ${CAPACITY}, ${RATE} tokens a second`,
  xLabel: "seconds",
  yLabel: "requests so far",
  points,
  series: [
    { key: "sent", color: "#9ca3af" },
    { key: "limit", color: "#dc2626" },
    { key: "allowed", color: "#2563eb" },
  ],
}));
console.log("\nwrote chart.svg");
```

## Step 4: part 2, the window limiters

Part 2 needs no server: it runs three window limiters on a fake clock, so every run gives exactly the same numbers. The limit is 10 requests per 1,000 ms. The traffic is built to hit each limiter's weak spot: 10 requests just before the boundary at 1,000 ms, 10 just after it, then a steady 25 a second. The last column checks every 1,000 ms stretch that starts at an allowed request and reports the most allowed inside any of them. Create `part-2-sliding-window/window.js`:

```js
// Part 2: the same traffic through three window limiters, on a fake clock.
// Limit: 10 requests in any 1,000 ms. The traffic sends 10 just before a
// window boundary and 10 just after it, then a steady 25 a second.
import { writeFileSync } from "node:fs";
import { lineChart } from "../../../toolkit/chart.js";
import { createFixedWindow, createSlidingLog, createSlidingWindowCounter } from "../limiters.js";

const LIMIT = 10;
const WINDOW_MS = 1000;
const END_MS = 5000;

const plan = [];
for (let i = 0; i < 10; i++) plan.push(950 + i * 5); // 950 to 995 ms
for (let i = 0; i < 10; i++) plan.push(1000 + i * 5); // 1,000 to 1,045 ms
for (let t = 1500; t < END_MS; t += 40) plan.push(t); // 25 a second

// The most allowed requests inside any 1,000 ms stretch, starting at any request.
function mostInAnyWindow(times) {
  let most = 0;
  for (const start of times) {
    const inside = times.filter((t) => t >= start && t < start + WINDOW_MS).length;
    most = Math.max(most, inside);
  }
  return most;
}

const makers = {
  fixed: createFixedWindow,
  log: createSlidingLog,
  counter: createSlidingWindowCounter,
};

const allowedTimes = {};
for (const [name, make] of Object.entries(makers)) {
  let t = 0;
  const limiter = make({ limit: LIMIT, windowMs: WINDOW_MS, now: () => t });
  allowedTimes[name] = [];
  for (const at of plan) {
    t = at;
    if (limiter.allow().allowed) allowedTimes[name].push(at);
  }
}

console.log(`limit ${LIMIT} per ${WINDOW_MS} ms; ${plan.length} requests sent\n`);
console.log("limiter   burst at 950-1045 ms   allowed in total   most in any 1,000 ms");
for (const [name, times] of Object.entries(allowedTimes)) {
  const inBurst = times.filter((t) => t < 1500).length;
  console.log(`${name.padEnd(8)}  ${String(inBurst).padStart(20)}   ${String(times.length).padStart(16)}   ${String(mostInAnyWindow(times)).padStart(20)}`);
}

const points = [];
for (let end = 500; end <= END_MS; end += 500) {
  const row = { x: end / 1000 };
  for (const [name, times] of Object.entries(allowedTimes)) row[name] = times.filter((t) => t < end).length;
  points.push(row);
}
writeFileSync(new URL("./chart.svg", import.meta.url), lineChart({
  title: `Window limiters, ${LIMIT} per second: allowed so far`,
  xLabel: "seconds",
  yLabel: "requests allowed so far",
  points,
  series: [
    { key: "fixed", color: "#dc2626" },
    { key: "log", color: "#16a34a" },
    { key: "counter", color: "#2563eb" },
  ],
}));
console.log("\nwrote chart.svg");
```

And its test, `part-2-sliding-window/window.test.js`, which pins down the boundary burst and the weighting with exact numbers:

```js
import test from "node:test";
import assert from "node:assert/strict";
import { createFixedWindow, createSlidingLog, createSlidingWindowCounter } from "../limiters.js";

// Send `count` requests at each of the given times; return how many were allowed.
function run(make, times) {
  let t = 0;
  const limiter = make({ limit: 10, windowMs: 1000, now: () => t });
  let allowed = 0;
  for (const at of times) {
    t = at;
    if (limiter.allow().allowed) allowed += 1;
  }
  return allowed;
}

const boundaryBurst = [...Array(10).fill(990), ...Array(10).fill(1000)];

test("a fixed window lets 2 times the limit through at a boundary", () => {
  assert.equal(run(createFixedWindow, boundaryBurst), 20);
});

test("a sliding log and a sliding window counter stop the boundary burst", () => {
  assert.equal(run(createSlidingLog, boundaryBurst), 10);
  assert.equal(run(createSlidingWindowCounter, boundaryBurst), 10);
});

test("the counter weighs the previous window by how much of it is still inside", () => {
  let t = 0;
  const counter = createSlidingWindowCounter({ limit: 10, windowMs: 1000, now: () => t });
  for (let i = 0; i < 8; i++) counter.allow(); // 8 in the window 0 to 1,000 ms
  t = 1250; // a quarter into the next window: 75% of the old one still counts
  assert.equal(counter.allow().estimate, 8 * 0.75);
});

test("a sliding log stores one time per allowed request", () => {
  let t = 0;
  const log = createSlidingLog({ limit: 100, windowMs: 1000, now: () => t });
  for (let i = 0; i < 60; i++) log.allow();
  assert.equal(log.size(), 60);
  t = 1000; // all 60 have left the window
  log.allow();
  assert.equal(log.size(), 1);
});
```

The burst column is the lesson of 6.5. The fixed window allowed all 20 within 95 ms, twice its limit. The sliding log and your counter allowed 10.

The last column holds a surprise. The sliding log never allowed more than 10 in any 1,000 ms stretch: it is exact. Your counter allowed 19 in one stretch. That is not a bug in your code. The counter assumes the previous window's requests were spread evenly across it, but this traffic put all 10 of them in its last 50 ms. Half a second into the next window, the counter believes half of them have slid out, while in truth all 10 are still inside the last 1,000 ms. It lets the steady traffic in early. Cloudflare measured an error of 0.003% on real traffic [S29], where requests are rarely bunched this precisely; an attacker who knows your windows could bunch them on purpose. In your `results.md`, write the table, then two or three sentences on why the fixed window failed the burst, why the counter passed the burst but not the last column, and which limiter you would choose for a login form and which for a search API. End with `![Window limiters](chart.svg)`.

## Step 6: part 3, one limit across two servers

A load balancer spreads one client's requests across every server. If each server keeps its own bucket, the client gets one full bucket per server. Part 3 runs two servers and tries three places for the bucket: in each server's memory, in Valkey read and written in two steps, and in Valkey changed by one script.

The script is the heart of this part. Valkey runs a Lua script as one step: while it runs, no other command touches the data, so "read the bucket, catch up, spend a token, save it" cannot be split by another request. It is your 6.8 formula, written in Lua. It also reads the time from Valkey's own clock with `TIME`, so two servers whose clocks disagree still share one consistent bucket. Create `challenges/challenge-5-rate-limiter/shared-limiters.js`:

```js
// shared-limiters.js: one token bucket per client, kept in Valkey, so every
// instance of the server spends from the same bucket.
import { connect } from "../../toolkit/valkey.js";

// Runs inside Valkey, as one step: no other command can run in between.
// KEYS[1] is the bucket; ARGV is capacity, tokens per second and cost.
const TOKEN_BUCKET_LUA = `
local capacity = tonumber(ARGV[1])
local rate = tonumber(ARGV[2])
local cost = tonumber(ARGV[3])
local time = redis.call('TIME')
local now = tonumber(time[1]) * 1000 + tonumber(time[2]) / 1000
local saved = redis.call('HMGET', KEYS[1], 'tokens', 'at')
local tokens = tonumber(saved[1]) or capacity
local at = tonumber(saved[2]) or now
if now > at then
  tokens = math.min(capacity, tokens + (now - at) * rate / 1000)
  at = now
end
local allowed = 0
local retry = 0
if tokens >= cost then
  tokens = tokens - cost
  allowed = 1
else
  retry = math.ceil((cost - tokens) * 1000 / rate)
end
redis.call('HSET', KEYS[1], 'tokens', tostring(tokens), 'at', tostring(at))
redis.call('PEXPIRE', KEYS[1], math.ceil(capacity * 1000 / rate) * 2)
return { allowed, retry }
`;

export function sharedLimiter(mode, { capacity, rate }) {
  const db = connect();

  // The same maths as the script, but in two trips: read, then write.
  // Between the two, another request can read the same old value.
  async function naive(client) {
    const key = `bucket:${client}`;
    const [savedTokens, savedAt] = await db.send("HMGET", key, "tokens", "at");
    const now = Date.now();
    let tokens = savedTokens === null ? capacity : Number(savedTokens);
    let at = savedAt === null ? now : Number(savedAt);
    if (now > at) {
      tokens = Math.min(capacity, tokens + ((now - at) * rate) / 1000);
      at = now;
    }
    const allowed = tokens >= 1;
    if (allowed) tokens -= 1;
    await db.send("HSET", key, "tokens", tokens, "at", at);
    return { allowed, retryAfterMs: allowed ? 0 : Math.ceil(((1 - tokens) * 1000) / rate) };
  }

  async function script(client) {
    const [allowed, retry] = await db.send("EVAL", TOKEN_BUCKET_LUA, 1, `bucket:${client}`, capacity, rate, 1);
    return { allowed: allowed === 1, retryAfterMs: retry };
  }

  if (mode === "valkey-naive") return naive;
  if (mode === "valkey-script") return script;
  throw new Error(`unknown LIMITER ${mode}`);
}
```

## Step 7: part 4, idempotency keys

Part 4 rebuilds Huda's double charge from 6.1 and fixes it. The payments server has three modes. `none` charges on every request. `check` looks for a saved reply first and saves the reply after charging, the gap the predict in 6.4 asked about. `claim` claims the key with `SET ... NX` before charging, so only one request per key can charge; a request that finds the key pending gets 409 and asks again, and one that finds it done gets the saved reply. A fingerprint of the request body is saved with the key, so a key reused for a different payment gets 422. Create `part-4-idempotency-keys/pay-server.js`:

```js
// pay-server.js: a payments endpoint in front of a slow, fake card provider.
// IDEMPOTENCY picks how it treats a request it may have seen before:
//   none    every request charges the card
//   check   look for a saved reply first; save the reply after charging
//   claim   claim the key in one atomic step, then charge
import http from "node:http";
import { createHash } from "node:crypto";
import { connect } from "../../../toolkit/valkey.js";

const MODE = process.env.IDEMPOTENCY ?? "claim";
const KEEP_MS = 24 * 60 * 60 * 1000; // keep each key for 24 hours
const db = connect();
const ledger = []; // the fake provider's list of every charge it made
const sleep = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

// The provider takes providerMs to answer. The charge is real once it answers,
// even if the client stopped waiting long ago.
async function chargeCard(purchase, providerMs) {
  await sleep(providerMs);
  const charge = { id: `ch_${ledger.length + 1}`, purchase, amount: 1800 };
  ledger.push(charge);
  return charge;
}

function reply(res, status, body) {
  res.writeHead(status, { "content-type": "application/json" });
  res.end(JSON.stringify(body));
}

// A saved entry answers a repeat: the same reply again, or "still running".
function replay(res, saved, fingerprint) {
  if (saved.fingerprint !== fingerprint) return reply(res, 422, { error: "key reused with a different request" });
  if (saved.status === "pending") return reply(res, 409, { error: "first request with this key is still running" });
  reply(res, saved.status, saved.body);
}

async function pay(req, res, body) {
  const key = req.headers["idempotency-key"];
  const client = req.headers["x-client-id"] ?? "anonymous";
  const providerMs = Number(req.headers["x-provider-ms"] ?? 100); // set by the experiment
  const { purchase } = JSON.parse(body);
  if (MODE === "none" || !key) return reply(res, 201, await chargeCard(purchase, providerMs));

  const slot = `idem:${client}:${key}`; // scoped to the client, so two clients never clash
  const fingerprint = createHash("sha256").update(body).digest("hex");
  const done = (charge) => JSON.stringify({ fingerprint, status: 201, body: charge });

  if (MODE === "check") {
    const saved = await db.send("GET", slot);
    if (saved) return replay(res, JSON.parse(saved), fingerprint);
    const charge = await chargeCard(purchase, providerMs); // a retry can arrive while this runs
    await db.send("SET", slot, done(charge), "PX", KEEP_MS);
    return reply(res, 201, charge);
  }

  // claim: SET with NX succeeds for exactly one request with this key.
  const pending = JSON.stringify({ fingerprint, status: "pending" });
  const claimed = await db.send("SET", slot, pending, "NX", "PX", KEEP_MS);
  if (claimed !== "OK") return replay(res, JSON.parse(await db.send("GET", slot)), fingerprint);
  const charge = await chargeCard(purchase, providerMs);
  await db.send("SET", slot, done(charge), "PX", KEEP_MS);
  reply(res, 201, charge);
}

const server = http.createServer((req, res) => {
  let body = "";
  req.on("data", (chunk) => (body += chunk));
  req.on("end", () => {
    if (req.method === "GET" && req.url === "/ledger") return reply(res, 200, ledger);
    if (req.method === "POST" && req.url === "/payments") return pay(req, res, body);
    reply(res, 404, { error: "not found" });
  });
});

server.listen(0, "127.0.0.1", () => {
  const { port } = server.address();
  if (process.send) process.send({ port });
  else console.log(`listening on http://127.0.0.1:${port}/ (idempotency ${MODE})`);
});
```

```js
// Part 4: a phone app pays, stops waiting after 250 ms and tries again.
// Count how many times the fake provider charged each purchase.
import { writeFileSync } from "node:fs";
import { randomUUID } from "node:crypto";
import { spawnServer } from "../../../toolkit/load.js";
import { seededRandom } from "../../../toolkit/stats.js";
import { lineChart } from "../../../toolkit/chart.js";

const PURCHASES = 60;
const TIMEOUT_MS = 250; // the app stops waiting after this long
const MAX_ATTEMPTS = 4;
const MODES = ["none", "check", "claim"];
const sleep = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

// One purchase, the way the app does it: one key for the purchase, made
// before the first attempt and sent again with every retry.
async function buy(url, purchase, providerMs) {
  const key = randomUUID();
  const body = JSON.stringify({ purchase, amount: 1800 });
  const headers = {
    "content-type": "application/json",
    "idempotency-key": key,
    "x-client-id": "huda",
    "x-provider-ms": String(providerMs),
  };
  const tally = { attempts: 0, timeouts: 0, conflicts: 0, confirmed: false };
  while (tally.attempts < MAX_ATTEMPTS && !tally.confirmed) {
    tally.attempts += 1;
    try {
      const res = await fetch(`${url}payments`, { method: "POST", body, headers, signal: AbortSignal.timeout(TIMEOUT_MS) });
      await res.text();
      if (res.status === 201) tally.confirmed = true;
      if (res.status === 409) {
        tally.conflicts += 1;
        await sleep(200); // the first try is still running: wait, then ask again
      }
    } catch {
      tally.timeouts += 1; // no answer in time: charged or not? The app cannot tell.
      await sleep(50);
    }
  }
  return tally;
}

const random = seededRandom(5);
const providerMs = Array.from({ length: PURCHASES }, () => 100 + Math.round(random() * 500)); // 100 to 600 ms

console.log(`${PURCHASES} purchases; provider takes 100 to 600 ms; the app waits ${TIMEOUT_MS} ms, up to ${MAX_ATTEMPTS} tries\n`);
console.log("mode   attempts  timeouts  409s  charges  charged 2+ times  never confirmed");
const perPurchase = {};
for (const mode of MODES) {
  const server = await spawnServer(new URL("./pay-server.js", import.meta.url), { IDEMPOTENCY: mode });
  const runs = [];
  for (let i = 0; i < PURCHASES; i++) {
    runs.push(buy(server.url, `order-${i}`, providerMs[i]));
    await sleep(30);
  }
  const tallies = await Promise.all(runs);
  await sleep(1000); // let charges the app gave up on finish at the provider
  const ledger = await (await fetch(`${server.url}ledger`)).json();
  server.stop();

  perPurchase[mode] = providerMs.map((_, i) => ledger.filter((c) => c.purchase === `order-${i}`).length);
  const sum = (field) => tallies.reduce((n, t) => n + t[field], 0);
  const twice = perPurchase[mode].filter((n) => n >= 2).length;
  const unconfirmed = tallies.filter((t) => !t.confirmed).length;
  console.log(
    `${mode.padEnd(5)}  ${String(sum("attempts")).padStart(8)}  ${String(sum("timeouts")).padStart(8)}  ` +
    `${String(sum("conflicts")).padStart(4)}  ${String(ledger.length).padStart(7)}  ${String(twice).padStart(16)}  ${String(unconfirmed).padStart(15)}`
  );
}

// Average charges per purchase, grouped by how slow the provider was.
const points = [];
for (let from = 100; from < 600; from += 100) {
  const row = { x: from + 50 };
  for (const mode of MODES) {
    const counts = perPurchase[mode].filter((_, i) => providerMs[i] >= from && providerMs[i] < from + 100);
    row[mode] = counts.length ? counts.reduce((a, b) => a + b, 0) / counts.length : 0;
  }
  points.push(row);
}
writeFileSync(new URL("./chart.svg", import.meta.url), lineChart({
  title: `Charges per purchase (the app waits ${TIMEOUT_MS} ms)`,
  xLabel: "provider time in ms (middle of each 100 ms band)",
  yLabel: "charges per purchase",
  points,
  series: [
    { key: "none", color: "#dc2626" },
    { key: "check", color: "#f59e0b" },
    { key: "claim", color: "#2563eb" },
  ],
}));
console.log("\nwrote chart.svg");
```

## When something goes wrong

**`SyntaxError: The requested module '../limiters.js' does not provide an export named 'createTokenBucket'`.** You pasted your 6.8 functions without `export`, or not at all. Fix `limiters.js`.

**`connect ECONNREFUSED 127.0.0.1:6379`.** Valkey is not running, or it runs on another port. Run `docker compose ps` in the challenge folder. If it shows nothing, start it with `docker compose up -d`. If you started it with `VALKEY_PORT`, set the same variable before running the scripts. If Docker itself answers "Cannot connect to the Docker daemon", start Docker Desktop first.

**`Bind for 127.0.0.1:6379 failed: port is already allocated`.** Another container already uses 6379. Run `docker ps` to find it. Stop it, or start this one on another port as in step 5.

**`ERR Error compiling script`, or another error that mentions `user_script`, in part 3.** The Lua script has a typing mistake. The message gives the line inside the script after `user_script:`. Compare it with the listing above, character by character, especially the quotes and `local` keywords.

**Part 3 shows `valkey-script` allowing more than about 28.** Two servers are running against two different Valkeys, or the same client id was reused from an earlier run with tokens left. The script uses a fresh client id per run; check that you did not change that line.

**Part 4 hangs or every attempt times out, even in `claim` mode.** The payments server could not reach Valkey, so it never answers. Run the PING check from step 5.

**Break it on purpose.** See each test fail once before you trust it. In `part-3-shared-limit/shared.test.js`, change `LIMITER: "valkey-script"` to `LIMITER: "valkey-naive"` and run the test: it fails with `actual: 20` where it expected 10, the race in a single number. Undo it. In `part-4-idempotency-keys/pay.test.js`, change the first test's `IDEMPOTENCY: "claim"` to `"check"`: the "charge once" test fails because both requests charge. Undo it. In `server.js`, remove the `retry-after` header: the part 1 test fails on its last line. Undo that too.
