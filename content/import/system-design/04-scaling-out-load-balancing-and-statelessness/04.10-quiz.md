```quiz
type: mcq
question: "A service needs 6 servers to carry its peak. It runs in 3 zones and must keep carrying the peak if a whole zone goes down. What is the smallest fleet that does this, spread evenly?"
options:
  - "9, with three in each zone"
  - "7, six plus one spare"
  - "6, with two in each zone"
  - "12, with four servers in each zone"
correct: 0
explanations:
  - "Right. If any zone goes, the other two zones must hold 6 servers, so each zone needs 3. Three zones of 3 is 9."
  - "One spare covers one server, not a zone. Losing a zone of 7 spread over 3 zones takes out 2 or 3 servers at once."
  - "This is the peak with no spare at all. Losing a zone leaves 4 servers for a load that needs 6."
  - "This survives, but it is more than needed. With 4 per zone, losing one zone leaves 8, two more than the peak."
```

```quiz
type: mcq
question: "Daftar moves from one server to four. Students now say the language they picked keeps switching back to English on some page loads, but not all. Nothing has crashed. What is the most likely cause?"
options:
  - "The balancer's health checks remove servers at random"
  - "The four servers run different versions of the app"
  - "The choice is saved in one server's memory only"
  - "A copy of the database is out of date"
correct: 2
explanations:
  - "A server removed by health checks would cause errors, not a quiet change of language. Nothing has failed here."
  - "Mixed versions can cause odd behaviour, but the symptom here follows which server answers a request, which points at state."
  - "Right. The setting is kept where it was chosen. Requests that land on the other three servers do not see it. It belongs in the session store or the database."
  - "This app has one database in this story, so there is no second copy to be out of date. Copies that fall behind are a real cause of similar symptoms, but module 8 is where they appear."
```

```quiz
type: mcq
question: "A balancer spreads 120 requests a second over 4 servers. It checks every 5 seconds and removes a server after 3 failed checks in a row. One server crashes just after passing a check. About how many requests fail before it is removed?"
options:
  - "About 120, one second of all traffic"
  - "About 30, one second of its share"
  - "About 1,800, all traffic for 15 seconds"
  - "About 450, its share for 15 seconds"
correct: 3
explanations:
  - "The crash does not stop all traffic, only the dead server's share, and it lasts for more than one second."
  - "That is one second of the dead server's share. The balancer keeps sending it requests until the third failed check."
  - "Only the dead server's quarter fails. The other three servers keep answering."
  - "Right. Its share is 120 / 4 = 30 a second, and removal takes up to 5 x 3 = 15 seconds, so about 30 x 15 = 450 requests fail."
```

```quiz
type: mcq
question: "An image service has 60 servers behind 3 load balancers. A request takes anywhere from 5 ms to 3 seconds, depending on the image. The team sees p99 spikes while some servers sit idle. Which picker fits best?"
options:
  - "Round robin, weighted by server size"
  - "Two random choices at each balancer"
  - "Hash of the image id, modulo 60"
  - "A full scan for the least busy of 60"
correct: 1
explanations:
  - "The servers are the same size; the requests differ. Weights by size do not see a server stuck on a slow request."
  - "Right. It avoids servers with long lines by comparing two counts, cheap with 60 servers, and random pairs keep three balancers from all choosing the same server."
  - "Hashing keeps an image on one server but ignores load, and modulo moves most keys when the count changes."
  - "A full scan reads 60 counts per request, and each balancer only sees its own requests, so all three may pick the same server at once."
```

```quiz
type: mcq
question: "The team wants every request to /admin to reach two separate servers that have extra logging, while all other requests spread over the main fleet. Which load balancer can do this by itself?"
options:
  - "A layer 4 balancer, with a flow hash"
  - "A DNS name with a 60-second TTL"
  - "A layer 7 balancer, with a path rule"
  - "Any balancer, with sticky sessions on"
correct: 2
explanations:
  - "A layer 4 balancer sees addresses and ports, not the path inside the request, so it cannot tell /admin from other requests."
  - "DNS turns a name into addresses. It never sees the path either."
  - "Right. A layer 7 balancer reads each request, so a rule can send paths that start with /admin to their own servers."
  - "Stickiness keeps a user on one server. It does not choose servers by path."
```
