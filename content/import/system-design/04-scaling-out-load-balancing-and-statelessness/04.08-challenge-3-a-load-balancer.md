## How the pieces fit

Three choices make the experiment honest, and two of them you know from challenge 1.

**Each backend is one worker.** A backend spends a random time around its average on a busy loop for each request, then answers with its own name. While that loop runs, the backend can do nothing else, so a request that arrives meanwhile waits. Each backend behaves like the single-server queue in chapter 2.5: with 10 ms of average work it can finish about 100 requests a second.

**Each backend is a separate process.** Killing it with `child.kill()` is a real crash: its port closes, and the next connection to it is refused. That is what lets part 2 show a dead backend the way a real load balancer sees one.

**The proxy counts what is in flight.** For every request it forwards, it adds one to that backend's `active` count, and it takes one away when the answer has been sent on. That is the number least connections and two choices read, exactly as in chapter 4.7.

## Step 2: the backend and the proxy

Create `challenges/challenge-3-load-balancer/backend.js`. It is challenge 1's server with three changes: it answers with its name, it answers `GET /health` at once without doing the work, and it can listen on a fixed port so part 2 can start it again where it was.

```js
// One backend server: about SERVICE_MS of work per request, then it answers
// with its own name. GET /health answers at once, without the work.
import http from "node:http";
import { exponential, seededRandom } from "../../toolkit/stats.js";

const NAME = process.env.NAME ?? "backend";
const SERVICE_MS = Number(process.env.SERVICE_MS ?? 10); // average work per request
const PORT = Number(process.env.PORT ?? 0); // 0: any free port
const random = seededRandom([...NAME].reduce((sum, c) => sum + c.charCodeAt(0), 0));

function busyWork(ms) {
  const end = performance.now() + ms;
  while (performance.now() < end) {
    // spin: this loop is the "work", and it blocks, so this is one worker
  }
}

const server = http.createServer((req, res) => {
  if (req.url === "/health") return res.end("ok\n");
  busyWork(exponential(random, SERVICE_MS));
  res.end(`${NAME}\n`);
});

server.listen(PORT, "127.0.0.1", () => {
  const { port } = server.address();
  if (process.send) process.send({ port });
  else console.log(`${NAME} listening on http://127.0.0.1:${port}/ (service ${SERVICE_MS} ms)`);
});
```

Now the load balancer, `challenges/challenge-3-load-balancer/proxy.js`. Read it slowly; every line matters. It keeps a pool of backend objects with the three fields your pickers expect (`name`, `active`, `healthy`), asks the picker for one per request, forwards the request with Node's `http.request`, and pipes the answer back.

```js
// A small L7 load balancer: for every request it asks `pick` for a backend,
// forwards the request there and sends the answer back.
import http from "node:http";

const agent = new http.Agent({ keepAlive: true, maxSockets: Infinity });

// backends: [{ name, url }]. pick(pool) returns one pool entry, or null.
export function startProxy({ backends, pick }) {
  const pool = backends.map((b) => ({ name: b.name, url: b.url, active: 0, healthy: true, served: 0 }));
  let errors = 0;

  const server = http.createServer((req, res) => {
    const backend = pick(pool);
    if (!backend) {
      errors++;
      res.writeHead(503).end("no healthy backend\n");
      return;
    }
    backend.active++; // the request is now in flight on this backend
    let finished = false;
    const finish = () => {
      if (!finished) { finished = true; backend.active--; }
    };
    const target = new URL(req.url, backend.url);
    const upstream = http.request(target, { method: req.method, headers: req.headers, agent }, (answer) => {
      res.writeHead(answer.statusCode, answer.headers);
      answer.pipe(res);
      answer.on("end", () => { backend.served++; finish(); });
    });
    upstream.on("error", () => {
      // The backend refused or dropped the connection: a 502 Bad Gateway.
      finish();
      errors++;
      if (!res.headersSent) res.writeHead(502);
      res.end("bad gateway\n");
    });
    req.pipe(upstream);
  });

  return new Promise((resolve) => {
    server.listen(0, "127.0.0.1", () => {
      resolve({
        url: `http://127.0.0.1:${server.address().port}/`,
        pool,
        errors: () => errors,
        stop: () => { server.closeAllConnections(); server.close(); },
      });
    });
  });
}
```

Three details are worth a second look. The `finished` flag makes sure `active` goes down exactly once, even if a backend dies halfway through an answer and both the `end` and the `error` paths run; a count that drifts upward would slowly poison least connections. The two error codes mean different things: `503 Service Unavailable` says the proxy had no healthy backend to try, while `502 Bad Gateway` says it tried one and the backend failed. And the proxy runs in the same process as the load generator. That is fine because the proxy only moves bytes and never blocks, but it is a simplification: a real balancer runs on its own machines.

## Step 3: part 1, round robin

Create `part-1-round-robin/spread.js`. It starts three backends with 10 ms of average work each, then sends the same rising traffic through the proxy twice: first with only backend A behind it, then with all three. Every step prints p50, p99 and how many requests each backend served.

```js
// Part 1: the same traffic through the proxy to one backend, then to three.
import { writeFileSync } from "node:fs";
import { runLoad, spawnServer } from "../../../toolkit/load.js";
import { summarize } from "../../../toolkit/stats.js";
import { lineChart } from "../../../toolkit/chart.js";
import { createRoundRobin } from "../../../toolkit/pickers.js";
import { startProxy } from "../proxy.js";

const SECONDS = Number(process.env.STEP_SECONDS ?? 8); // how long each step runs
const RATES = [30, 60, 90, 120, 150]; // requests per second
const backendUrl = new URL("../backend.js", import.meta.url);

const backends = [];
for (const name of ["A", "B", "C"]) {
  const server = await spawnServer(backendUrl, { NAME: name, SERVICE_MS: "10" });
  backends.push({ name, url: server.url, stop: server.stop });
}

console.log("backends  rate/s  p50 ms  p99 ms  served per backend");
const points = new Map(RATES.map((rate) => [rate, { x: rate }]));
for (const count of [1, 3]) {
  const proxy = await startProxy({ backends: backends.slice(0, count), pick: createRoundRobin() });
  for (const rate of RATES) {
    for (const b of proxy.pool) b.served = 0;
    const { latencies } = await runLoad({ url: proxy.url, rate, seconds: SECONDS });
    const s = summarize(latencies);
    points.get(rate)[`${count} backend${count > 1 ? "s" : ""}`] = s.p99;
    const served = proxy.pool.map((b) => `${b.name} ${b.served}`).join(", ");
    console.log(`${String(count).padStart(8)}  ${String(rate).padStart(6)}  ${s.p50.toFixed(1).padStart(6)}  ${s.p99.toFixed(1).padStart(6)}  ${served}`);
  }
  proxy.stop();
}
for (const b of backends) b.stop();

writeFileSync(new URL("./chart.svg", import.meta.url), lineChart({
  title: "p99 through the proxy: one backend or three",
  xLabel: "requests per second",
  yLabel: "p99 in milliseconds",
  points: [...points.values()],
  series: [{ key: "1 backend", color: "#dc2626" }, { key: "3 backends", color: "#2563eb" }],
}));
console.log("\nwrote chart.svg");
```

```js
  return new Promise((resolve, reject) => {
    http.get(url, (res) => {
```

## Step 4: part 2, health checks

So far, if a backend dies, the proxy keeps sending it a third of the traffic, and every one of those requests fails with a 502. Part 2 fixes that with health checks, the mechanism from chapter 4.4, and measures the difference.

You write `challenges/challenge-3-load-balancer/health.js` yourself. Here is its contract. It exports one function:

```js
// Every `everyMs`, send GET /health to every backend in `pool`.
// failAfter failures in a row mark a backend unhealthy (healthy = false);
// passAfter passes in a row mark it healthy again. A check that takes
// longer than timeoutMs counts as a failure. Call onChange(backend) whenever
// a backend's healthy flag changes. Returns { stop } to end the checks.
export function startHealthChecks(pool, { everyMs = 500, failAfter = 2, passAfter = 2, timeoutMs = 1000, onChange = () => {} } = {}) {
  // your code here
}
```

The one network call is given to you; put it above your function. It resolves `true` for a 200 answer and `false` for anything else, including a refused connection or a timeout. It never rejects, so you do not need `try` and `catch` around it.

```js
import http from "node:http";

function check(url, timeoutMs) {
  return new Promise((resolve) => {
    const req = http.get(new URL("/health", url), { timeout: timeoutMs }, (res) => {
      res.resume();
      res.on("end", () => resolve(res.statusCode === 200));
    });
    req.on("timeout", () => req.destroy());
    req.on("error", () => resolve(false));
  });
}
```

Three decisions are yours, and each has a hint. First, you need to remember a streak per backend, how many passes or failures in a row it has had; a `Map` keyed by the backend object works, and one signed number per backend can hold both kinds of streak. Second, use `setInterval` to run a round of checks, check all backends of a round at once with `Promise.all`, and skip a round if the previous one has not finished yet, so slow checks do not pile up. Third, change `healthy` only when a streak reaches its threshold, and only if the flag is actually changing; that is when you call `onChange`.

Run `node --test "challenges/challenge-3-load-balancer/part-2-health-checks/*.test.js"` until all three pass. Then create the experiment, `part-2-health-checks/failover.js`. It runs 150 requests a second over three backends for 12 seconds, kills backend B at 4 seconds and starts it again at 8. It does this twice, without and with health checks, and prints the errors and the p99 for each second.

```js
// Part 2: kill backend B in the middle of a run, with and without health
// checks, then start it again. Count errors and p99 second by second.
import { writeFileSync } from "node:fs";
import { runLoad, spawnServer } from "../../../toolkit/load.js";
import { percentile } from "../../../toolkit/stats.js";
import { lineChart } from "../../../toolkit/chart.js";
import { createRoundRobin } from "../../../toolkit/pickers.js";
import { startProxy } from "../proxy.js";
import { startHealthChecks } from "../health.js";

const RATE = 150; // requests per second, about 50% of three backends
const SECONDS = 12;
const KILL_AT = 4; // seconds into the run
const RESTART_AT = 8;
const CHECKS = { everyMs: 500, failAfter: 2, passAfter: 2 };
const backendUrl = new URL("../backend.js", import.meta.url);

async function run(withChecks) {
  const backends = [];
  for (const name of ["A", "B", "C"]) {
    const server = await spawnServer(backendUrl, { NAME: name, SERVICE_MS: "10" });
    backends.push({ name, url: server.url, stop: server.stop });
  }
  const proxy = await startProxy({ backends, pick: createRoundRobin() });
  const t0 = performance.now();
  const at = () => ((performance.now() - t0) / 1000).toFixed(1);
  const checks = withChecks
    ? startHealthChecks(proxy.pool, { ...CHECKS, onChange: (b) => console.log(`  ${at()} s: ${b.name} marked ${b.healthy ? "healthy" : "unhealthy"}`) })
    : null;
  const B = backends[1];
  setTimeout(() => { B.stop(); console.log(`  ${at()} s: B killed`); }, KILL_AT * 1000);
  setTimeout(async () => {
    // Start B again on the same port, so the proxy's address for it still works.
    const again = await spawnServer(backendUrl, { NAME: "B", SERVICE_MS: "10", PORT: new URL(B.url).port });
    B.stop = again.stop;
    console.log(`  ${at()} s: B started again`);
  }, RESTART_AT * 1000);

  const { results } = await runLoad({ url: proxy.url, rate: RATE, seconds: SECONDS });
  checks?.stop();
  proxy.stop();
  for (const b of backends) b.stop();

  // Group the requests by the second they were sent in.
  return Array.from({ length: SECONDS }, (_, s) => {
    const inSecond = results.filter((r) => r.at >= s && r.at < s + 1);
    const ok = inSecond.filter((r) => r.ok).map((r) => r.ms);
    return { second: s, sent: inSecond.length, errors: inSecond.length - ok.length, p99: percentile(ok, 99) };
  });
}

console.log("Run 1: no health checks");
const off = await run(false);
console.log("Run 2: health checks every 500 ms, out after 2 failures, back after 2 passes");
const on = await run(true);

console.log("\nsecond  sent  errors (no checks)  errors (checks)  p99 ms (checks)");
for (let s = 0; s < SECONDS; s++) {
```

## Step 5: part 3, least loaded and two choices

Round robin did perfectly in part 1 because the three backends were the same. Part 3 makes backend C three times slower, 30 ms of average work instead of 10, like an older machine or one sharing its host with a noisy neighbour. C can now finish only about 33 requests a second. Create `part-3-two-choices/compare.js`:

```js
// Part 3: one backend is three times slower than the others. Send the same
// traffic with round robin, least connections and two random choices.
import { writeFileSync } from "node:fs";
import { runLoad, spawnServer } from "../../../toolkit/load.js";
import { summarize } from "../../../toolkit/stats.js";
import { lineChart } from "../../../toolkit/chart.js";
import { createRoundRobin, leastConnections, twoChoices } from "../../../toolkit/pickers.js";
import { startProxy } from "../proxy.js";

const SECONDS = Number(process.env.STEP_SECONDS ?? 6);
const RATES = [60, 90, 120, 150]; // requests per second
const SPEEDS = { A: 10, B: 10, C: 30 }; // average ms of work: C can finish only about 33 a second
const PICKERS = {
  "round robin": () => createRoundRobin(),
  "least connections": () => leastConnections,
  "two choices": () => (pool) => twoChoices(pool),
};
const backendUrl = new URL("../backend.js", import.meta.url);

const backends = [];
for (const [name, ms] of Object.entries(SPEEDS)) {
  const server = await spawnServer(backendUrl, { NAME: name, SERVICE_MS: String(ms) });
  backends.push({ name, url: server.url, stop: server.stop });
}

console.log("picker             rate/s  p50 ms  p99 ms  share sent to slow C");
const points = new Map(RATES.map((rate) => [rate, { x: rate }]));
for (const [label, makePick] of Object.entries(PICKERS)) {
  const proxy = await startProxy({ backends, pick: makePick() });
  for (const rate of RATES) {
    for (const b of proxy.pool) b.served = 0;
    const { latencies } = await runLoad({ url: proxy.url, rate, seconds: SECONDS });
    const s = summarize(latencies);
    const total = proxy.pool.reduce((sum, b) => sum + b.served, 0);
    const shareC = proxy.pool[2].served / total;
    points.get(rate)[label] = s.p99;
    console.log(`${label.padEnd(17)}  ${String(rate).padStart(6)}  ${s.p50.toFixed(1).padStart(6)}  ${s.p99.toFixed(1).padStart(6)}  ${(shareC * 100).toFixed(0).padStart(5)}%`);
  }
  proxy.stop();
}
for (const b of backends) b.stop();

writeFileSync(new URL("./chart.svg", import.meta.url), lineChart({
  title: "p99 with one slow backend, by picker",
  xLabel: "requests per second",
  yLabel: "p99 in milliseconds",
  points: [...points.values()],
  series: [
    { key: "round robin", color: "#dc2626" },
    { key: "least connections", color: "#2563eb" },
    { key: "two choices", color: "#16a34a" },
  ],
}));
console.log("\nwrote chart.svg");
```

Notice the small wrapper for two choices, `(pool) => twoChoices(pool)`. The proxy calls `pick(pool)` with one argument, so `random` takes its default, `Math.random`. Passing `twoChoices` directly would also work today, but the wrapper makes the choice of random source visible in one place.

```js
import test from "node:test";

test("least connections picks the least busy healthy backend", () => {
  const pool = [
    { name: "A", active: 4, healthy: true },
    { name: "B", active: 1, healthy: false },
    { name: "C", active: 2, healthy: true },
  ];
  assert.equal(leastConnections(pool).name, "C");
});

test("two choices never picks the single busiest backend", () => {
  const pool = [
    { name: "A", active: 0, healthy: true },
    { name: "B", active: 9, healthy: true },
    { name: "C", active: 3, healthy: true },
  ];
  for (let i = 0; i < 200; i++) assert.notEqual(twoChoices(pool).name, "B");
});

test("least connections sends less work to a slow backend", async () => {
  const backends = [];

    backends.push({ name, url: server.url, stop: server.stop });
  }
  const proxy = await startProxy({ backends, pick: leastConnections });
  try {
    await runLoad({ url: proxy.url, rate: 100, seconds: 2 });
    const total = proxy.pool.reduce((sum, b) => sum + b.served, 0);
    const shareC = proxy.pool[2].served / total;
    assert.ok(shareC < 0.25, `the slow backend got ${(shareC * 100).toFixed(0)}% of requests`);
  } finally {
    proxy.stop();
    for (const b of backends) b.stop();
  }
});
```

## When something goes wrong

**`does not provide an export named 'createRoundRobin'`.** Your pickers are in `toolkit/pickers.js` without `export`, or under other names. The names must be exactly `createRoundRobin`, `leastConnections` and `twoChoices`.

**`TypeError: Invalid URL` from `proxy.js`, and the script stops.** Your picker returned something that is not a pool entry, often a name instead of the object, so `backend.url` is undefined. Log what `pick(pool)` returns for one request.

**Errors keep coming in part 2 even with checks on.** Your health checker never sets `healthy` to `false`, or sets it on a copy instead of the pool object. Print `proxy.pool.map((b) => b.healthy)` once a second during the run.

**Healthy backends get marked unhealthy under load.** This one is a real lesson, not just a bug. A backend in this challenge is one worker, so its `/health` answer waits in line behind real requests. If the line is long and `timeoutMs` is short, the check times out on a backend that is only busy. Removing it puts more load on the others, their checks time out too, and the whole pool can go unhealthy, then come back, then go again. With `timeoutMs` set to 250 ms, an early draft of this challenge did exactly that at 75% load, and the p99 went past two seconds. It is the deep-check cascade from chapter 4.4 on a small scale. Keep the timeout well above your p99, and do not remove a backend for being slow when it is only busy.

**`EADDRINUSE` when B starts again.** The old B process has not exited yet. Wait a moment and run the script again; if it keeps happening, raise `RESTART_AT`.

**Break it on purpose.** In `toolkit/pickers.js`, change `<` to `>` in `leastConnections` and run `npm test`: the part 3 tests fail. Undo it. Then in `health.js`, make `check` always resolve `true`: the first part 2 test fails, because the dead backend is never removed. Undo that too.
