```quiz
type: mcq
question: "Souq's cart store keeps each key on N = 3 nodes. The team wants an add to succeed as long as one of the key's nodes is up, and accepts that a read may briefly miss the newest add. Which setting fits?"
options:
  - "W = 3 and R = 1, so every write reaches every node"
  - "W = 2 and R = 2, so any two nodes decide each time"
  - "W = 1 and R = 1, so one live node can do both jobs"
  - "W = 3 and R = 3, so every read sees every write"
correct: 2
explanations:
  - "W = 3 needs all three nodes to confirm. One node down stops every write, which is the opposite of what the team asked for."
  - "W = 2 needs two live nodes. With only one node up, writes fail. This is the common setting, but it does not meet this goal."
  - "Right. One confirmation is enough to write, and one answer is enough to read. The cost is that a read can miss the newest add, which the team accepts."
  - "W = 3 and R = 3 need every node for every request. This is the safest overlap and the least available setting of all."
```

```quiz
type: mcq
question: "Two of a key's three nodes are down and writes use W = 2, so every write to the key is refused. The team wants writes to keep succeeding. What should they change, and what does it cost?"
options:
  - "A sloppy quorum with hints; reads can miss the write at first"
  - "Raise R to 3, so every read asks all three nodes of the key"
  - "Switch to last write wins, so a write needs fewer confirmations"
  - "Lower N to 1, so the key sits on a node that is still alive"
correct: 0
explanations:
  - "Right. Stand-in nodes take the write with a hint, so it succeeds. The cost is that a read of the usual nodes can miss it until the hints are delivered."
  - "R is about reads. Raising it does nothing for writes, and a read that needs all three nodes would fail too, with two nodes down."
  - "Last write wins is a way to settle conflicts, not a way to count confirmations. W is still 2 and the key still has only one live node."
  - "With N = 1 the key lives on one node and has no copy. If that node fails, the data is gone. This trades safety for nothing."
```

```quiz
type: mcq
question: "Hana's cart write is confirmed. 4 ms later, Dina, who saw it, saves another cart through a server whose clock is 12 ms slow. The store keeps the larger timestamp. What does the cart show afterwards?"
options:
  - "The later write: it came after the first was confirmed"
  - "Both writes, kept as siblings because the clocks differ"
  - "An error, because the two stamps are within 12 ms"
  - "The first write: the later one has the smaller stamp"
correct: 3
explanations:
  - "Real time says so, but the store compares stamps. Dina's stamp is 4 ms later minus 12 ms of slow clock, so it is smaller than Hana's."
  - "Last write wins keeps one version. It does not keep siblings, because it does not compare vector clocks at all."
  - "The store raises no error. It sees two stamps, picks the larger, and drops the other without telling anyone."
  - "Right. Hana's stamp is the real time. Dina's is 4 ms later but 12 ms behind, so it is 8 ms smaller. The later write is dropped silently."
```

```quiz
type: mcq
question: "In a leaderless store, Souq's cart must keep a removal, and must keep an add that happens at the same time as a removal elsewhere. Which design meets both?"
options:
  - "Siblings merged by union, since a union never loses an add"
  - "Last write wins on the whole cart, with synced clocks"
  - "An OR-Set, where a remove kills only the adds it saw"
  - "A set that remembers each removed name for good"
correct: 2
explanations:
  - "A union keeps every add, but it undoes removals, because the other copy still holds the item. The removal does not stick."
  - "Even with synced clocks, last write wins keeps one whole cart and drops the other, so either the removal or the add is lost."
  - "Right. Each add has its own tag, and a remove marks only the tags it has seen. A concurrent add has a new tag, so it survives, and the removal still sticks."
  - "A removed name that is remembered for good hides a later add of the same item. The removal sticks, but a concurrent add is lost."
```
