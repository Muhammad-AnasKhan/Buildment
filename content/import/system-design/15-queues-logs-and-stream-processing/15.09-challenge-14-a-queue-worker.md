## What a Valkey stream is

Valkey is an open-source in-memory data store (BSD licence). Besides simple keys, it has a data type called a stream: an append-only log. The command `XADD` adds an entry at the end and gives it an id that grows, like `1760000000000-0`. Entries are not removed when they are read, so a stream is a log in the sense of chapter 15.3.

On top of the log, Valkey offers consumer groups. A group remembers which entries it has handed out. The command `XREADGROUP` with the id `>` asks for entries that no worker in the group has been given yet. Valkey gives each entry to one worker and writes it on the group's pending list: entries that were delivered but not yet acknowledged. The worker confirms with `XACK`, and the entry leaves the pending list. If the worker crashes, the entry stays pending until another worker takes it over with `XAUTOCLAIM`, which hands over entries that have been idle for a given time. Valkey also counts how many times it has delivered each entry.

{/* source needed: Valkey streams documentation (https://valkey.io/topics/streams-intro/, read 2026-10-24): XREADGROUP with >, the pending entries list, XACK, XPENDING with idle time and delivery count, XAUTOCLAIM, and the remark that a consumer may process a message more than once, so exactly-once cannot be had in the general case. */}

That is a queue (each entry goes to one worker in the group, and is acknowledged), a log (the entries stay in the stream) and a crash-recovery rule (idle entries can be claimed), in one data type. It is a good size for learning. Kafka and Redpanda do the same on a much larger scale, with partitions and offsets instead of a pending list. The ideas carry over, and the commands do not.

Three design choices keep the numbers honest.

**Each worker has its own connection.** A worker waits for a new entry with `XREADGROUP ... BLOCK`, and a blocked connection cannot be used for anything else. So every worker, and the producer, opens its own connection.

**The work is a sleep.** A worker "sends an email" by waiting for a random time around 50 ms, with the same exponential shape as in challenge 1: many short jobs and a few long ones. A real email call waits on the network in the same way, and a wait does not block the other workers.

**Crashes are scripted.** A real crash is a process that disappears. Here a worker throws a special error at a chosen point, closes its connection and a new worker with a new name starts 200 ms later. That is what a restarted container looks like to Valkey: the old name still owns its pending entries, and the new name has to claim them.

## Step 1: the toolkit

First, `toolkit/valkey.js`. Valkey talks a simple text protocol over TCP, called RESP. A command is a counted list of counted strings, and a reply is one of five shapes. The file writes the first and reads the second, in about 100 lines, so you can see that there is no magic between your code and the server.

```js
// toolkit/valkey.js: a tiny Valkey client in plain Node. It speaks RESP2,
// the text protocol Valkey and Redis use over a TCP socket. No packages.
import net from "node:net";

export const VALKEY_PORT = Number(process.env.VALKEY_PORT ?? 6396);

// Turn one command, like ["SET", "a", 1], into the bytes Valkey expects:
// "*3\r\n$3\r\nSET\r\n$1\r\na\r\n$1\r\n1\r\n"
export function encode(args) {
  let out = `*${args.length}\r\n`;
  for (const arg of args) {
    const text = String(arg);
    out += `$${Buffer.byteLength(text)}\r\n${text}\r\n`;
  }
  return out;
}

// Read one reply from the start of a buffer. Returns [value, bytesUsed],
// or null when the reply has not fully arrived yet.
export function decode(buf, at = 0) {
  const end = buf.indexOf("\r\n", at);
  if (end === -1) return null;
  const kind = String.fromCharCode(buf[at]);
  const line = buf.toString("utf8", at + 1, end);
  const next = end + 2;
  if (kind === "+") return [line, next];
  if (kind === "-") return [new Error(line), next];
  if (kind === ":") return [Number(line), next];
  if (kind === "$") {
    const length = Number(line);
    if (length === -1) return [null, next];
    if (buf.length < next + length + 2) return null;
    return [buf.toString("utf8", next, next + length), next + length + 2];
  }
  if (kind === "*") {
    const count = Number(line);
    if (count === -1) return [null, next];
    const items = [];
    let pos = next;
    for (let i = 0; i < count; i++) {
      const item = decode(buf, pos);
      if (item === null) return null;
      items.push(item[0]);
      pos = item[1];
    }
    return [items, pos];
  }
  throw new Error(`Unknown reply type ${kind}`);
}

// Open one connection. send("GET", "a") returns a promise for the reply.
// Replies come back in the order the commands were sent. A command that
// blocks (XREADGROUP ... BLOCK) holds this connection, so give each
// worker its own connection.
export function connect({ host = "127.0.0.1", port = VALKEY_PORT } = {}) {
  return new Promise((resolve, reject) => {
    const socket = net.createConnection({ host, port });
    socket.setNoDelay(true);
    let buffer = Buffer.alloc(0);
    const waiting = [];
    socket.on("data", (chunk) => {
      buffer = Buffer.concat([buffer, chunk]);
      for (let reply = decode(buffer); reply !== null; reply = decode(buffer)) {
        buffer = buffer.subarray(reply[1]);
        const { resolve: ok, reject: fail } = waiting.shift();
        if (reply[0] instanceof Error) fail(reply[0]);
        else ok(reply[0]);
      }
    });
    socket.on("error", (error) => {
      for (const { reject: fail } of waiting.splice(0)) fail(error);
      reject(error);
    });
    socket.once("connect", () =>
      resolve({
        send: (...args) =>
          new Promise((ok, fail) => {
            waiting.push({ resolve: ok, reject: fail });
            socket.write(encode(args));
          }),
        close: () => socket.destroy(),
      })
    );
  });
}

// True when a Valkey answers PING. Tests use it to skip when Docker is off.
export async function valkeyIsUp(options = {}) {
  try {
    const db = await connect(options);
    const reply = await Promise.race([db.send("PING"), new Promise((r) => setTimeout(r, 1000, null))]);
    db.close();
    return reply === "PONG";
  } catch {
    return false;
  }
}
```

Next, `toolkit/streams.js`. These are the stream commands from the start of this chapter, each in one small function. Read the comments: they are the 101 of consumer groups. The last function, `claimAndApply`, is a short Lua script that Valkey runs without interruption. It marks a job id as done and does the work in the same step. You will use it in part 2.

```js
// toolkit/streams.js: the few Valkey stream commands a queue worker needs,
// wrapped in small functions. A stream is an append-only log. A consumer
// group lets several workers share it: each entry goes to one worker, and
// stays on that worker's "pending" list until the worker acknowledges it.

// Turn ["id", "7", "to", "a@b.c"] into { id: "7", to: "a@b.c" }.
export function toObject(flat) {
  const out = {};
  for (let i = 0; i < flat.length; i += 2) out[flat[i]] = flat[i + 1];
  return out;
}

export const toFlat = (object) => Object.entries(object).flat();

// Start from an empty stream and a fresh group that reads from the beginning.
export async function resetStream(db, stream, group) {
  await db.send("DEL", stream);
  await db.send("XGROUP", "CREATE", stream, group, "0", "MKSTREAM");
}

// Append a job. Returns the entry id Valkey gives it, like "1760000000000-0".
export const enqueue = (db, stream, fields) => db.send("XADD", stream, "*", ...toFlat(fields));

// Read up to `count` new entries for this consumer. ">" means "entries no
// worker has been given yet". Waits up to blockMs for one to arrive.
export async function readNew(db, stream, group, consumer, { count = 1, blockMs = 200 } = {}) {
  const reply = await db.send("XREADGROUP", "GROUP", group, consumer, "COUNT", count, "BLOCK", blockMs, "STREAMS", stream, ">");
  if (!reply) return [];
  return reply[0][1].map(([id, flat]) => ({ id, ...toObject(flat) }));
}

// Tell Valkey the entry is done, so it leaves the pending list.
export const ack = (db, stream, group, id) => db.send("XACK", stream, group, id);

// Take over entries that another worker received but did not acknowledge
// for at least minIdleMs. This is how a crashed worker's jobs come back.
export async function claimIdle(db, stream, group, consumer, minIdleMs, count = 50) {
  const reply = await db.send("XAUTOCLAIM", stream, group, consumer, minIdleMs, "0-0", "COUNT", count);
  return reply[1].map(([id, flat]) => ({ id, ...toObject(flat) }));
}

// How many entries are received but not yet acknowledged.
export async function pendingCount(db, stream, group) {
  const reply = await db.send("XPENDING", stream, group);
  return reply[0];
}

// How many times Valkey has handed this entry to a worker.
export async function deliveryCount(db, stream, group, id) {
  const reply = await db.send("XPENDING", stream, group, id, id, 1);
  return reply.length ? reply[0][3] : 0;
}

// Delete every key that starts with a prefix, so a script can start clean
// without touching anything else that lives in the same Valkey.
export async function clearPrefix(db, prefix) {
  let cursor = "0";
  do {
    const [next, keys] = await db.send("SCAN", cursor, "MATCH", `${prefix}*`, "COUNT", 500);
    if (keys.length) await db.send("DEL", ...keys);
    cursor = next;
  } while (cursor !== "0");
}

// Do the work for a job once, however often the job arrives. Valkey runs a
// script without interruption, so marking the id as done and doing the work
// happen in one step: no crash can fall between them.
const CLAIM_AND_APPLY = `
  if redis.call('SET', KEYS[1], '1', 'NX') then
    redis.call('HINCRBY', KEYS[2], ARGV[1], 1)
    return 1
  end
  return 0`;
export const claimAndApply = (db, jobId, { doneKey = `c14:done:${jobId}`, hash = "c14:applied" } = {}) =>
  db.send("EVAL", CLAIM_AND_APPLY, 2, doneKey, hash, jobId);
```

Then `toolkit/backoff.js`, which you will use in part 3. It has the backoff formula from chapter 15.5, and a thought experiment that counts how many of 200 failing clients retry at the same moment.

```js
// toolkit/backoff.js: how long to wait before try number `attempt`.
// The waiting time doubles with each attempt (1, 2, 4, 8 ... times baseMs)
// until it reaches capMs. With jitter, the real wait is a random time
// between 0 and that ceiling, so many clients do not retry at the same moment.
export function backoffDelay(attempt, { baseMs = 100, capMs = 2000, jitter = true, random = Math.random } = {}) {
  if (!Number.isInteger(attempt) || attempt < 1) throw new RangeError(`attempt must be 1 or more, got ${attempt}`);
  const ceiling = Math.min(capMs, baseMs * 2 ** (attempt - 1));
  return jitter ? random() * ceiling : ceiling;
}

// A thought experiment, no network needed: `clients` clients fail at the same
// moment and each retries `tries` times. Returns the largest number of retries
// that land in one bucketMs-wide slice of time.
export function peakRetries({ clients = 200, tries = 5, bucketMs = 50, jitter, baseMs = 500, capMs = 8000, random }) {
  const perBucket = new Map();
  for (let c = 0; c < clients; c++) {
    let t = 0;
    for (let attempt = 1; attempt <= tries; attempt++) {
      t += backoffDelay(attempt, { baseMs, capMs, jitter, random });
      const bucket = Math.floor(t / bucketMs);
      perBucket.set(bucket, (perBucket.get(bucket) ?? 0) + 1);
    }
  }
  return Math.max(...perBucket.values());
}
```

Last, `toolkit/series-chart.js`. It is like the `lineChart` of challenge 1, but every line has its own list of points, so one line can end earlier than another. It also moves the labels apart when two lines end close together.

```js
// toolkit/series-chart.js: a line chart where every series has its own points,
// so one line can stop earlier than another. Returns SVG text.
// series: [{ name: "1 worker", color: "#dc2626", points: [{ x: 0, y: 0 }, ...] }]
export function seriesChart({ title, xLabel, yLabel, series }) {
  const W = 560, H = 340, L = 60, R = 70, T = 44, B = 50;
  const all = series.flatMap((s) => s.points);
  const xMax = Math.max(...all.map((p) => p.x), 1);
  const yMax = Math.max(...all.map((p) => p.y), 1);
  const X = (x) => L + (x / xMax) * (W - L - R);
  const Y = (y) => H - B - (y / yMax) * (H - T - B);
  const lines = series.map((s) => {
    const d = s.points.map((p, i) => `${i ? "L" : "M"}${X(p.x).toFixed(1)},${Y(p.y).toFixed(1)}`).join(" ");
    return `<path d="${d}" fill="none" stroke="${s.color}" stroke-width="2.5"/>`;
  });
  // Direct labels at the end of each line, nudged apart when they would touch.
  const ends = series.map((s) => ({ s, x: X(s.points.at(-1).x) + 6, y: Y(s.points.at(-1).y) + 4 })).sort((a, b) => a.y - b.y);
  for (let i = 1; i < ends.length; i++) ends[i].y = Math.max(ends[i].y, ends[i - 1].y + 15);
  const labels = ends.map((e) => `<text x="${e.x.toFixed(1)}" y="${e.y.toFixed(1)}" fill="${e.s.color}">${e.s.name}</text>`);
  const xTicks = [0, 0.25, 0.5, 0.75, 1].map((f) => `<text x="${X(f * xMax).toFixed(1)}" y="${H - B + 18}" text-anchor="middle">${Math.round(f * xMax * 10) / 10}</text>`);
  return `<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 ${W} ${H}" font-family="sans-serif" font-size="13">
<rect width="${W}" height="${H}" fill="white"/>
<text x="${L}" y="26" font-size="15" font-weight="bold">${title}</text>
<line x1="${L}" y1="${H - B}" x2="${W - R}" y2="${H - B}" stroke="#999"/>
<line x1="${L}" y1="${T}" x2="${L}" y2="${H - B}" stroke="#999"/>
<text x="${L - 8}" y="${T + 4}" text-anchor="end">${Math.round(yMax)}</text>
<text x="${L - 8}" y="${H - B}" text-anchor="end">0</text>
<text x="${(L + W - R) / 2}" y="${H - 10}" text-anchor="middle">${xLabel}</text>
<text x="16" y="${(T + H - B) / 2}" transform="rotate(-90 16 ${(T + H - B) / 2})" text-anchor="middle">${yLabel}</text>
${xTicks.join("\n")}
${lines.join("\n")}
${labels.join("\n")}
</svg>
`;
}
```

## Step 2: part 1, the backlog

This part sends jobs into a stream at 40 per second for 10 seconds. A job takes a worker about 50 ms, so one worker finishes about 20 jobs per second. The script runs the same load with 1, 2, 3 and 4 workers in one consumer group, and for each run it writes down the number of jobs in the system (waiting or being served), how long jobs wait before a worker starts them, and when the stream is empty again. It also adds up "jobs in the system times time", as in challenge 1, so you can check Little's law on your queue.

Create `part-1-the-backlog/backlog.js`:

```js
// Part 1: the same stream of jobs, 1 to 4 workers in one consumer group.
// Watch the backlog (jobs waiting or being served) grow, then drain.
import { writeFileSync } from "node:fs";
import { connect } from "../../../toolkit/valkey.js";
import { ack, enqueue, readNew, resetStream } from "../../../toolkit/streams.js";
import { exponential, percentile, seededRandom } from "../../../toolkit/stats.js";
import { seriesChart } from "../../../toolkit/series-chart.js";

const STREAM = "c14:welcome-emails";
const GROUP = "senders";
const RATE = 40; // jobs arriving per second
const SECONDS = 10; // how long jobs keep arriving
const SERVICE_MS = 50; // average time a worker needs for one job
const WORKERS = [1, 2, 3, 4];
const sleep = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

async function waitUntil(t) {
  while (performance.now() < t) await new Promise((resolve) => setImmediate(resolve));
}

// One run: send jobs at random moments, let `workers` workers share them.
async function run(workers, seed) {
  const admin = await connect();
  await resetStream(admin, STREAM, GROUP);

  const start = performance.now();
  const waits = []; // ms from "job sent" to "worker starts it"
  const sojourns = []; // ms from "job sent" to "job acknowledged"
  const backlog = []; // [seconds, jobs in the system] sampled every 0.5 s
  let produced = 0;
  let done = 0;
  let producing = true;
  // Little's law bookkeeping: add up (jobs in the system x time).
  let inSystem = 0;
  let area = 0;
  let lastChange = start;
  const change = (delta) => {
    const now = performance.now();
    area += inSystem * (now - lastChange);
    lastChange = now;
    inSystem += delta;
  };

  const loops = Array.from({ length: workers }, async (_, i) => {
    const db = await connect(); // a worker that blocks needs its own connection
    const random = seededRandom(seed + i);
    while (producing || done < produced) {
      for (const job of await readNew(db, STREAM, GROUP, `worker-${i}`, { count: 1, blockMs: 200 })) {
        const startedAt = performance.now();
        waits.push(startedAt - Number(job.born));
        await sleep(exponential(random, SERVICE_MS)); // the "work": sending the email
        await ack(db, STREAM, GROUP, job.id);
        sojourns.push(performance.now() - Number(job.born));
        change(-1);
        done++;
      }
    }
    db.close();
  });

  const sampler = setInterval(() => backlog.push([(performance.now() - start) / 1000, inSystem]), 500);
  const random = seededRandom(seed + 99);
  let planned = start;
  while (true) {
    planned += exponential(random, 1000 / RATE);
    if (planned > start + SECONDS * 1000) break;
    await waitUntil(planned);
    change(+1);
    await enqueue(admin, STREAM, { born: performance.now(), to: `user-${produced}@example.com` });
    produced++;
  }
  producing = false;
  await Promise.all(loops);
  clearInterval(sampler);
  change(0);
  admin.close();

  const elapsed = performance.now() - start;
  const meanSojourn = sojourns.reduce((a, b) => a + b, 0) / sojourns.length;
  return {
    workers,
    produced,
    peak: Math.max(...backlog.map((b) => b[1])),
    p50: percentile(waits, 50),
    p95: percentile(waits, 95),
    emptyAt: elapsed / 1000,
    L: area / elapsed, // average jobs in the system
    lambdaW: (produced / (elapsed / 1000)) * (meanSojourn / 1000),
    backlog,
  };
}

console.log(`arrivals ${RATE}/s for ${SECONDS} s, one job takes about ${SERVICE_MS} ms, so one worker does about ${1000 / SERVICE_MS}/s\n`);
console.log("workers  capacity/s  peak backlog  p50 wait ms  p95 wait ms  empty at s  L     lambda x W");
const colors = ["#dc2626", "#d97706", "#2563eb", "#16a34a"];
const series = [];
for (const workers of WORKERS) {
  const r = await run(workers, 11);
  console.log(
    `${String(workers).padStart(7)}  ${String((1000 / SERVICE_MS) * workers).padStart(10)}  ${String(r.peak).padStart(12)}  ` +
    `${r.p50.toFixed(0).padStart(11)}  ${r.p95.toFixed(0).padStart(11)}  ${r.emptyAt.toFixed(1).padStart(10)}  ` +
    `${r.L.toFixed(2).padStart(5)} ${r.lambdaW.toFixed(2).padStart(10)}`
  );
  series.push({
    name: `${workers} worker${workers > 1 ? "s" : ""}`,
    color: colors[workers - 1],
    points: [{ x: 0, y: 0 }, ...r.backlog.map(([x, y]) => ({ x, y })), { x: r.emptyAt, y: 0 }],
  });
}
writeFileSync(
  new URL("./chart.svg", import.meta.url),
  seriesChart({ title: "Jobs in the system over time", xLabel: "seconds", yLabel: "jobs waiting or in service", series })
);
console.log("\nwrote chart.svg");
```

```js
import test from "node:test";
import assert from "node:assert/strict";
import { connect, decode, encode, valkeyIsUp } from "../../../toolkit/valkey.js";
import { ack, enqueue, pendingCount, readNew, resetStream } from "../../../toolkit/streams.js";

const up = await valkeyIsUp();
const skip = !up && "start Valkey first: docker compose -f challenges/challenge-14-queue-worker/docker-compose.yml up -d";

test("a command is written as a counted list of counted strings", () => {
  assert.equal(encode(["SET", "a", 1]), "*3\r\n$3\r\nSET\r\n$1\r\na\r\n$1\r\n1\r\n");
});
```

## Step 3: part 2, crashes at the worst moment

This part sends 200 jobs through 3 workers. Each job adds 1 to a counter in Valkey, so afterwards you can count what really happened to each job: 0 times is a lost job, more than 1 is a doubled job. At a chosen chance per job, a worker crashes between two steps. The script tries three ways to write the worker, which are the three consumers from chapter 15.4 and 14.5:

- **ack first**: acknowledge the entry, then do the work. A crash after the ack loses the job.
- **work, then ack**: do the work, then acknowledge. A crash between the two leaves the entry pending, a live worker claims it after one second, and the work happens again.
- **work, ack, one claim**: the same order, but the work is done by `claimAndApply`, which does the work only if nobody has done it for this job id.

Two details are easy to miss. Idle entries are taken over with `XAUTOCLAIM` after 1,000 ms, and every worker checks for them twice a second, so a crash costs at least a second of delay for that job. And the crash decision uses a seeded random number, so two runs with the same seed crash at the same points in the sequence of jobs, though the timing of workers still varies a little. Create `part-2-crash-and-redelivery/crash.js`:

```js
// Part 2: workers crash at the worst moment. Three ways to handle a job:
//   "ack first"            acknowledge, then do the work
//   "work, then ack"       do the work, then acknowledge
//   "work, ack, one claim" same, but the work happens only once per job id
import { writeFileSync } from "node:fs";
import { connect } from "../../../toolkit/valkey.js";
import { ack, claimAndApply, claimIdle, clearPrefix, enqueue, readNew, resetStream } from "../../../toolkit/streams.js";
import { seededRandom } from "../../../toolkit/stats.js";
import { seriesChart } from "../../../toolkit/series-chart.js";

const STREAM = "c14:credits";
const GROUP = "workers";
const JOBS = 200;
const WORKERS = 3;
const SERVICE_MS = 20; // time the work takes
const MIN_IDLE_MS = 1000; // a job nobody acknowledged for this long is taken over
const sleep = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

// The effect, written to Valkey so we can count it afterwards.
// Plain: add 1 to the job's counter every time it runs.
const plainEffect = (db, jobId) => db.send("HINCRBY", "c14:applied", jobId, 1);
// One claim: mark the id as done and do the work in ONE step (see claimAndApply
// in toolkit/streams.js), so no crash can fall between the two.
const claimedEffect = (db, jobId) => claimAndApply(db, jobId);

class Crash extends Error {}

async function run(strategy, crashChance, seed) {
  const admin = await connect();
  await clearPrefix(admin, "c14:");
  await resetStream(admin, STREAM, GROUP);
  for (let i = 1; i <= JOBS; i++) await enqueue(admin, STREAM, { job: `job-${i}` });

  const random = seededRandom(seed);
  const maybeCrash = () => { if (random() < crashChance) throw new Crash(); };
  let deliveries = 0;
  let acked = 0;
  let crashes = 0;
  let nameCounter = 0;

  async function handle(db, job) {
    deliveries++;
    if (strategy === "ack first") {
      await ack(db, STREAM, GROUP, job.id);
      acked++;
      maybeCrash(); // crash after the ack: the work is never done
      await sleep(SERVICE_MS);
      await plainEffect(db, job.job);
      return;
    }
    await sleep(SERVICE_MS);
    await (strategy === "work, then ack" ? plainEffect : claimedEffect)(db, job.job);
    maybeCrash(); // crash after the work, before the ack
    await ack(db, STREAM, GROUP, job.id);
    acked++;
  }

  // One worker. When it crashes, its connection closes and a new worker
  // with a new name starts 200 ms later, like a restarted container.
  async function worker() {
    const name = `worker-${++nameCounter}`;
    const db = await connect();
    let lastClaim = Date.now();
    try {
      while (acked < JOBS) {
        if (Date.now() - lastClaim > 500) {
          lastClaim = Date.now();
          for (const job of await claimIdle(db, STREAM, GROUP, name, MIN_IDLE_MS)) await handle(db, job);
        }
        for (const job of await readNew(db, STREAM, GROUP, name, { count: 1, blockMs: 100 })) await handle(db, job);
      }
    } catch (error) {
      if (!(error instanceof Crash)) throw error;
      crashes++;
      db.close();
      await sleep(200);
      return worker();
    }
    db.close();
  }

  await Promise.all(Array.from({ length: WORKERS }, worker));
  const applied = await admin.send("HGETALL", "c14:applied");
  admin.close();
  const counts = new Map();
  for (let i = 0; i < applied.length; i += 2) counts.set(applied[i], Number(applied[i + 1]));
  let lost = 0;
  let duplicated = 0;
  let effects = 0;
  for (let i = 1; i <= JOBS; i++) {
    const n = counts.get(`job-${i}`) ?? 0;
    effects += n;
    if (n === 0) lost++;
    if (n > 1) duplicated++;
  }
  return { strategy, crashChance, deliveries, effects, lost, duplicated, crashes };
}

const STRATEGIES = ["ack first", "work, then ack", "work, ack, one claim"];
console.log(`${JOBS} jobs, ${WORKERS} workers, a crash happens between two steps with the chance shown\n`);
console.log("crash chance  strategy              crashes  deliveries  effects  lost  duplicated");
const lines = new Map(STRATEGIES.map((s) => [s, []]));
for (const crashChance of [0.02, 0.05, 0.1, 0.2]) {
  for (const strategy of STRATEGIES) {
    const r = await run(strategy, crashChance, 5);
    console.log(
      `${(crashChance * 100).toFixed(0).padStart(11)}%  ${strategy.padEnd(20)}  ${String(r.crashes).padStart(7)}  ` +
      `${String(r.deliveries).padStart(10)}  ${String(r.effects).padStart(7)}  ${String(r.lost).padStart(4)}  ${String(r.duplicated).padStart(10)}`
    );
    lines.get(strategy).push({ x: crashChance * 100, y: r.lost + r.duplicated });
  }
}
const colors = { "ack first": "#dc2626", "work, then ack": "#d97706", "work, ack, one claim": "#2563eb" };
writeFileSync(
  new URL("./chart.svg", import.meta.url),
  seriesChart({
    title: "Wrong results out of 200 jobs",
    xLabel: "crash chance per job (%)",
    yLabel: "jobs lost or done twice",
    series: STRATEGIES.map((s) => ({ name: s === "work, ack, one claim" ? "one claim" : s, color: colors[s], points: [{ x: 0, y: 0 }, ...lines.get(s)] })),
  })
);
```

## Step 4: part 3, retries and the dead letter queue

This part sends 100 jobs through one consumer that keeps order: 5 jobs always fail (a bad address), 10 fail twice and then work, and 85 are healthy. Three modes handle failures differently:

- **retry in place, forever**: the consumer retries a failing job until it works. A poison job never works.
- **retry in place, then dead letter**: the consumer waits with backoff and jitter between tries, and after 5 tries writes the job and the reason to another stream and acknowledges it. The line waits during each backoff.
- **retry later, then dead letter**: after a failure the consumer does not wait. It puts the job in a sorted set with the time to try again, acknowledges it and takes the next one. A small mover loop copies jobs back into the stream when their time comes. After 5 tries the job goes to the dead letter stream.

The script stops watching a mode after 15 seconds, and reports how many jobs finished, how many were parked, how many were still stuck, when the last healthy job finished, and how many jobs finished after a job with a higher number. Create `part-3-retries-and-dead-letters/dead-letters.js`:

```js
// Part 3: some jobs always fail (poison) and some fail twice and then work
// (flaky). Three ways to deal with them, on a stream of 100 jobs.
import { writeFileSync } from "node:fs";
import { connect } from "../../../toolkit/valkey.js";
import { ack, clearPrefix, enqueue, readNew, resetStream } from "../../../toolkit/streams.js";
import { backoffDelay } from "../../../toolkit/backoff.js";
import { seededRandom } from "../../../toolkit/stats.js";
import { seriesChart } from "../../../toolkit/series-chart.js";

const STREAM = "c14:receipts";
const GROUP = "senders";
const DEAD = "c14:receipts:dead"; // the dead letter queue is just another stream
const RETRY = "c14:receipts:retry"; // a sorted set: score = when to try again
const JOBS = 100;
const POISON = new Set([10, 30, 50, 70, 90]); // always fail: a bad email address
const FLAKY = new Set([5, 15, 25, 35, 45, 55, 65, 75, 85, 95]); // fail on tries 1 and 2
const MAX_ATTEMPTS = 5;
const SERVICE_MS = 20;
const DEADLINE_MS = 15000; // stop watching a run after this long
const sleep = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

function sendReceipt(job) {
  const n = Number(job.n);
  if (POISON.has(n)) throw new Error("bad address");
  if (FLAKY.has(n) && Number(job.attempt) < 2) throw new Error("provider timeout");
}

async function run(mode, seed) {
  const db = await connect();
  await clearPrefix(db, "c14:");
  await resetStream(db, STREAM, GROUP);
  for (let n = 1; n <= JOBS; n++) await enqueue(db, STREAM, { n, attempt: 0 });

  const random = seededRandom(seed);
  const start = performance.now();
  const finished = []; // [job number, seconds] for every success
  const curve = [{ x: 0, y: 0 }];
  let dead = 0;
  const seconds = () => (performance.now() - start) / 1000;
  const succeeded = (n) => {
    finished.push([n, seconds()]);
    curve.push({ x: seconds(), y: finished.length });
  };

  // The retry mover: copies jobs whose time has come from the sorted set
  // back into the stream. Only the "retry later" mode uses it.
  let moving = mode === "retry later, then dead letter";
  const mover = (async () => {
    const mdb = await connect();
    while (moving) {
      const due = await mdb.send("ZRANGEBYSCORE", RETRY, "-inf", Date.now(), "LIMIT", 0, 50);
      for (const member of due) {
        if ((await mdb.send("ZREM", RETRY, member)) === 1) await enqueue(mdb, STREAM, JSON.parse(member));
      }
      await sleep(25);
    }
    mdb.close();
  })();

  const worker = await connect();
  let timedOut = false; // true when the time limit ends a run
  while (!timedOut && seconds() * 1000 < DEADLINE_MS) {
    const [job] = await readNew(worker, STREAM, GROUP, "w1", { count: 1, blockMs: 100 });
    if (!job) {
      if (finished.length + dead >= JOBS) break;
      continue;
    }
    const retryable = mode === "retry in place, forever" ? Infinity : MAX_ATTEMPTS;
    let attempt = Number(job.attempt);
    while (true) {
      try {
        await sleep(SERVICE_MS);
        sendReceipt({ ...job, attempt });
        succeeded(Number(job.n));
        await ack(worker, STREAM, GROUP, job.id);
        break;
      } catch (error) {
        attempt++;
        if (attempt >= retryable) {
          // Give up: park the job in the dead letter queue with the reason.
          await enqueue(worker, DEAD, { n: job.n, attempts: attempt, error: error.message });
          dead++;
          await ack(worker, STREAM, GROUP, job.id);
          break;
        }
        const wait = backoffDelay(attempt, { baseMs: 50, capMs: 1000, random });
        if (mode === "retry later, then dead letter") {
          // Do not wait here. Put the job in the sorted set and move on.
          await worker.send("ZADD", RETRY, Date.now() + wait, JSON.stringify({ n: job.n, attempt }));
          await ack(worker, STREAM, GROUP, job.id);
          break;
        }
        if (seconds() * 1000 + wait > DEADLINE_MS) {
          await sleep(Math.max(0, DEADLINE_MS - seconds() * 1000));
          timedOut = true; // the job is still stuck, and so is everything behind it
          break;
        }
        await sleep(wait); // wait right here: nothing behind this job moves
      }
    }
  }
  moving = false;
  await mover;
  worker.close();
  db.close();

  const healthy = finished.filter(([n]) => !POISON.has(n) && !FLAKY.has(n));
  // Count jobs that finished after a job with a higher number: out of order.
  let outOfOrder = 0;
  let highest = 0;
  for (const [n] of finished) (n < highest ? outOfOrder++ : (highest = n));
  return {
    mode,
    ok: finished.length,
    dead,
    stuck: JOBS - finished.length - dead,
    healthyDone: healthy.length,
    lastHealthyAt: healthy.length ? Math.max(...healthy.map(([, t]) => t)) : NaN,
    outOfOrder,
    curve: [...curve, { x: Math.max(seconds(), curve.at(-1).x), y: finished.length }],
  };
}

const MODES = ["retry in place, forever", "retry in place, then dead letter", "retry later, then dead letter"];
console.log(`${JOBS} jobs: ${POISON.size} always fail, ${FLAKY.size} fail twice and then work, ${JOBS - POISON.size - FLAKY.size} are healthy\n`);
console.log("mode                              ok  dead  stuck  healthy done  last healthy at s  out of order");
const colors = ["#dc2626", "#d97706", "#2563eb"];
const series = [];
for (const [i, mode] of MODES.entries()) {
  const r = await run(mode, 21);
  console.log(
    `${mode.padEnd(32)} ${String(r.ok).padStart(3)}  ${String(r.dead).padStart(4)}  ${String(r.stuck).padStart(5)}  ` +
    `${String(r.healthyDone).padStart(12)}  ${(Number.isNaN(r.lastHealthyAt) ? "-" : r.lastHealthyAt.toFixed(1)).padStart(17)}  ${String(r.outOfOrder).padStart(12)}`
  );
  series.push({ name: ["forever", "in place", "later"][i], color: colors[i], points: r.curve });
}
writeFileSync(
  new URL("./chart.svg", import.meta.url),
  seriesChart({ title: "Jobs finished over time", xLabel: "seconds", yLabel: "jobs finished", series })
);
console.log("\nwrote chart.svg");
```

```js
  const options = { baseMs: 100, capMs: 1000, jitter: false };
  assert.deepEqual([1, 2, 3, 4, 5, 6].map((n) => backoffDelay(n, options)), [100, 200, 400, 800, 1000, 1000]);
});

test("with jitter the wait is a random time between 0 and the ceiling", () => {
  assert.equal(backoffDelay(3, { baseMs: 100, capMs: 1000, random: () => 0 }), 0);
  assert.equal(backoffDelay(3, { baseMs: 100, capMs: 1000, random: () => 0.5 }), 200);
  assert.ok(backoffDelay(3, { baseMs: 100, capMs: 1000, random: () => 0.999999 }) < 400);
});

test("attempt 0 or a fraction is a RangeError", () => {
  assert.throws(() => backoffDelay(0), RangeError);
  assert.throws(() => backoffDelay(1.5), RangeError);
});

test("jitter spreads a crowd of retries out", () => {
  const together = peakRetries({ jitter: false });
  const spread = peakRetries({ jitter: true, random: seededRandom(3) });
  assert.equal(together, 200, "without jitter every client retries at the same moment");
  assert.ok(spread < together / 3, `with jitter the busiest slice still had ${spread} of ${together}`);
});

test("a sorted set holds a retry until its time has come", { skip }, async () => {
  const db = await connect();

  } finally {
```

## When something goes wrong

**`connect ECONNREFUSED 127.0.0.1:6396`.** Valkey is not running, or Docker is off. Start Docker Desktop and run the `docker compose ... up -d --wait` command again. The live tests skip in this case, but the scripts need the server.

**`port is already allocated`.** Something else uses 6396. Change the left number in `ports` and set `VALKEY_PORT` to the same number in the terminal you run the scripts from.

**`ERR unknown command 'XAUTOCLAIM'`, or `XGROUP` errors.** You are talking to an old Redis, not the Valkey from the compose file. Run `docker compose ... ps` and check the port, or run `docker exec <container> valkey-server --version`.

**`BUSYGROUP Consumer Group name already exists`.** The script resets its stream at the start of every run, so this means two scripts are running at the same time against the same Valkey. Wait for the first to finish.

**Part 1 never finishes.** A worker threw an error and stopped, so the job count never reaches the total. Look for the first error in the output. A common cause is a typo in a toolkit function name.

**Part 2 numbers differ from mine.** The crash points depend on the order in which workers take jobs, which varies a little between runs. The pattern must hold: `ack first` loses jobs and has 200 deliveries, `work, then ack` duplicates and has more than 200, and `one claim` has `effects` of exactly 200. If `one claim` shows a different number, check that the script marks the id and does the work in one `EVAL`.

**Part 3 shows `stuck` jobs in the second row.** The run hit the 15 second limit. Your machine is slower than mine, or the backoff waits were long. Run again, or raise `DEADLINE_MS`.

**Break it on purpose.** See a test fail before you trust it. In `toolkit/backoff.js`, change `2 ** (attempt - 1)` to `2 ** attempt` and run `npm test`: the two backoff tests fail, because every wait is now twice as long. Undo the change. Then in `toolkit/streams.js`, delete `'NX',` from the Lua script, and run `npm test` again: the claim-script test fails with "the copy must be recognised", because the marker is overwritten every time and the work runs twice. Undo that too.
