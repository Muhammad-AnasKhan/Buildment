```quiz
type: mcq
question: "Tiny Crawl (a made-up service) must fetch 600 million pages a month. A month has about 2.6 million seconds. It waits 2 seconds between requests to one site. About how many different sites must have work waiting at the same moment to keep up?"
options:
  - "About 460 sites"
  - "About 230 sites"
  - "About 115 sites"
  - "About 14,000 sites"
correct: 0
explanations:
  - "Right. 600,000,000 / 2,600,000 is about 230 pages a second. Each site allows one request every 2 seconds, so 230 x 2 is about 460 sites."
  - "That is only the pages a second. With a 2 second wait each site gives half a page a second, so twice as many sites are needed."
  - "That divides by the wait instead of multiplying. A longer wait means each site gives fewer pages a second, so more sites are needed, not fewer."
  - "That treats the month as one day, using 86,400 seconds. The pages are spread over the whole month, which is about 2.6 million seconds."
```

```quiz
type: mcq
question: "A seen-URL check uses a Bloom filter at 1% error for 5 billion URLs. It needs about 9.6 bits per URL. About how much memory does it use, and what does the 1% error cost?"
options:
  - "About 6 GB; 1 in 100 seen URLs is fetched again"
  - "About 6 GB; 1 in 100 new URLs is skipped"
  - "About 40 GB; 1 in 100 new URLs is skipped"
  - "About 40 GB; no URL is ever skipped by mistake"
correct: 1
explanations:
  - "The memory is right, but the error runs the other way. A Bloom filter never forgets a URL it saw, so a seen URL is never fetched again."
  - "Right. 5,000,000,000 x 9.6 bits is about 6 GB. The error is a false 'maybe seen' for a URL that is new, so that page is skipped."
  - "That is the memory of exact 8-byte fingerprints (5 billion x 8 bytes). A filter at 1% error needs about 9.6 bits per URL, not 64."
  - "That describes an exact set of 8-byte fingerprints, not a Bloom filter. The filter's whole trade is less memory for a small chance of a skip."
```

```quiz
type: mcq
question: "DalilBot asks a site for robots.txt, and the server answers 503 (service unavailable). DalilBot has no saved copy. What should it do?"
options:
  - "Crawl everything, since it found no rules to obey"
  - "Reuse the rules it read from some other site"
  - "Crawl nothing from it for now; try again later"
  - "Crawl only the home page, to test the site"
correct: 2
explanations:
  - "A missing file (404) means no rules, but a 503 means the rules could not be read. Crawling anyway could break rules the site really has."
  - "Rules belong to one site. Another site's rules say nothing about what this site allows."
  - "Right. A server error means the crawler cannot know the rules, so it assumes everything is blocked for now and asks again later."
  - "Even one page is a request the site may have forbidden. Until the rules are known, no path is safe to fetch."
```

```quiz
type: mcq
question: "After a week, DalilBot is fetching only about 1 page a second although its fetchers sit idle. The frontier holds 40 million URLs, almost all from one calendar site that makes new pages for ever. What should the team do first?"
options:
  - "Add more fetcher machines to take URLs in parallel"
  - "Cut that site's wait from 1 second to 0.1 seconds"
  - "Make the Bloom filter bigger to lower its error"
  - "Give every host a page budget and flag that site"
correct: 3
explanations:
  - "The fetchers are already idle. The limit is one request a second to the one site that has work, so more machines add nothing."
  - "That makes DalilBot 10 times ruder to a site that is not even worth the visits. It speeds up the waste and risks a block."
  - "Every calendar address is really new, so a more accurate filter correctly says 'not seen' each time. It cannot stop a trap."
  - "Right. A budget of pages per host ends the endless calendar, and the freed fetchers move on to the many other sites with real work."
```
