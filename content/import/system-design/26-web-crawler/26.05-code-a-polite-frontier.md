In chapter 26.3 you saw the structure that keeps DalilBot polite: a queue for each host, a clock for each host, and a pick among the hosts that are ready. In 26.4 you saw the budget that ends a crawler trap. The part in between is small. A function adds a URL to the right host's queue. Another hands out the best URL whose host is ready, and starts that host's wait. A third tells the caller how long to sleep when nothing is ready.

Each piece is short, and each is easy to get slightly wrong. A frontier that keeps one global clock passes every test with one site and calls a site twice in a second when two sites share the queue. A frontier that always takes the best priority first passes the priority tests and then sits idle behind a site that is waiting. In this chapter you write the frontier in plain JavaScript and test it against the cases that catch those mistakes.

## What the tests do to your code

The tests are built around the places where frontiers fail. They run on a fake clock: a variable `t` that the test moves by hand, so the wait between calls is exact and no test ever sleeps. They check that a host cannot be called twice inside its delay, to the millisecond, and that other hosts are not held back by it. They mix priorities across hosts and inside one host. They put a high-priority URL on a waiting host next to a low-priority URL on a ready host. They break ties between ready hosts. They add the same URL twice, fill a host's budget, change one host's delay in the middle of a run, and send in bad input. The last test runs a whole small crawl and checks the speed you worked out in chapter 26.3.

Nothing is `async`, and nothing reads the real clock or a random number. Each test gives the same answer every time, and the message of a failing test tells you which rule you broke.

## The contract

**`createFrontier({ now, delayMs = 1000, maxPerHost = Infinity })`** returns an object with five methods. `now` is a function that returns the current time in milliseconds. In production it is `Date.now`, and in the tests it reads the fake clock. `delayMs` is the minimum gap between two URLs handed out for the same host. `maxPerHost` is the most URLs the frontier will accept for one host, over its whole life. It throws a `TypeError` if `now` is not a function, and a `RangeError` if `delayMs` is not a finite number of 0 or more, or if `maxPerHost` is neither `Infinity` nor a positive integer.

**`add(url, priority = 1)`** puts a URL in the queue of its host. A priority is 0 (high), 1 (normal) or 2 (low), and anything else is a `RangeError`. The URL must be a string that `new URL` can read, with the scheme `http` or `https`, or `add` throws a `TypeError`. The host is `new URL(url).host`: lower-case, and with the port if it is not the default one. It returns `true` if the URL was accepted. It returns `false`, and changes nothing, if the same string was added before (even if it has already been handed out), or if the host has already accepted `maxPerHost` URLs. A repeat does not use up any of the budget.

**`next()`** returns the next URL, or `null` if nothing can be fetched right now. It looks at the hosts that have URLs waiting and whose wait is over (their ready time is not after `now()`). Among those it takes the host whose best waiting priority is the highest (the lowest number). If two hosts tie, it takes the one whose ready time is earlier. If they still tie, it takes the one that was added to the frontier first. From that host it removes the oldest URL of its best priority, sets the host's ready time to `now() + delay`, and returns the URL. The delay is `delayMs`, unless `setDelay` gave that host its own.

**`nextReadyIn()`** returns how many milliseconds the caller must wait before `next()` can return a URL. That is 0 if some host with URLs waiting is ready now, and the smallest wait over hosts with URLs waiting otherwise. It returns `null` if no URL is waiting. A host with no URLs waiting is not counted.

**`setDelay(host, ms)`** gives one host its own delay, for example from a `Crawl-delay` line in its `robots.txt`. The host is written like `shop.example` or `shop.example:8443`, in any letter case. The new delay applies to URLs handed out after the call. A host that is already waiting keeps its ready time. It throws a `TypeError` if `host` is not a non-empty string, and a `RangeError` if `ms` is not a finite number of 0 or more.

**`size()`** returns the number of URLs waiting.

## A worked example by hand

Here is the frontier applied by hand to a case that is not in the tests. The delay is 1,000 ms. Three URLs are added at time 0: `a/1` (priority 1) on host a, then `a/2` (priority 0) on host a, then `b/1` (priority 2) on host b.

| Time | Call | Hosts that are ready | Answer | Why |
|---|---|---|---|---|
| 0 | `next()` | a, b | `a/2` | Host a's best waiting priority is 0, better than b's 2. Host a is now ready at 1000 |
| 0 | `next()` | b | `b/1` | Host a is waiting, so only b is looked at. Host b is now ready at 1000 |
| 0 | `next()` | none | `null` | Both hosts wait. `nextReadyIn()` is 1000 |
| 1000 | `next()` | a | `a/1` | Host a's wait is over, and it still has `a/1` |
| 1200 | `add("b/2", 0)` then `next()` | b | `b/2` | Host b has been ready since 1000. Its new URL is high priority. Host a waits until 2000 |

At time 0 the first call returns `a/2` even though `a/1` was added first. Priority decides inside host a, and priority decides between the hosts. At time 0 the third call shows why `next()` must return `null` and not the better URL of a waiting host: the caller then calls `nextReadyIn()`, sleeps 1000 ms, and asks again. The wait is time that other hosts can use, and when no other host has work, sleeping is the polite thing to do.

## Six ways this goes wrong

**One clock for everyone.** If the frontier remembers a single "last fetch time", then a fetch of host a delays host b. With 770 hosts the crawl would run at one page a second. The clock belongs to the host.

**Priority before politeness.** Pick the best URL in the whole frontier first, and then wait for its host, and every fetcher idles whenever the best URL is on a busy site. Filter by ready first, then pick by priority.

**Forgetting the tie.** Two ready hosts with the same priority must be chosen by a rule, or the same host wins every time and the other one starves. The rule is the earlier ready time, because that host has been waiting longest.

**Counting a repeat against the budget.** If a duplicate uses up a place in `maxPerHost`, a site with many repeated links runs out of budget on pages it already has. A repeat changes nothing, and a URL turned away by the budget is not remembered either.

**Counting the empty hosts in `nextReadyIn()`.** A host that has been fetched and has nothing left still has a ready time. If you include it, the caller wakes up early and finds nothing to do, again and again. Only hosts with URLs waiting count.

**Comparing hosts by their text.** `Shop.EXAMPLE` and `shop.example` are the same host, and `shop.example:8443` is a different one. Take the host from `new URL(url).host` and never from the string you were given.

When a test fails, read its message first. Each one names the input, what it expected and what your code returned.

  function createFrontier({ now, delayMs = 1000, maxPerHost = Infinity } = {}) {
    if (typeof now !== "function") throw new TypeError("now must be a function");
    if (typeof delayMs !== "number" || !Number.isFinite(delayMs) || delayMs < 0) {
      throw new RangeError("delayMs must be a number of 0 or more");
    }
    if (maxPerHost !== Infinity && (!Number.isInteger(maxPerHost) || maxPerHost < 1)) {
      throw new RangeError("maxPerHost must be a positive integer or Infinity");
    }
    const hosts = new Map();
    const delays = new Map();
    const seen = new Set();
    let size = 0;

    function hostOf(url) {
      if (typeof url !== "string") throw new TypeError("url must be a string");
      let parsed;
      try {
        parsed = new URL(url);
      } catch {
        throw new TypeError("not a valid URL: " + url);
      }
      if (parsed.protocol !== "http:" && parsed.protocol !== "https:") {
        throw new TypeError("only http and https URLs are crawled: " + url);
      }
      return parsed.host;
    }

    return {
      add(url, priority = 1) {
        if (!Number.isInteger(priority) || priority < 0 || priority > 2) {
          throw new RangeError("priority must be 0, 1 or 2");
        }
        const host = hostOf(url);
        if (seen.has(url)) return false;
        let entry = hosts.get(host);
        if (!entry) {
          entry = { queues: [[], [], []], waiting: 0, readyAt: 0, accepted: 0 };
          hosts.set(host, entry);
        }
        if (entry.accepted >= maxPerHost) return false;
        seen.add(url);
        entry.queues[priority].push(url);
        entry.waiting++;
        entry.accepted++;
        size++;
        return true;
      },
      next() {
        const t = now();
        let best = null;
        let bestHost = null;
        let bestPriority = 3;
        for (const [host, entry] of hosts) {
          if (entry.waiting === 0 || entry.readyAt > t) continue;
          const priority = entry.queues.findIndex((q) => q.length > 0);
          if (priority < bestPriority || (priority === bestPriority && entry.readyAt < best.readyAt)) {
            best = entry;
            bestHost = host;
            bestPriority = priority;
          }
        }
        if (!best) return null;
        const url = best.queues[bestPriority].shift();
        best.waiting--;
        size--;
        best.readyAt = t + (delays.get(bestHost) ?? delayMs);
        return url;
      },
      nextReadyIn() {
        const t = now();
        let wait = null;
        for (const entry of hosts.values()) {
          if (entry.waiting === 0) continue;
          const w = Math.max(0, entry.readyAt - t);
          if (wait === null || w < wait) wait = w;
        }
        return wait;
      },
      setDelay(host, ms) {
        if (typeof host !== "string" || host === "") throw new TypeError("host must be a non-empty string");
        if (typeof ms !== "number" || !Number.isFinite(ms) || ms < 0) {
          throw new RangeError("ms must be a number of 0 or more");
        }
        delays.set(host.toLowerCase(), ms);
      },
      size() {
        return size;
      },
    };

## Check your understanding before you submit

Run one more case in your head with your code. Make a frontier with `delayMs` 2,000 and `maxPerHost` 2. At time 0, add `x/1`, `x/2` and `x/3` on host x, and `y/1` on host y. The third `add` returns `false`, because host x has taken two URLs, so `size()` is 3. At time 0, `next()` returns `x/1`, then `y/1`, and then `null`. `nextReadyIn()` is 2000, because host x still has `x/2` waiting and host y has nothing waiting. At time 2000, `next()` returns `x/2`.

Now change one thing: add `y/9` with priority 0 at time 500. Host y was handed out at time 0, so it is ready at 2000, and the new URL waits for it. At time 2000 both x and y are ready. Host y's best priority is 0 against host x's 1, so `next()` returns `y/9` first. The very next call returns `x/2`, because host x is ready too.

Last, think about what the real fetcher adds. The frontier here starts the wait when a URL is handed out. A slow download of 3 seconds at a 1 second delay would let the next request go out while the first is still running, which breaks the "one request at a time" rule from chapter 26.3. A real version has the fetcher report back when it is done, and only then starts the wait. You do not write that here, because the point of this exercise is that the choosing is exact.

## How to say it in an interview

**Say:** "The frontier keeps a record for each host: three queues by priority, a count, and the time the host may be called again. To hand out a URL I look only at hosts that have work and whose time has passed, take the best priority among them, and break ties by who has been ready longest. Then I set that host's time to now plus its delay. If nothing is ready I tell the caller how long to sleep. I keep a budget of URLs per host to stop traps, and a set of URLs already accepted so a repeat costs nothing."

**Expect:** "How does it scale past one machine?" **Answer:** "Hash the host to pick the machine, so one machine sees all the requests to a host and keeps its clock. A million hosts is a million small records, and I can keep the heads of the queues in memory and the rest on disk."

## What this unlocks

The pattern, one small clock for each key, is not only for crawlers. A per-user rate limiter (chapter 6.5) is the same structure with a token bucket in place of a ready time. A pool of workers that must not all hit one database shard uses it as well. The wider idea is to put the rule about one key next to that key's queue, and to let the picking logic stay simple. Chapter 26.7 asks you to use the frontier, the Bloom filter and the trap defences on scenarios you have not seen.
