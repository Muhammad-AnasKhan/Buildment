```quiz
type: mcq
question: "Hawa (a made-up chat app) has 4 million daily users. Each user has 1.5 devices, and 25% of all devices are connected at the busiest time. One gateway is planned for 50,000 lines. About how many gateways does Hawa need?"
options:
  - "About 8 gateways"
  - "About 30 gateways"
  - "About 120 gateways"
  - "About 80 gateways"
correct: 1
explanations:
  - "This divides 4 million by 500,000 and ignores both the devices and the share online. It is far too low."
  - "Right. 4,000,000 x 1.5 is 6 million devices, 25% of that is 1.5 million lines, and 1,500,000 / 50,000 is 30."
  - "This counts every device as connected: 6,000,000 / 50,000 is 120. Only 25% are online at the busiest time."
  - "This counts one line for each user: 4,000,000 / 50,000 is 80. It ignores the 1.5 devices and the 25% share online."
```

```quiz
type: mcq
question: "In a group chat, Dana and Omar send a message at almost the same moment. One member's phone shows Dana first, and another member's phone shows Omar first. Which change makes every phone agree?"
options:
  - "Sort by the clock on the sender's phone"
  - "Sort by the time each phone received it"
  - "Add more chat servers to deliver faster"
  - "Number messages per chat; sort by number"
correct: 3
explanations:
  - "Phone clocks are wrong by seconds, and a person can change theirs. Two senders would disagree with the real order and with each other."
  - "Receive times differ from phone to phone, because the copies take different paths. That is how the phones disagreed in the first place."
  - "Faster delivery makes a swap less likely but never impossible. A slow path still exists, so the order can still differ."
  - "Right. One owner gives each message the next number in its chat, so every phone sorts the same way and holds back a message if one is missing."
```

```quiz
type: mcq
question: "3 million phones ping every 30 seconds, and each ping renews a key in the presence store. A manager wants the store load cut a lot, with the green dot never more than a minute late. Which change does that best?"
options:
  - "End each ping at the gateway, write only changes"
  - "Ping every 5 seconds to spot offline phones faster"
  - "Send each status change to all 500 contacts"
  - "Raise the key time limit from 60 s to 10 minutes"
correct: 0
explanations:
  - "Right. The gateway already holds the line, so it can keep the last ping in memory. The store then sees only status changes, a few thousand a second instead of 100,000."
  - "A shorter gap multiplies the pings by 6, to 600,000 a second. It finds offline phones faster and makes the load far worse."
  - "Sending to every contact multiplies the updates by 500. Only people looking at that chat need to be told."
  - "A 10 minute limit does nothing for the write load, and it leaves a phone that left looking online for up to 10 minutes."
```

```quiz
type: mcq
question: "The registry restarts empty, so every lookup misses while the gateways still hold their lines. What should the chat service do with new messages?"
options:
  - "Refuse new messages until the registry is full again"
  - "Send every message to all 60 gateways"
  - "Save it, treat the user as offline, limit pushes"
  - "Drop messages for users with no registry entry"
correct: 2
explanations:
  - "Refusing breaks the promise to the sender for a problem users did not cause. Messages can still be saved while the registry heals."
  - "That is 60 sends for every delivery, about 2.5 million a second at peak. The gateways would drown in messages they cannot deliver."
  - "Right. Nothing is lost, because the message is saved. Pushes are limited per person so people who are online do not get a flood, and the gateways re-register their lines."
  - "Dropping loses messages the sender has already seen as sent. That breaks the one rule the tick promises."
```

```quiz
type: mcq
question: "Login codes arrive at 80 a second. The SMS provider is down for 3 minutes, then sends 120 a second. After the provider returns, about how long until the queue is empty again, if no code is dropped?"
options:
  - "About 2 minutes"
  - "About 6 minutes"
  - "About 9 minutes"
  - "About 3 minutes"
correct: 1
explanations:
  - "That divides the backlog of 14,400 by 120 and forgets that 80 new codes keep arriving each second."
  - "Right. 3 minutes at 80 a second leaves 14,400 codes. The queue then shrinks by 120 minus 80, which is 40 a second, so 14,400 / 40 is 360 seconds."
  - "This adds the 3 minute outage to the 6 minutes of catch-up. The question measures from the moment the provider returns."
  - "This is only the length of the outage. The backlog it leaves still has to be worked off at the spare capacity."
```
