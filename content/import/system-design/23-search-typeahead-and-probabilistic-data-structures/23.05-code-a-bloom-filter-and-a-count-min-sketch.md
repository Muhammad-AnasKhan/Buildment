In chapter 23.4 you met three structures that trade a little accuracy for a lot of memory. Two of them are short enough to write in one sitting: a Bloom filter, which says "no" for sure or "maybe", and a count-min sketch, which counts without storing the keys. In this chapter you write both in plain JavaScript, together with the two small functions that size them for a target error.

Each structure fits on a page, and each is easy to get slightly wrong. A Bloom filter that ignores its hash count passes every test that uses one word and fails when the error rate matters. A sketch that adds its rows instead of taking the smallest cell gives counts that are too high by a factor of the depth. Because these errors are statistical, the tests do not check one answer. They check rates and bounds, over thousands of keys, and they run the same way every time.

## What the tests do to your code

The tests are built around the places where these structures fail. For the filter they add thousands of words and check that none is ever forgotten, since a false negative is the one mistake a Bloom filter must never make. Then they test thousands of words that were never added, count the wrong maybes and compare the rate with the formula from chapter 23.4. They run the same filter with 1, 7 and 20 hashes, so ignoring the hash count fails at once. They check that the share of bits set matches what the formula predicts, and that two filters merge.

For the sketch they check that a single key is counted exactly, that an estimate is never below the truth even when the sketch is crowded, and that nearly every key stays inside the error bound of epsilon times the total. They check that more rows really give a smaller error, which only happens if you take the minimum. They merge two sketches built on two halves of a stream and expect the same answers as one sketch built on all of it.

Nothing is asynchronous, and nothing reads a clock or a random number. The hash function is given to you, so a test that passes on one machine passes on every machine. A failing test names the input, the rate it expected and the rate your code produced.

## The contract

**`hash(text, seed)`** is given, and you keep it as it is. It turns a string and a seed into a number from 0 to 4,294,967,295. Different seeds give different, unrelated hashes of the same text, which is what a Bloom filter and a sketch both need.

**`bloomSize(n, p)`** says how big a filter must be for `n` words at a wrong-maybe rate `p`. It returns `{ bits, hashes }`. The number of bits is `n` times the natural log of `1 / p`, divided by the square of the natural log of 2, rounded up. The number of hashes is the bits per word times the natural log of 2, rounded to the nearest whole number and never less than 1. It throws a `RangeError` if `n` is not a positive integer or `p` is not strictly between 0 and 1.

**`createBloomFilter({ bits, hashes })`** returns an object with four methods. `add(key)` sets one bit for each seed from 0 to `hashes - 1`, at the position `hash(key, seed) % bits`. `has(key)` looks at the same positions and returns `false` as soon as it finds a bit that is 0, and `true` if it finds none. `fillRatio()` returns the share of bits that are set, from 0 to 1. `merge(other)` ORs the bits of another filter into this one, and throws a `RangeError` if the other filter has a different number of bits or hashes. A key that is not a string is a `TypeError`. Settings that are not positive integers are a `RangeError`.

**`sketchSize(epsilon, delta)`** returns `{ width, depth }`. The width is the constant e divided by `epsilon`, rounded up. The depth is the natural log of `1 / delta`, rounded up. Epsilon is how large an error you accept, as a share of all events. Delta is the chance that the bound fails. Both must be strictly between 0 and 1. {/* source needed: the width and depth rules come from the count-min sketch paper by Cormode and Muthukrishnan (2005), which the dossier did not read; the exercise states them as its contract. */}

**`createCountMinSketch({ width, depth })`** returns an object with four methods. `add(key, count = 1)` adds `count` to the cell `hash(key, row) % width` in every row, and `count` must be a positive integer. `estimate(key)` returns the smallest of the key's cells, one from each row. `total()` returns the sum of every count added. `merge(other)` adds another sketch of the same width and depth cell by cell, and throws a `RangeError` if the sizes differ.

## A worked example by hand

Here is the code applied by hand to a case that is not in the tests, using the given `hash`. A filter has 16 bits and 2 hashes. For each word, the two positions are `hash(word, 0) % 16` and `hash(word, 1) % 16`. Running the function gives these positions.

| Word | Position from seed 0 | Position from seed 1 |
|---|---|---|
| red | 12 | 3 |
| shoe | 3 | 5 |
| blue | 4 | 15 |

Add all three. The bits set are 3, 4, 5, 12 and 15, so the row reads `0001110000001001`, counting from position 0. Now ask about four words that were never added.

| Word | Positions | Bits found | Answer |
|---|---|---|---|
| hiking | 4, 0 | 1, 0 | no, for sure |
| coat | 8, 5 | 0, 1 | no, for sure |
| tent | 8, 0 | 0, 0 | no, for sure |
| shirt | 5, 15 | 1, 1 | maybe, which is wrong |

The last row is a wrong maybe, called a false positive. Nobody added shirt. Bit 5 was set by shoe, and bit 15 was set by blue, and together they cover shirt's two positions. This is a tiny, crowded filter: 3 words in 16 bits is 5 bits per word, far from the 10 you used in chapter 23.4. The rule from that chapter still holds, though: a "no" is always true.

Now the sketch. Take width 6 and depth 2. The positions are `hash(word, row) % 6`: red goes to cells 4 and 5, shoe to cells 5 and 3, and blue to cells 4 and 5. Add red, shoe, blue, red, red and shoe. The true counts are red 3, shoe 2 and blue 1.

| | Cell 3 | Cell 4 | Cell 5 |
|---|---|---|---|
| Row 0 | 0 | red 3 + blue 1 = 4 | shoe 2 |
| Row 1 | shoe 2 | 0 | red 3 + blue 1 = 4 |

Row 0 reads cell 4 for red and blue, and cell 5 for shoe. Row 1 reads cell 5 for red and blue, and cell 3 for shoe. So `estimate("red")` is the smaller of 4 and 4, which is 4, one too many. `estimate("shoe")` is the smaller of 2 and 2, which is exactly 2. `estimate("blue")` is 4, against a true 1, because blue shares both of its cells with red. This is the worst case for a sketch, two keys that collide in every row, and it is why the width and depth matter. Each added row is another chance for blue to get a cell to itself.

## Five ways this goes wrong

**Ignoring the hash count.** A filter that always uses one hash passes tests with a handful of words and fails when the tests measure the wrong-maybe rate with 7 and 20 hashes. The tests run the same filter at 1, 7 and 20 hashes for this reason.

**Storing the words.** A `Set` is the easy way to pass a membership test, and it breaks the point of the exercise: it uses memory for every word and never makes a mistake. A test expects at least a few wrong maybes at 10 bits per word, because a filter that size must make some.

**Adding instead of taking the smallest.** If `estimate` adds the rows, a key counted 5 times estimates 25 in a sketch of 5 rows. If it takes the largest, the counts are too high again. Only the smallest cell is the closest to the truth. The depth test catches both.

**Merging with the wrong operation.** Two filters merge with OR, because a bit set in either is set in the union. AND would forget words. Two sketches merge with addition, because counts from two streams add. Taking the larger cell would lose counts.

**Not checking the size on merge.** A cell at position 7 in a sketch of width 500 and one of width 501 are different things. Merging them gives numbers that mean nothing, so the code must refuse with a `RangeError`.

When a test fails, read its message first. Each one names the rate it expected and the rate your code returned.

  function bloomSize(n, p) {
    if (!Number.isInteger(n) || n < 1) throw new RangeError("n must be a positive integer");
    if (typeof p !== "number" || !(p > 0 && p < 1)) throw new RangeError("p must be between 0 and 1");
    const bits = Math.ceil((-n * Math.log(p)) / Math.LN2 ** 2);
    const hashes = Math.max(1, Math.round((bits / n) * Math.LN2));
    return { bits, hashes };
  }

      has(key) {
        need(key);
        for (let s = 0; s < hashes; s++) if (row[hash(key, s) % bits] === 0) return false;
        return true;
      },
      fillRatio() {
        let set = 0;
        for (const b of row) set += b;
        return set / bits;
      },
      merge(other) {
        if (!other || other.size !== bits || other.hashCount !== hashes) throw new RangeError("filters must have the same bits and hashes");
        for (let i = 0; i < bits; i++) row[i] |= other.cells[i];
      },
      size: bits,
      hashCount: hashes,
      cells: row,
    };
  }

  function sketchSize(epsilon, delta) {
    if (typeof epsilon !== "number" || !(epsilon > 0 && epsilon < 1)) throw new RangeError("epsilon must be between 0 and 1");
    if (typeof delta !== "number" || !(delta > 0 && delta < 1)) throw new RangeError("delta must be between 0 and 1");
    return { width: Math.ceil(Math.E / epsilon), depth: Math.ceil(Math.log(1 / delta)) };
  }

  function createCountMinSketch({ width, depth } = {}) {
    if (!Number.isInteger(width) || width < 1) throw new RangeError("width must be a positive integer");
    if (!Number.isInteger(depth) || depth < 1) throw new RangeError("depth must be a positive integer");
    const rows = Array.from({ length: depth }, () => new Uint32Array(width));
    let sum = 0;
    return {
      add(key, count = 1) {
        if (typeof key !== "string") throw new TypeError("key must be a string");
        if (!Number.isInteger(count) || count < 1) throw new RangeError("count must be a positive integer");
        for (let r = 0; r < depth; r++) rows[r][hash(key, r) % width] += count;
        sum += count;
      },
      estimate(key) {
        if (typeof key !== "string") throw new TypeError("key must be a string");
        let best = Infinity;
        for (let r = 0; r < depth; r++) best = Math.min(best, rows[r][hash(key, r) % width]);
        return best;
      },
      total() {
        return sum;
      },
      merge(other) {
        if (!other || other.width !== width || other.depth !== depth) throw new RangeError("sketches must have the same width and depth");
        for (let r = 0; r < depth; r++) for (let c = 0; c < width; c++) rows[r][c] += other.rows[r][c];
        sum += other.total();
      },
      width,
      depth,
      rows,
    };

## Check your understanding before you submit

Run two more cases in your head. First, size a filter for 1,000 words at a 1% wrong-maybe rate. The bits are 1,000 x ln(100) / (ln 2)^2, which is 1,000 x 4.605 / 0.4805 = 9,585.06, rounded up to 9,586. The bits per word are 9.586, and times ln 2 that is 6.64, which rounds to 7 hashes. Then size a sketch for epsilon 0.01 and delta 0.01. The width is e / 0.01 = 271.8, rounded up to 272. The depth is ln(100) = 4.6, rounded up to 5. That sketch has 272 x 5 = 1,360 cells, about 5 KB at 4 bytes a cell. After 10,000 events its estimates are too high by at most about 0.01 x 10,000 = 100 for nearly every key.

Now the other direction. If your sketch from the worked example had width 6 and depth 2, and blue and red collided in both rows, what would a third row change? A third hash gives blue a third cell. If that cell is not shared with red, its value is 1, and the minimum of 4, 4 and 1 is 1, the true count. One more row rescued the estimate. That is the whole argument for depth.

## How to say it in an interview

**Say:** "A Bloom filter is a bit array and k hash functions. Add sets k bits, lookup checks them. A zero means definitely not present, all ones means maybe. About 10 bits per item and 7 hashes gives a 1% false positive rate. A count-min sketch is a grid of counters with one hash per row. Add increments one cell in each row, and the estimate is the minimum, so it never undercounts and overcounts at most epsilon times the total, with high probability. Both merge, and neither stores the keys."

**Expect:** "How do you pick the sizes?" **Answer:** "From the error I can accept. For a Bloom filter, m = n ln(1/p) / (ln 2) squared and k = (m/n) ln 2. For a sketch, width e over epsilon and depth ln(1/delta). I check the result with a test that counts the real error."
