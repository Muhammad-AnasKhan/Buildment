## How the lab works

The picture shows what runs where. Docker starts two PostgreSQL servers. The primary accepts writes. The replica copies the primary's log, as in chapter 8.2, and answers read-only queries. Your scripts talk to both, one connection each.

Three design choices make the lab honest. Each one removes a trap.

**The lag is real replication, with a delay on top.** Nothing is faked. The replica really streams the primary's log. PostgreSQL has a setting for the replica, `recovery_min_apply_delay`, that makes it wait before it applies each commit. At `600ms` the replica holds every commit for about 600 ms after it was committed on the primary, which is the slow replica from chapter 8.4. You change the setting while the servers run, with `ALTER SYSTEM` and a reload, so one script can try several lags.

**Positions are real log positions.** A position is a log sequence number (LSN), a 64-bit number that PostgreSQL prints as two hex halves, like `0/3065158`. After a write, your code asks the primary for `pg_current_wal_lsn()` and keeps it as the token. The replica reports how far it has applied with `pg_last_wal_replay_lsn()`. To compare two positions, you parse them into numbers. Comparing the strings would be wrong, because `0/A` is a smaller position than `0/10`, yet as text it sorts after.

**The position is read before the data.** The router asks the replica for its position, and only then reads the row. The replica only moves forward, so a read that comes after the check is at least as new as the position you saw. If you did it the other way round, a replica could pass the token between your read and your check, and you would believe you had a fresh answer when you had an old one. The order is the whole trick.

## Step 2: the primary and the replica

Create `challenges/challenge-7-replicas-and-lag/docker-compose.yml`. It looks long, but it does only two things: it starts a primary that allows replication, and it starts a replica that copies the primary the first time it runs.

```yaml
# Challenge 7: one PostgreSQL primary and one replica, on your own machine.
# Primary on 127.0.0.1:5437, replica on 127.0.0.1:5438. Throwaway password.
name: challenge-7-replicas-and-lag

services:
  primary:
    image: postgres:18-alpine
    environment:
      POSTGRES_PASSWORD: lagtest
    ports:
      - "127.0.0.1:5437:5432"
    volumes:
      - primary-data:/var/lib/postgresql
    # The first start (only) lets a replica connect for replication: the
    # normal "host all" rule does not cover replication connections.
    command:
      - sh
      - -c
      - |
        printf '%s\n' '#!/bin/sh' 'echo "host replication all all scram-sha-256" >> "$$PGDATA/pg_hba.conf"' > /docker-entrypoint-initdb.d/10-replication.sh
        chmod +x /docker-entrypoint-initdb.d/10-replication.sh
        exec docker-entrypoint.sh postgres -c wal_level=replica -c max_wal_senders=5
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres"]
      interval: 2s
      timeout: 3s
      retries: 30

  replica:
    image: postgres:18-alpine
    user: postgres
    environment:
      PGPASSWORD: lagtest
    depends_on:
      primary:
        condition: service_healthy
    ports:
      - "127.0.0.1:5438:5432"
    volumes:
      - replica-data:/var/lib/postgresql
    # The first start (only) copies the primary with pg_basebackup. -R writes
    # the settings that make this server a replica. Every start then runs
    # PostgreSQL as a read-only hot standby.
    command:
      - sh
      - -c
      - |
        if [ ! -s "$$PGDATA/PG_VERSION" ]; then
          chmod 700 "$$PGDATA"
          pg_basebackup -h primary -U postgres -D "$$PGDATA" -R -X stream
        fi
        exec postgres -c hot_standby=on

volumes:
  primary-data:
  replica-data:
```

Read the two `command` blocks, because they are the whole setup. On its first start only, the primary writes a small script into the folder PostgreSQL runs once, and the script adds a rule that lets a replica connect for replication. The ordinary "all databases" rule does not cover replication connections, which surprises people. On the first start only, the replica runs `pg_basebackup`, which copies the primary's data, and `-R` writes the settings that turn the copy into a replica. Every start after that runs PostgreSQL as a read-only standby, with `hot_standby=on`. The password is a throwaway for your own laptop, and both ports are bound to `127.0.0.1`, so nothing outside your machine can reach them.

```bash
docker compose -f challenges/challenge-7-replicas-and-lag/docker-compose.yml up -d

`sent_lsn` is how far the primary has sent, and `replay_lsn` is how far the replica has applied. Here they are equal: no lag. Your address and positions will differ. ## Step 3: the toolkit

Create `toolkit/lsn.js`. It turns a log position into a number you can compare.

```js
// toolkit/lsn.js: PostgreSQL write-ahead log positions (LSNs).
// Postgres prints a position as two hex numbers, like "0/3000148".
// It is one 64-bit number split in two halves: high 32 bits, "/", low 32 bits.

export function parseLsn(text) {
  const match = /^([0-9A-Fa-f]{1,8})\/([0-9A-Fa-f]{1,8})$/.exec(String(text));
  if (!match) throw new Error(`not an LSN: ${text}`);
  return (BigInt(`0x${match[1]}`) << 32n) | BigInt(`0x${match[2]}`);
}

// True when a node that has applied `applied` has every change up to `token`.
export function lsnAtLeast(applied, token) {
  return parseLsn(applied) >= parseLsn(token);
}

// How many bytes of log separate two positions (never negative).
export function lsnGap(ahead, behind) {
  const gap = parseLsn(ahead) - parseLsn(behind);
  return Number(gap > 0n ? gap : 0n);
}
```

Create `toolkit/pgpair.js`. It opens one connection to each server, sets the replica's lag, and waits for the replica to catch up. The lag setting is the only place where the code reaches into the replica's configuration.

```js
// toolkit/pgpair.js: connect to the challenge 7 primary and replica.
import pg from "pg";

export const PRIMARY_URL = process.env.PRIMARY_URL ?? "postgres://postgres:lagtest@127.0.0.1:5437/postgres";
export const REPLICA_URL = process.env.REPLICA_URL ?? "postgres://postgres:lagtest@127.0.0.1:5438/postgres";

export const sleep = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

// Open one connection to each server. Call close() when you are done.
export async function connectPair() {
  const primary = new pg.Client({ connectionString: PRIMARY_URL });
  const replica = new pg.Client({ connectionString: REPLICA_URL });
  await Promise.all([primary.connect(), replica.connect()]);
  return { primary, replica, close: () => Promise.all([primary.end(), replica.end()]) };
}

// True when both servers answer (used to skip tests when Docker is off).
export async function pairIsRunning() {
  try {
    const pair = await connectPair();
    await pair.close();
    return true;
  } catch {
    return false;
  }
}

// The knob that creates lag. recovery_min_apply_delay makes the replica wait
// before it applies each commit, so reads on it fall behind by about `ms`.
export async function setReplicaDelay(replica, ms) {
  await replica.query(`ALTER SYSTEM SET recovery_min_apply_delay = '${Number(ms)}ms'`);
  await replica.query("SELECT pg_reload_conf()");
  await sleep(300); // give the replica a moment to read the new setting
}

// Wait until the replica has applied everything the primary has written so far.
export async function waitForCatchUp(primary, replica) {
  const { rows } = await primary.query("SELECT pg_current_wal_lsn()::text AS lsn");
  for (;;) {
    const r = await replica.query("SELECT pg_last_wal_replay_lsn() >= $1::pg_lsn AS ok", [rows[0].lsn]);
    if (r.rows[0].ok) return;
    await sleep(5);
  }
}
```

## Step 4: part 1, lag you can see

Part 1 asks one question: how long after a write does the new row appear on the replica? For each of four lag settings, it makes 20 writes. After each write it asks the replica, every 2 ms, "do you have it yet?", and records the time until the answer is yes. It also records how many bytes of log the replica was behind right after the write. Create `part-1-lag-you-can-see/lag.js`:

```js
// Part 1: make the replica lag on purpose, and measure how long a write takes
// to become visible there.
import { writeFileSync } from "node:fs";
import { connectPair, setReplicaDelay, sleep, waitForCatchUp } from "../../../toolkit/pgpair.js";
import { lsnGap } from "../../../toolkit/lsn.js";
import { summarize } from "../../../toolkit/stats.js";
import { lineChart } from "../../../toolkit/chart.js";

const DELAYS_MS = [0, 100, 300, 600]; // the lag we ask the replica to add
const SAMPLES = Number(process.env.SAMPLES ?? 20); // writes per setting

const { primary, replica, close } = await connectPair();
await primary.query("DROP TABLE IF EXISTS ticks");
await primary.query("CREATE TABLE ticks (id serial PRIMARY KEY, sent_at timestamptz DEFAULT now())");
await setReplicaDelay(replica, 0);
await waitForCatchUp(primary, replica);

console.log("asked ms  samples  median ms  p95 ms  max ms  log behind (bytes)");
const points = [];
for (const delay of DELAYS_MS) {
  await setReplicaDelay(replica, delay);
  const visible = [];
  let bytesBehind = 0;
  for (let i = 0; i < SAMPLES; i++) {
    const start = performance.now();
    const { rows } = await primary.query("INSERT INTO ticks DEFAULT VALUES RETURNING id");
    // How far behind is the replica's log right now? Bytes of log not yet applied.
    const [p, r] = await Promise.all([
      primary.query("SELECT pg_current_wal_lsn()::text AS lsn"),
      replica.query("SELECT pg_last_wal_replay_lsn()::text AS lsn"),
    ]);
    bytesBehind = Math.max(bytesBehind, lsnGap(p.rows[0].lsn, r.rows[0].lsn));
    // Ask the replica until the new row shows up.
    for (;;) {
      const seen = await replica.query("SELECT 1 FROM ticks WHERE id = $1", [rows[0].id]);
      if (seen.rowCount === 1) break;
      await sleep(2);
    }
    visible.push(performance.now() - start);
    await sleep(20);
  }
  const s = summarize(visible);
  points.push({ x: delay, "median ms": s.p50, "p95 ms": s.p95 });
  console.log(
    `${String(delay).padStart(8)}  ${String(SAMPLES).padStart(7)}  ${s.p50.toFixed(0).padStart(9)}  ` +
    `${s.p95.toFixed(0).padStart(6)}  ${s.max.toFixed(0).padStart(6)}  ${String(bytesBehind).padStart(18)}`
  );
}
await setReplicaDelay(replica, 0);
await close();

writeFileSync(new URL("./chart.svg", import.meta.url), lineChart({
  title: "Time until a write is visible on the replica",
  xLabel: "delay asked of the replica (ms)",
  yLabel: "milliseconds",
  points,
  series: [{ key: "median ms", color: "#2563eb" }, { key: "p95 ms", color: "#dc2626" }],
}));
console.log("\nwrote chart.svg");
```

Its test, `part-1-lag-you-can-see/lag.test.js`, has two pure tests for the position helpers that need no database, and one live test that sets a 300 ms lag and checks that a new row takes at least 250 ms. The live test is skipped when the pair is not running.

```js
import test from "node:test";
import assert from "node:assert/strict";
import { lsnAtLeast, lsnGap, parseLsn } from "../../../toolkit/lsn.js";
import { connectPair, pairIsRunning, setReplicaDelay, sleep, waitForCatchUp } from "../../../toolkit/pgpair.js";

test("a log position is one growing number written as two hex halves", () => {
  assert.equal(parseLsn("0/10"), 16n);
  assert.equal(parseLsn("1/0"), 4294967296n);
  assert.throws(() => parseLsn("latest"));
});

test("positions compare as numbers, not as text", () => {
  assert.ok(lsnAtLeast("0/10", "0/9")); // as text "0/10" sorts before "0/9", as numbers it is larger
  assert.ok(lsnAtLeast("1/0", "0/FFFFFFFF"));
  assert.ok(!lsnAtLeast("0/3000148", "0/3000150"));
  assert.equal(lsnGap("0/150", "0/100"), 80);
  assert.equal(lsnGap("0/100", "0/150"), 0);
});

const running = await pairIsRunning();

test("with a 300 ms delay, a new row takes at least 250 ms to reach the replica", { skip: !running && "start the pair first: docker compose up -d" }, async () => {
  const { primary, replica, close } = await connectPair();
  try {
    await primary.query("CREATE TABLE IF NOT EXISTS ticks (id serial PRIMARY KEY, sent_at timestamptz DEFAULT now())");
    await waitForCatchUp(primary, replica);
    await setReplicaDelay(replica, 300);
    const start = performance.now();
    const { rows } = await primary.query("INSERT INTO ticks DEFAULT VALUES RETURNING id");
    for (;;) {
      const seen = await replica.query("SELECT 1 FROM ticks WHERE id = $1", [rows[0].id]);
      if (seen.rowCount === 1) break;
      await sleep(2);
    }
    const took = performance.now() - start;
    assert.ok(took >= 250, `the row was visible after ${took.toFixed(0)} ms, so the delay did not work`);
  } finally {
    await setReplicaDelay(replica, 0);
    await close();
  }
});
```

## Step 5: part 2, the bug

Part 2 is Amna's story on a real database. It posts a comment on the primary and then, either at once or after 300 ms, reads it from the replica. It counts how often the comment is missing. Create `part-2-read-your-writes-bug/bug.js`:

```js
// Part 2: post a comment, then read it back from the replica. Count how often
// your own comment is missing. Run it at three lag settings, and with the
// reader waiting 0 ms or 300 ms before the read.
import { writeFileSync } from "node:fs";
import { connectPair, setReplicaDelay, sleep, waitForCatchUp } from "../../../toolkit/pgpair.js";
import { lineChart } from "../../../toolkit/chart.js";

const DELAYS_MS = [0, 100, 600]; // lag added to the replica
const TRIALS = Number(process.env.TRIALS ?? 60); // comments per setting
const PAUSES_MS = [0, 300]; // how long the user waits before the read

const { primary, replica, close } = await connectPair();
await primary.query("DROP TABLE IF EXISTS comments");
await primary.query("CREATE TABLE comments (id serial PRIMARY KEY, body text NOT NULL)");
await setReplicaDelay(replica, 0);
await waitForCatchUp(primary, replica);

// One user action: post a comment (write to the primary), wait a moment,
// then load the page (read from the replica). True when the comment shows.
async function postThenRead(pauseMs) {
  const { rows } = await primary.query("INSERT INTO comments (body) VALUES ('hello') RETURNING id");
  if (pauseMs > 0) await sleep(pauseMs);
  const seen = await replica.query("SELECT 1 FROM comments WHERE id = $1", [rows[0].id]);
  return seen.rowCount === 1;
}

console.log("lag ms  pause ms  trials  own comment missing");
const points = [];
for (const delay of DELAYS_MS) {
  await setReplicaDelay(replica, delay);
  const point = { x: delay };
  for (const pause of PAUSES_MS) {
    let missing = 0;
    for (let i = 0; i < TRIALS; i++) {
      if (!(await postThenRead(pause))) missing += 1;
    }
    const share = (missing / TRIALS) * 100;
    point[`read after ${pause} ms`] = share;
    console.log(
      `${String(delay).padStart(6)}  ${String(pause).padStart(8)}  ${String(TRIALS).padStart(6)}  ` +
      `${String(missing).padStart(5)} (${share.toFixed(0)}%)`
    );
  }
  points.push(point);
}
await setReplicaDelay(replica, 0);
await close();

writeFileSync(new URL("./chart.svg", import.meta.url), lineChart({
  title: "Own comment missing when read from the replica (%)",
  xLabel: "lag added to the replica (ms)",
  yLabel: "% of reads",
  points,
  series: [{ key: "read after 0 ms", color: "#dc2626" }, { key: "read after 300 ms", color: "#2563eb" }],
}));
console.log("\nwrote chart.svg");
```

The test, `part-2-read-your-writes-bug/bug.test.js`, sets a 600 ms lag, posts a comment, reads it straight back from the replica, and asserts that the replica does not have it while the primary does. In other words it checks that the bug is there. It is the one test in the course that passes because something is broken.

```js
import test from "node:test";
import assert from "node:assert/strict";
import { connectPair, pairIsRunning, setReplicaDelay, waitForCatchUp } from "../../../toolkit/pgpair.js";

const running = await pairIsRunning();
const skip = !running && "start the pair first: docker compose up -d";

test("with 600 ms of lag, a comment read straight back from the replica is missing", { skip }, async () => {
  const { primary, replica, close } = await connectPair();
  try {
    await primary.query("CREATE TABLE IF NOT EXISTS comments (id serial PRIMARY KEY, body text NOT NULL)");
    await waitForCatchUp(primary, replica);
    await setReplicaDelay(replica, 600);
    const { rows } = await primary.query("INSERT INTO comments (body) VALUES ('hello') RETURNING id");
    const seen = await replica.query("SELECT 1 FROM comments WHERE id = $1", [rows[0].id]);
    assert.equal(seen.rowCount, 0, "the replica already had the row, so there is no bug to reproduce");
    const onPrimary = await primary.query("SELECT 1 FROM comments WHERE id = $1", [rows[0].id]);
    assert.equal(onPrimary.rowCount, 1, "the primary must always have the row");
  } finally {
    await setReplicaDelay(replica, 0);
    await close();
  }
});
```

## Step 6: part 3, position tokens

Part 3 is the fix. Create `part-3-position-tokens/router.js`. It has four small functions. `newSession` makes the object that holds a user's token. `raise` moves a token forward and never back. `writeComment` saves a comment on the primary and stores the primary's log position as the token. `readComment` follows the rule of this chapter: read the replica's position first, use the replica if it has reached the token, otherwise wait a little (if you allowed it) and then use the primary. Every read raises the token to the position of the node that served it, so a later read can never be older.

```js
// A read-your-writes router for the challenge 7 pair.
// The session keeps one token: the highest log position this user has seen.
import { lsnAtLeast } from "../../../toolkit/lsn.js";
import { sleep } from "../../../toolkit/pgpair.js";

export function newSession() {
  return { token: null };
}

// Move the token forward, never back.
export function raise(session, lsn) {
  if (session.token === null || !lsnAtLeast(session.token, lsn)) session.token = lsn;
}

// Writes go to the primary. The token is the primary's log position just
// after the commit: any node that has applied it has this comment.
export async function writeComment(pair, session, body) {
  const { rows } = await pair.primary.query("INSERT INTO comments (body) VALUES ($1) RETURNING id", [body]);
  const pos = await pair.primary.query("SELECT pg_current_wal_lsn()::text AS lsn");
  raise(session, pos.rows[0].lsn);
  return rows[0].id;
}

// Reads try the replica first. Check its position BEFORE reading: the replica
// only moves forward, so a read that comes after the check is at least as new.
// If the replica is behind the token, wait up to waitMs, then use the primary.
export async function readComment(pair, session, id, { waitMs = 0 } = {}) {
  const deadline = performance.now() + waitMs;
  for (;;) {
    const pos = await pair.replica.query("SELECT pg_last_wal_replay_lsn()::text AS lsn");
    const applied = pos.rows[0].lsn;
    if (session.token === null || lsnAtLeast(applied, session.token)) {
      const { rows } = await pair.replica.query("SELECT body FROM comments WHERE id = $1", [id]);
      raise(session, applied); // later reads can never be older than this one
      return { body: rows[0]?.body ?? null, from: "replica" };
    }
    if (performance.now() >= deadline) break;
    await sleep(5);
  }
  const { rows } = await pair.primary.query(
    "SELECT (SELECT body FROM comments WHERE id = $1) AS body, pg_current_wal_lsn()::text AS lsn", [id]
  );
  raise(session, rows[0].lsn);
  return { body: rows[0].body, from: "primary" };
}
```

  );

With a 100 ms lag and no waiting, none of the reads were served by the replica; the router sent all of them to the primary, so the replicas did no work. One more detail. The first column "naive: missing" shows 19 of 60 at zero lag here, but 59 of 60 in part 2. The write in part 3 asks the primary for its position after the insert, which adds a round trip, and that small gap gave the replica time to catch up on some runs. Timing at zero lag is a matter of luck, which is why you never design for it.

## When something goes wrong

**`connect ECONNREFUSED 127.0.0.1:5437`.** The pair is not running, or Docker is off. Start Docker Desktop and run `docker compose ... up -d`. The live tests skip instead of failing for this reason, but the scripts need the pair.

**`port is already allocated` or `address already in use`.** Something else uses port 5437 or 5438. Change the left number in the `ports` lines of `docker-compose.yml`, and set the environment variables `PRIMARY_URL` and `REPLICA_URL` to match.

**The replica container keeps restarting.** Run `docker compose ... logs replica`. If you see `no pg_hba.conf entry for replication connection`, the primary was first started before the rule was in place. The rule is only written on the very first start, so run `docker compose ... down -v` to delete the old data, then `up -d` again. If you see `has invalid permissions`, the line `chmod 700` is missing from the replica's command.

**Part 1 shows a median much larger than you asked.** Something is slowing the machine, or the replica was still catching up from earlier work. Wait a few seconds and run again. Close heavy programs and plug in the laptop.

**Tests fail only when run together.** Two test files are changing the replica's lag at once. Check that `package.json` has `--test-concurrency=1` in the test script.

**GitHub says `Cannot find package 'pg'`.** The workflow did not install it. Add the `npm ci` line, and make sure `package-lock.json` is committed.

**Break it on purpose.** See a test fail before you trust it. In `part-3-position-tokens/router.js`, replace the condition `session.token === null || lsnAtLeast(applied, session.token)` with `true`, and run `npm test`. Two tests fail: the fake-pair test "a replica behind the token is skipped, and the primary answers", and the live test, with the message `comment 619 was missing (read from the replica)` (your number will differ). This is the bug returning, caught by your own test. Undo the change. Then, in `toolkit/lsn.js`, compare the two positions as text instead of as numbers, and watch the position test fail.
