```quiz
type: mcq
question: "A leader in North America East waits for confirmation from any one of two followers: one in the same region (0.25 ms round trip) and one in North America West (60 ms round trip). Its own disk write takes 0.3 ms. About how long does each write wait?"
options:
  - "About 60 ms, since it waits for the farther one"
  - "About 30 ms, the average of the two round trips"
  - "About 0.55 ms: the nearer one answers first"
  - "About 60.5 ms, since both round trips add up"
correct: 2
explanations:
  - "The rule needs any one confirmation, not both. The leader goes on as soon as the nearer follower answers, so the far one does not slow the write."
  - "Nothing averages the two. The write waits for the first confirmation to arrive, not for a mix of both."
  - "Right. The disk write of 0.3 ms plus the 0.25 ms round trip to the near follower is about 0.55 ms. The far follower still gets the copy, but the leader does not wait for it."
  - "The round trips happen at the same time, not one after the other, and the rule needs only one of them."
```

```quiz
type: mcq
question: "Samir's session token is 500. Replica A has applied up to position 498, replica B up to 505, and the leader is at 510. The router follows the rule from chapter 8.4 and raises the token after each read. Where does his read go, and what is his token afterwards?"
options:
  - "Replica B, and the token becomes 505"
  - "Replica A, and the token becomes 498"
  - "The leader, and the token becomes 510"
  - "Replica B, and the token stays at 500"
correct: 0
explanations:
  - "Right. Replica B is at 505, past his token 500, so it has everything he wrote. Reading from it moves his token to 505, so no later read can land on an older replica."
  - "Replica A is at 498, below his token 500. It is missing a write he made, and the token cannot go down."
  - "The leader would be correct but is not needed. A replica is caught up, and the leader should keep its time for the reads that need it."
  - "Replica B is the right place, but the token must rise to 505. If it stays at 500, a later read could go to replica A and show him an older state."
```

```quiz
type: mcq
question: "A database with three followers and asynchronous replication loses its leader's machine. Which follower should be promoted to lose the fewest acknowledged writes?"
options:
  - "The one nearest to most users"
  - "The one with the most free disk space"
  - "The one that answered its last heartbeat first"
  - "The one with the highest applied position"
correct: 3
explanations:
  - "Distance to users matters for speed afterwards. It says nothing about which follower has the most of the old leader's writes."
  - "Free space is useful later, but it does not tell you how much of the log a follower has applied."
  - "Heartbeat speed shows the network, not the data. A fast follower can still be far behind in the log."
  - "Right. The follower that has applied the most of the log is missing the fewest writes. Even it may be behind the old leader, so some acknowledged writes can still be lost."
```

```quiz
type: mcq
question: "Two regions edit shared invoices, each with its own leader. The business rule is that no edit may ever be silently lost. Which strategy fits best?"
options:
  - "Last writer wins on the whole invoice"
  - "Give each invoice one home region"
  - "Let each region keep its own copy for good"
  - "Retry the lost edit automatically later"
correct: 1
explanations:
  - "Last writer wins keeps one of two concurrent edits and drops the other without a message. That is the silent loss the rule forbids."
  - "Right. If every write to an invoice goes to the same region, two leaders never edit it at once. A merge rule built for invoices would also work, but would need to be designed first (module 13)."
  - "Copies that never agree mean different regions show different invoices. That is a broken replica, not a strategy."
  - "The system does not know an edit was lost, because last writer wins reports nothing. There is nothing to retry."
```

```quiz
type: mcq
question: "A key lives on 3 nodes, with W = 2 and R = 2 as in Dynamo's common setting. One node is down. What happens?"
options:
  - "Writes work, but reads fail since a read needs all nodes"
  - "Both work, but a read may miss the newest write"
  - "Both work, and a read still overlaps the write"
  - "Both fail until the node comes back"
correct: 2
explanations:
  - "A read needs only R = 2 answers, and two nodes are still up. Reads do not need every node."
  - "With R + W = 4, more than 3, every read group shares a node with every write group. This holds with one node down, since both still reach 2 nodes."
  - "Right. Two nodes are up, enough for W = 2 and R = 2. The sum 4 is more than 3, so any 2 nodes read share at least one node with the 2 nodes written."
  - "Both need only two nodes, and two are still up. They would fail only if two nodes were down."
```
