## Same code, different result

<InteractiveCanvas slug="sysdesign-m18-laptop-vs-server" />

Hana's laptop has Node.js 24 and a local settings file. The server has an older Node.js and no settings file. The code is the same, but it needs those things, so it crashes there. Users see an error page. Nothing in the repository says what the code needs around it.

<GoDeeper title="Go deeper: what hides around your code">

Code never runs alone. It runs on a language version (here Node.js), it reads settings from the environment (a database address, a secret key), it loads libraries, and it sits on an operating system with its own files and tools. Hana's laptop and the server differ in each of these.

The differences are easy to miss because nobody wrote them down. Her laptop got its Node.js version two years ago. The settings file lives only on her disk and is not in the repository. A library was installed by hand one afternoon. Each of these works silently until the code moves to a machine that lacks it.

The team has a few choices. It can write a long setup document, but documents go out of date. It can use a script that sets up each machine, but machines drift apart over time. Or it can package the code together with everything it needs, once, and run that package everywhere. The rest of this module is about that third choice.

Daftar and Hana are a course story, not a real incident. The versions are examples.

</GoDeeper>

## Ship the whole kitchen

<InteractiveCanvas slug="sysdesign-m18-same-image" />

A recipe is not enough, because every kitchen is different. Pack the whole kitchen: the code, Node.js and its libraries, in one **image**. The laptop, the CI machine and the server all run that same image. If it works on one, it works on all three.

<GoDeeper title="Go deeper: where this module goes">

An image is built once, so it is the same on every machine. A container is that image running as a process. Chapter 18.2 shows what a container really is under Linux, and why it is not a small virtual machine. Chapter 18.3 builds images that are small, fast to rebuild and safe to stop.

One server is not enough for Daftar in exam week, as module 4 showed. Chapter 18.4 adds Kubernetes, which keeps several copies of the container running and replaces any that fail. Chapter 18.5 builds the pipeline that tests the code, builds the image and ships it without Hana copying anything by hand. Chapter 18.6 compares ways to release a new version so that a bad one hurts few users and is easy to undo. Chapter 18.7 names the cloud services that provide each building block.

In challenge 17 you ship a small service through all of this on your own laptop. You build an image, run a pipeline, deploy to a local Kubernetes cluster, and break things on purpose.

A note on honesty: packing everything into an image does not remove every difference. The image still needs a compatible kernel and CPU type, and settings and secrets still arrive from outside. It removes the differences that cause most surprises, which is why teams use it.

</GoDeeper>
