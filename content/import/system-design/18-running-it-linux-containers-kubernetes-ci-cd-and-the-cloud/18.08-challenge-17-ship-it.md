In this module you saw containers, pipelines and clusters in pictures. Now you will ship a real service through all of them, on your own laptop, and break it on purpose to see what each safeguard buys. The service is a small version of the Daftar API. It is about 100 lines of Node.js, with a health check, a readiness check, a graceful shutdown and a few routes that exist only to cause trouble: one holds memory, one burns CPU, one gets stuck.

By the end of this chapter, your `system-design-challenges` repository has `challenges/challenge-17-ship-it/` with four parts. Part 1 builds the image two ways and measures layers, size, shutdown and limits. Part 2 runs a pipeline of gates and shows why cheap checks go first. Part 3 deploys to a local Kubernetes cluster with kind, kills a pod, breaks a probe, and rolls out version 2 while requests keep coming. Part 4 is optional: it talks to S3 and SQS, running on your laptop in a container called moto, with no cloud account. Each part has a script, a `node:test` test, a `results.md` with your own numbers, a `chart.svg` and a README that teaches the idea from zero.

**What you need to download.** Docker must already work from chapter 1.5. Part 1 pulls two Node.js images: `node:24-alpine` is about 62.5 MB packed, and the full `node:24` is about 410 MB, which part 1 uses on purpose for the naive Dockerfile (sizes from the Docker Hub API on 24 October 2026, [S119]). Part 3 needs kind and kubectl. kind is a small program, and it pulls a node image of about 388 MB [S119]. Docker Desktop already includes kubectl. Part 4 pulls the moto image, about 104 MB [S127]. If your data is limited, do part 1 and part 2 first; they need only the two Node images. Plan for about 2.5 hours, plus download time. You will not need any account except the GitHub one you already have.

**A safety rule for part 3.** `kubectl` works on whichever cluster your computer is set to use. If you ever worked with a real cluster, a mistake could delete real things. Every script in this challenge refuses to run unless the context name starts with `kind-`, and you should check `kubectl config current-context` yourself before you type any `kubectl` command by hand.

You reuse `toolkit/` from the earlier challenges and add three small files: one to run commands and time them, one to draw bar charts as SVG, and one to run `kubectl` safely. Three design choices make the experiments honest.

**The service is real enough to fail like a real one.** It logs one JSON line per event, it has a liveness route and a readiness route, and it handles SIGTERM. Its extra routes are the way you cause each failure: `/alloc` holds memory, `/burn` spends CPU time, `/slow` keeps a request in flight, `/break` makes `/health` fail.

**Every measurement has a baseline.** Each script compares a careless setup with a careful one, so a number never stands alone: 10.8 seconds means little until you see 2.5 seconds next to it.

**Time is not hidden.** Builds, stops and rollouts are timed with the same `run()` helper. Your numbers will differ from the ones printed here, because your laptop, your network and your Docker are different. The ranking and the shape are what to look for.

## Step 1: the toolkit

Three small helpers. First `toolkit/docker.js`. Its `run()` waits for a command to finish and reports how long it took. `runAsync()` does the same without blocking, which matters in part 3, where a load generator must keep sending while `kubectl` waits.

```js
// toolkit/docker.js: run docker and kubectl commands from a script, and time them.
import { spawn, spawnSync } from "node:child_process";

// Run a command to the end. Returns what it printed, its exit code and how long it took.
export function run(command, args = [], options = {}) {
  const start = performance.now();
  const result = spawnSync(command, args, { encoding: "utf8", maxBuffer: 64 * 1024 * 1024, ...options });
  return {
    ok: result.status === 0,
    code: result.status,
    stdout: (result.stdout ?? "").trim(),
    stderr: (result.stderr ?? "").trim(),
    ms: performance.now() - start,
  };
}

// True when the docker command exists and the engine answers within 15 seconds.
export function dockerAvailable() {
  return run("docker", ["info", "--format", "{{.ServerVersion}}"], { timeout: 15000 }).ok;
}

// Pause without blocking the timers of other work.
export const sleep = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

// Wait until check() returns something truthy, or give up after timeoutMs.
export async function waitFor(check, timeoutMs = 30000, everyMs = 250) {
  const end = performance.now() + timeoutMs;
  while (performance.now() < end) {
    const value = await check();
    if (value) return value;
    await sleep(everyMs);
  }
  throw new Error(`timed out after ${timeoutMs} ms`);
}

// Like run(), but does not block. Use it while something else, such as a load
// generator, must keep running in the same script.
export function runAsync(command, args = [], options = {}) {
  return new Promise((resolve) => {
    const start = performance.now();
    let stdout = "";
    let stderr = "";
    const child = spawn(command, args, options);
    child.stdout.on("data", (d) => (stdout += d));
    child.stderr.on("data", (d) => (stderr += d));
    child.on("error", (error) => resolve({ ok: false, code: null, stdout, stderr: String(error), ms: performance.now() - start }));
    child.on("close", (code) => resolve({ ok: code === 0, code, stdout: stdout.trim(), stderr: stderr.trim(), ms: performance.now() - start }));
  });
}
```

```js
// toolkit/bars.js: draw grouped bars as SVG text, one group per label.
// groups: [{ label: "naive", values: { first: 40, code: 38 } }]; series: [{ key, name, color }]
export function barChart({ title, yLabel, groups, series }) {
  const W = 560, H = 340, L = 60, R = 24, T = 44, B = 64;
  const yMax = Math.max(1, ...groups.flatMap((g) => series.map((s) => g.values[s.key] ?? 0)));
  const Y = (y) => H - B - (y / yMax) * (H - T - B);
  const slot = (W - L - R) / groups.length;
  const barW = Math.min(46, (slot - 20) / series.length);
  const bars = groups.flatMap((g, gi) => {
    const x0 = L + gi * slot + (slot - barW * series.length) / 2;
    return series.map((s, si) => {
      const v = g.values[s.key] ?? 0;
      const x = x0 + si * barW;
      return `<rect x="${x.toFixed(1)}" y="${Y(v).toFixed(1)}" width="${(barW - 4).toFixed(1)}" height="${(H - B - Y(v)).toFixed(1)}" fill="${s.color}"/>\n` +
        `<text x="${(x + barW / 2 - 2).toFixed(1)}" y="${(Y(v) - 6).toFixed(1)}" text-anchor="middle">${Number(v.toFixed(1))}</text>`;
    });
  });
  const labels = groups.map((g, gi) => `<text x="${(L + gi * slot + slot / 2).toFixed(1)}" y="${H - B + 18}" text-anchor="middle">${g.label}</text>`);
  const legend = series.map((s, i) => `<rect x="${L + i * 150}" y="${H - 22}" width="12" height="12" fill="${s.color}"/><text x="${L + i * 150 + 18}" y="${H - 12}">${s.name}</text>`);
  return `<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 ${W} ${H}" font-family="sans-serif" font-size="13">
<rect width="${W}" height="${H}" fill="white"/>
<text x="${L}" y="26" font-size="15" font-weight="bold">${title}</text>
<line x1="${L}" y1="${H - B}" x2="${W - R}" y2="${H - B}" stroke="#999"/>
<line x1="${L}" y1="${T}" x2="${L}" y2="${H - B}" stroke="#999"/>
<text x="${L - 8}" y="${T + 4}" text-anchor="end">${Math.round(yMax)}</text>
<text x="${L - 8}" y="${H - B}" text-anchor="end">0</text>
<text x="16" y="${(T + H - B) / 2}" transform="rotate(-90 16 ${(T + H - B) / 2})" text-anchor="middle">${yLabel}</text>
${labels.join("\n")}
${bars.join("\n")}
${legend.join("\n")}
</svg>
`;
}
```

Last, `toolkit/kube.js`. Read `assertLocalContext`: it is the safety rule from the start of the chapter, in code.

```js
// toolkit/kube.js: run kubectl against your kind cluster, and only against it.
import { run, runAsync } from "./docker.js";

export const CONTEXT = process.env.KUBE_CONTEXT ?? "kind-ship";

// Refuse to touch any cluster that is not a kind cluster. A script that deletes pods
// must never run against a real cluster by accident.
export function assertLocalContext(context = CONTEXT) {
  if (!context.startsWith("kind-")) {
    throw new Error(`Refusing to use kubectl context "${context}". Use a kind cluster (its context starts with kind-).`);
  }
}

export function kubectl(args, options = {}) {
  assertLocalContext();
  return run("kubectl", ["--context", CONTEXT, ...args], options);
}

// The same, but it does not block, so a load generator keeps sending while kubectl waits.
export function kubectlAsync(args, options = {}) {
  assertLocalContext();
  return runAsync("kubectl", ["--context", CONTEXT, ...args], options);
}

// The pods of the app as simple objects, from kubectl's JSON output.
export function parsePods(json) {
  return JSON.parse(json).items.map((pod) => ({
    name: pod.metadata.name,
    phase: pod.status.phase,
    deleting: Boolean(pod.metadata.deletionTimestamp),
    ready: (pod.status.conditions ?? []).some((c) => c.type === "Ready" && c.status === "True"),
    restarts: (pod.status.containerStatuses ?? []).reduce((sum, c) => sum + c.restartCount, 0),
    image: pod.spec.containers[0].image,
  }));
}

export function pods() {
  const r = kubectl(["get", "pods", "-l", "app=daftar-api", "-o", "json"]);
  if (!r.ok) throw new Error(r.stderr);
  return parsePods(r.stdout);
}

// The same list, without blocking the script while kubectl runs.
export async function podsAsync() {
  const r = await kubectlAsync(["get", "pods", "-l", "app=daftar-api", "-o", "json"]);
  if (!r.ok) throw new Error(r.stderr);
  return parsePods(r.stdout);
}
```

Now `app/server.js`. Read it before you run it. The comments explain each route, and the last block is the graceful shutdown from chapter 18.2. Three settings change how it behaves: `GRACEFUL` chooses between a clean drain (`1`), no handler at all (`0`), and quitting at once (`exit`); `WARMUP_MS` is the time before it is ready; `WORK_MS` is how long a request takes.

```js
// The Daftar API used in challenge 17: a small HTTP service that is easy to ship.
// It has liveness and readiness endpoints, structured logs on stdout, and a
// graceful shutdown. Settings come from environment variables.
import http from "node:http";
import os from "node:os";
import pino from "pino";

const PORT = Number(process.env.PORT ?? 3000);
const VERSION = process.env.APP_VERSION ?? "dev";
const WARMUP_MS = Number(process.env.WARMUP_MS ?? 0); // time before the service is ready
const FAIL_RATE = Number(process.env.FAIL_RATE ?? 0); // share of "/" requests that answer 500
const WORK_MS = Number(process.env.WORK_MS ?? 0); // how long a "/" request takes, to have requests in flight
// "1" drains and exits (default), "0" has no SIGTERM handler at all, "exit" quits the moment SIGTERM arrives
const GRACEFUL = process.env.GRACEFUL ?? "1";
const SHUTDOWN_DELAY_MS = Number(process.env.SHUTDOWN_DELAY_MS ?? 0); // wait before closing, so load balancers notice
const FORCE_EXIT_MS = Number(process.env.FORCE_EXIT_MS ?? 8000); // give up on slow requests after this long

const log = pino({ base: undefined }); // one JSON line per event, on stdout

let ready = false; // true once warm-up is over
let draining = false; // true once SIGTERM has arrived
let healthy = true; // set to false by /break to imitate a stuck process
let served = 0;
const held = []; // memory that /alloc keeps alive

const send = (res, status, body) => {
  // While draining, tell the client to close the connection after this answer.
  res.writeHead(status, { "content-type": "application/json", ...(draining ? { connection: "close" } : {}) });
  res.end(JSON.stringify(body) + "\n");
};

const server = http.createServer((req, res) => {
  const url = new URL(req.url, "http://localhost");
  if (url.pathname === "/health") {
    // Liveness: "is the process working at all?" It checks nothing outside this process.
    return healthy ? send(res, 200, { status: "alive" }) : send(res, 500, { status: "stuck" });
  }
  if (url.pathname === "/ready") {
    // Readiness: "should I get traffic right now?"
    const ok = ready && !draining;
    return send(res, ok ? 200 : 503, { ready: ok, draining });
  }
  if (url.pathname === "/slow") {
    // A request that takes a while, to have something in flight during a shutdown.
    const ms = Number(url.searchParams.get("ms") ?? 1000);
    return setTimeout(() => send(res, 200, { slept: ms, version: VERSION }), ms);
  }
  if (url.pathname === "/burn") {
    // CPU work, to see CPU limits and throttling. It counts CPU time, not clock time,
    // so a container that is throttled takes longer on the clock to finish.
    const wanted = Number(url.searchParams.get("ms") ?? 100) * 1000; // microseconds of CPU
    const before = process.cpuUsage();
    let used = 0;
    while (used < wanted) {
      for (let i = 0; i < 20000; i++) Math.sqrt(i);
      const now = process.cpuUsage(before);
      used = now.user + now.system;
    }
    return send(res, 200, { burned: true });
  }
  if (url.pathname === "/alloc") {
    // Hold memory, to see a memory limit kill the process.
    const mb = Number(url.searchParams.get("mb") ?? 10);
    held.push(Buffer.alloc(mb * 1024 * 1024, 1)); // filled, so the memory is really used
    return send(res, 200, { heldMb: held.length * mb });
  }
  if (url.pathname === "/break") {
    healthy = false;
    return send(res, 200, { healthy });
  }
  if (url.pathname === "/") {
    // Until warm-up is over, the process runs but cannot serve yet (cold caches, say).
    if (!ready) return send(res, 503, { error: "warming up", version: VERSION });
    served += 1;
    return setTimeout(() => {
      if (Math.random() < FAIL_RATE) return send(res, 500, { error: "boom", version: VERSION });
      send(res, 200, { app: "daftar-api", version: VERSION, host: os.hostname(), served });
    }, WORK_MS);
  }
  send(res, 404, { error: "not found" });
});

server.listen(PORT, "0.0.0.0", () => {
  log.info({ port: PORT, version: VERSION, warmupMs: WARMUP_MS, graceful: GRACEFUL }, "listening");
  setTimeout(() => {
    ready = true;
    log.info("ready");
  }, WARMUP_MS);
});

if (GRACEFUL === "exit") {
  // The shortcut many services take: stop at once and drop whatever is in flight.
  process.on("SIGTERM", () => process.exit(0));
}

if (GRACEFUL === "1") {
  const shutdown = (signal) => {
    if (draining) return;
    draining = true; // /ready now answers 503
    log.info({ signal, inFlightWaitMs: SHUTDOWN_DELAY_MS }, "draining");
    setTimeout(() => {
      // Stop accepting new connections. The callback runs when the last open request ends.
      server.close(() => {
        log.info("all requests finished, exiting");
        process.exit(0);
      });
      server.closeIdleConnections();
    }, SHUTDOWN_DELAY_MS);
    setTimeout(() => {
      log.error("requests did not finish in time, exiting anyway");
      process.exit(1);
    }, FORCE_EXIT_MS).unref();
  };
  process.on("SIGTERM", () => shutdown("SIGTERM"));
  process.on("SIGINT", () => shutdown("SIGINT"));
}
```

Its tests start `server.js` as a child process on a free port and call it. Create `app/server.test.js`. The two shutdown tests are skipped on Windows, because Node cannot send a real SIGTERM to another process there. They run in CI on Linux, and part 1 tests the same behaviour through Docker.

```js
// Tests for the service itself. They start server.js as a child process, so no Docker is needed.
import test from "node:test";
import assert from "node:assert/strict";
import { spawn } from "node:child_process";
import net from "node:net";
import { fileURLToPath } from "node:url";

// Node cannot send a real SIGTERM to a child process on Windows: it just ends the process.
// These tests run on Linux and macOS, and in CI. The Docker test in part 1 covers Windows.
const noSignals = process.platform === "win32" && "cannot send SIGTERM on Windows";

const serverFile = fileURLToPath(new URL("./server.js", import.meta.url));

// Ask the operating system for a free port.
function freePort() {
  return new Promise((resolve) => {
    const s = net.createServer().listen(0, () => {
      const { port } = s.address();
      s.close(() => resolve(port));
    });
  });
}

// Start the service and wait until it answers. By default also wait until it is ready.
async function startServer(env = {}, { untilReady = true } = {}) {
  const port = await freePort();
  const child = spawn(process.execPath, [serverFile], { env: { ...process.env, PORT: String(port), ...env }, stdio: "ignore" });
  const exited = new Promise((resolve) => child.once("exit", (code) => resolve(code)));
  const base = `http://127.0.0.1:${port}`;
  for (let i = 0; i < 100; i++) {
    const up = await fetch(`${base}${untilReady ? "/ready" : "/health"}`).then((r) => r.ok).catch(() => false);
    if (up) return { base, child, exited };
    await new Promise((resolve) => setTimeout(resolve, 50));
  }
  child.kill();
  throw new Error("server did not start");
}

test("/ answers with the app name and version", async () => {
  const s = await startServer({ APP_VERSION: "v7" });
  try {
    const body = await fetch(`${s.base}/`).then((r) => r.json());
    assert.equal(body.app, "daftar-api");
    assert.equal(body.version, "v7");
  } finally {
    s.child.kill();
  }
});

test("/health is alive at once, /ready and / wait for the warm-up", async () => {
  const s = await startServer({ WARMUP_MS: "600" }, { untilReady: false });
  try {
    assert.equal((await fetch(`${s.base}/health`)).status, 200);
    assert.equal((await fetch(`${s.base}/ready`)).status, 503);
    assert.equal((await fetch(`${s.base}/`)).status, 503);
    await new Promise((resolve) => setTimeout(resolve, 800));
    assert.equal((await fetch(`${s.base}/ready`)).status, 200);
    assert.equal((await fetch(`${s.base}/`)).status, 200);
  } finally {
    s.child.kill();
  }
});

test("a stuck process fails /health", async () => {
  const s = await startServer();
  try {
    await fetch(`${s.base}/break`);
    assert.equal((await fetch(`${s.base}/health`)).status, 500);
  } finally {
    s.child.kill();
  }
});

test("on SIGTERM it finishes the request in flight, then exits with code 0", { skip: noSignals }, async () => {
  const s = await startServer();
  const slow = fetch(`${s.base}/slow?ms=500`).then((r) => r.status);
  await new Promise((resolve) => setTimeout(resolve, 100));
  s.child.kill("SIGTERM");
  assert.equal(await slow, 200, "the request in flight was cut off");
  assert.equal(await s.exited, 0);
});

test("while draining, /ready says 503", { skip: noSignals }, async () => {
  const s = await startServer({ SHUTDOWN_DELAY_MS: "1000" });
  s.child.kill("SIGTERM");
  await new Promise((resolve) => setTimeout(resolve, 200));
  assert.equal((await fetch(`${s.base}/ready`)).status, 503);
  assert.equal(await s.exited, 0);
});
```

## Step 3: part 1, containers

Part 1 has four scripts and one test file. They answer four questions: what makes a Dockerfile good, how much does it save, what does stopping a container really do, and what do the limits do.

### The two Dockerfiles and .dockerignore

First the naive Dockerfile, the version most people write first. Create `app/Dockerfile.naive`:

```dockerfile
# The version most people write first. Every line here has a better version.
FROM node:24
WORKDIR /app
COPY . .
RUN npm install
CMD node server.js
```

Then the good one, `app/Dockerfile`. It is the one from chapter 18.3:

```dockerfile
# syntax=docker/dockerfile:1
# A small image for the Daftar API. Slow-changing layers come first.
FROM node:24-alpine
ENV NODE_ENV=production
WORKDIR /app

# 1. Dependencies change rarely, so they get their own layer.
COPY package.json package-lock.json ./
RUN npm ci --omit=dev

# 2. Your code changes on every commit, so it comes last.
COPY server.js ./

# 3. The version is baked into the image: build once, run the same image everywhere.
ARG APP_VERSION=dev
ENV APP_VERSION=$APP_VERSION

# 4. Do not run as root.
USER node
EXPOSE 3000
HEALTHCHECK --interval=10s --timeout=2s --start-period=5s --retries=3 \
  CMD node -e "fetch('http://127.0.0.1:3000/health').then(r=>process.exit(r.ok?0:1)).catch(()=>process.exit(1))"

# Exec form: node itself is process 1 and receives SIGTERM.
```

### A linter for Dockerfiles

`part-1-containers/lint.js` reads a Dockerfile and lists the habits from chapter 18.3 that it breaks. The pipeline in part 2 runs it as its first stage.

```js
// Part 1, script 4: read a Dockerfile and list the habits from chapter 18.3 it breaks.
// Run: node lint.js ../app/Dockerfile
import { readFileSync } from "node:fs";
import { fileURLToPath } from "node:url";

export function lintDockerfile(text) {
  const lines = text.split("\n").map((l) => l.trim()).filter((l) => l && !l.startsWith("#"));
  const find = (pattern) => lines.findIndex((l) => pattern.test(l));
  const problems = [];

  const from = lines.find((l) => /^FROM\s/i.test(l)) ?? "";
  if (/^FROM\s+node:[^\s]*$/i.test(from) && !/alpine|slim/.test(from)) {
    problems.push("The base image is the full Debian image (about 400 MB packed). Try node:24-alpine.");
  }
  if (find(/^COPY\s+\.\s+\./i) !== -1) {
    problems.push("COPY . . copies your code before the install, so every code change reinstalls everything.");
  }
  const install = find(/^RUN\s+npm\s+(ci|install)/i);
  const copyPackage = find(/^COPY\s+package/i);
  if (install !== -1 && (copyPackage === -1 || copyPackage > install)) {
    problems.push("Copy package.json (and the lock file) in their own step before the install step.");
  }
  if (find(/^RUN\s+npm\s+install/i) !== -1) {
    problems.push("Use npm ci: it installs exactly what package-lock.json says.");
  }
  if (!lines.some((l) => /^USER\s+(?!root\b)\S+/i.test(l))) {
    problems.push("The container runs as root. Add USER node.");
  }
  if (find(/^HEALTHCHECK\s/i) === -1) {
    problems.push("There is no HEALTHCHECK.");
  }
  const cmd = lines.findLast((l) => /^CMD\s/i.test(l));
  if (!cmd) problems.push("There is no CMD.");
  else if (!/^CMD\s+\[/i.test(cmd)) {
    problems.push('CMD is in shell form. Use the exec form, CMD ["node", "server.js"], so node receives signals.');
  }
  return problems;
}

if (process.argv[1] === fileURLToPath(import.meta.url)) {
  const file = process.argv[2];
  if (!file) {
    console.error("Usage: node lint.js path/to/Dockerfile");
    process.exit(1);
  }
  const problems = lintDockerfile(readFileSync(file, "utf8"));
  if (problems.length === 0) console.log(`${file}: no problems found`);
  for (const p of problems) console.log(`- ${p}`);
  process.exitCode = problems.length === 0 ? 0 : 1;
}
```

### Layers: change one file, rebuild

`layers.js` builds both Dockerfiles from a temporary copy of `app/`, so your files stay untouched. For each it measures a first build with no cache, a rebuild after editing `server.js`, and a rebuild after editing `package.json`. It counts the steps Docker took from its cache by reading the plain-text build log.

```js
// Part 1, script 1: build the naive and the good Dockerfile, change one file,
// and see how much each one rebuilds. Needs Docker. Run: node layers.js
import { appendFileSync, cpSync, mkdtempSync, readFileSync, rmSync, writeFileSync } from "node:fs";
import { tmpdir } from "node:os";
import path from "node:path";
import { fileURLToPath } from "node:url";
import { barChart } from "../../../toolkit/bars.js";
import { dockerAvailable, run } from "../../../toolkit/docker.js";

// Read the plain-text build log (docker build --progress=plain) and count
// the steps, and how many of them Docker took from its cache.
export function layerStats(log) {
  const steps = new Set();
  const cached = new Set();
  for (const line of log.split("\n")) {
    const header = line.match(/^#(\d+) \[(?:[^\]]*\s)?\d+\/\d+\]/);
    if (header) steps.add(header[1]);
    const hit = line.match(/^#(\d+) CACHED/);
    if (hit) cached.add(hit[1]);
  }
  const reused = [...steps].filter((id) => cached.has(id)).length;
  return { total: steps.size, reused };
}

function build(dir, dockerfile, tag, extra = []) {
  const r = run("docker", ["build", "--progress=plain", "-f", dockerfile, "-t", tag, ...extra, "."], { cwd: dir });
  if (!r.ok) throw new Error(`docker build failed:\n${r.stderr.slice(-1500)}`);
  return { seconds: r.ms / 1000, ...layerStats(r.stderr + "\n" + r.stdout) };
}

function measure(dockerfile, label) {
  const appDir = fileURLToPath(new URL("../app/", import.meta.url));
  const dir = mkdtempSync(path.join(tmpdir(), "layers-")); // a copy, so your own files stay untouched
  cpSync(appDir, dir, { recursive: true, filter: (src) => !src.includes("node_modules") });
  const tag = `daftar-api:layers-${label}`;
  try {
    const first = build(dir, dockerfile, tag, ["--no-cache"]);
    const size = Number(run("docker", ["image", "inspect", tag, "--format", "{{.Size}}"]).stdout) / 1e6;

    appendFileSync(path.join(dir, "server.js"), `\n// edit ${Date.now()}\n`);
    const codeEdit = build(dir, dockerfile, tag);

    const pkg = JSON.parse(readFileSync(path.join(dir, "package.json"), "utf8"));
    pkg.version = `1.0.${Date.now() % 100000}`; // a new value every run, so Docker cannot reuse an older build
    writeFileSync(path.join(dir, "package.json"), JSON.stringify(pkg, null, 2));
    const depEdit = build(dir, dockerfile, tag);
    return { label, size, first, codeEdit, depEdit };
  } finally {
    rmSync(dir, { recursive: true, force: true });
  }
}
```

### Shutdown: what docker stop really does

`shutdown.js` starts three versions of the service, sends a 2-second request, and stops the container with `docker stop -t 10` half a second later. It records how long the stop took, the exit code, and what happened to the request.

```js
// Part 1, script 2: send "docker stop" to three versions of the service while a
// request is in flight, and see which one shuts down properly. Needs Docker.
// Run: node shutdown.js   (build the image first: docker build -t daftar-api:good app)
import { writeFileSync } from "node:fs";
import { fileURLToPath } from "node:url";
import { barChart } from "../../../toolkit/bars.js";
import { dockerAvailable, run, sleep, waitFor } from "../../../toolkit/docker.js";

export const VARIANTS = [
  { label: "no handler", env: ["GRACEFUL=0"], flags: [] },
  { label: "no handler + init", env: ["GRACEFUL=0"], flags: ["--init"] },
  { label: "SIGTERM handler", env: ["GRACEFUL=1"], flags: [] },
];

// docker prints the exit code of a stopped container. 137 means 128 + 9: killed by SIGKILL.
// 143 means 128 + 15: ended by SIGTERM. 0 means the program chose to exit cleanly.
export function explainExit(code) {
  if (code === 0) return "clean exit";
  if (code === 137) return "killed (SIGKILL)";
  if (code === 143) return "ended by SIGTERM";
  return `exit code ${code}`;
}

async function trial(variant, image) {
  const name = `shutdown-${variant.label.replaceAll(" ", "-").replaceAll("+", "p")}`;
  run("docker", ["rm", "-f", name]);
  const envArgs = variant.env.flatMap((e) => ["-e", e]);
  const started = run("docker", ["run", "-d", "--name", name, ...variant.flags, ...envArgs, "-p", "127.0.0.1::3000", image]);
  if (!started.ok) throw new Error(started.stderr);
  const port = run("docker", ["port", name, "3000/tcp"]).stdout.split(":").pop();
  const base = `http://127.0.0.1:${port}`;
  await waitFor(async () => fetch(`${base}/ready`).then((r) => r.ok).catch(() => false), 20000);

  // A request that needs 2 seconds, sent just before the stop.
  const inFlight = fetch(`${base}/slow?ms=2000`).then((r) => `finished with ${r.status}`).catch((e) => `cut off (${e.cause?.code ?? e.message})`);
  await sleep(500);
  const stop = run("docker", ["stop", "-t", "10", name]); // SIGTERM, then SIGKILL after 10 seconds
  const exit = Number(run("docker", ["inspect", "-f", "{{.State.ExitCode}}", name]).stdout);
  const result = await inFlight;
  run("docker", ["rm", "-f", name]);
  return { label: variant.label, stopSeconds: stop.ms / 1000, exit, result };
}

if (process.argv[1] === fileURLToPath(import.meta.url)) {
  if (!dockerAvailable()) {
    console.error("Docker is not running. Start Docker Desktop and try again.");
    process.exit(1);
  }
  const rows = [];
  for (const v of VARIANTS) rows.push(await trial(v, process.env.IMAGE ?? "daftar-api:good"));
  console.log("variant             docker stop  exit               the request in flight");
  for (const r of rows) console.log(`${r.label.padEnd(18)}  ${r.stopSeconds.toFixed(1).padStart(8)} s  ${explainExit(r.exit).padEnd(18)} ${r.result}`);
  writeFileSync(new URL("./shutdown-chart.svg", import.meta.url), barChart({
    title: "Seconds docker stop takes",
    yLabel: "seconds",
    groups: rows.map((r) => ({ label: r.label, values: { stop: r.stopSeconds } })),
    series: [{ key: "stop", name: "docker stop", color: "#2563eb" }],
  }));
  console.log("\nwrote shutdown-chart.svg");
}
```

The first row is the surprise from chapter 18.2. With no handler and node as process 1, SIGTERM is ignored, and Docker waits the whole 10 seconds before killing it (exit 137). ### Limits: memory kills, CPU slows

`limits.js` runs the service twice. First under a 100 MB memory limit, asking it to hold 20 MB more again and again. Then with and without `--cpus=0.5`, timing a request that needs 200 ms of CPU.

```js
// Part 1, script 3: give a container a memory limit and a CPU limit, and see
// the two different ways a limit hurts. Needs Docker.
// Run: node limits.js   (build the image first: docker build -t daftar-api:good app)
import { fileURLToPath } from "node:url";
import { dockerAvailable, run, waitFor } from "../../../toolkit/docker.js";

export const median = (values) => {
  const sorted = [...values].sort((a, b) => a - b);
  return sorted[Math.floor((sorted.length - 1) / 2)];
};

async function start(name, dockerArgs, image) {
  run("docker", ["rm", "-f", name]);
  const r = run("docker", ["run", "-d", "--name", name, ...dockerArgs, "-p", "127.0.0.1::3000", image]);
  if (!r.ok) throw new Error(r.stderr);
  const port = run("docker", ["port", name, "3000/tcp"]).stdout.split(":").pop();
  const base = `http://127.0.0.1:${port}`;
  await waitFor(async () => fetch(`${base}/ready`, { signal: AbortSignal.timeout(1000) }).then((x) => x.ok).catch(() => false), 20000);
  return base;
}

// Memory: ask the service to hold 20 MB more, again and again, under a 100 MB limit.
async function memoryTrial(image) {
  const base = await start("limit-memory", ["--memory=100m", "--memory-swap=100m"], image);
  let held = 0;
  for (let i = 0; i < 20; i++) {
    const answer = await fetch(`${base}/alloc?mb=20`, { signal: AbortSignal.timeout(3000) }).then((r) => r.json()).catch(() => null);
    if (!answer) break; // the process is gone
    held = answer.heldMb;
  }
  await new Promise((resolve) => setTimeout(resolve, 500));
  const state = run("docker", ["inspect", "-f", "{{.State.Status}} exit={{.State.ExitCode}} oomKilled={{.State.OOMKilled}}", "limit-memory"]).stdout;
  run("docker", ["rm", "-f", "limit-memory"]);
  return { held, state };
}

// CPU: a request that needs 200 ms of CPU, with a full CPU and with half a CPU.
async function cpuTrial(image, cpus) {
  const base = await start(`limit-cpu-${cpus || "none"}`, cpus ? [`--cpus=${cpus}`] : [], image);
  const times = [];
  for (let i = 0; i < 7; i++) {
    const t0 = performance.now();
    await fetch(`${base}/burn?ms=200`).then((r) => r.text());
    times.push(performance.now() - t0);
  }
  run("docker", ["rm", "-f", `limit-cpu-${cpus || "none"}`]);
  return median(times);
}

if (process.argv[1] === fileURLToPath(import.meta.url)) {
  if (!dockerAvailable()) {
    console.error("Docker is not running. Start Docker Desktop and try again.");
    process.exit(1);
  }
  const image = process.env.IMAGE ?? "daftar-api:good";
  const mem = await memoryTrial(image);
  console.log(`memory limit 100 MB: the service held ${mem.held} MB, then: ${mem.state}`);
  const free = await cpuTrial(image, 0);
  const half = await cpuTrial(image, 0.5);
  console.log(`cpu: a 200 ms request takes ${free.toFixed(0)} ms with no limit and ${half.toFixed(0)} ms with --cpus=0.5`);
  console.log(`slowdown: ${(half / free).toFixed(1)} times, and nothing was killed`);
}
```

### A smoke test

`part-2-pipeline/smoke.js` starts an image, waits for it to be ready, checks three routes and prints each problem it finds. `checkService` is separate so a test can feed it a broken server.

```js
// Part 2: a small pipeline you can run on your laptop. It runs the same stages as
// .github/workflows/ship.yml, in order, and stops at the first red stage.
//   node pipeline.js                                  fast checks first
//   node pipeline.js --order slow-first               the slow build first
//   node pipeline.js --dockerfile Dockerfile.naive    use the naive Dockerfile
//   node pipeline.js --cold                           build with no cache, like a fresh CI machine
//   node pipeline.js --compare --cold --dockerfile Dockerfile.naive   both orders side by side, and chart.svg
import { writeFileSync } from "node:fs";
import path from "node:path";
import { fileURLToPath } from "node:url";
import { barChart } from "../../../toolkit/bars.js";
import { run } from "../../../toolkit/docker.js";

const here = path.dirname(fileURLToPath(import.meta.url));
const app = path.join(here, "..", "app");
const MAX_IMAGE_MB = 300; // the size gate: an image bigger than this does not ship

export function makeStages({ dockerfile = "Dockerfile", tag = "daftar-api:pipeline", cold = false } = {}) {
  return {
    lint: { name: "lint the Dockerfile", cmd: "node", args: [path.join(here, "..", "part-1-containers", "lint.js"), path.join(app, dockerfile)] },
    unit: { name: "service tests", cmd: process.execPath, args: ["--test", path.join(app, "server.test.js")] },
    build: { name: "build the image", cmd: "docker", args: ["build", ...(cold ? ["--no-cache"] : []), "-f", path.join(app, dockerfile), "-t", tag, app] },
    smoke: { name: "smoke test the image", cmd: "node", args: [path.join(here, "smoke.js"), tag] },
    size: { name: "size gate", check: () => imageGate(tag) },
  };
}

function imageGate(tag) {
  const bytes = Number(run("docker", ["image", "inspect", tag, "--format", "{{.Size}}"]).stdout);
  const mb = bytes / 1e6;
  return mb <= MAX_IMAGE_MB ? { ok: true, note: `${mb.toFixed(0)} MB` } : { ok: false, note: `${mb.toFixed(0)} MB is over the ${MAX_IMAGE_MB} MB limit` };
}

export const ORDERS = {
  "fast-first": ["lint", "unit", "build", "smoke", "size"],
  "slow-first": ["build", "smoke", "unit", "lint", "size"],
};

// Run the stages in order. Stop at the first one that fails; the rest are skipped.
// `runStage` is a parameter so a test can run the pipeline without running anything real.
export function runPipeline(stageKeys, stages, runStage) {
  const results = [];
  let failed = false;
  for (const key of stageKeys) {
    const stage = stages[key];
    if (failed) {
      results.push({ key, name: stage.name, status: "skipped", seconds: 0 });
      continue;
    }
    const start = performance.now();
    const outcome = runStage(stage);
    const seconds = (performance.now() - start) / 1000;
    results.push({ key, name: stage.name, status: outcome.ok ? "passed" : "FAILED", seconds, note: outcome.note });
    if (!outcome.ok) failed = true;
  }
  return results;
}

const realStage = (stage) => {
  if (stage.check) return stage.check();
  const r = run(stage.cmd, stage.args);
  return { ok: r.ok, note: r.ok ? "" : (r.stdout + "\n" + r.stderr).trim().split("\n").slice(-3).join(" | ") };
};

// Seconds until the first red stage, or the whole run if everything passed.
export function timeToFeedback(results) {
  return results.filter((r) => r.status !== "skipped").reduce((sum, r) => sum + r.seconds, 0);
}

function show(orderName, results) {
  console.log(`order: ${orderName}`);
  for (const r of results) console.log(`${r.status.padEnd(8)} ${r.name.padEnd(24)} ${r.seconds.toFixed(1).padStart(6)} s  ${r.note ?? ""}`);
  console.log(`time until you know: ${timeToFeedback(results).toFixed(1)} s`);
}

if (process.argv[1] === fileURLToPath(import.meta.url)) {
  const arg = (name, fallback) => (process.argv.includes(name) ? process.argv[process.argv.indexOf(name) + 1] : fallback);
  const stages = makeStages({ dockerfile: arg("--dockerfile", "Dockerfile"), cold: process.argv.includes("--cold") });
  const orders = process.argv.includes("--compare") ? Object.keys(ORDERS) : [arg("--order", "fast-first")];
  const times = [];
  let anyFailed = false;
  for (const orderName of orders) {
    const results = runPipeline(ORDERS[orderName], stages, realStage);
    show(orderName, results);
    times.push({ label: orderName, values: { t: timeToFeedback(results) } });
    anyFailed ||= results.some((r) => r.status === "FAILED");
  }
  if (process.argv.includes("--compare")) {
    writeFileSync(new URL("./chart.svg", import.meta.url), barChart({
      title: "Seconds until the pipeline tells you",
      yLabel: "seconds",
      groups: times,
      series: [{ key: "t", name: "time until the first red stage", color: "#2563eb" }],
    }));
    console.log("\nwrote chart.svg");
  }
  process.exitCode = anyFailed ? 1 : 0;
}
```

### The tests for part 2

`pipeline.test.js` runs the pipeline with a fake `runStage` function, so it needs no Docker. It checks that a red stage skips the rest, that failing early is cheaper, and that `checkService` names what is wrong with a broken server.

```js
import test from "node:test";
import assert from "node:assert/strict";
import { ORDERS, makeStages, runPipeline, timeToFeedback } from "./pipeline.js";
import { checkService } from "./smoke.js";
import http from "node:http";

const stages = makeStages();
const passAll = () => ({ ok: true });

test("a pipeline that passes runs every stage in order", () => {
  const seen = [];
  const results = runPipeline(ORDERS["fast-first"], stages, (s) => (seen.push(s.name), { ok: true }));
  assert.deepEqual(seen, ["lint the Dockerfile", "service tests", "build the image", "smoke test the image", "size gate"]);
  assert.ok(results.every((r) => r.status === "passed"));
});

test("a red stage stops the pipeline and the later stages are skipped", () => {
  const results = runPipeline(ORDERS["fast-first"], stages, (s) => ({ ok: s.name !== "service tests" }));
  assert.deepEqual(results.map((r) => r.status), ["passed", "FAILED", "skipped", "skipped", "skipped"]);
});

test("skipped stages cost no time, so failing early is cheap", () => {
  const slowBuild = (s) => {
    const until = performance.now() + (s.name === "build the image" ? 60 : 1);
    while (performance.now() < until) { /* wait */ }
    return { ok: s.name !== "lint the Dockerfile" };
  };
  const fast = timeToFeedback(runPipeline(ORDERS["fast-first"], stages, slowBuild));
  const slow = timeToFeedback(runPipeline(ORDERS["slow-first"], stages, slowBuild));
  assert.ok(slow > fast + 0.05, `slow-first ${slow.toFixed(3)} s should take clearly longer than fast-first ${fast.toFixed(3)} s`);
});

test("both orders run the same stages", () => {
  assert.deepEqual([...ORDERS["fast-first"]].sort(), [...ORDERS["slow-first"]].sort());
  for (const key of ORDERS["fast-first"]) assert.ok(stages[key], `missing stage ${key}`);
});

test("the smoke check names what is wrong with a service", async () => {
  const broken = http.createServer((req, res) => {
    res.writeHead(req.url === "/ready" ? 503 : 200, { "content-type": "application/json" });
    res.end(JSON.stringify({ app: "other" }));
  });
  await new Promise((resolve) => broken.listen(0, "127.0.0.1", resolve));
  const problems = await checkService(`http://127.0.0.1:${broken.address().port}`);
  broken.close();
  assert.equal(problems.length, 2);
  assert.match(problems[0], /\/ready answered 503/);
  assert.match(problems[1], /did not answer as daftar-api/);
});
```

### Roll out version 2 under load

`rollout.js` does the experiment for each manifest: delete the old Deployment, apply the new one, start 20 requests a second, change the image to `daftar-api:2`, wait for the rollout to finish, and count what the users saw. The load generator opens a new connection for every request and does not wait for answers, like many separate users.

```js
// Part 3, script 1: roll out version 2 while requests keep coming, once with the
// careless manifest and once with the careful one, and count the failed requests.
// Needs a kind cluster (see kind.yaml) with the images daftar-api:1 and daftar-api:2 loaded.
import { writeFileSync } from "node:fs";
import path from "node:path";
import { fileURLToPath } from "node:url";
import { barChart } from "../../../toolkit/bars.js";
import { sleep } from "../../../toolkit/docker.js";
import { kubectl, kubectlAsync } from "../../../toolkit/kube.js";

const here = path.dirname(fileURLToPath(import.meta.url));
const BASE = `http://127.0.0.1:${process.env.HOST_PORT ?? "8080"}/`;

// samples: [{ ok: true, version: "1" } or { ok: false }]
export function summarize(samples) {
  const failed = samples.filter((s) => !s.ok).length;
  const byVersion = {};
  for (const s of samples) if (s.ok) byVersion[s.version] = (byVersion[s.version] ?? 0) + 1;
  return { total: samples.length, failed, failedPercent: samples.length ? (failed / samples.length) * 100 : 0, byVersion };
}

// Send `rate` requests a second, whether or not earlier ones have answered (an open loop),
// each on its own connection, like many different users.
export function startLoad(url, rate) {
  const samples = [];
  const pending = new Set();
  const timer = setInterval(() => {
    const p = fetch(url, { headers: { connection: "close" }, signal: AbortSignal.timeout(1500) })
      .then(async (r) => (r.ok ? { ok: true, version: (await r.json()).version } : { ok: false }))
      .catch(() => ({ ok: false }))
      .then((s) => samples.push(s));
    pending.add(p);
    p.finally(() => pending.delete(p));
  }, 1000 / rate);
  return async () => {
    clearInterval(timer);
    await Promise.all(pending);
    return samples;
  };
}

function must(result, what) {
  if (!result.ok) throw new Error(`${what} failed:\n${result.stderr}`);
  return result;
}

async function trial(label, manifest) {
  kubectl(["delete", "deployment", "daftar-api", "--ignore-not-found", "--wait=true"]);
  must(kubectl(["apply", "-f", path.join(here, "k8s", "service.yaml"), "-f", path.join(here, "k8s", manifest)]), "apply");
  must(kubectl(["rollout", "status", "deployment/daftar-api", "--timeout=120s"]), "first rollout");
  await sleep(2000);

  const stop = startLoad(BASE, 20);
  await sleep(3000);
  must(await kubectlAsync(["set", "image", "deployment/daftar-api", "api=daftar-api:2"]), "set image");
  must(await kubectlAsync(["rollout", "status", "deployment/daftar-api", "--timeout=120s"]), "second rollout");
  await sleep(3000);
  const result = summarize(await stop());
  return { label, ...result };
}

if (process.argv[1] === fileURLToPath(import.meta.url)) {
  const rows = [await trial("careless", "deployment-careless.yaml"), await trial("careful", "deployment.yaml")];
  console.log("manifest   requests  failed  failed %  answered by version");
  for (const r of rows) {
    console.log(`${r.label.padEnd(9)}  ${String(r.total).padStart(8)}  ${String(r.failed).padStart(6)}  ${r.failedPercent.toFixed(1).padStart(7)}  ${JSON.stringify(r.byVersion)}`);
  }
  writeFileSync(new URL("./chart.svg", import.meta.url), barChart({
    title: "Failed requests during a rollout (20 per second)",
    yLabel: "failed requests",
    groups: rows.map((r) => ({ label: r.label, values: { failed: r.failed } })),
    series: [{ key: "failed", name: "failed requests", color: "#dc2626" }],
  }));
  console.log("\nwrote chart.svg");
}
```

```text
> HOST_PORT=8080 node challenges/challenge-17-ship-it/part-3-kubernetes/rollout.js
manifest   requests  failed  failed %  answered by version
careless        183     112     61.2  {"1":54,"2":17}
careful         392       0      0.0  {"1":263,"2":129}

wrote chart.svg
```

The careless rollout failed more than half of its requests, and it was over sooner. Two things went wrong at once. Its new pods were "ready" the moment the container started, so the Service sent them requests during the 3-second warm-up, and the service answers 503 until it is warm. And its old pods quit the instant they got SIGTERM, so requests already on their way to them failed. The careful rollout took longer and failed none. It answered from version 1 and version 2 side by side, as a rolling update does, with always three ready pods. Run it twice; the careless count changes from run to run, but the gap does not.

### Kill a pod, break a probe

`selfheal.js` deletes a pod while requests keep coming and times the replacement. Then it makes one pod's `/health` fail with the `/break` route, and times the liveness restart.

```js
// Part 3, script 2: break the cluster on purpose and watch it repair itself.
//   1. delete a pod while requests keep coming
//   2. make one pod's /health fail, so its liveness probe restarts it
// Needs the careful deployment from rollout.js (or: kubectl apply -f k8s/).
import path from "node:path";
import { fileURLToPath } from "node:url";
import { sleep, waitFor } from "../../../toolkit/docker.js";
import { kubectl, kubectlAsync, podsAsync } from "../../../toolkit/kube.js";
import { startLoad, summarize } from "./rollout.js";

const here = path.dirname(fileURLToPath(import.meta.url));
const BASE = `http://127.0.0.1:${process.env.HOST_PORT ?? "8080"}/`;
const readyCount = async () => (await podsAsync()).filter((p) => p.ready && !p.deleting).length;
const restartsOf = async (name) => (await podsAsync()).find((p) => p.name === name)?.restarts ?? 0;

export const elapsed = (start) => ((performance.now() - start) / 1000).toFixed(1);

if (process.argv[1] === fileURLToPath(import.meta.url)) {
  kubectl(["apply", "-f", path.join(here, "k8s", "service.yaml"), "-f", path.join(here, "k8s", "deployment.yaml")]);
  await kubectlAsync(["rollout", "status", "deployment/daftar-api", "--timeout=120s"]);
  await waitFor(async () => (await readyCount()) === 3, 60000);

  // 1. Delete one pod under load.
  const stop = startLoad(BASE, 20);
  await sleep(2000);
  const victim = (await podsAsync())[0].name;
  const t0 = performance.now();
  await kubectlAsync(["delete", "pod", victim, "--wait=false"]);
  console.log(`+0.0 s  deleted ${victim}`);
  await waitFor(async () => (await podsAsync()).filter((p) => !p.deleting).length === 3, 30000, 100);
  console.log(`+${elapsed(t0)} s  the Deployment started a replacement`);
  await waitFor(async () => (await readyCount()) === 3 && (await podsAsync()).length === 3, 60000, 200);
  console.log(`+${elapsed(t0)} s  3 pods ready again`);
  const result = summarize(await stop());
  console.log(`requests sent: ${result.total}, failed: ${result.failed}`);

  // 2. Make one pod stuck. Its liveness probe fails 3 times in a row (every 5 seconds), then the kubelet restarts it.
  const target = (await podsAsync())[0].name;
  const t1 = performance.now();
  await kubectlAsync(["exec", target, "--", "wget", "-qO-", "http://127.0.0.1:3000/break"]);
  console.log(`\n+0.0 s  ${target}: /health now fails (restarts: ${await restartsOf(target)})`);
  await waitFor(async () => (await restartsOf(target)) >= 1, 60000, 500);
```

Part 4 needs no cloud account. moto is an open-source program that answers the same HTTP calls as S3 and SQS. It is Apache-2.0 licensed and the image is about 104 MB [S127]. Skip this part if your data is limited; the gate does not depend on it.

Start moto and check that it answers:

```bash

```

We use plain `fetch` calls instead of the AWS software kit, so there is nothing to install. `aws.js` has a function for each call. S3 uses ordinary HTTP verbs on a bucket and an object name; SQS uses form-encoded "Action" requests and answers XML. One detail surprised us. Real AWS requests carry a signature that names the service, and moto does not check the signature but does read the service name, to know whether a call on its one address is for S3 or SQS. Without any credentials it also treats you as an anonymous visitor, who may not read objects. So every call sends a fake `authorization` header. Real AWS would reject it.

```js
// Part 4: talk to S3 and SQS with plain fetch. Point ENDPOINT at moto (the default).
// moto does not check signatures; real AWS does, so this file only works against an emulator.
export const ENDPOINT = process.env.AWS_ENDPOINT_URL ?? "http://127.0.0.1:5000";

// A real AWS request is signed, and the signature names the service ("s3" or "sqs"). moto does
// not check the signature, but it reads the service name to know which service a request on the
// shared address is for, and it treats a request with no credentials as an anonymous visitor
// who may not read objects. The key and signature below are fake.
const auth = (service) => ({ authorization: `AWS4-HMAC-SHA256 Credential=test/20260101/us-east-1/${service}/aws4_request, SignedHeaders=host, Signature=fake` });

// ---- S3: buckets hold objects, an object is a file plus its name (key) ----

export async function createBucket(bucket) {
  const res = await fetch(`${ENDPOINT}/${bucket}`, { method: "PUT", headers: auth("s3") });
  if (!res.ok && res.status !== 409) throw new Error(`create bucket: ${res.status} ${await res.text()}`);
}

export async function putObject(bucket, key, body) {
  const res = await fetch(`${ENDPOINT}/${bucket}/${key}`, { method: "PUT", headers: auth("s3"), body });
  if (!res.ok) throw new Error(`put object: ${res.status} ${await res.text()}`);
}

export async function getObject(bucket, key) {
  const res = await fetch(`${ENDPOINT}/${bucket}/${key}`, { headers: auth("s3") });
  if (!res.ok) throw new Error(`get object: ${res.status}`);
  return res.text();
}

// S3 answers a listing as XML. Pull the <Key> values out of it.
export function parseKeys(xml) {
  return [...xml.matchAll(/<Key>([^<]*)<\/Key>/g)].map((m) => m[1]);
}

export async function listKeys(bucket) {
  const res = await fetch(`${ENDPOINT}/${bucket}?list-type=2`, { headers: auth("s3") });
  if (!res.ok) throw new Error(`list: ${res.status}`);
  return parseKeys(await res.text());
}

// ---- SQS: a queue holds messages until a worker deletes them ----

// SQS takes form-encoded "Action" requests and answers XML.
async function sqs(params) {
  const res = await fetch(ENDPOINT, {
    method: "POST",
    headers: { "content-type": "application/x-www-form-urlencoded", ...auth("sqs") },
    body: new URLSearchParams({ Version: "2012-11-05", ...params }),
  });
  const text = await res.text();
  if (!res.ok) throw new Error(`sqs ${params.Action}: ${res.status} ${text}`);
  return text;
}

// The text inside <name>...</name>, or undefined.
export const tag = (xml, name) => xml.match(new RegExp(`<${name}>([^<]*)</${name}>`))?.[1];

export async function createQueue(name, visibilitySeconds = 30) {
  const xml = await sqs({ Action: "CreateQueue", QueueName: name, "Attribute.1.Name": "VisibilityTimeout", "Attribute.1.Value": String(visibilitySeconds) });
  return tag(xml, "QueueUrl");
}

export async function sendMessage(queueUrl, body) {
  await sqs({ Action: "SendMessage", QueueUrl: queueUrl, MessageBody: body });
}

// Returns { body, receipt }, or null when no message is visible.
export async function receiveMessage(queueUrl) {
  const xml = await sqs({ Action: "ReceiveMessage", QueueUrl: queueUrl, MaxNumberOfMessages: "1" });
  const receipt = tag(xml, "ReceiptHandle");
  if (!receipt) return null;
  return { body: tag(xml, "Body").replaceAll("&quot;", '"'), receipt };
}

export async function deleteMessage(queueUrl, receipt) {
  await sqs({ Action: "DeleteMessage", QueueUrl: queueUrl, ReceiptHandle: receipt });
}
```

`exports.js` plays a small story from Daftar. The API writes a student's notes export to a bucket and puts a job on a queue. A worker takes the job, reads the file, and deletes the job. Then it shows what a visibility timeout does: a worker that takes a message and crashes without deleting it sees the message come back after the timeout, so the job is done again. That is at-least-once delivery from chapter 15, with real numbers.

```js
// Part 4: Daftar exports a student's notes. The API writes the export file to S3,
// puts a job on SQS, and a worker picks the job up. Then a worker that crashes
// shows what the visibility timeout does. Needs moto running:
//   docker run -d --name moto -p 127.0.0.1:5000:5000 motoserver/moto:5.2.4
import { writeFileSync } from "node:fs";
import { fileURLToPath } from "node:url";
import { barChart } from "../../../toolkit/bars.js";
import { sleep } from "../../../toolkit/docker.js";
import { createBucket, createQueue, deleteMessage, getObject, listKeys, putObject, receiveMessage, sendMessage } from "./aws.js";

// How long until a message that nobody deleted shows up again?
// Receive it, do not delete it (the worker "crashed"), and poll.
export async function secondsUntilBack(queueName, visibilitySeconds) {
  const queue = await createQueue(queueName, visibilitySeconds);
  await sendMessage(queue, JSON.stringify({ export: "notes/crash.json" }));
  const first = await receiveMessage(queue);
  const taken = performance.now();
  if (!first) throw new Error("no message to receive");
  while (performance.now() - taken < (visibilitySeconds + 5) * 1000) {
    if (await receiveMessage(queue)) return (performance.now() - taken) / 1000;
    await sleep(100);
  }
  throw new Error("the message never came back");
}

if (process.argv[1] === fileURLToPath(import.meta.url)) {
  await createBucket("daftar-exports");
  await putObject("daftar-exports", "notes/1.json", JSON.stringify([{ title: "Revise Raft", text: "terms, votes, logs" }]));
  console.log("objects in daftar-exports:", await listKeys("daftar-exports"));

  const queue = await createQueue("export-jobs");
  await sendMessage(queue, JSON.stringify({ export: "notes/1.json" }));
  const job = await receiveMessage(queue);
  const { export: key } = JSON.parse(job.body);
  console.log(`worker got a job for ${key}; the file says: ${await getObject("daftar-exports", key)}`);
  await deleteMessage(queue, job.receipt);
  console.log("worker deleted the job; the next receive returns:", await receiveMessage(queue));

  console.log("\nvisibility timeout   message back after");
  const rows = [];
  for (const seconds of [1, 2, 4]) {
    const back = await secondsUntilBack(`crash-${seconds}`, seconds);
    rows.push({ label: `${seconds} s`, values: { back } });
    console.log(`${String(seconds).padStart(8)} s        ${back.toFixed(1).padStart(8)} s`);
  }
  writeFileSync(new URL("./chart.svg", import.meta.url), barChart({
    title: "When a crashed worker's message comes back",
    yLabel: "seconds",
    groups: rows,
    series: [{ key: "back", name: "seconds until visible again", color: "#2563eb" }],
  }));
  console.log("\nwrote chart.svg");
}
```

## When something goes wrong

**`docker build` fails with `npm ci` errors.** The lock file is missing or out of date. Run `npm install` in `app/` and commit `package-lock.json`. `npm ci` refuses to run if the lock file and `package.json` disagree.

**`layers.js` says every build is "1 of 4 reused" or shows 0 steps.** Docker printed its log in a different format. Check you have a recent Docker (BuildKit is the default). The script reads lines such as `#5 [3/5] RUN npm ci` and `#5 CACHED`. Run one build by hand with `--progress=plain` and compare.

**`docker stop` in `shutdown.js` takes the full 10 seconds for the third row too.** Your image is older than your `server.js`. Rebuild: `docker build -t daftar-api:good challenges/challenge-17-ship-it/app`. The scripts use the image named in the `IMAGE` environment variable, `daftar-api:good` by default.

**On Windows, the two shutdown tests in `server.test.js` are skipped.** That is expected. Node on Windows cannot send a real SIGTERM to another process. Part 1's Docker test covers the same behaviour.

**`Refusing to use kubectl context ...`.** Your `kubectl` is pointing at another cluster. Run `kubectl config get-contexts`. If `kind-ship` is not listed, the cluster does not exist: run `kind create cluster --name ship ...` again. Do not change the safety check to make the error go away.

**Pods show `ErrImagePull` or `ImagePullBackOff`.** The cluster cannot find the image. Run `kind load docker-image daftar-api:1 daftar-api:2 --name ship` again after every rebuild. The manifests use `imagePullPolicy: IfNotPresent` so the cluster uses the loaded image and does not look for it on the internet.

**`curl` to port 8080 is refused or hangs.** The port mapping in `kind.yaml` only applies when the cluster is created. If you changed it, delete and recreate the cluster. Also check that no other program uses port 8080.

**The rollout numbers look odd: the careful run fails a few requests.** Your laptop is busy. The load generator and the cluster compete for the same CPU. Close other programs, or lower the rate in `rollout.js` from 20 to 10 requests a second. The careless run should still fail far more.

**`moto` tests are skipped, or `fetch failed`.** moto is not running or uses another port. Run `docker ps` and look for `motoserver/moto`. If port 5000 is in use, start it on another port and set `AWS_ENDPOINT_URL=http://127.0.0.1:5001`.

**Break it on purpose.** In `app/Dockerfile`, change `COPY package.json package-lock.json ./` to `COPY . .` and run `node challenges/challenge-17-ship-it/part-1-containers/lint.js challenges/challenge-17-ship-it/app/Dockerfile`: the linter and the part 1 test fail. Undo it. In `k8s/deployment.yaml`, delete the `readinessProbe` block and the `kube.test.js` manifest test fails. Undo that too. In `server.js`, change `const ok = ready && !draining;` to `const ok = false;` and run `node challenges/challenge-17-ship-it/part-2-pipeline/pipeline.js`: the service tests fail first and the pipeline stops there. Undo it.
