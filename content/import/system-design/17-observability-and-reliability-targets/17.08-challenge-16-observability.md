## How the experiment works

Part 1 runs the whole app for real. The app is Souq Express, a made-up delivery service, with three services: `api` takes an order and calls `menu`, then `payments`. Each runs as its own process, so they behave like three servers. The card provider that payments calls is simulated: most charges take about 40 ms, 5 in 100 take over 400 ms, and 2 in 100 fail. The script is also the collector. It starts a small web server that receives every finished span, then it sends 20 orders a second for 15 seconds with the load generator from challenge 1.

Four design choices keep the experiment honest.

**The services are separate processes.** One process with three functions would hide the real problem, which is passing context between servers. With three processes, the trace id has to travel in an HTTP header, exactly as it does in production.

**Spans, logs and metrics are three separate paths.** The spans go to the collector over HTTP, the log lines go to a file per service, and the metrics stay inside each service until you scrape them. That mirrors how real tools work, and it lets you break one path and see that the others still work.

**A tracing problem must never break an order.** The code that reports a span ignores its own errors. If the collector is down, orders still go through, and you lose only the trace. That is the right trade for observability code, and it is also why a silent gap in your traces is something you have to look for.

**Part 2 uses a made-up day.** You cannot wait 24 hours for an incident, so part 2 generates a log of 431,000 requests with a seeded random number generator: the same seed gives the same day, so your numbers match the ones in this chapter. The log entries have exactly the shape of chapter 17.7: `{ ts, status, ms }`. The generator injects three incidents, and you will test two alerts against them.

## Step 1: tracing

First, `toolkit/tracing.js`. It does three jobs: it reads and writes the `traceparent` header from chapter 17.2, it starts and ends spans, and it groups a flat list of spans into traces. A span is a plain object, so it is easy to send as JSON.

```js
// toolkit/tracing.js: trace context and spans, with no packages.
// The header format is the W3C Trace Context "traceparent":
//   00-<32 hex trace id>-<16 hex parent span id>-<2 hex flags>
import { randomBytes } from "node:crypto";

const hex = (bytes) => randomBytes(bytes).toString("hex");
// Milliseconds since 1970 with sub-millisecond detail, so spans from different
// processes on one machine can be put on the same timeline.
const nowMs = () => performance.timeOrigin + performance.now();

export function parseTraceparent(header) {
  const m = /^00-([0-9a-f]{32})-([0-9a-f]{16})-([0-9a-f]{2})$/.exec(header ?? "");
  if (!m || /^0+$/.test(m[1]) || /^0+$/.test(m[2])) return null; // all zeros is invalid
  return { traceId: m[1], parentId: m[2], sampled: (parseInt(m[3], 16) & 1) === 1 };
}

export function formatTraceparent(traceId, spanId, sampled = true) {
  return `00-${traceId}-${spanId}-${sampled ? "01" : "00"}`;
}

// Start a span. With a good incoming header the span joins that trace and its
// parent is the span that sent the header. Without one it starts a new trace.
export function startSpan({ service, name, traceparent }) {
  const incoming = parseTraceparent(traceparent);
  const span = {
    traceId: incoming ? incoming.traceId : hex(16),
    spanId: hex(8),
    parentId: incoming ? incoming.parentId : null,
    service,
    name,
    startMs: nowMs(),
    endMs: null,
    status: "ok",
  };
  return {
    span,
    // The header to put on the next call, so the next span is this span's child.
    header: formatTraceparent(span.traceId, span.spanId),
    end(status = "ok") {
      span.endMs = nowMs();
      span.status = status;
      return span;
    },
  };
}

// Send a finished span to the collector. A tracing problem must never break
// the real request, so errors are ignored.
export function reportSpan(collectorUrl, span) {
  if (!collectorUrl) return;
  fetch(collectorUrl, {
    method: "POST",
    headers: { "content-type": "application/json" },
    body: JSON.stringify(span),
  }).catch(() => {});
}

// Group a flat list of spans into traces: Map of traceId -> spans sorted by start.
export function groupByTrace(spans) {
  const traces = new Map();
  for (const s of spans) {
    if (!traces.has(s.traceId)) traces.set(s.traceId, []);
    traces.get(s.traceId).push(s);
  }
  for (const list of traces.values()) list.sort((a, b) => a.startMs - b.startMs);
  return traces;
}
```

Look at `startSpan`. With a good incoming header, the new span joins that trace and its `parentId` is the span that made the call. Without one, it starts a new trace with a fresh 32 character id. The `header` it returns is what the caller puts on the next request, so that the next span becomes its child. That one line, `header: formatTraceparent(span.traceId, span.spanId)`, is how a trace crosses a server.

## Step 2: metrics

Next, `toolkit/metrics.js`. Each service gets a counter of requests by status code and a histogram of durations. The text format follows the Prometheus style: one line per series, with the name, the labels and a value. {/* source needed: Prometheus exposition format and cumulative histogram buckets (prometheus.io docs) */} The functions at the bottom read that text back into numbers, read a percentile from the buckets, and add two histograms together.

```js
// toolkit/metrics.js: a counter and a histogram per service, exported as text.
// The text follows the Prometheus exposition format: one line per series,
// "name{labels} value". Histogram buckets are cumulative ("le" = less than or equal).

export const BUCKETS_MS = [5, 10, 25, 50, 100, 250, 500, 1000];

export function createMetrics(service) {
  const byStatus = new Map(); // "200" -> count
  const perBucket = new Array(BUCKETS_MS.length + 1).fill(0); // last slot is +Inf
  let sumMs = 0;
  let count = 0;
  return {
    observe(status, ms) {
      byStatus.set(String(status), (byStatus.get(String(status)) ?? 0) + 1);
      let i = BUCKETS_MS.findIndex((upper) => ms <= upper);
      if (i === -1) i = BUCKETS_MS.length;
      perBucket[i]++;
      sumMs += ms;
      count++;
    },
    text() {
      const lines = ["# TYPE http_requests_total counter"];
      for (const [code, n] of byStatus) lines.push(`http_requests_total{service="${service}",code="${code}"} ${n}`);
      lines.push("# TYPE http_request_duration_ms histogram");
      let running = 0;
      BUCKETS_MS.forEach((upper, i) => {
        running += perBucket[i];
        lines.push(`http_request_duration_ms_bucket{service="${service}",le="${upper}"} ${running}`);
      });
      running += perBucket[BUCKETS_MS.length];
      lines.push(`http_request_duration_ms_bucket{service="${service}",le="+Inf"} ${running}`);
      lines.push(`http_request_duration_ms_sum{service="${service}"} ${sumMs.toFixed(1)}`);
      lines.push(`http_request_duration_ms_count{service="${service}"} ${count}`);
      return lines.join("\n") + "\n";
    },
  };
}

// Read the text back into numbers: { byCode: {"200": 281}, buckets: [[5, 40], ...], count, sumMs }
export function parseMetrics(text) {
  const out = { byCode: {}, buckets: [], count: 0, sumMs: 0 };
  for (const line of text.split("\n")) {
    let m;
    if ((m = /^http_requests_total\{.*code="(\d+)"\} (\d+)$/.exec(line))) out.byCode[m[1]] = Number(m[2]);
    else if ((m = /^http_request_duration_ms_bucket\{.*le="([^"]+)"\} (\d+)$/.exec(line))) {
      out.buckets.push([m[1] === "+Inf" ? Infinity : Number(m[1]), Number(m[2])]);
    } else if ((m = /^http_request_duration_ms_sum\{.*\} ([\d.]+)$/.exec(line))) out.sumMs = Number(m[1]);
    else if ((m = /^http_request_duration_ms_count\{.*\} (\d+)$/.exec(line))) out.count = Number(m[1]);
  }
  return out;
}

// A percentile read from cumulative buckets. It can only say "at most this
// many ms": the upper edge of the first bucket that holds the rank. Same
// nearest-rank idea as chapter 2.4, but the answer is a bucket edge, not a
// measured value. Returns Infinity when the rank falls past the last bucket.
export function quantileFromBuckets(buckets, count, p) {
  if (count === 0) return NaN;
  const rank = Math.max(1, Math.ceil((p * count) / 100));
  for (const [upper, cumulative] of buckets) if (cumulative >= rank) return upper;
  return Infinity;
}

// Histograms from two servers add bucket by bucket. Percentiles do not.
export function mergeBuckets(a, b) {
  return a.map(([upper, n], i) => [upper, n + b[i][1]]);
}
```

The bucket edges, `5, 10, 25, 50, 100, 250, 500, 1000`, are your resolution. A request that took 503 ms lands in the `1000` bucket, so a percentile read from buckets can only say "at most 1,000 ms". You will see this gap in the results.

## Step 3: drawing a trace

`toolkit/waterfall.js` turns the spans of one trace into a text waterfall for the terminal and an SVG file for GitHub. It puts each span right under its parent, indented by depth. Sorting by start time alone would be wrong: the clocks of different processes can differ by a fraction of a millisecond, and a child could appear above its parent.

```js
// toolkit/waterfall.js: draw one trace as a waterfall, as text and as SVG.
// Each row is a span: when it started (relative to the first span) and how long it took.

const COLORS = { api: "#2563eb", menu: "#059669", payments: "#d97706" };

function rows(spans) {
  const t0 = Math.min(...spans.map((s) => s.startMs));
  const total = Math.max(...spans.map((s) => s.endMs)) - t0;
  // Put each span right under its parent, children in start order. (Clocks in
  // different processes can differ by a fraction of a millisecond, so sorting
  // by start time alone could print a child above its parent.)
  const ids = new Set(spans.map((s) => s.spanId));
  const childrenOf = (id) => spans.filter((s) => s.parentId === id).sort((a, b) => a.startMs - b.startMs);
  const roots = spans.filter((s) => !s.parentId || !ids.has(s.parentId)).sort((a, b) => a.startMs - b.startMs);
  const list = [];
  const walk = (s, depth) => {
    list.push({ ...s, offset: Math.max(0, s.startMs - t0), ms: s.endMs - s.startMs, depth });
    for (const child of childrenOf(s.spanId)) walk(child, depth + 1);
  };
  for (const root of roots) walk(root, 0);
  return { total, list };
}

export function waterfallText(spans, width = 40) {
  const { total, list } = rows(spans);
  return list
    .map((r) => {
      const from = Math.round((r.offset / total) * width);
      const len = Math.max(1, Math.round((r.ms / total) * width));
      const bar = " ".repeat(from) + (r.status === "error" ? "x" : "#").repeat(len);
      const name = `${"  ".repeat(r.depth)}${r.service} ${r.name}`.padEnd(34);
      return `${name}|${bar.padEnd(width + 1)}| +${String(Math.round(r.offset)).padStart(4)} ms, ${String(Math.round(r.ms)).padStart(4)} ms`;
    })
    .join("\n");
}

export function waterfallSvg(spans, title) {
  const { total, list } = rows(spans);
  const W = 640, L = 250, R = 20, top = 50, rowH = 30;
  const H = top + list.length * rowH + 40;
  const X = (ms) => L + (ms / total) * (W - L - R);
  const bars = list.map((r, i) => {
    const y = top + i * rowH;
    const color = r.status === "error" ? "#dc2626" : COLORS[r.service] ?? "#6b7280";
    const w = Math.max(2, X(r.ms) - X(0));
    return `<text x="${10 + r.depth * 14}" y="${y + 15}">${r.service} ${r.name}</text>\n` +
      `<rect x="${X(r.offset).toFixed(1)}" y="${y + 3}" width="${w.toFixed(1)}" height="18" fill="${color}" rx="2"/>\n` +
      `<text x="${Math.min(X(r.offset) + w + 4, W - 60).toFixed(1)}" y="${y + 16}" font-size="11">${Math.round(r.ms)} ms</text>`;
  });
  return `<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 ${W} ${H}" font-family="sans-serif" font-size="12">
<rect width="${W}" height="${H}" fill="white"/>
<text x="10" y="26" font-size="15" font-weight="bold">${title}</text>
<line x1="${L}" y1="${top - 6}" x2="${L}" y2="${H - 30}" stroke="#999"/>
${bars.join("\n")}
<text x="${L}" y="${H - 10}" text-anchor="middle">0 ms</text>
<text x="${W - R}" y="${H - 10}" text-anchor="end">${Math.round(total)} ms</text>
</svg>
`;
}
```

## Step 4: the app

Now the three services. `app.js` is one file that becomes `api`, `menu` or `payments` depending on the `SERVICE` environment variable. Read it from the top: each service logs one JSON line per request, counts the request in its metrics, and opens a span when the request arrives. The `api` calls the other two in turn, and each call is its own span with the header attached. The `PROPAGATE` setting is for the break-on-purpose step later.

```js
// One file, three services. SERVICE picks which one this process is:
//   menu      looks up the menu in a "database"
//   payments  calls an outside card provider, which is sometimes slow or failing
//   api       takes an order: calls menu, then payments
// Every service writes one JSON log line per request, counts requests in a
// metrics object, and records spans that it sends to a collector.
import http from "node:http";
import { appendFileSync } from "node:fs";
import { reportSpan, startSpan } from "../../toolkit/tracing.js";
import { createMetrics } from "../../toolkit/metrics.js";
import { exponential, seededRandom } from "../../toolkit/stats.js";

const SERVICE = process.env.SERVICE;
const COLLECTOR_URL = process.env.COLLECTOR_URL;
const LOG_FILE = process.env.LOG_FILE;
const MENU_URL = process.env.MENU_URL;
const PAYMENTS_URL = process.env.PAYMENTS_URL;
const SLOW_CHANCE = Number(process.env.SLOW_CHANCE ?? 0.05); // payments: share of slow provider calls
const SLOW_MS = Number(process.env.SLOW_MS ?? 400); // how long a slow provider call takes
const FAIL_CHANCE = Number(process.env.FAIL_CHANCE ?? 0.02); // payments: share of failed provider calls
const PROPAGATE = process.env.PROPAGATE !== "0"; // "0": api forgets to pass the trace header (break it on purpose)

const random = seededRandom({ api: 1, menu: 2, payments: 3 }[SERVICE]);
const sleep = (ms) => new Promise((resolve) => setTimeout(resolve, ms));
const metrics = createMetrics(SERVICE);

function log(level, msg, fields) {
  if (!LOG_FILE) return;
  appendFileSync(LOG_FILE, JSON.stringify({ ts: new Date().toISOString(), service: SERVICE, level, msg, ...fields }) + "\n");
}

// Run one step as a child span: it starts under `parentHeader`, and ends when `work` is done.
async function inSpan(name, parentHeader, work) {
  const s = startSpan({ service: SERVICE, name, traceparent: parentHeader });
  try {
    return await work(s.header);
  } catch (error) {
    reportSpan(COLLECTOR_URL, s.end("error"));
    throw error;
  } finally {
    if (s.span.endMs === null) reportSpan(COLLECTOR_URL, s.end("ok"));
  }
}

// Call another service, passing the trace header on.
async function call(name, url, header) {
  return inSpan(name, header, async (clientHeader) => {
    const res = await fetch(url, { headers: PROPAGATE ? { traceparent: clientHeader } : {} });
    if (res.status >= 500) throw new Error(`${name} answered ${res.status}`);
    return res.json();
  });
}

const handlers = {
  async menu(span) {
    await inSpan("SELECT items", span.header, () => sleep(5 + exponential(random, 12)));
    return { items: 42 };
  },
  async payments(span) {
    await inSpan("provider.charge", span.header, async () => {
      await sleep(random() < SLOW_CHANCE ? SLOW_MS + exponential(random, 40) : 25 + exponential(random, 15));
      if (random() < FAIL_CHANCE) throw new Error("provider declined");
    });
    return { charged: true };
  },
  async api(span) {
    await call("call menu", MENU_URL, span.header);
    await call("call payments", PAYMENTS_URL, span.header);
    return { ordered: true, traceId: span.span.traceId };
  },
};

const server = http.createServer(async (req, res) => {
  if (req.url === "/metrics") {
    res.setHeader("content-type", "text/plain");
    return res.end(metrics.text());
  }
  const started = performance.now();
  const s = startSpan({ service: SERVICE, name: `${req.method} /${SERVICE === "api" ? "order" : SERVICE}`, traceparent: req.headers.traceparent });
  let status = 200;
  let body;
  try {
    body = await handlers[SERVICE](s);
  } catch (error) {
    status = SERVICE === "api" ? 502 : 500;
    body = { error: error.message };
    log("error", "request failed", { traceId: s.span.traceId, error: error.message });
  }
  const ms = performance.now() - started;
  log("info", "request done", { traceId: s.span.traceId, status, ms: Math.round(ms) });
  metrics.observe(status, ms);
  reportSpan(COLLECTOR_URL, s.end(status >= 500 ? "error" : "ok"));
  res.writeHead(status, { "content-type": "application/json", "x-trace-id": s.span.traceId });
  res.end(JSON.stringify(body));
});

server.listen(0, "127.0.0.1", () => {
  const { port } = server.address();
  if (process.send) process.send({ port });
  else console.log(`${SERVICE} listening on http://127.0.0.1:${port}/`);
});
```

`system.js` starts everything for an experiment: the collector first, then `menu` and `payments`, then `api`, which needs their addresses. It uses `spawnServer` from challenge 1, so each service sends `{ port }` to its parent when it is ready.

```js
// Start the whole app for an experiment: a collector, then menu, payments and
// api, each in its own process. Used by the part 1 script and its test.
import http from "node:http";
import { mkdirSync, rmSync } from "node:fs";
import { spawnServer } from "../../toolkit/load.js";
import { parseMetrics } from "../../toolkit/metrics.js";

const APP = new URL("./app.js", import.meta.url);

export async function startSystem({ logDir, env = {} }) {
  rmSync(logDir, { recursive: true, force: true });
  mkdirSync(logDir, { recursive: true });

  // The collector is this process: services POST every finished span to it.
  const spans = [];
  const collector = http.createServer((req, res) => {
    let body = "";
    req.on("data", (chunk) => (body += chunk));
    req.on("end", () => {
      spans.push(JSON.parse(body));
      res.end("ok");
    });
  });
  await new Promise((resolve) => collector.listen(0, "127.0.0.1", resolve));
  const COLLECTOR_URL = `http://127.0.0.1:${collector.address().port}/`;

  const logFile = (service) => `${logDir}/${service}.log`;
  const common = (service) => ({ SERVICE: service, COLLECTOR_URL, LOG_FILE: logFile(service) });
  const menu = await spawnServer(APP, { ...common("menu"), ...env });
  const payments = await spawnServer(APP, { ...common("payments"), ...env });
  const api = await spawnServer(APP, { ...common("api"), MENU_URL: menu.url, PAYMENTS_URL: payments.url, ...env });

  return {
    api,
    spans,
    logFile,
    // Read each service's /metrics text and turn it into numbers.
    async scrape() {
      const out = {};
      for (const [name, server] of Object.entries({ api, menu, payments })) {
        out[name] = parseMetrics(await (await fetch(`${server.url}metrics`)).text());
      }
      return out;
    },
    async stop() {
      for (const s of [api, menu, payments]) s.stop();
      await new Promise((resolve) => collector.close(resolve));
    },
  };
}
```

## Step 5: part 1, three questions

Create `part-1-traces-and-metrics/observe.js`. It runs the load, then asks the three questions of chapter 17.2 in order. Metrics: is something wrong? Traces: where did the time go in the slowest order? Logs: what did each service write about that order?

```js
// Part 1: run the three-service app under load, then ask the three questions:
// metrics (is something wrong?), traces (where did the time go?), logs (what happened there?).
import { readFileSync, writeFileSync } from "node:fs";
import { fileURLToPath } from "node:url";
import { runLoad } from "../../../toolkit/load.js";
import { percentile } from "../../../toolkit/stats.js";
import { quantileFromBuckets } from "../../../toolkit/metrics.js";
import { groupByTrace } from "../../../toolkit/tracing.js";
import { waterfallSvg, waterfallText } from "../../../toolkit/waterfall.js";
import { startSystem } from "../system.js";

const RATE = 20; // orders per second
const SECONDS = Number(process.env.SECONDS ?? 15);
const logDir = fileURLToPath(new URL("./logs", import.meta.url));

const system = await startSystem({ logDir, env: { PROPAGATE: process.env.PROPAGATE ?? "1" } });
console.log(`sending ${RATE} orders per second for ${SECONDS} seconds ...\n`);
const { latencies } = await runLoad({ url: system.api.url, rate: RATE, seconds: SECONDS });
await new Promise((resolve) => setTimeout(resolve, 500)); // let the last spans arrive
const metrics = await system.scrape();
system.stop();

// 1. Metrics: the RED table, one row per service.
console.log("METRICS (RED)");
console.log("service   rate/s  errors   p50 <= ms  p99 <= ms  exact p99 ms");
for (const name of ["api", "menu", "payments"]) {
  const m = metrics[name];
  const errors = Object.entries(m.byCode).filter(([code]) => code >= 500).reduce((sum, [, n]) => sum + n, 0);
  // A "server span" is the span a service opens when a request arrives: its name starts with GET /.
  const exact = system.spans.filter((s) => s.service === name && s.name.startsWith("GET /"));
```

```js
// Problems with a set of spans from `orders` orders. An empty list means every
// order is one trace with the right shape.
function traceProblems(spans, orders) {
  const problems = [];
  const traces = groupByTrace(spans);
  if (traces.size !== orders) problems.push(`${orders} orders made ${traces.size} traces`);

    const roots = list.filter((s) => !s.parentId || !ids.has(s.parentId));
```

Next, `toolkit/simlog.js`. It makes a log with a steady base error rate and lets you say, in minutes, when an incident starts and ends and how bad it is. About 2 requests in 100 are 404s, so your SLI has something to leave out.

```js
// toolkit/simlog.js: make a fake access log for the order service, minute by minute.
// A real log would take hours to collect, so we invent one with a seeded random
// generator: the same seed always gives the same log.
import { exponential, seededRandom } from "./stats.js";

// incidents: [{ from, to, errorRate }] in minutes since the start.
// Every request is { ts (ms since the start), status, ms }.
export function simulateLog({ seed = 11, minutes, ratePerSecond, baseErrorRate, incidents = [] }) {
  const random = seededRandom(seed);
  const requests = [];
  const endMs = minutes * 60_000;
  let ts = 0;
  while (true) {
    ts += exponential(random, 1000 / ratePerSecond);
    if (ts > endMs) break;
    const minute = ts / 60_000;
    const incident = incidents.find((i) => minute >= i.from && minute < i.to);
    const errorRate = incident ? incident.errorRate : baseErrorRate;
    const roll = random();
    // 2 requests in 100 are the caller's mistake (404): they never count against us.
    const status = roll < errorRate ? 503 : roll < errorRate + 0.02 ? 404 : 200;
    requests.push({ ts, status, ms: Math.round(30 + exponential(random, 50)) });
  }
  return requests;
}
```

Now `part-2-burn-rate-alert/alert.js`. It builds a day of traffic at 5 orders a second, with a base error rate of 0.05%, which is half of what a 99.9% SLO allows. The three incidents are a 3 minute blip at 8% errors, a 5 hour slow leak at 1.2% from a bad cache setting, and a 30 minute outage at 5% from a bad deploy. Then it steps through the day one minute at a time, from hour 6 on so that the 6 hour window is full. At each minute it asks two alerts whether to page: the naive one, with a 5 minute window at a burn rate of 1, and the burn-rate alert with the two rules from chapter 17.4. A page "opens" when an alert turns on.

```js

//   naive:     page when the error rate over the last 5 minutes is above the SLO's allowance
//   burn rate: page when a long window AND a short window both burn the budget fast
import { writeFileSync } from "node:fs";

import { simulateLog } from "../../../toolkit/simlog.js";

const SLO = 0.999; // 99.9% of valid requests succeed, over 30 days
const RATE = 5; // orders per second
const MINUTES = 24 * 60;
const WARM_UP = 6 * 60; // judge only after 6 hours of history, so the longest window is full
// The two page rules: [long window, short window, burn rate].
const RULES = [
  { longMs: 3_600_000, shortMs: 300_000, burn: 14.4 }, // fast: 2% of a 30-day budget in 1 hour
  { longMs: 21_600_000, shortMs: 1_800_000, burn: 6 }, // slow: 5% of a 30-day budget in 6 hours
];

  { name: "blip: a node restarts", from: 420, to: 423, errorRate: 0.08 },
  { name: "slow leak: a bad cache setting", from: 560, to: 860, errorRate: 0.012 },
  { name: "outage: a bad deploy", from: 1250, to: 1280, errorRate: 0.05 },
];

const log = simulateLog({ seed: 11, minutes: MINUTES, ratePerSecond: RATE, baseErrorRate: 0.0005, incidents: INCIDENTS });

// The log is sorted by time, so a binary search finds where a window starts.
function lowerBound(ts) {
  let lo = 0, hi = log.length;
  while (lo < hi) {
    const mid = (lo + hi) >> 1;
    if (log[mid].ts <= ts) lo = mid + 1; else hi = mid;
  }
  return lo;
}
const upTo = (minute) => log.slice(lowerBound(minute * 60_000 - 21_600_000), lowerBound(minute * 60_000));

  naive: { opens: [], on: false },
  "burn-rate": { opens: [], on: false },
};
const curve = [];

    const s = strategies[name];
    if (firing && !s.on) s.opens.push(minute); // a page opens when the alert turns on
    s.on = firing;
  }
  if (minute % 10 === 0) curve.push({ minute, burn1h: result.burns[0].long, burn5m: result.burns[0].short });
}

const badBetween = (from, to) => log.filter((r) => r.ts >= from * 60_000 && r.ts < to * 60_000 && r.status >= 500).length;
console.log(`${log.length} requests over ${MINUTES / 60} hours, SLO ${SLO * 100}%, 30-day budget about ${Math.round(budget)} bad requests\n`);
// A page is "real" when it opens while an incident is running (or within 5 minutes after it ends).
const real = (m) => INCIDENTS.some((i) => m >= i.from && m <= i.to + 5);
for (const [name, s] of Object.entries(strategies)) {
  const good = s.opens.filter(real).length;
  console.log(`${name.padEnd(10)} pages opened: ${String(s.opens.length).padStart(2)}   during an incident: ${good}   noise: ${s.opens.length - good}`);
}

console.log("\nincident                          starts  paged at  minutes late  bad requests before page  share of 30-day budget");
for (const inc of INCIDENTS) {
  const page = strategies["burn-rate"].opens.find((m) => m >= inc.from && m <= inc.to);
  const naive = strategies.naive.opens.find((m) => m >= inc.from && m <= inc.to);
  const bad = page === undefined ? null : badBetween(inc.from, page);
  console.log(
    `${inc.name.padEnd(33)} ${String(inc.from).padStart(5)}  ${String(page ?? "never").padStart(8)}  ` +
    `${String(page === undefined ? "-" : page - inc.from).padStart(12)}  ${String(bad ?? "-").padStart(24)}  ` +
    `${bad === null ? "-".padStart(22) : ((bad / budget) * 100).toFixed(1).padStart(21) + "%"}   (naive: ${naive ?? "no page"})`
  );
}

// chart.svg: the 1-hour burn rate, the page line at 14.4, and the incidents.
const W = 640, H = 300, L = 50, R = 20, T = 40, B = 40;
const yMax = Math.ceil(Math.max(...curve.map((p) => p.burn1h)) / 10) * 10;
const X = (m) => L + ((m - WARM_UP) / (MINUTES - WARM_UP)) * (W - L - R);
const Y = (v) => H - B - (v / yMax) * (H - T - B);

const shade = INCIDENTS.map((i) => `<rect x="${X(i.from).toFixed(1)}" y="${T}" width="${Math.max(2, X(i.to) - X(i.from)).toFixed(1)}" height="${H - T - B}" fill="#fde68a" opacity="0.7"/>`);
const pages = strategies["burn-rate"].opens.map((m) => `<line x1="${X(m)}" y1="${T}" x2="${X(m)}" y2="${H - B}" stroke="#dc2626" stroke-width="2"/><text x="${X(m) + 3}" y="${T + 12}" fill="#dc2626">page</text>`);
writeFileSync(new URL("./chart.svg", import.meta.url), `<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 ${W} ${H}" font-family="sans-serif" font-size="12">
```

Now the table. The blip at minute 420 never paged the burn-rate alert, as it should: 3 minutes at 8% is a burn of only about 4 over the hour. The outage at minute 1250 was paged at minute 1267, 17 minutes after it started, when 246 bad requests had been spent. That is 1.9% of the 30-day budget, which matches the 2% that the 14.4 rule is designed to catch. The slow leak at minute 560 was paged at minute 702, 142 minutes after it began, by the 6 hour rule, with 4.1% of the budget gone. The fast rule never saw it, because the leak burns at about 12, below 14.4.

This is the trade the chapter promised. The naive alert paged within a minute of the outage, which is faster than the burn-rate alert's 17 minutes. But it was right 3 times and wrong 27 times. The burn-rate alert gave up some speed to be right every time. Notice also that the numbers differ a little from the clean model in chapter 17.4 (the leak at minute 142 and not 173). The traffic is random, and the earlier blip adds a small amount to the 6 hour window.

## When something goes wrong

**`Cannot find module` for `toolkit/stats.js` or `toolkit/load.js`.** These come from challenge 1. If you skipped it, do chapter 2.8 first. The scripts find each other through their own location, so it does not matter which folder you run them from.

**The services never start, and the script waits for ever.** One of them failed on startup and never sent its port. Run `SERVICE=menu node challenges/challenge-16-observability/app.js` on its own (in PowerShell, `$env:SERVICE="menu"` first) and read the error.

**`ECONNREFUSED` or an order that returns no trace id.** You ran an old copy of a service. Stop every `node` process from an earlier run, and start again.

**Traces stored is smaller than orders sent.** Some spans did not arrive before the script read them. The script waits 500 ms after the last order. On a slow machine, raise it to 1,000.

**The api's p99 is "Infinity".** The slowest request was above the last bucket edge of 1,000 ms. That happens when the laptop is busy or saving power. Close other programs and plug in.

**Part 2 pages at different minutes from the ones printed here.** The generator is seeded, so the log is the same. A different result means a different `shouldPage`. Compare with the tests in 17.7, especially the window edges and the short window.

**Break it on purpose.** A test you have never seen fail proves little. First, break propagation. Run `PROPAGATE=0 node challenges/challenge-16-observability/part-1-traces-and-metrics/observe.js` (in PowerShell, set `$env:PROPAGATE="0"` first). The same 269 orders now make 807 traces, three per order, because menu and payments each start a trace of their own. The waterfall for the slowest order shows only the api and its two calls, with no spans below them, and you can no longer see where the time went. Then break the code: in `app.js`, replace `PROPAGATE ? { traceparent: clientHeader } : {}` with just `{}`, run the part 1 test, and read the first failure:

```text
✖ every order is one trace, joined by the traceparent header (3329.7062ms)
  AssertionError [ERR_ASSERTION]: Expected values to be strictly deep-equal:
  + actual - expected
  + [
  +   '25 orders made 75 traces'
  + ]
  - []
```

Undo the change. Second, break the alert. In `toolkit/slo.js`, change the `&&` in `shouldPage` to `||`, so that one window is enough to fire, and run the part 2 test. The blip test fails, because the short window alone is burning fast:

```text
✖ a 3-minute blip does not page, even though a naive 5-minute alert would (64.7113ms)
  AssertionError [ERR_ASSERTION]: Expected values to be strictly equal:
  true !== false
```

Undo that too, and run `npm test` once more to check that you are back to green.
