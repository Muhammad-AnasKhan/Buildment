## Three pieces: docs, a tiny project, notes

### 1. Start with the official docs

Most tools have a "Getting started", "Quickstart" or "Tutorial" page. Start there, not with a random blog post. Official docs are written by the people who make the tool, and they are updated when the tool changes.

You do not need to read everything. Read the overview, then only the parts you need for your task. Come back for the rest later.

<Callout type="warning" title="Check the version">
Tools change between versions. Before you copy an example, check that the docs match the version your project uses. Many docs sites have a version menu near the top of the page.
</Callout>

### 2. Build a tiny practice project

A practice project is much smaller than the real task. It has one job. Ziad's practice project is one API endpoint that returns a list of three books. It takes him 40 minutes.

Then he changes it on purpose: he adds a filter, sends a wrong value, and reads the error. Breaking a small thing on purpose teaches you how the tool fails, before it fails in the client's project.

### 3. Keep your own notes

Write short notes in your own words while you learn. They become your personal guide, and they work with no internet.

```text
FastAPI notes (version 0.115)
- Start the server: fastapi dev main.py
- Types in the function decide how input is checked
- Error 422 = the input did not match the type
- Question: how do I connect a database? Docs: "SQL (Relational) Databases"
```

Good notes have the commands that worked, the errors you met and how you fixed them, and your open questions.

## Learning with little or no internet

Many of you learn with power and internet for only a few hours a day. You can still learn well if you plan for it. The idea is simple: **use online time to collect, and offline time to practice.**

| When you are online | When you are offline |
|---|---|
| Download the docs, or save the pages you need | Read the saved docs and pages |
| Install the tool and its packages | Build and break your practice project |
| Copy example projects to your laptop | Write and update your notes |
| Send your help questions | Write the next questions to send |

Some useful ways to keep docs with you:

- **Download the docs.** Some tools offer their docs as a download. For example, the Python docs have a download page. DevDocs, a free website, can save docs from many tools in your browser to read offline.
- **Use built-in help.** Many command-line tools explain themselves with `--help`. On Linux and macOS, `man` shows the manual for a command. These work with no internet.
- **Make a cheat sheet.** A cheat sheet is one short page with the commands and patterns you use most. Write your own; it is smaller and more useful than any you download. Keep it on your phone.
- **Prefer text to video.** A docs page is far smaller to download than a video. If you need a video, download it in low quality while the connection is good.
