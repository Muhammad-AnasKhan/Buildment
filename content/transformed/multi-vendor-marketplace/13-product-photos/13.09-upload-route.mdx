JSON routes cannot carry image files. This lesson adds a **multipart upload endpoint** that sends bytes to Cloudinary and saves only the URL on the product document.

<BigWordAlert term="Multipart upload" plainEnglish="HTTP request encoding file binary in multipart/form-data — standard for file upload endpoints." whyItMatters="FreshMarket's upload route accepts FormData from the browser and forwards to Cloudinary." />

## Step 1 — Create multer middleware

**File:** `server/src/modules/products/upload.middleware.js`

| Setting | Value |
|---|---|
| Storage | `multer.memoryStorage()` |
| Field name | `image` (client must match) |
| Max size | 5 MB |
| Allowed types | `image/jpeg`, `image/png`, `image/webp` |

Export: `uploadProductImage = upload.single('image')`

---

## Step 2 — Add the route

```
POST /api/products/:id/image
Middleware: requireAuth → requireRole('vendor') → uploadProductImage → handler
```

**Handler sequence:**

1. Load product by `:id`
2. Assert vendor owns product's store (same as PATCH)
3. If `!req.file` → 400
4. Upload buffer to Cloudinary via helper from 13.8
5. Update product: `imageUrl`, `imagePublicId`
6. Return updated product JSON

Do **not** delete old image yet — that is 13.10.

## Step 4 — Error cases to handle

| Condition | Status |
|---|---|
| No token | 401 |
| Customer role | 403 |
| Wrong vendor's product | 403 |
| Product not found | 404 |
| No file / bad type / too large | 400 |
| Cloudinary down | 502/500 — generic message to client |

Run ownership check **before** uploading to Cloudinary — saves failed uploads on 403.

---

## Common mistakes

| Mistake | Fix |
|---|---|
| Base64 in JSON body | Use multipart only |
| Skip MIME check | Validate server-side |
| Cloudinary secret in client | Server-only upload |
| Accept image on PATCH JSON | Separate route |
