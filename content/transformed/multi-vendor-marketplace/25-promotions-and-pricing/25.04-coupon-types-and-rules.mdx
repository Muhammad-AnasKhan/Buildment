# 25.04 — Coupon types and rules

Think of validation as a **pipeline** — cheap checks first, expensive aggregation last.

## Validation pipeline

1. Normalize code → lookup active coupon
2. Window: `startsAt <= now <= endsAt`
3. Scope: store coupon must match at least one cart line from that store
4. `minSubtotalCents` on **eligible** lines only
5. Global redemptions `< maxRedemptions`
6. User redemptions `< maxRedemptionsPerUser`
7. Compute discount

## Percent vs fixed

**Percent:** `discount = round(eligibleSubtotal * value / 100)`, then `min(discount, maxDiscountCents)`.

**Fixed:** apply up to `value` cents, not more than eligible subtotal.

## Allocation across lines (proportional)

For platform $10 off a cart with two vendors, split by line subtotals so vendor payouts stay explainable:

```
lineDiscount_i = floor(totalDiscount * lineSubtotal_i / eligibleSubtotal)
```

Adjust rounding remainder on the largest line — document one cent drift in tests.

## FreshMarket examples

| Code | Rule | Intent |
|---|---|---|
| `FRESH10` | Platform 10% max $15 | Launch campaign |
| `BAKERY5` | Store fixed $5, min $20 at Sunrise Bakery | Vendor-funded promo |
| `ONCE24` | `maxRedemptionsPerUser: 1` | New customer offer |

## Errors (user-facing)

Use one message for security-sensitive failures: **“This code isn’t valid for your cart.”** Log detailed reason server-side (`COUPON_EXPIRED`, `SCOPE_MISMATCH`).
