## Why this step matters

Store settings — name, description, address — change over time. `PATCH /stores/:id` reuses Chapter 8's ownership assert so only the leaseholder edits their stall. Chapter 10's settings page calls this route on save.

**Where the project is now:** Vendor can create and fetch own store.

**After this step:** `PATCH /api/stores/:id` updates mutable fields when caller owns the store — **200** + updated document. Wrong vendor → **403**. Invalid id or missing store → **404**.

## Handler flow (spec)

```
PATCH /api/stores/:id
  1. requireAuth
  2. requireRole('vendor')
  3. validateObjectId(id) → 404 if invalid format
  4. validateUpdateStore(req.body) → 400 if invalid
  5. assertStoreOwner(id, userId) → 403 if not owner
  6. updateStore(id, userId, validBody)
  7. 200 + updated store JSON
```

Reuse **`assertStoreOwner`** from Chapter 8 — do not rewrite ownership query inline.

## Service: `updateStore(storeId, vendorId, data)`

| Step | Action |
|---|---|
| 1 | Find by `_id` — if missing, NotFoundError (404) |
| 2 | Ownership already checked in middleware OR re-verify `store.vendorId` equals vendorId |
| 3 | Apply allowed fields only — `$set` partial update |
| 4 | Return updated document |

**Immutable:** `vendorId`, `_id` — strip from PATCH body in validation.

## Mutable fields

Per 9.4 — typically:

- `name`  
- `description`  
- `address`  
- `logoUrl`  

Empty PATCH body `{}` → 400 or 200 no-op — pick one; recommend **400 "no fields to update"** for clarity.

## Error matrix

| Condition | Status |
|---|---|
| Invalid ObjectId format | 404 |
| Store not found | 404 |
| Store owned by another vendor | 403 |
| Invalid field values | 400 |
| Owner, valid patch | 200 |

**403 vs 404:** Some APIs return 404 for non-owner to hide existence — this course uses **403** per Chapter 8 IDOR test convention. Stay consistent with `AUTHORIZATION.md`.

## IDOR test (required)

| Actor | Action | Expected |
|---|---|---|
| Vendor A | PATCH `/stores/:idA` with token A | 200 |
| Vendor B | PATCH `/stores/:idA` with token B | 403 |
| Vendor A | PATCH `/stores/:fakeId` | 404 |

This reproduces Chapter 8 test with **real** update body — e.g. change `name`.

## curl verify

```bash
curl -s -X PATCH http://localhost:5000/api/stores/STORE_ID \
  -H "Authorization: Bearer TOKEN_A" \
  -H "Content-Type: application/json" \
  -d '{"description":"Updated blurb"}'
```

Confirm `updatedAt` changes if using timestamps.

Cross-vendor test with TOKEN_B → 403.

## Partial update semantics

PATCH is **partial** — omitting `name` leaves existing name unchanged. Do not require full resource body like PUT.

## ✅ Do / ❌ Don't

**✅ Do:** Reuse shared ownership helper — single implementation.

**✅ Do:** Validate ObjectId before DB hit — avoid CastError 500.

**❌ Don't:** Allow `vendorId` in PATCH body to transfer ownership.

**❌ Don't:** Return 200 with another vendor's store — ever.
