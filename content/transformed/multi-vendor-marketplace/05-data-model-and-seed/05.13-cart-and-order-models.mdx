**Why this step matters:** Cart references live products; orders embed **snapshot** lines — the hardest modelling choice in the marketplace. Getting embed field names right here makes Chapter 18 checkout a wiring task instead of a schema rescue.

<BigWordAlert term="Cart vs order" plainEnglish="Cart is mutable pre-checkout intent; order is an immutable record created at payment — different lifecycles." whyItMatters="FreshMarket clears the cart after checkout but keeps orders forever for receipts and vendor fulfillment." />

**Where the project is now:** User, Profile, Store, and Product models exist. Cart and checkout collections missing.

**After this step:** `cartItem.model.js` and `order.model.js` complete the data model — cart lines as refs, order lines as embedded snapshots.

## CartItem schema specification

Persistent cart — not browser localStorage (Ch 16 API).

| Field | Type | Required | Notes |
|---|---|---|---|
| `userId` | ObjectId ref User | yes | Cart owner — customer only |
| `productId` | ObjectId ref Product | yes | Live product ref |
| `storeId` | ObjectId ref Store | yes | Denormalised for checkout split |
| `quantity` | Number | yes | min 1 integer |
| timestamps | auto | yes | |

**Indexes:**

- `{ userId: 1 }` — fetch cart
- `{ userId: 1, productId: 1 }` unique optional — one line per product per user (merge qty on add — Ch 16)

**Why storeId on line:** Checkout groups by store without joining Product at split time.

## Order schema specification

One Order document = **one vendor's portion** of a checkout — not the whole multi-vendor cart.

### Top-level fields

| Field | Type | Required | Notes |
|---|---|---|---|
| `customerId` | ObjectId ref User | yes | Buyer |
| `storeId` | ObjectId ref Store | yes | Fulfilling vendor |
| `status` | String enum | yes | See below |
| `paymentStatus` | String enum | yes | `pending` until Ch 19; `paid` after Stripe checkout |
| `stripePaymentIntentId` | String | no | Set at checkout in Ch 19 — same id across orders in one batch |
| `orderItems` | [OrderItemSchema] | yes | Embedded array |
| `subtotal` | Number | yes | Sum of line totals at purchase |
| timestamps | auto | yes | |

**status enum (MVP):**

```
pending | packed | dispatched | cancelled
```

**paymentStatus enum:**

```
pending | paid | failed
```

Chapter 18 creates orders with `paymentStatus: 'pending'`. Chapter 19 sets `paid` after Stripe verifies the Payment Intent. `stripePaymentIntentId` links all orders from one checkout batch.

### Embedded OrderItem sub-schema (no separate collection)

| Field | Type | Required | Notes |
|---|---|---|---|
| `productId` | ObjectId ref Product | yes | Traceability — product may be deleted later |
| `nameAtPurchase` | String | yes | Snapshot |
| `priceAtPurchase` | Number | yes | Snapshot |
| `unitAtPurchase` | String | yes | Snapshot |
| `quantity` | Number | yes | min 1 |
| `lineTotal` | Number | yes | priceAtPurchase × quantity |

**Snapshot rule:** Values copied from Product at checkout (Ch 18) — never updated when Product.price changes.

## Multi-vendor checkout preview

Customer cart with items from Store A and Store B:

```
Checkout → Order #1 (storeId: A, orderItems: [...])
        → Order #2 (storeId: B, orderItems: [...])
```

Two documents, same `customerId`, different `storeId`.

## Relationship diagram

```
User (customer) ←—— CartItem.userId
Product ←—— CartItem.productId
Store ←—— CartItem.storeId

User (customer) ←—— Order.customerId
Store ←—— Order.storeId
Product ←—— orderItems[].productId (ref + snapshot fields)
```

Vendor reads: `Order.find({ storeId: myStoreId })`

## CartItem vs Order — ref vs snapshot

| Aspect | CartItem | Order.orderItems[] |
|---|---|---|
| Price | Read live from Product at display | Frozen at checkout |
| Mutability | PATCH quantity, DELETE line | Immutable after create |
| Lifetime | Until checkout clears cart | Permanent history |

## ✅ Do / ❌ Don't

**✅ Do:** Embed orderItems — separate `orderlines` collection out of scope.

**✅ Do:** Include all snapshot field names ending in `AtPurchase`.

**❌ Don't:** Embed full Product in CartItem — refs only.

**❌ Don't:** Single Order for whole multi-vendor cart — breaks vendor fulfilment.
