**Why this step matters:** Every auth and ownership feature anchors on User — email, role, verification state — and Profile for display data. These schemas are prerequisites for register in Chapter 6; get field names right now.

**Where the project is now:** Module folders exist; no Mongoose schemas yet.

**After this step:** `user.model.js` and `profile.model.js` export registered models. User holds auth identity; Profile holds display fields linked by `userId`.

## Design decision — identity vs profile split

| Concern | User | Profile |
|---|---|---|
| Login email | ✓ | |
| Password hash | ✓ | |
| Role (vendor/customer) | ✓ | |
| OTP / verification flags | ✓ | |
| Display name | | ✓ |
| Phone | | ✓ |
| Avatar URL | | ✓ |

**Why split:** Auth chapter rotates tokens and hashes passwords on User without touching profile display fields. Vendor dashboard shows profile name without exposing hash in same document queries.

Alternative single-document User is valid in industry — **this course mandates split**.

## User schema specification

| Field | Type | Required | Notes |
|---|---|---|---|
| `email` | String | yes | Lowercase trim; unique index |
| `passwordHash` | String | yes | Plain password never stored — Ch 6 hashes |
| `role` | String enum | yes | `'vendor'` \| `'customer'` |
| `isVerified` | boolean | yes | default `false` — OTP in Ch 6 |
| `refreshTokenHash` | String | no | Ch 6 refresh flow |
| timestamps | auto | yes | `createdAt`, `updatedAt` |

**Indexes:**

- `{ email: 1 }` unique

**Seed note:** Seed may store pre-hashed placeholder or plain string documented as "replaced at auth" — prefer bcrypt hash in seed if Ch 6 bcrypt cost known; or document re-seed after auth.

## Profile schema specification

| Field | Type | Required | Notes |
|---|---|---|---|
| `userId` | ObjectId ref User | yes | One profile per user |
| `displayName` | String | yes | Shown in UI |
| `phone` | String | no | Optional contact |
| `avatarUrl` | String | no | Cloudinary later |
| timestamps | auto | yes | |

**Indexes:**

- `{ userId: 1 }` unique — enforces 1:1

Verify in Compass after seed — collection names pluralized lowercase.

## Validation rules (schema-level)

Implement in Mongoose schema — not HTTP layer:

- `email` — format validator or regex; lowercase on save
- `role` — enum only vendor/customer
- `passwordHash` — min length on hash string (bcrypt ~60 chars)

**Do not** implement register route here.

## ✅ Do / ❌ Don't

**✅ Do:** Unique index on email — duplicate registration must fail at DB level too.

**✅ Do:** Use `passwordHash` field name — not `password`.

**❌ Don't:** Store role on Profile — JWT reads User.role in Ch 6.

**❌ Don't:** Export plain password from seed without documenting Ch 6 re-hash.
