## Step 1 — Form fields

| Field | Validation |
|---|---|
| email | required |
| password | required |

Disable submit button while request is in flight.

---

## Step 2 — Submit flow

```
1. await login(email, password)   // calls POST /auth/login
2. useAuth stores access token in memory + user object
3. Redirect by role:
   - vendor → /vendor (layout gate handles open-shop in Ch 10)
   - customer → / or /shop
4. On 401 → "Invalid email or password"
5. On 403 → "Please verify your email" + link to /verify-otp
```

---

## Step 3 — Cookie / refresh handling

Login fetch should use `credentials: 'include'` if the server sets a refresh token cookie.

Access token lives in **memory** (from 7.4) — not localStorage.

---

## Step 4 — Show banner from verify flow

If user arrives from OTP verification with `location.state.message`, display it once at the top.

---

## Step 5 — Test both roles

| Account | Expected |
|---|---|

| customer-a@test.local | Redirect to customer home |

Network tab: login returns 200; Set-Cookie if using cookie refresh.

---

## Common mistakes

| Mistake | Fix |
|---|---|
| Redirect unverified user on 403 | Show verify message instead |
| Store access token in localStorage | Memory only — see 7.4 |
| Same redirect for all roles | Branch on user.role |
