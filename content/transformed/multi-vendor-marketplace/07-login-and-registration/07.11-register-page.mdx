Registration is often a user's **first screen**. It must call the Chapter 6 API correctly, show clear errors, and send new users to email verification — not straight into the dashboard.

<BigWordAlert term="Form validation" plainEnglish="Client-side checks (email format, password length) before submitting to the server — faster feedback." whyItMatters="FreshMarket register page catches obvious errors before a round-trip to `/api/auth/register`." />

## Step 1 — Form fields

| Field | Client validation |
|---|---|
| email | required, valid email shape |
| password | min 8 characters |
| confirmPassword | must match password |
| role | **vendor** or **customer** — required |
| displayName | optional |

Do **not** send `confirmPassword` to the API.

---

## Step 2 — Submit flow

```
1. Client validate all fields
2. await register({ email, password, role, displayName })
3. On 201 → navigate('/verify-otp', { state: { email } })
4. On 409 → "Email already registered"
5. On 400 → show server message / field errors
```

Disable submit while loading.

---

## Step 3 — Error display

Show API `message` from the JSON body. Field-level errors are better than a generic alert.

Link to login at the bottom: "Already have an account? Log in"

---

## Step 4 — Dev OTP hint (optional)

If your dev API returns `otp` in the response body, show a dismissible hint: "Dev OTP: 123456" — saves time during local testing.

---

## Step 5 — Verify in browser

1. Open `/register`
2. Register a new vendor email
3. Land on `/verify-otp` with email pre-filled (from router state)
4. Compass: new user with `isVerified: false`

---

## Common mistakes

| Mistake | Fix |
|---|---|
| Auto-login after register | Must verify OTP first |
| Skip role picker | Needed for vendor vs customer routing |
| Untrimmed email | trim() before submit |
