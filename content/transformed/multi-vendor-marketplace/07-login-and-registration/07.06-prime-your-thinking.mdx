Before building auth pages, skim React patterns for context, protected routes, and fetch credentials.

## Why this matters for absolute beginners

Chapter 7 combines React Router, forms, cookies, and async boot logic — easy to glue wrong. Thirty minutes on Navigate, credentials, and your Chapter 6 curl notes prevents building pages that work in isolation but fail after reload or CORS.

## Common beginner questions

<FaqGroup>

<FaqItem question="Why read fetch credentials docs for a React course?">

Refresh cookies **require** `credentials: 'include'` — missing it looks like "refresh always 401."

</FaqItem>

<FaqItem question="Controlled inputs without a form library — really?">

Yes for gate — fewer dependencies; focus on auth flow correctness.

</FaqItem>

<FaqItem question="CORS `*` with credentials?">

Invalid combo — server must echo specific Vite origin with `Allow-Credentials: true`.

</FaqItem>

</FaqGroup>


## Mandatory reads

| Resource | Focus |
|---|---|
| [React Router — Navigate](https://reactrouter.com/en/main/components/navigate) | Redirect unauthenticated |
| [React Router — useNavigate](https://reactrouter.com/en/main/hooks/use-navigate) | Post-login redirect |
| [MDN fetch credentials](https://developer.mozilla.org/en-US/docs/Web/API/fetch#credentials) | include for cookies |
| Your Ch 6 curl notes | Exact API shapes |

Optional: React Context vs custom hook for auth state — pick one pattern.

## Patterns to decide

| Decision | Options |
|---|---|
| Auth state | Context + useAuth hook |
| Form library | Controlled inputs native — no library required |
| Error display | Single message string vs field errors |
| Email to VerifyOtp | location.state from Register |

Document choices in learning log.

## CORS + credentials

Server must respond:

```
Access-Control-Allow-Origin: http://localhost:5173  (not * when credentials)
Access-Control-Allow-Credentials: true
```

Update server CORS config in build cluster if not already.
