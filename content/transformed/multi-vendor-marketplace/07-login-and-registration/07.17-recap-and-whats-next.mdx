## What you built

Four client-side pieces, each wrapping a Chapter 6 endpoint. If you can name what each one is *for* without opening the file, this chapter's learning has landed.

**Pages:** Register, VerifyOtp, Login with API error handling.

**useAuth:** Memory access token, boot refresh, login/logout/register/verify.

**API client:** Bearer attachment, 401 refresh retry once.

**ProtectedRoute:** Unauthenticated redirect, optional role prop, loading gate.

## Security properties

The four properties below are the *point* of this chapter — they are what a senior engineer checks when they review your auth. Holding a session in the browser is not the hard part; holding it *safely* is.

- Access not in localStorage  
- Refresh httpOnly cookie (when server configured)  
- Short-lived access with renewal  
- Unverified users blocked in UI
