You entered Chapter 16 with a browse-only marketplace. You leave with a **persisted, user-scoped cart API** — multi-vendor lines with `storeId`, stock checks, full CRUD — ready for the cart UI in Chapter 17.

## What you built

**POST /cart:** Validates product, storeId match, stock; upserts line with userId from JWT.

**GET /cart:** Populated products and stores — no cross-user leakage.

**PATCH /cart/:itemId:** Quantity updates with ownership + stock rules.

**DELETE /cart/:itemId:** Remove own lines only.

**Isolation:** User B cannot access User A's itemIds — verified in 16.13.

**Multi-vendor:** One cart holds lines from multiple storeIds — checkout split enabled for Ch 18.

## Next chapter — Your cart (Chapter 17)

Chapter 17 is the **frontend pair** to this chapter — the same relationship Chapter 7 had to Chapter 6. You proved the cart with curl; now the customer sees and edits it in the browser.

| What Chapter 17 builds | Which Chapter 16 endpoint it calls |
|---|---|
| Cart page grouped by store | `GET /cart` |
| Quantity + / − buttons | `PATCH /cart/:itemId` |
| Remove line button | `DELETE /cart/:itemId` |
| Add to cart on product detail | `POST /cart` |
| Header badge count | `GET /cart` (after every mutation) |
| Reload persistence demo | All of the above — cart lives in MongoDB |

## Handoff to Chapter 17 — API fields → UI components

Chapter 17 does not invent cart rules. Every row on the cart page maps to a field you already tested in curl:

| API response field | Chapter 17 component | Common student mistake |
|---|---|---|
| `items[].storeId` | Store section heading key | Flat list — customer confused at checkout split |
| `items[].store.name` (populated) | Section title text | Hardcoding "Store 1" instead of API name |
| `items[]._id` | PATCH/DELETE path param | Using `productId` instead of cart line id |
| `items[].product.name` + `price` + `unit` | CartItemRow display | Stale prices from old React state |
| `items[].quantity` | Quantity display (then controls in 17.6) | Showing quantity without refetch after PATCH |
| Multi-vendor `items[]` | Two+ store sections visible | Only testing one vendor in the UI |

<Callout type="warning" title="Gate before the cart page">
Do not open Chapter 17 until **16.15 checklist** is ticked. A blank cart page with spinner forever is usually a broken `GET /cart` or missing auth token — not a React bug. Run your Chapter 16 curl tests again before touching JSX.
</Callout>
