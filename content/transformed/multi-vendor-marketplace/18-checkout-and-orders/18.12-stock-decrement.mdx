Two customers must not buy the last kilo of rice at the same time. Stock decrement uses a **conditional database update** — if stock is insufficient, checkout fails completely.

<BigWordAlert term="Inventory deduction" plainEnglish="Reducing product.stock when order confirms — ties catalogue availability to real fulfillment." whyItMatters="FreshMarket must not sell stock already committed to another pending checkout." />

---

## Step 1 — Where this runs in checkout

Inside `checkout(userId)`, **before** inserting orders (ideally in one transaction):

For each distinct `productId` in the cart (sum quantities if duplicate lines):

```javascript
const updated = await Product.findOneAndUpdate(
  { _id: productId, stockQty: { $gte: qty } },
  { $inc: { stockQty: -qty } },
  { new: true }
)
if (!updated) throw new InsufficientStockError(productId)
```

---

## Step 2 — Fail-all semantics

| Outcome | Cart | Orders | Stock |
|---|---|---|---|
| All decrements OK | cleared in 18.13 | created | reduced |
| Any decrement fails | **unchanged** | **none created** | unchanged |

If one product fails mid-loop, **roll back** any decrements already done in that request — use a MongoDB transaction when available.

---

## Step 3 — HTTP response on failure

Return **409** or **400**:

```json
{ "message": "Insufficient stock", "productId": "..." }
```

Chapter 20 checkout UI can show which product failed.

---

## Step 4 — Concurrency test (recommended)

1. Set one product `stockQty = 1` in Compass
2. Send **two parallel** checkout requests with that product
3. **One succeeds, one fails** — final stock is 0, only one order exists

Write the result in your learning log — interviewers ask about this.

---

## Common mistakes

| Mistake | Fix |
|---|---|
| Decrement after cart clear | Hard to retry — decrement first |
| Partial success | Fail-all + rollback |
| Negative stock allowed | Conditional `$gte` on update |
| Decrement twice for duplicate lines | Aggregate qty per productId first |
