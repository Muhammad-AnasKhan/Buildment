# 3.7 — Prime your thinking

## What you'll do

Before you create `docs/erd-draft.md`, read MongoDB's official data modelling guide. This aligns your design with the vocabulary engineers and interviewers recognize.

## Why this matters

Course prose and official docs use slightly different words for the same ideas. Reading MongoDB's modelling introduction **once** means your ERD and interview answers use vocabulary employers recognize — "embedding for contained data," "reference when entity has independent lifecycle."

&lt;Callout type="info">
You're not learning MongoDB from zero here. You're aligning your sketch with how the manual describes relationships.
&lt;/Callout>

## Mandatory read

**Search for:** *MongoDB manual data modeling introduction*

Read these sections (or the current equivalent):

- Data modeling introduction — relationships
- Embedded data vs references
- One-to-many relationships
- Data duplication and updates

After reading, you should answer:

1. When does MongoDB recommend embedding?
2. When does it recommend referencing?
3. What is the 16 MB document limit implication?

## Mongoose — skim only

**Search for:** *Mongoose schemas getting started*

Skim only — Chapter 5 implements:

- How `ref: 'Store'` enables `populate()`
- Schema types: String, Number, Boolean, ObjectId, Array

**Do not** implement schemas yet — just know what a Mongoose schema will look like.
