# 3.9 — Map actors to collections

**Why this step matters:** Diagrams show structure; actor paragraphs show **behaviour** — who reads which collection, how checkout splits orders, why Vendor B must never see Vendor A's products.

<BigWordAlert term="Collection mapping" plainEnglish="Assigning each business entity (user, store, product, order) to a MongoDB collection name." whyItMatters="FreshMarket ends with users, stores, products, carts, and orders collections — one home per entity type." />

**Where the project is now:** `docs/erd-draft.md` exists with the diagram and collection inventory from 3.8 — the actor × collection behaviour is still unanalysed.

**After this step:** `docs/erd-draft.md` grows an "Actors and collections" section — one read/write paragraph per actor plus the actor × collection table — that becomes your isolation test list for Chapter 8.

<Callout type="info">
Chapter 8 isolation tests start as sentences you write here. "Vendor reads orders where storeId matches their store" becomes the isolation test you write later.
</Callout>

## What to add to your ERD

Extend **`docs/erd-draft.md`** with a section **## Actors and collections** containing one paragraph per actor.

### Vendor (role: `vendor`)

Write a paragraph covering:

- Registers as `users` document with role vendor
- Creates exactly one `stores` document linked by `userId`
- Creates `products` documents with `storeId` pointing to their store only
- Reads `orders` where `storeId` matches their store — never other vendors' orders

### Customer (role: `customer`)

Write a paragraph covering:

- Registers as `users` with role customer
- Browses `products` across all stores — public catalogue
- Creates `cartitems` linked to their userId; multiple vendors in one cart
- Checkout creates one `orders` document per distinct `storeId` in cart

### Actor × collection table

Add this table to your doc:

| Collection | Vendor read | Vendor write | Customer read | Customer write |
|---|---|---|---|---|
| users | own | own register | own | own register |
| profiles | own | own | own | own |
| stores | own | own create one | public info | no |
| products | own store | own store CRUD | published only | no |
| cartitems | no | no | own | own |
| orders | own store's | status update | own as customer | create via checkout |

## Isolation test preview

From vendor paragraph, derive test:

- Vendor B token + Vendor A `product._id` on PATCH → must fail

Document under **## Isolation tests to implement**:

```
- [ ] Vendor cannot PATCH another vendor's product
- [ ] Vendor cannot PATCH another vendor's store
- [ ] Customer cannot GET another customer's cart
```
