# 19.3 — What you'll build

> **[Read]** · Chapter 19 — Payment processing · *Payment Intents, webhook, gated checkout*

Blueprint for the **payments module**, Stripe config, checkout refactor, and webhook route. Read once; verify against repo after 19.16.

## The flow in plain English

| Step | Who | What happens |
|---|---|---|
| 1 | Server | `POST /payments/intent` — read cart, compute total, create Stripe Payment Intent |
| 2 | Browser (Ch 20) | Stripe.js confirms card using `clientSecret` |
| 3 | Server | `POST /checkout { paymentIntentId }` — verify PI with Stripe API, then run Ch 18 pipeline |
| 4 | Stripe | `POST /webhooks/stripe` — signed event as backup / idempotency |

Customer experience: **one charge** for the whole cart. Vendor experience: **split orders** as today — each tagged with the same Payment Intent id.

## Server tree at end of Chapter 19

```
server/src/shared/
  stripe.js                 ← Stripe SDK client from STRIPE_SECRET_KEY

server/src/modules/payments/
  payments.routes.js        ← POST /payments/intent
  payments.service.js       ← cart total → Payment Intent create
  payments.schema.js        ← validate intent request if needed

server/src/modules/orders/
  orders.routes.js          ← POST /checkout now requires paymentIntentId
  orders.service.js         ← verify PI, then existing checkout pipeline

server/src/modules/webhooks/   ← or mount under payments/
  webhooks.routes.js        ← POST /webhooks/stripe (raw body)
  webhooks.service.js       ← signature verify, event dispatch
```

Order model **extends** (migration or schema update):

| Field | Value |
|---|---|
| `stripePaymentIntentId` | Same string on all orders from one checkout |
| `paymentStatus` | `'paid'` when checkout succeeds |

## Endpoints contract

| Method | Path | Auth | Purpose |
|---|---|---|---|
| POST | `/payments/intent` | Customer | Create Payment Intent from **server** cart total |
| POST | `/checkout` | Customer | Body `{ paymentIntentId }` — verify paid, then Ch 18 pipeline |
| POST | `/webhooks/stripe` | Stripe (signature) | Raw body; verify `Stripe-Signature` header |

Mount under `/api` per your app convention. Webhook route must use **`express.raw`** for this path only — JSON parser breaks signature verification.

```bash

# client/.env.example (Chapter 20 UI)
VITE_STRIPE_PUBLISHABLE_KEY=pk_test_...
```

| Variable | Where | Secret? |
|---|---|---|
| `STRIPE_SECRET_KEY` | Server only | **Yes** — never in client or Git |
| `STRIPE_WEBHOOK_SECRET` | Server only | **Yes** — from Stripe CLI or Dashboard webhook |
| `VITE_STRIPE_PUBLISHABLE_KEY` | Client bundle | Public by design — still test mode only |

Add validation in `shared/config.js` — fail fast at boot if secret key missing in dev.

**Currency:** Use one currency for the course (e.g. `inr` or `usd`). Stripe amounts are in **smallest unit** (paise/cents). Document your choice in README.

## POST /payments/intent — behaviour contract

**Input:** Authenticated customer. Cart is source of truth — **no amount in body**.

**Process (spec — you implement):**

1. Load user's cart with products (same as checkout).
2. Reject empty cart → 400.
3. Validate lines (published, stock ≥ quantity) — same pre-checks as checkout.
4. Compute **total in smallest currency unit** — sum of line totals from current product prices.
5. Call Stripe `paymentIntents.create` with that amount, currency, metadata (`userId`, optional cart hash).
6. Return `{ paymentIntentId, clientSecret, amount, currency }` — client needs `clientSecret` for Stripe.js.

**Do not** create orders here. Intent only reserves the payment flow.

## POST /checkout — revised contract

**Input:** `{ paymentIntentId: string }` — required.

**Process (spec — you implement):**

1. Retrieve Payment Intent from Stripe API (server SDK).
2. Reject unless `status === 'succeeded'`.
3. Reject unless `amount` matches server-computed cart total (same formula as 19.10).
4. Reject if this `paymentIntentId` already used for orders (idempotency — 19.13).
5. Run **existing** Chapter 18 pipeline: split, snapshot, stock, clear cart.
6. Set on **each** created order: `stripePaymentIntentId`, `paymentStatus: 'paid'`.
7. Return `{ orders: [...] }` as today.

**Breaking change:** Bare `POST /checkout` without payment must return **400** after this chapter.

## POST /webhooks/stripe — behaviour contract

**Input:** Raw request body + `Stripe-Signature` header.

**Process (spec — you implement):**

1. Verify signature with `STRIPE_WEBHOOK_SECRET` and `stripe.webhooks.constructEvent`.
2. Handle at minimum: `payment_intent.succeeded` (and optionally `payment_intent.payment_failed`).
3. Idempotent: if orders already exist for this PI id, acknowledge without duplicate insert.
4. Return 200 quickly — heavy work can delegate to same checkout service as 19.11.

Register webhook URL in Stripe Dashboard or Stripe CLI forward for local dev.
