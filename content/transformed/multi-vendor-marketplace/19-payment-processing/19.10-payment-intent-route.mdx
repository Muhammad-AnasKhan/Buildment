Before the customer enters a card, the server tells Stripe **how much to charge**. The amount must come from the cart on the server — never from the client.

<BigWordAlert term="POST /payments/intent" plainEnglish="Server route creating Stripe Payment Intent for pending checkout total." whyItMatters="FreshMarket client calls this before showing card form — amount computed server-side." />

---

## Step 1 — Scaffold payments module

```
server/src/modules/payments/
  payments.routes.js
  payments.service.js
```

Mount: `POST /api/payments/intent`  
Middleware: `requireAuth` + `requireRole('customer')`

---

## Step 2 — createPaymentIntent(userId)

1. Load cart (same as checkout) — empty → **400**
2. Validate each line: published, stock OK (same pre-checks as Ch 18)
3. Compute `amount` in **smallest currency unit** (paise for INR, cents for USD)
4. Call Stripe:

```javascript
paymentIntents.create({
  amount,
  currency: 'inr',  // or your config
  automatic_payment_methods: { enabled: true },
  metadata: { userId }
})
```

5. Return:

```json
{
  "paymentIntentId": "pi_...",
  "clientSecret": "pi_..._secret_...",
  "amount": 34500,
  "currency": "inr"
}
```

**Do not** create orders. **Do not** decrement stock. **Do not** clear cart.

## Common mistakes

| Mistake | Fix |
|---|---|
| Accept amount from client body | Server computes from cart |
| Clear cart on intent create | Cart clears only on successful checkout |
| Vendor can create intent | Customer role only |
| Different total formula than checkout | Shared helper |
