**Why this step matters:** Payment integrations fail in invisible ways — wrong amount unit, unconfirmed PI, signature parse errors. This sub-chapter is your **proof script** before Chapter 19 gate and before Chapter 20 UI.

**Where the project is now:** Intent route, gated checkout, webhook, and idempotency implemented — possibly tested piecemeal.

**After this step:** You have reproduced **intent → confirm → checkout → paid orders** with test card `4242…`, verified in Compass and Stripe Dashboard, and exercised webhook signature at least once.

## Test harness overview

Full server path without React (Stripe CLI or API confirm):

```
1. POST /payments/intent     → paymentIntentId + clientSecret
2. Confirm PI (Stripe CLI or test helper) → status succeeded
3. POST /checkout { paymentIntentId } → split orders, paymentStatus paid
4. stripe listen + trigger or replay → webhook 200, no dup orders
```

Chapter 20 adds Stripe.js in browser — not required for **this** gate if steps 1–3 pass via CLI.

## Step 1 — Intent from cart

Customer token; cart with items (two stores ideal):

```bash
curl -s -X POST http://localhost:5000/api/payments/intent \\
  -H "Authorization: Bearer <customer-token>" \\
  -H "Content-Type: application/json" \\
  -d '{}'
```

Save `paymentIntentId`, `clientSecret`, `amount`.

**Check:** Dashboard → Payment Intents → new row, amount matches cart in smallest unit.

## Step 2 — Confirm payment (test mode)

**Option A — Stripe CLI (recommended):**

```bash
stripe payment_intents confirm <paymentIntentId> \\
  --payment-method=pm_card_visa
```

Use test PM from [Stripe testing docs](https://stripe.com/docs/testing) if `pm_card_visa` differs on your account.

**Option B — Minimal HTML scratch page** with Stripe.js and `confirmCardPayment(clientSecret, { payment_method: { card: ... } })` — delete after test; Chapter 20 replaces with checkout page.

**Check:** Dashboard PI status **`succeeded`**.

## Step 3 — Gated checkout

```bash
curl -s -X POST http://localhost:5000/api/checkout \\
  -H "Authorization: Bearer <customer-token>" \\
  -H "Content-Type: application/json" \\
  -d '{"paymentIntentId":"pi_..."}'
```

**Expected:**

- 201 (or 200 on replay) with `orders` array
- Each order: `paymentStatus: "paid"`, same `stripePaymentIntentId`
- Cart empty on subsequent `GET /cart`
- Stock reduced per Ch 18

**Negative tests:**

```bash
# Unpaid or fake PI
curl -s -X POST http://localhost:5000/api/checkout \\
  -H "Authorization: Bearer <customer-token>" \\
  -H "Content-Type: application/json" \\
  -d '{"paymentIntentId":"pi_invalid"}'
```

**Expected:** 4xx — no orders.

## Step 4 — Webhook

Terminal 1:

```bash
stripe listen --forward-to localhost:5000/api/webhooks/stripe
```

Terminal 2 — repeat checkout flow or:

```bash
stripe trigger payment_intent.succeeded
```

**Expected:** Server 200; signature verified log; no duplicate orders when checkout already ran (19.13).

## Step 5 — Idempotency smoke test

Run **same** checkout curl twice with same succeeded PI.

**Expected:** Same order ids; order count in Compass unchanged; stock not double-decremented.

## Decline path (optional)

Confirm with decline test card `4000 0000 0000 9995` or let confirm fail.

**Expected:** PI not succeeded; checkout rejected; **no** orders; cart still full.
