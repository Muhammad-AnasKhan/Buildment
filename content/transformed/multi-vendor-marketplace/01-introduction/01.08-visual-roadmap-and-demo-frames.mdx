Large projects feel easier when you can **see** the destination before implementing details.  
This lesson gives you visual anchors for each major phase, so you always know whether your current build looks correct.

<BigWordAlert term="UI reference frame" plainEnglish="A visual mock of a screen you are aiming for — not pixel-perfect design, but enough to guide layout." whyItMatters="Vendor dashboards and shop pages in this course have target frames so you know what 'done' looks like." />

## Why this matters

Many learners get stuck not because code is impossible, but because success is vague:

- "Is my vendor dashboard supposed to look like this?"
- "Am I done with checkout or still missing core behavior?"
- "What exactly should I demo at the end of the week?"

These frames answer that with clear, observable targets.

## What to capture as proof (image checklist)

Take screenshots as you progress. Treat these as mini deliverables, not optional notes.

| Milestone | Screenshot proof to capture |
|---|---|
| Week 1 complete | Browser shows health response + Compass shows seeded collections |
| Week 2 complete | Vendor logged in, store settings visible, products table with at least one uploaded image |
| Week 3 complete | Cart contains items from two vendors + checkout success screen + order split proof |
| Week 4 complete | Live HTTPS shop page + vendor order inbox + worker notification logs |

Put these files in your project repo under `docs/demo/`:

```text
docs/
  demo/
    week1-foundation.png
    week2-vendor.png
    week3-checkout.png
    week4-production.png
```

## Common beginner mistakes this prevents

| Mistake | What to do instead |
|---|---|
| Building pages that don't map to the intended flow | Check the matching UI preview table before writing UI |
| Skipping a weak chapter and hoping later chapters fix it | Stop and complete the missing milestone screenshot first |
| Finishing features but unable to explain architecture | Practice explaining client → API → data stores → workers weekly |

## Mini reflection

Before opening Chapter 2, answer this to yourself:

1. If someone asks "show me the vendor journey," can I name all steps in order?
2. If checkout "works," can I show visual proof of split orders and price snapshots?
3. Can I explain where Redis and the worker sit in the final architecture?

If any answer is "not yet," keep this page open while building.
