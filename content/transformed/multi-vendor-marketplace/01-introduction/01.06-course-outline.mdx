You will build FreshMarket in four passes. Each pass ends with something you can show in a browser or explain from your repo. The sidebar lists every lesson; this page gives you the bigger picture so you know why the work is in this order.

## Week 1 — Make the project real

Chapters **2–5** give you a running React client, an Express API, a MongoDB connection, and the first data model. The client should call `GET /health`, and your seed script should create two vendors and products you can inspect. Keep an ERD in `docs/erd.md` that shows who owns each store and product.

At the end of the week, open the app and show the API health response. Then open the database and explain one ownership path: Vendor → Store → Product. If either part is missing, finish it before moving into auth.

## Week 2 — Let vendors work safely

Chapters **6–13** add registration, login, role checks, store setup, product management, a vendor dashboard, and product photos. API work is followed by UI work so you can test each feature in the browser. For example, build the store API in Chapter 9, then use it in the "Open your shop" UI in Chapter 10.

The demo is a vendor adding a product with a photo and seeing it in their dashboard. Also sign in as a second vendor and prove they cannot edit the first vendor's product. A working screen without the ownership check is not finished.

## Week 3 — Let shoppers buy across stores

Chapters **14–20** build the public catalogue, a saved cart, checkout, Stripe test payments, and order history. A cart can contain products from two stores. The server groups those lines into separate vendor orders while the shopper makes one checkout attempt. Each order stores the product name, unit, and price at purchase time.

For the week demo, buy from two stores. Show two orders in the database, then change a product price and show that the old receipt stays the same. The payment confirmation and order status shown in the UI must come from the server, not a browser guess.

## Week 4 — Make it reliable and ship it

Chapters **21–25** and the closing module are required work. Add search and cache invalidation, move slow work to a queue, and deploy the first public version in Chapter 23. Then add inventory holds in Chapter 24 and server-calculated promotions in Chapter 25. Deploy those changes too; the first deployment is a baseline, not the end of the course.

The final demo should show a public HTTPS link, a checkout that does not oversell the last unit, and a promotion whose server total matches the Stripe test amount. Finish with the README, a short demo recording, and a case study you can defend to a mentor.

## How to move through a module

Start with the problem and the decision. Use the short check to see whether you understand it. Then build the feature, run the verification steps, and keep evidence for the module gate. Some modules include a reading card, diagram, or interactive canvas to make a difficult relationship easier to see. Those help you reason; your repo and test results are still the proof.

The course content and the app you build are separate. Your FreshMarket code starts in the repo you create in Chapter 2. If you forget where a lesson lives, use the course sidebar instead of scrolling through a long table of filenames.
