Four weeks is long enough for good habits to matter and long enough for bad ones to wreck you. This page is the last read before the Chapter 1 gate. Internalize these habits now — you'll hear them again when you deploy secrets, debug auth, or fix checkout at midnight.

## Commit every day

Commit at the end of every work session — when a **sub-chapter step verifies**, not when it's perfect.

**Good moments:** health route returns 200, seed runs clean, register creates a hashed user.

**Bad moments:** "wip" with broken server, one 4,000-line commit you can't explain.

**Commit message shape:** Short imperative — `add vendor product PATCH with ownership check`.

## Secrets never enter Git

Before every push:

```bash
git status
git check-ignore -v server/.env client/.env
```

Before deploy, run `git log --all --full-history -- "**/.env"` — empty output is good.

Secrets live in `.env` on your machine and in the host's env panel — nowhere else.

## Read the error before the tutorial

1. Read the full error — stack trace bottom to top
2. Identify the layer — MongoDB? JWT? CORS? React?
3. Read the doc for that error
4. Reduce — curl without UI; one query in Compass
5. Ask with *"I expected X, got Y, I tried Z"*

## One sub-chapter at a time — finish the gate

Complete the verify step before the next lesson. Tick the chapter gate only when every box is observable. Write learning log answers in the platform before marking the chapter complete.

## Keep the repo runnable

After every chapter gate, `npm run dev` in both folders should work without fixing broken imports first.

## When to use AI — and when not to

**Good:** explain an error you read first, clarify a concept, sample curl commands.

**Risky:** paste the spec and ask for the handler, accept code you can't walk through, skip the learning log.

## Physical rhythm

~60 hours/week is full-time. Scale weeks if part-time — still clear every gate. Two terminal tabs (server + client), Compass open during database chapters.
