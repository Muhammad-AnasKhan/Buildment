## Single-page vs wizard

Both ship the same data — the difference is how many screens the vendor has to click through before the API call happens.

| | Single form (course default) | Multi-step wizard |
|---|---|---|
| Steps | One screen — all fields | Name → address → confirm |
| Chapter 10 scope | ✓ faster to ship | Optional stretch |
| API calls | One POST | Still one POST at end |

**✅ Do:** Ship single page for gate. **Optional stretch:** Split UI only — still one POST.

## Layout + Outlet mental model

```
Route: /vendor element=<VendorLayout>
  Child: open-shop → <OpenShop />     ← no gate redirect
  Child: settings  → <StoreSettings /> ← gate required
  Child: products  → <Stub />          ← gate required
```

`VendorLayout`:

1. If path is open-shop → render Outlet without gate (or gate only checks auth)  
2. Else → fetch GET me → 404 redirect open-shop  
3. Else → render nav + Outlet  

## Loading states

The three phases below cover every request the layout makes. Getting them right is what separates "feels instant" from "flash of wrong screen."

| Phase | UI |
|---|---|
| GET me pending | Full-layout spinner or skeleton |
| GET me 404 on gated route | Redirect — no flash of dashboard |
| POST pending | Disable submit + "Opening shop…" |

**❌ Don't:** Show empty dashboard for 200ms then redirect — jarring.

## Preserve return URL (stretch)

After login, redirect vendor to intended path:

- Tried `/vendor/products` → 404 store → open-shop → after POST → **optional** land on products  

Not required for gate — note in learning log if implemented.
