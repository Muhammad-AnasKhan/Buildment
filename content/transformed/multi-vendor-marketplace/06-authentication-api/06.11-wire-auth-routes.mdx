**Why this step matters:** Unmounted routers are dead code — Express must expose `/api/auth/*` before any handler runs. One mount line in `app.js` is how every future module (stores, products) attaches too.

<BigWordAlert term="Route mounting" plainEnglish="Attaching a router module to a URL prefix like `/api/auth` in the main Express app." whyItMatters="FreshMarket mounts auth at `/api/auth/register`, `/api/auth/login` — predictable URLs for the client." />

**Where the project is now:** Auth router exists but not mounted on Express app.

**After this step:** `app.js` mounts auth routes at `/api/auth`. Unregistered paths under prefix return 404; health route unchanged.

## Mount specification

In `server/src/app.js`:

```
import authRoutes from './modules/auth/auth.routes.js'

app.use('/api/auth', authRoutes)
```

**Order:**

1. `express.json()` middleware  
2. CORS (if configured from Ch 2)  
3. `/health` route  
4. `/api/auth` router  
5. 404 handler optional  

## Path resolution

Full paths become:

| Router path | Full URL |
|---|---|
| POST `/register` | POST `/api/auth/register` |
| GET `/me` | GET `/api/auth/me` |

curl must use full path including `/api`.

## CORS note for Chapter 7

If client will send credentials (refresh cookie), CORS must allow credentials from Vite origin — configure when adding cookies in Ch 7. Bearer-only curl in Ch 6 works without credential CORS.

## ✅ Do / ❌ Don't

**✅ Do:** Use `/api` prefix — separates API from future static routes.

**✅ Do:** Restart server after app.js change.

**❌ Don't:** Mount auth before json parser — body undefined.

**❌ Don't:** Remove or relocate health route.
