Chapter 6 turned an anonymous API into an **authenticated** one. Every protected route from here forward builds on `requireAuth` and the token contracts you tested with curl.

<BigWordAlert term="Authenticated API" plainEnglish="Server that can register users, issue tokens, and reject unauthenticated requests on protected routes." whyItMatters="Chapter 7 wires the React client to store tokens; Chapter 8 adds authorization on top of identity." />

## What you built

**Register:** bcrypt password hash, User + Profile creation, OTP generation, duplicate email rejection.

**Verify OTP:** isVerified gate before login.

**Login:** Credential check, 403 for unverified, access + refresh tokens issued.

**Access JWT:** Short-lived, sub + role, Bearer header.

**Refresh:** Hashed in DB, rotation endpoint, revocation on logout.

**requireAuth:** 401 on bad/missing/expired token; req.user for downstream handlers.

**GET /me:** Protected smoke test returning user + profile without secrets.

## Handoff to Chapter 7 — keep contracts stable

Chapter 7 will call these exact shapes from React. Do **not** rename fields after the gate.

| Your curl response field | Chapter 7 usage |
|---|---|
| `accessToken` | Stored in useAuth memory; sent as Bearer |
| `refreshToken` | Moved to httpOnly cookie in 7.x (body OK for 6.x curl) |
| `user.id` | Auth context identity |
| `user.role` | Post-login redirect (vendor vs customer) |
| `user.displayName` | Navbar / profile stub |
| 401 on bad token | Triggers client refresh loop |
| 403 on unverified | VerifyOtp page redirect from Register |

<InterestingRead title="Refresh tokens: why one token is not enough" hook="Short access tokens limit damage; refresh tokens limit annoyance." readMinutes={5}>

If access tokens lived for weeks, a stolen token would stay valid for weeks. If they expired every minute, users would log in constantly. FreshMarket uses brief access tokens plus longer refresh tokens — a pattern you will wire on both server and client.

</InterestingRead>
