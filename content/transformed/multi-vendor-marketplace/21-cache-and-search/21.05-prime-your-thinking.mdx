## Topics to understand

Four concepts, one chapter. The first is the one that will appear in every interview answer about caching; the others protect you from foot-guns you might otherwise only discover in production. None of them needs to be implemented *perfectly* — they need to be understood before you type `redis.js`.

## Mandatory reading pointers

Read in this order: start with Redis's own commands so you know the primitive you are building on, then the cache-aside pattern so you know the shape of the flow, then MongoDB text indexes so search in 21.12 does not surprise you.

**Primary:** Redis documentation — `GET`, `SET`, `EX` (expiry), connection URL format.

**Secondary:** Search "cache-aside pattern" — any article that shows read path: check cache → miss → DB → set cache.

**Tertiary:** MongoDB text indexes — official docs section on `$text` queries.

## In plain English

| Pattern | Simple meaning |
|---|---|
| **Cache-aside** | Application code decides when to read/write cache — you control it in middleware or service |
| **Read-through** | Cache library fetches from DB automatically — not what this course uses |
| **Thundering herd** | TTL expires → 100 users all miss cache at once → 100 MongoDB queries simultaneously |

## Common beginner mistakes (read before coding)

1. **Caching before measuring** — 21.7/21.10 want before/after numbers; measure baseline first.
2. **One global cache key** — filters and pagination need distinct keys or you serve wrong pages.
3. **Forgetting invalidation on DELETE** — product gone from DB but still in cache.
4. **`KEYS catalogue:*` in production** — blocks Redis; use `SCAN` in invalidation helper.
5. **Caching authenticated responses on public route** — catalogue is public; cart is not.
