Filters let customers narrow the catalogue — "only fruit" or "only from Green Valley". The important lesson: **changing a filter refetches the API**, it does not hide rows in React.

<BigWordAlert term="Client-side filter state" plainEnglish="React state (or URL sync) tracking category, search, sort — drives API query params." whyItMatters="FreshMarket filter bar refetches `/products?…` when shopper changes filters." />

## Why refetch, not client-side filter?

The API returns **one page** of products (20 items). If you filter those 20 in React, you miss products on page 2, 3, etc. Always send `category` and `storeId` as query params to `GET /products`.

## Step 1 — Create the filter component

**File:** `client/src/components/CatalogueFilters.jsx` (or build inline in Shop.jsx)

**Props:**

| Prop | Purpose |
|---|---|
| `category` | Current category value |
| `storeId` | Current store value |
| `onCategoryChange` | Parent updates state |
| `onStoreChange` | Parent updates state |

## Step 2 — Category dropdown

| Option | Value sent to API |
|---|---|
| All categories | `''` — omit param |
| vegetables | `vegetables` |
| fruit | `fruit` |
| … | Match your seed categories exactly |

Store options in `client/src/constants/categories.js` — same strings as seed script.

Use a `<select>` with a visible label: "Category".

---

## Step 3 — Store dropdown

For MVP, hardcode store ids from your seed:

```javascript
// client/src/constants/stores.js
export const SHOP_STORES = [
  { id: '...paste from Compass...', name: 'Green Valley Grocer' },
  { id: '...', name: 'Harbor Fresh Market' },
]
```

| Option | Value |
|---|---|
| All stores | `''` |
| Each store | store `id` string |

A public `GET /stores` endpoint is optional — hardcoding is fine for this chapter.

---

## Step 4 — Wire state in Shop.jsx

```javascript
const [category, setCategory] = useState('')
const [storeId, setStoreId] = useState('')
const [page, setPage] = useState(1)

function handleCategoryChange(value) {
  setCategory(value)
  setPage(1)  // always reset page when filter changes
}

function handleStoreChange(value) {
  setStoreId(value)
  setPage(1)
}
```

Pass handlers to `CatalogueFilters`.

---

## Step 5 — Map UI to query params

| UI state | Query param |
|---|---|
| category `''` | omit `category` |
| category `'fruit'` | `?category=fruit` |
| storeId `''` | omit `storeId` |
| storeId set | `?storeId=...` |

Build params object and strip empty strings before calling `getProducts()`.

---

## Step 6 — Add Clear filters button

One button that sets `category` and `storeId` to `''` and `page` to `1`, then refetches.

Disable filter controls while a fetch is in progress — prevents double-clicks.

---

## Verify in Network tab

| Action | Network request should show |
|---|---|
| Select "fruit" | `GET /products?...&category=fruit` |
| Select a store | `...&storeId=...` |
| Clear filters | Params removed |
| Both filters | Both params present |

---

## Common mistakes

| Mistake | Fix |
|---|---|
| Filter array in React only | Refetch API |
| Wrong category casing | Match seed exactly — `fruit` not `Fruit` |
| Forget page reset | Empty grid on page 5 after filter |
| Require login for filters | Public browse — no auth needed |
