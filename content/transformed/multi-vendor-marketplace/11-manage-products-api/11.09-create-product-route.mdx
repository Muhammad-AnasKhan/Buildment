This is where vendors add stock to their stall. The critical rule: **`storeId` comes from the vendor's store** — never from the request body. Accepting storeId from the client would let a vendor put products in someone else's shop.

<BigWordAlert term="Product creation" plainEnglish="POST endpoint that attaches a new product to the vendor's store with validated fields." whyItMatters="FreshMarket vendors add mangoes and milk through this route — links product.storeId automatically." />

## Step 1 — Route middleware chain

```
POST /api/products
  requireAuth
  requireRole('vendor')
  validateCreateProduct(body)
  createProductHandler
```

---

## Step 2 — Service: createProduct(vendorId, body)

| Step | Action |
|---|---|
| 1 | Find vendor's store: `getStoreByVendorId(vendorId)` |
| 2 | No store → **404** (vendor must complete Ch 10 first) |
| 3 | Build product: validated fields + `storeId: store._id` |
| 4 | Default `isPublished: false` |
| 5 | Save → return 201 |

**Strip** any `storeId` sent in the body — ignore client tampering.

---

## Step 3 — Request body fields

| Field | Rule |
|---|---|
| name | required |
| price | required, > 0 |
| unit | required enum (kg, litre, each, …) |
| stockQty | required, ≥ 0 |
| isPerishable | boolean |
| description | optional |
| weightOrQuantity | per your ERD |

Match your Product schema exactly.

## Error matrix

| Condition | Status |
|---|---|
| No token | 401 |
| Customer | 403 |
| Vendor, no store | 404 |
| Invalid body | 400 |
| Valid | 201 |

---

## Common mistakes

| Mistake | Fix |
|---|---|
| storeId from request body | Resolve from JWT + store lookup |
| Customer can POST | requireRole('vendor') |
| Auto-publish on create | Default isPublished false |
