Vendors need to see **their own inventory** — drafts and published together. This is a different route from the public shop catalogue (Chapter 14).

<BigWordAlert term="Vendor product list" plainEnglish="GET endpoint returning all products for the authenticated vendor's store — including unpublished." whyItMatters="Dashboard product table loads from this route — drives publish toggles and edit links." />

| Route | Who | What it returns |
|---|---|---|
| `GET /vendor/products` | Vendor | All own products (draft + published) |
| `GET /products` | Public | Published + in-stock only (Ch 14) |

---

## Step 1 — Add the route

```
GET /api/vendor/products
  requireAuth
  requireRole('vendor')
  listVendorProductsHandler
```

Customer token → **403**

---

## Step 2 — Service logic

```
1. Find store for vendorId from JWT
2. No store → 404 (matches POST product behaviour)
3. Product.find({ storeId: store._id }).sort({ createdAt: -1 })
4. Return { products: [...] }
```

**Never** accept `storeId` as a query param from the client — scope comes from auth only.

---

## Step 3 — Response shape

Include fields the dashboard needs:

- `_id`, `name`, `price`, `unit`, `stockQty`, `isPublished`, `isPerishable`, `imageUrl` (after Ch 13)

Pick one JSON shape and document it:

```json
{ "products": [ ... ] }
```

Chapter 12 UI depends on this shape.

## Common mistakes

| Mistake | Fix |
|---|---|
| Reuse public GET /products | Wrong filters — separate route |
| Filter published only | Vendor needs drafts too |
| storeId from query string | Derive from JWT |
