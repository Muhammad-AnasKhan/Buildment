# 24.02 — Why overselling hurts trust

A single field `stockQty: 4` on a MongoDB product document feels like inventory control. It is only **accounting after the fact** unless every checkout path updates that number inside an atomic rule that concurrent requests cannot bypass.

## The race you already have

Imagine two tabs, one customer, or two customers one second apart:

```
Tab A reads stockQty = 1
Tab B reads stockQty = 1
Tab A checkout succeeds → order created
Tab B checkout succeeds → order created
Both paid → you owe two units, shelf has one
```

No bug in Stripe caused this. **Read-modify-write without a guard** did.

<Callout variant="warning" title="Common junior fix that fails">

Setting `stockQty = stockQty - 1` in application code after saving the order still races — two requests both read `1`, both write `0`, both create orders.

</Callout>

## Why grocery is worse than generic e-commerce

| Factor | Generic SKU | FreshMarket grocery |
|---|---|---|
| Substitutions | Optional | Expected for produce |
| Shelf life | Long | Hours to days |
| Vendor ops | Pick/pack later | Same-day pick windows |
| Customer emotion | Annoyance | “You wasted my trip” |

Overselling pushes work onto vendors at the worst time — when they are picking for delivery slots.

## What production systems do

They separate **physical stock** from **sellable stock**:

- **On hand** — what the vendor counted this morning.
- **Reserved** — promised to in-flight checkouts.
- **Available to promise (ATP)** — on hand minus reserved (and sometimes minus safety stock).

FreshMarket v1 keeps one `stockQty` as on-hand and tracks reservations in a sibling collection so you do not rewrite Chapter 5’s product shape entirely.

## Failure modes to design for

1. **Payment succeeds, reservation missing** — never double-sell; confirm must be idempotent on `paymentIntentId`.
2. **Payment abandoned** — hold must expire; stock returns to ATP without manual ops.
3. **Worker slow** — expiry job must not release a hold that flipped to `confirmed` milliseconds earlier.
4. **Partial cart** — reserve per line item; releasing one line must not drop the whole checkout hold incorrectly.

## Interview sentence

> “We hold inventory at checkout with a TTL, confirm on webhook, and expire holds in a worker with compare-and-set on reservation status so retries are safe.”
