# 24.07 — Where the project is now

> **[Bridge]** · Chapter 24 — Inventory reservations · *Baseline*

You should be starting this module from a **deployed or locally production-parity** tree: Chapters 16–20 checkout and payment, Chapter 22 worker running, Chapter 23 env discipline.

## Expected starting behaviour

- `Product.stockQty` exists from Chapter 5.
- Checkout creates orders and a Stripe PaymentIntent without checking concurrent ATP.
- Catalogue APIs may expose `stockQty` directly to the client.
- Worker processes `order.created` — not inventory yet.

## Files you will extend (not replace)

| Area | Typical path | Change |
|---|---|---|
| Checkout controller | `server/modules/checkout/` | Call `reserveForCheckout` before PI |
| Stripe webhook | `server/modules/payments/webhook` | Call `confirmReservations` |
| Product serializers | catalogue routes | Add `availableQty` |
| Worker processors | `worker.js` | Register expiry handler |

## Environment

No new secrets. Reuse `REDIS_URL` if you schedule expiry via BullMQ delayed jobs — optional pattern documented in 24.11.

## Smoke before you code

1. `npm run dev` (API) + `npm run worker`
2. One product with `stockQty: 2` in seed data
3. Complete a paid checkout — note current stock behaviour (likely unchanged until you implement confirm)

Tick mentally: **payment works**; **concurrency does not**. That is the gap.
