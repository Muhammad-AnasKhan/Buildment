# Canvas spec: sysdesign-m8-leader-followers

- **Course and chapter:** system-design, 8.2 beat 4 ("Send writes, read anywhere, kill the leader").
- **Renderer:** custom component on `BeatFrame` and `useBeatClock`. The traffic playground cannot carry a log strip and a refusal chip, so the picture is drawn here with `SvgNode`, `SvgButton`, `DotGrid` and `VerdictBanner`. A reason for custom: the learner taps three different things (Write, a node to read, Kill) and the log strips fill at different times.
- **Claim:** followers copy the leader's log in the leader's order and can answer reads, possibly one write behind. When the leader dies, reads continue and writes stop.
- **Model (`model.ts`):** a leader and two followers. Each Write tap appends the next entry to the leader (the app's request takes 0.3 s of scene time) and sends it to the followers. Copy delay in model time: follower 1 300 ms, follower 2 800 ms (made up; real lag is usually under a second [S38]), slowed down 4 times so a learner can read a node before the copy arrives. A node shows `x = n` for the last entry it applied. A Read tap returns that value and compares it with the leader's value at that moment: equal is green "up to date", smaller is amber "one behind" (or "N behind"). Kill leader: a write that has not reached the leader yet is lost with it; copies already sent still arrive.
- **Inputs:** tap Write (at most 9 entries, then the chip becomes "Reset log"); tap any node card to Read; outside the picture Kill leader and Reset.
- **What moves:** numbered dots travel app to leader and leader to each follower; three log strips fill box by box (dashed box: the leader has it, this copy not yet); the read chip sits beside the node; after Kill the leader dims, turns red and Write shows a "no leader" chip.
- **Verdicts:** "Followers copy the leader's log"; "That read is one write behind"; "That copy is up to date"; "Reads work; writes are stopped"; "No leader: nobody can take writes"; start: "Tap Write to send a change"; leader read after kill: "The leader is down: no answer".
- **Deviations from the written spec:** no separate Kill chip inside the picture; Kill leader is the outside button (the spec asks for both, which would be the same action twice). Reduced motion shows a settled picture: copies arrive at once, so a stale read cannot be shown there.
- **Accessibility:** the picture is a group with a live summary label; Write and every node card are real `role="button"` groups with Enter and Space; focus ring from `SvgButton`; colours are always paired with words ("one behind", "up to date", "down").
- **Sources:** [S38] hot standby, asynchronous streaming replication; [S39] Aurora replicas; [S44] each DynamoDB partition has a leader.
