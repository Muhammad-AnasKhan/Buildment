# Canvas spec: sysdesign-m18-isolation-layers

- **Course and chapter:** system-design, 18.2 "Linux under containers", beat 2 ("Namespaces decide what a process sees").
- **Renderer:** custom beat canvas on `BeatFrame`, `SvgChip` (four switches), `TightRailSlider` with `SliderRail` (memory and CPU limits), `InfoChip`, `VerdictBanner`, `useBeatClock`.
- **Claim:** A container is an ordinary process with a limited view (namespaces) and limited resources (cgroups). Each namespace hides one kind of thing. A memory limit kills; a CPU limit only slows.
- **Model:** `model.ts`, unit tested. One service on a made-up host with 212 processes, port 3000 taken on the host and the host name `ops-server`. Switches PID, Network, Mount, Host name (all on at first). PID on: 1 process (itself, as number 1), off: 212. Network on: its own free port 3000, off: the host's port 3000 is taken. Mount on: only the image's files, off: the host's `/etc` and `/home`. Host name on: `a1b2c3d4e5f6`, off: `ops-server`. Killed when the memory limit is below 150 MB. Request time in ms = 200 / min(CPUs, 1).
- **Check points (tested):** 256 MB, 1 CPU: runs, 200 ms. 128 MB, 1 CPU: killed (exit 137). 256 MB, 0.5 CPU: 400 ms (course measurement 406 ms). 256 MB, 0.25 CPU: 800 ms.
- **Inputs:** tap four chips in the container card (real buttons, `aria-pressed`). Two rails: memory 64 to 512 MB on 16 MB steps (128 and 256 are steps and carry labelled ticks; a red tick marks 150), CPU 0.25 to 2 on quarter steps (0.5 and 1 carry ticks). Arrow keys, Page keys, Home and End move a rail. Outside the picture: Reset.
- **Motion:** the "what it sees" rows change at once (a single dot for one process becomes sixteen small dots and "212 on the host"; the port row turns red on a clash). The memory bar fills to 150 MB with a red cut line at the limit; below 150 MB the bar turns red and stops at the cut. A request dot crosses the lane in a time that follows the CPU limit (200 ms is 0.9 s of picture time). A killed container dims its rows and shows "killed: exit 137"; the request dot disappears. Reduced motion shows the dot at the far end.
- **Verdicts (all 38 characters or fewer):** "Isolated: it sees only itself"; "It can see and signal host processes"; "Port 3000 clashes with the host"; "It can read the host's files"; "It sees the host's name"; "Over the memory limit: killed"; "CPU limit: slower, never killed". When several apply the most severe shows first: killed, then the first switch that is off (PID, Network, Mount, Host name), then a CPU limit.
- **What to notice:** each switch off leaks exactly one kind of thing; a CPU limit never kills, a memory limit does.
- **Limits (in the fold):** one service, one made-up host, four of the namespaces; one thread, rounded request times.
- **Sources:** namespaces(7) and cgroups(7) [S117]; course measurements 213 ms and 406 ms (challenge 17).
