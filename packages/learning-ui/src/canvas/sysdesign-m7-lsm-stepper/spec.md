# Canvas spec: sysdesign-m7-lsm-stepper

- **Course and chapter:** system-design, 7.3 ("Indexes, B-trees and LSM trees"), beat "Step through writes, flushes and merges".
- **Renderer:** custom beat canvas on `BeatFrame`, with the step state from `primitives/stepper.ts` (`stepperReducer`, Play stops on the last step, arrow keys step) and a picture of its own. `primitives/design-stepper.tsx` was not used: it steps through fixed text, and here the two counters are computed from the toy engine's state. Model: `models/lsm-stepper.ts`.
- **Claim:** An LSM tree gets fast writes by appending and pays later: more files mean slower reads, and merging them rewrites data (write amplification).
- **Model (made up, toy sizes):** memory table limit 4 keys; each put is 1 log write; a full memory table flushes 4 key writes into a new sorted file (newest first); a merge rewrites every file into one with one disk write per distinct key, newer values winning. Disk writes = log + flush + merge. Write amplification = disk writes / puts. A read of seat-01 checks memory first (0 files if found there), then files newest to oldest, counting each file opened. With Bloom filters on, a file is opened only if it holds the key (an exact toy filter with no false positives).
- **Script (18 steps, one per press):** steps 1 to 12 put seat-01 to seat-12 (flush after 4, 8, 12); 13 and 14 overwrite seat-03 and seat-07 ("sold"); 15 merges the 3 files; 16 and 17 put seat-13 and seat-14 (flush after 17, which also writes the two overwrites); 18 merges the 2 files.
- **Counters (checked in the unit test):** step 4: 4 puts, 1 file, 8 disk writes, 2.00, 1 / 1 files read; step 8: 2 files, 16, 2.00, 2 / 1; step 12: 3 files, 24, 2.00, 3 / 1; step 14: 14 puts, memory 2 keys, 26, 1.86, 3 / 1; step 15: 1 file, 38, 2.71, 1 / 1; step 17: 16 puts, 2 files, 44, 2.75, 2 / 1; step 18: 1 file, 58, 3.63, 1 / 1.
- **Inputs:** Back, Next, Play and Pause under the picture, arrow keys on the picture, and one toggle "Bloom filters" (default off).
- **Picture:** a Memory table card with four key slots; two counter cards on the right ("files per read", "writes per put"); a dashed guide line with a dot that walks to each file the read opens; up to three file cards (newest first) with a status pill (found, opened or skipped), the key range and one cell per key (blue for seat-01, amber for an overwritten key); two bars, "You wrote" (puts) and "Disk wrote" (log, flush, merge segments), on one scale; a progress strip of 18 ticks. New keys fade in, a flushed file slides down from the memory table, a merged file slides in from the right; the existing files slide to their new slot (CSS transitions, so the final state is always drawn).
- **Verdicts (38 characters or fewer):** "Press Next to put the first key in"; "Put seat-05: log, then memory"; "Table full: flushed to a new file"; step 12 off: "3 files: a read opens all of them"; on: "Bloom filter: opens 1 file of 3"; "Overwrite: old copy stays in a file"; step 15: "Merged: 1 file, 12 more writes"; step 18: "Fewer files, but 3.63 writes per put".
- **Reduced motion:** the dot rests on the file where the key is found; transitions and fades are off.
- **Accessibility:** the step group is focusable with arrow keys, Home and End; the SVG has a description with the counters; a live region says what each step did.
- **Limits shown to the learner:** toy sizes, 4 keys per memory table; real engines keep levels, many files, a log and background threads.
- **Sources:** RocksDB overview: memtable, log, flush, compaction [S37]; Bloom filter [S113].
