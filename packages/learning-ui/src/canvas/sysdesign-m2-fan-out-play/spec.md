# Canvas spec: sysdesign-m2-fan-out-play

- **Course and chapter:** system-design, 2.4 ("Percentiles and tail latency"), for the fan-out beats. New slug; the lead registers it. It can replace `sysdesign-m2-fan-out-odds` (the watched scene), whose numbers it matches, and could also stand in for `sysdesign-m2-fan-out-tail` (drag to 3 backends and wait for a slow load).
- **Renderer:** custom beat canvas on `BeatFrame`. It reuses `primitives/picture-slider.tsx` (the drag rail inside the picture, shared with the traffic playground), `SvgNode`, `DotGrid`, `VerdictBanner` and `BeatButton`. A custom component because the picture is a fan of up to 100 backends and a tally, which no renderer draws.
- **Claim:** Fan-out turns rare slowness into common slowness. A page that waits for n calls, each slow 1 time in 100, is slow with chance 1 - 0.99^n.
- **Input:** n, the backends one page calls, 1 to 100 on a linear rail inside the picture, snapping to 1, 10, 20, 50 and 100. Arrow keys step by 1, Page keys by 10, Home and End go to the ends. Default 20. One button: "Load the page" starts a new load at once; loads also repeat on their own every 3.6 seconds.
- **Model** (`models/fan-out.ts`): `slowChance(n) = 1 - 0.99^n`. `pageLoad(n, k)` draws load number k from a seeded random source: each call is slow (1,000 ms) with chance 1 in 100, otherwise 8 to 15 ms; backend i draws the same numbers whatever n is, so adding backends only adds chances to be slow. The page's time is its slowest call. `tallyLoads` counts finished loads since n last changed.
- **Numbers to check against the chapter:** n = 1: 1%. n = 10: 10% (9.6%). n = 20: 18%. n = 50: 39%. n = 100: 63%.
- **Picture:** a panel of backends above, the app server below it, and a tally card beside the app server, all on one dotted canvas (420 by 372). One wire joins the app server to the panel and lights up while the page waits; a request dot travels up it. The panel scales with n (`models/fan-out-layout.ts`): up to 6 backends are cards with a server icon and a reading ("asked", "slow", "12 ms", "1 s"); 7 to 100 are a grid of tiles that gets smaller as n grows (about 49 units at 7, 15 at 100), with the icon while the tile is at least 26 units. Each load: the call reaches the tiles in a wave from the left (blue), fast tiles answer within about a second (a green ripple, then green), a slow tile is red with a pulsing ring until its late reply, which ripples red and turns solid. The app server's pill counts replies ("17 of 20 back"), then says "fast: 14 ms" or "slow: 1,000 ms" and gets a red ring. The tally card draws the last 42 finished page loads as green and red squares (a dashed square is the load in progress), a "fast / slow" key, and "3 slow of 14".
- **Numbers visible at once:** the chance (in the verdict), the app server's pill, the tally line.
- **Verdict:** "N% of page loads hit a slow call", green under 5%, amber under 30%, red from 30%.
- **Reduced motion:** no automatic loads; each press of "Load the page" shows the next finished load and adds it to the tally.
- **Accessibility:** the picture is one `role="slider"` whose value text gives n and the verdict; the SVG description says n, the chance, this load's result and the tally. The button is a real button. Colour is never the only signal: the pill and tally say it in words.
- **Sources:** [S8] Dean and Barroso, The Tail at Scale, CACM 2013 (100 servers, 1 in 100 slow, 63%).
