# Canvas spec: sysdesign-m7-two-writers

- **Course and chapter:** system-design, 7.5 ("Locks, MVCC and compare-and-set"), beat "Two writers, one row".
- **Renderer:** custom beat canvas on `BeatFrame`, with `primitives/rail-slider.tsx` and `SliderRail` for the think time and `primitives/beat-segmented.tsx` for the rule. The kit's `timeline` renderer was not used because the picture needs hatched wait bars and red refused marks; the three rules are a pure model in `models/two-writers.ts` (the same rules can feed chapter 7.8's data).
- **Claim:** With no protection two writers lose an update when the think time opens a gap. A row lock makes the second writer wait for the first one's whole transaction. A version check makes the second writer repeat its work. Nothing is lost with either.
- **Model (ms, made up):** writer A starts at t = 0, writer B at t = 2. A read takes 1, a write 1, think time T is the same for both; A commits at 2 + T. Nothing: B reads at 2 to 3, so for T > 0 it works from an old read, one update is lost, finish 4 + T; for T = 0 there is no overlap and finish is 4. Row lock: B waits T, then reads, thinks and writes: finish 4 + 2T, no loss, no retry. Version check: B's compare-and-set at 3 + T is refused, B reads, thinks and writes again: finish 5 + 2T, one retry, wasted work T; for T = 0 there is no collision and finish is 4.
- **Worked values at T = 50 (tested):** Nothing: lost 1, retries 0, finish 54. Row lock: lost 0, B waits 50, finish 104. Version check: lost 0, retries 1, wasted 50, finish 105. At T = 0 all three finish at 4 with no loss.
- **Inputs:** think time on a rail inside the picture with snaps 0, 10, 25, 50, 100 ms (default 25); a segmented control under the picture: Nothing, Row lock, Version check (default Nothing).
- **Picture:** lanes Writer A, Writer B and Row over a time axis in ms (it rescales with the think time); bars for read (blue outline), think (grey), write (solid blue), a hatched bar for B's wait, a red mark for B's refused write; the Row lane shows 100, then 150, then 130 (red, the lost update) or 180 (green); three counters: lost updates, retries, ms to finish. Read, write and refused marks are drawn at least 6 units wide so a 1 ms bar can be seen. A marker sweeps the time axis and the bars it passes over light up.
- **Verdicts (38 characters or fewer):** Nothing with T > 0 "One update lost"; Nothing with T = 0 "No overlap, no loss (this time)"; Row lock "B waited, nothing lost" (with T = 0 "No wait, nothing lost"); Version check with a retry "B repeated its work, nothing lost"; without a retry "No collision, no retry".
- **Accessibility:** the rail is a `role="slider"` with a value text; the group description gives the counters and the row's end value.
- **Limits shown to the learner:** two writers only, made-up times; with many writers retries grow fast, and challenge 6 measures it on PostgreSQL.
- **Sources:** PostgreSQL explicit locking docs (read 2026-10-24); compare-and-set and conditional writes [S42], [S52]; retries and jitter [S89].
