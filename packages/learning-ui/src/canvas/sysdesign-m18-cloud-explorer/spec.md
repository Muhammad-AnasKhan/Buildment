# Canvas spec: sysdesign-m18-cloud-explorer

- **Course and chapter:** system-design, 18.7 "Cloud building blocks", beat 3 ("Play: pick a block for each need").
- **Renderer:** custom beat canvas on `BeatFrame`, `SvgButton` (six needs and eight blocks as real buttons with `aria-pressed`), `InfoChip`, `VerdictBanner`, `BeatButton` (Reset). `block-map` and `sorter` do not fit: `block-map` selects one block and shows a fixed panel, while this picture needs a need and a block selected together; the cards are drawn here in the same style.
- **Claim:** Every need maps to a block, and the best block is the one that matches the shape of the load. Managed blocks cost more per unit and remove work.
- **Model:** `model.ts`, unit tested. Needs: serve the API (steady, 100 requests a second), resize a photo (10 a day, about 2 seconds each), keep 2 TB of note exports, store notes in a relational database, queue the order emails, speed up repeated reads. Blocks with AWS names and made-up unit prices: virtual machine (EC2) $0.04 an hour; containers (ECS or EKS) $0.05 an hour per container; function (Lambda) $0.20 per million requests plus $0.0000167 per second of 1 GB; object storage (S3) $0.02 per GB-month; block storage (EBS) $0.10 per GB-month; managed database (RDS) $0.10 an hour; queue (SQS) $0.40 per million requests; cache (ElastiCache) $0.05 an hour. Each need has one best block, one acceptable block, and a one-line reason for every other pick. Monthly price = unit price x quantity, 720 hours a month; 2 TB = 2,000 GB. Only picks that could do the job have a price; the rest say "No price: it cannot do this job".
- **Fit table (tested):** API: containers best, virtual machine acceptable. Photo: function best, containers acceptable. Exports: object storage best, block storage acceptable. Notes: managed database best, virtual machine acceptable. Emails: queue best, managed database acceptable. Reads: cache best, managed database acceptable.
- **Check points (tested):** 2 TB costs $40 on object storage and $200 on block storage. The photo need costs $0.01 a month on a function and $29 on one virtual machine (720 x $0.04). Also: API on two containers $72, on two machines $58, on a function $485 (259 million requests of 100 ms); one container for photos runs 300 one-minute runs, $0.25; a database $72; the queue for 100,000 emails $0.04; a cache node $36.
- **Inputs:** tap a need, then tap a block. The block stays selected when the need changes, so the same block can be compared across needs. Outside the picture: Reset. No sliders.
- **Motion:** the chosen block card lifts toward the need and takes the colour of the fit; a line connects the need to the block in the same colour; the panel inside the picture names the block and its AWS name, what you manage, what the provider manages, the illustrative price and the one-line reason. All changes are CSS transitions.
- **Verdicts (all 38 characters or fewer):** nothing chosen "Now tap a block for this need"; best "Best fit for this load"; acceptable "Works, but costs more or needs work"; wrong "Wrong shape for this need".
- **What to notice:** the API on a function costs about seven times the containers; storing 2 TB on a disk costs five times the objects; a virtual machine for 20 seconds of work a day costs $29 a month.
- **Limits (in the fold):** made-up round prices, not AWS prices; one best and one acceptable block per need; real designs combine blocks; free tiers, discounts and set-up work left out. The picture also says "Prices are made up, not AWS prices."
- **Sources:** AWS service names and one-line definitions from AWS documentation (S3, EBS, EFS, EC2, ECS, Lambda; fetched 2026-10-24, dossier ids to be added); ALB and NLB [S15]; Aurora [S39]; DynamoDB [S40]; ElastiCache [S26]; SQS [S83 to S85].
