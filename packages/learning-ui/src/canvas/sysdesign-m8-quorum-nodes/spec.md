# Canvas spec: sysdesign-m8-quorum-nodes

- **Course and chapter:** system-design, 8.7 beat 2 ("Write to three of five, read from two").
- **Renderer:** custom component on `BeatFrame`, with `SvgNode` cards, `SvgButton` for the five tappable nodes and `SvgChip` for the buttons inside the picture. `block-map` is built for architecture maps with request paths, not for building two sets, so the five blocks are drawn here.
- **Claim:** a read is guaranteed to see the newest confirmed write when R + W is more than N, because every read group shares a node with every write group. With R + W = N a read can miss it.
- **Model (`model.ts`):** N = 5 nodes, each `x = 6` (version 1). Write phase: tap nodes to build the write set (W = their count). Confirm write: those nodes become `x = 7` (version 2). Read phase: tap nodes to build the read set (R = their count); the read returns the newest version among them. Found if at least one read node has version 2. If R + W > 5 found is true for every choice; if R + W <= 5 some choice misses. Worked values: W = 3, R = 2: reading the two nodes that missed returns x = 6. W = 3, R = 3; W = 4, R = 2; W = 5, R = 1; W = 1, R = 5: always found.
  - A node that is down cannot answer. A write or read set that includes a down node waits for an answer that never comes, so it stalls ("Not enough nodes up to confirm"); with two nodes down W = 4 cannot be confirmed.
- **Inputs:** tap nodes; the Confirm write and Switch off nodes chips inside the picture; outside the picture Reset and Auto-miss (confirms the write if it is ready, then picks the worst read nodes for the current R, 2 when none is picked yet).
- **What moves:** selected write nodes ring blue and show `x = 7 (v2)` after Confirm; selected read nodes ring amber; a node in both gets both rings; the client's pill shows the result; the header shows "W = 3, R = 2, R + W = 5 (not more than 5)" and the overlap verdict.
- **Verdicts:** "Read found the newest write"; "Read missed the newest write"; "Overlap guaranteed: R + W is over 5"; "A read can miss: R + W is not over 5"; "Not enough nodes up to confirm". Extra prompts: "Pick the nodes that get the write"; "Tap Confirm write"; "Now pick the nodes to read from".
- **Deviations from the written spec:** taps on a down node add it to the set and stall it, instead of refusing the tap, so the learner can see why W = 4 cannot be confirmed with two nodes down. Down is set with a "Switch off nodes" mode chip, not a double tap, because a tap already means "pick".
- **Accessibility:** the group label lists every node's value; each node is a real `role="button"` with its state in the name; rings are paired with the text of the header and verdict.
- **Sources:** [S45] Dynamo: N, R, W, (3, 2, 2) common; [S52] majority quorum (n + 1) / 2 and the limits of quorum reads.
