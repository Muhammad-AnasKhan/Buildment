# Canvas spec: sysdesign-m3-loss-toggle

- **Course and chapter:** system-design, 3.4 ("HTTP/1.1, HTTP/2 and HTTP/3"), beat 5 ("Drop a packet, compare the versions"). New slug. It matches the numbers of the watched scenes `sysdesign-m3-h2-stall` and `sysdesign-m3-h3-streams`.
- **Renderer:** custom beat canvas on `BeatFrame`, with the new `primitives/svg-chip.tsx` for the version chips. No existing primitive fits a per-packet animation, so the scene is built per input by `models/loss-compare.ts` (timelines and positions), the way `models/replica-lag-scene.ts` builds its variants.
- **Claim:** One lost packet delays different files depending on the HTTP version. HTTP/1.1: the lost file and every file queued behind it on that connection. HTTP/2: every stream. HTTP/3: only the stream that lost the packet (S12, S13).
- **Model** (`models/loss-compare.ts`): files a, b, c, one packet each, round trip 80 ms (S3); a packet crosses in half a round trip; a dropped packet's resend arrives one round trip later (illustrative). Usable times: no drop: HTTP/1.1 80, 160, 240 ms; HTTP/2 and HTTP/3 80, 80, 80 ms. Drop of file k: HTTP/1.1 file k and every later file one round trip later (drop a: 160, 240, 320); HTTP/2 all three at 160 ms; HTTP/3 file k at 160 ms, the others at 80 ms.
- **Inputs:** three version chips inside the picture (default HTTP/2); tap a packet (a button follows each packet along its lane, also at rest at the server) to drop it, tap again to undo; Replay under the picture. Default state: HTTP/2 with file a dropped.
- **Picture:** a Server and a Browser card with three lanes; packets fly along the lanes; the dropped packet stops part way, falls with a red cross and fades, the cross stays; the resend flies later in amber. On HTTP/2 the packets that arrived wait in a dashed "held by TCP" box until the resend arrives. Tags land on a millisecond strip, one row per file, green when on time, amber for the file that lost the packet, red for files delayed without losing one. The Browser pill counts ready files.
- **Numbers visible at once:** the three tags on the strip (a time per file).
- **Verdicts (38 characters or fewer):** "No loss: all 3 in 80 ms" (HTTP/2, HTTP/3) or "No loss: files arrive one by one" (HTTP/1.1); "HTTP/2: 1 loss delays all 3 files"; "HTTP/3: only {file} waits, 160 ms"; "HTTP/1.1: {file} and those behind it wait", or "HTTP/1.1: only c waits, 320 ms" when c is the dropped file.
- **Motion and reduced motion:** one loop of the network (1 second of the picture is 40 ms) and a pause at the end; tapping or choosing a version restarts it. With reduced motion the picture shows the final frame: every tag landed, nothing held, the cross where the packet was lost.
- **Accessibility:** each file has a `role="button"` with `aria-pressed` ("Drop the packet for file a" / "Undo the drop of file a"), reachable by keyboard whether or not the packet is in flight; chips are `role="button"` with `aria-pressed`; the SVG description gives the version, the dropped file and the usable time of each file.
- **Sources:** S12 RFC 9114 (HTTP/3, per-stream reliability); S13 RFC 9000 (QUIC streams); S3 napkin math (80 ms Western Europe to North America East).
