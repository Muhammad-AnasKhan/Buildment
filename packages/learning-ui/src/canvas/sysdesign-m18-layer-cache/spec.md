# Canvas spec: sysdesign-m18-layer-cache

- **Course and chapter:** system-design, 18.3 "Docker images and containers", beat 2 ("Change one file, see what rebuilds").
- **Renderer:** custom beat canvas on `BeatFrame`, `SvgRadioChip` (three files), `BeatChoice` (Dockerfile order, outside the picture), `VerdictBanner`. The stack view is new and local to this folder; neither `design-stepper` nor `block-map` fits a reorderable stack.
- **Claim:** A Docker build reuses every layer above the first changed one and rebuilds everything from there. Where a step sits decides how often it runs.
- **Model:** `model.ts`, unit tested. Order A: `FROM node:24-alpine` 0 s, `COPY . .` 0.3 s, `RUN npm install` 8 s, `CMD` 0 s. Order B: `FROM` 0 s, `COPY package*.json ./` 0.1 s, `RUN npm ci` 8 s, `COPY server.js ./` 0.3 s, `CMD` 0 s. Files: `README.md` (in `.dockerignore`, never copied), `server.js`, `package.json`. The first layer whose input changed, and every layer after it, is rebuilt; earlier layers are CACHED. Total = sum of rebuilt layer times (kept in tenths of a second).
- **Check points (tested):** A + server.js: `COPY . .`, install, `CMD`, 8.3 s. B + server.js: `COPY server.js`, `CMD`, 0.3 s. A + package.json: same layers as A + server.js, 8.3 s. B + package.json: package copy, `npm ci`, `COPY server.js`, `CMD`, 8.4 s. README.md in either order: nothing, 0 s.
- **Inputs:** three file chips in the picture (radio group; server.js is selected first); outside the picture one pair of buttons for the Dockerfile order.
- **Motion:** layer cards sit bottom to top; when the order changes they slide to their new places (CSS transform transition) and new cards fade in. Rebuilt cards turn amber and show their seconds; cached cards show a green CACHED pill. The "Build time" counter counts up from zero to the total after every change (a short requestAnimationFrame tween that ends exactly on the total; under reduced motion it shows the total at once).
- **Verdicts (all 38 characters or fewer):** B + server.js "Only the last copy step runs"; A + server.js "Everything after the copy reruns"; either order + package.json "Install reruns: dependencies changed"; README.md "Nothing changed: all layers cached".
- **What to notice:** the same edit costs 8.3 s in order A and 0.3 s in order B; a dependency change costs the install in both.
- **Limits (in the fold):** round times close to one run of the 13-package sample service, noisy with the network; real installs are longer; base-image updates, build arguments and multi-stage builds are left out.
- **Sources:** Docker build cache documentation (to add to the dossier); course measurement from challenge 17: editing server.js reused 1 of 4 steps with the naive order and 3 of 5 with the good order (7.3 s and 5.6 s).
