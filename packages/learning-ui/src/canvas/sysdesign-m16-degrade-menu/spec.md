# Canvas spec: sysdesign-m16-degrade-menu

- **Course and chapter:** system-design, 16.6 beat 2, "Break a service, choose a fallback". Playable; new slug.
- **Renderer:** custom beat canvas on `BeatFrame`: a row of six service chips (tap to break or fix), a phone-shaped screen with six feature cards (tap to cycle the fallback), an order button that lights only when the customer can order, `VerdictBanner`. One control outside the picture: Reset.
- **Claim:** What the customer still gets when a service fails depends on a fallback chosen ahead of time. With no fallback the page fails; with the right ones, the customer can still order when any one extra is down.
- **Input:** tap a service chip to break or fix it (several may be broken). Tap a feature card to cycle through its allowed fallbacks. Everything starts on "fail the page" with all services up.
- **Features** (`model.ts`): Shop list / Catalog / must work: fail, cached copy. Cart / Cart / must work: fail only (a card that shows "no fallback exists"; not a button). Payment / Payments / must work: fail, another way (cash on delivery). Delivery estimate / Routing / should work: fail, default range (30 to 45 min), hide. Picks for you / Picks / nice: fail, hide, cached popular items. Reviews / Reviews / nice: fail, hide, cached copy.
- **Model** (`evaluate`): a feature whose service is down and whose fallback is "fail the page" breaks the whole screen. Otherwise the card shows cached (amber), default (amber), another way (amber), hidden (grey) or live (green). The customer can order when no feature fails the page, Cart is up, the shop list is live or cached, and payment is live or another way. Verdict priority: Cart down, then the first page failure in table order, then payment by another way, then degraded features, then all live. Cart is checked first because its only option is to fail the page, and the table asks for "Cannot order: Cart is down" whatever the other fallbacks are.
- **Numbers to check** (tested): none broken "All features work"; Picks broken, all fail "Page fails: Picks is down"; Picks on hide, Reviews and Picks both on hide (2 degraded), Catalog on cached, Routing on default: "Customer can still order"; Cart "Cannot order: Cart is down"; Payments on another way "Orders work, cash on delivery only" (warn). With the safe set (hide for Picks and Reviews, default for Routing, cached for Catalog, another way for Payments) breaking any single service except Cart still lets the customer order.
- **Verdicts:** as above; every one is 38 characters or fewer ("Page fails: Payments is down" is the longest of its kind).
- **Layout note:** the six services are a row of chips above the screen, as the spec says; each feature card names its tier and shows "if down: ..." with the chosen fallback while its service is up, or the state it is in when it is down.
- **Reduced motion:** cards change colour and state without sliding or fading.
- **Accessibility:** every feature card is a button whose label reads like "Picks for you, service up, fallback: hide it"; every service chip is a toggle button "Picks service: up, press to break it".
- **Sources:** the fallbacks and the tiers are a course design; health checks and fail open [S19]; series availability from chapter 2.6 (a core path of three services at 99.9% is 99.7%, all six is 99.4%).
