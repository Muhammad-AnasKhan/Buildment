- **Course and chapter:** system-design, 1.2 beat 1 ("Functional: what users can do").

- **Claim:** Functional requirements are the actions users need the system to perform. You find them by listing the verbs.
- **Story:** A student uploads notes ("note saved"), searches CS101 ("3 notes found") and opens a note ("PDF shown"). After each, a message carries the verb to the feature list, which grows to "3: read". Verdict: "Functional: what users can do".

- **Sources:** none needed; Daftar is a fictional course app.
- **Ideal interactive (not built):** a requirement sorter where the learner taps each requirement card into Functional, Non-functional or Constraint and gets feedback per card (roadmap `[classify]`).
