# Canvas spec: sysdesign-m1-launch-day

- **Course and chapter:** system-design, 1.1 beat 1 ("One server, more students every minute").
- **Renderer:** custom beat canvas on `BeatFrame`, built on the reusable `primitives/traffic-playground.tsx` (also used by `sysdesign-m2-knee-play`). Replaces the earlier `scene` version of this slug; the slug and export name are unchanged.
- **Claim:** One server has a fixed capacity. As load nears it, every request waits longer, and past it the line grows without end, so pages time out.
- **Input:** students online, 10 to 100,000 on a log rail drawn inside the picture. Drag anywhere on the picture; arrow keys walk a ladder (10, 20, 50, 100, 200, 500, 1,000, 1,500, 1,800, 1,900, 2,000, 5,000, 10,000, 20,000, 50,000, 100,000), Page keys jump, Home and End go to the ends. A drag lands on two significant figures and snaps to 100, 1,000, 1,800 and 10,000 (the chapter's table rows). Default 1,000.
- **Model** (`models/server-load.ts`, `launchDay`): arrivals = students x 0.05 a second; busy = arrivals / 100; time per request = 10 ms / (1 - busy) (M/M/1); requests inside = busy / (1 - busy). Past 100% there is no steady state: the line grows by (arrivals - 100) every second.
- **Numbers to check against the chapter:** 100 students: 5% busy, 10.5 ms. 1,000: 50%, 20 ms. 1,800: 90%, 100 ms. 1,900: 95%, 200 ms. 10,000: 500% busy, line grows 400 a second.
- **Picture:** a Students card with a crowd of small figures under it that grows with the log of the count; request dots flowing to the Server card at a rate that rises with the load (capped, one dot stands for many); a line of dots in front of the server, one per request inside (up to 12, then an ellipsis); the server's pill shows the busy share and turns green, amber (from 70%) or red (from 100%); an inset curve of time per request against busy, with a dot that rides it and pins to the top with an arrow when it leaves the chart (above 200 ms). Past 100% the line grows to full, the server gets a red ring, and requests drop out of the line as timeouts.
- **Numbers visible at once:** students online (Students pill), busy share (Server pill), time per request or the line's growth (on the curve dot).
- **Verdict:** under 30% busy "Fast: the server is mostly idle"; under 70% "Fine: pages wait a little"; under 100% "Slower: requests wait in line"; at or past 100% "Overloaded: pages time out".
- **Motion:** request dots come from a fixed stream of slots thinned to the model's rate, so they arrive at random and never jump when the rate changes. The line steps forward as the server finishes requests. Reduced motion: a still frame with dots in flight and a full red line when overloaded.
- **Accessibility:** the picture is one `role="slider"` with a value text that says the count, the busy share, the time and the verdict. The SVG has a title and a description of the current state. Colour is never the only signal: the pill and the verdict say it in words.
- **Sources:** M/M/1 formulas, MIT OCW 2.854 notes [S6]; Brooker, "Latency Sneaks Up On You" [S7]. Research dossier, "Latency numbers, estimation, Little's law, queueing".
- **Limits shown to the learner:** made-up load numbers; M/M/1 shows the shape, not exact values; one dot stands for many requests.
